# 32-bit text-to-integer parses in product Go, one line per file: `count path`.
#
# The gate is `checkNumberParseSites` in numberparse.go, run by
# `./le repository check` and `./le repository tree-check`. Three things are an
# ISSUE: a file that parses a 32-bit integer and is not named here, a file whose
# count differs from its line, and a line whose file parses none. The count is
# EXACT, so deleting a justified parse leaves no free slot behind it.
#
# Each line records that somebody looked at the file's 32-bit parses and found
# no AS number read by hand. It does not say the file has nothing to do with AS
# numbers: `internal/core/bgp/asn/asn.go` is here because it is asn.Parse
# ITSELF, which is where an AS number is read, and the two halves of a dotted
# token are integers like any other.
#
# An AS number anywhere else is read with `asn.Parse` (internal/core/bgp/asn),
# which takes all three RFC 5396 spellings, and a file that does that is absent
# from this list.
#
# Adding a line is how a new parse is justified. Say in the commit message what
# the value is, and if it IS an AS number, call asn.Parse instead of writing the
# line. The evidence for the current population is the per-parser enumeration in
# plan/spec-bgp-as-notation.md, "Every Text-to-AS-Number Parser In The Tree".
#
# `./le repository check` names every file that differs from this list. Read
# what it names before you change a line.
