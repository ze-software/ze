Why Ze / Why Not Ze

Ze is a network operating system (NOS) with programmable routing. It combines its own BGP engine with Linux networking and network services, managed through one configuration and plugin engine. You can use it as a route controller, or evaluate it as the software that configures a router and its services.

Ze is pre-release software. This assessment was reviewed on November 16, 2026. APIs and configuration syntax can change. The feature inventory records implementation scope and maturity, including partial and experimental features. Corrections are welcome through the issue tracker.

Reasons to consider Ze

Programmable routing, with control of the device around it

Ze keeps ExaBGP's controller model: a process can receive BGP events and inject routes. Your controller can remain a separate program, written in a language that can read and write the process protocol. The Go plugin SDK provides another way to integrate custom logic.

That controller can run alongside the device functions Ze provides. The code includes interface configuration, routing-table installation, firewall rules and IPsec, plus access services such as L2TP and PPPoE. Each has its own scope and maturity record. A route-injection deployment can use the BGP functions without configuring those services.

For an existing ExaBGP deployment, ze exabgp migrate converts configuration and ze exabgp plugin bridges process scripts. The migration guide explains the differences to check with your own configuration and scripts before replacing a deployment.

Operator tools that share the configuration model

Ze uses YANG to describe configuration. Its CLI and web editor use that schema, so operators can inspect and edit the same configuration through either interface. The editor provides completion, comparisons and commit validation. The configuration editor guide shows the workflow.

Operational tools include a live BGP dashboard, a looking glass and ze doctor for configuration and runtime diagnostics. These are useful when the task is to understand the device as well as exchange routes. The operations guide describes the diagnostic commands.

Automation through native APIs and MCP

REST and gRPC are implemented command transports. They share an execution engine and expose command discovery and execution, with streaming for registered streaming commands. The gRPC service also provides configuration sessions. The API guide documents authentication and listener requirements.

Ze's Model Context Protocol (MCP) server builds tools from command metadata, so an AI assistant can discover commands and call the daemon. This gives an assistant access to the operator's tools. The MCP guide explains the connection and access controls.

API compatibility still matters when you choose an implementation. Ze's gRPC service uses Ze's command model, so an integration written for another daemon's protobuf service needs an adapter. API completion is unimplemented, and the REST/gRPC feature remains experimental. gNMI is a separate configuration and telemetry interface.

Deployment as a service or an appliance

Ze can run as a Linux daemon or in a container. There is also an immutable appliance image built with Linux and gokrazy, with a read-only root filesystem and persistent storage under /perm. The appliance guide and Docker guide describe those deployment choices.

Optional subsystems have build tags, so you can compile a focused service or include the wider network OS. An omitted subsystem's code and schema are excluded from the build. The available functions therefore depend on both the build and its configuration.

Routing policy, monitoring and protocol tools

BGP functions include route-server and route-reflector plugins, routing information base (RIB) storage, graceful restart and filter plugins. Custom plugins can extend policy through the same plugin interfaces. The plugin guide explains those interfaces and their configuration requirements.

For monitoring and analysis, Ze includes BGP events, a looking glass and MRT recording. The MRT recorder can write UPDATEs, all BGP messages and periodic TABLE_DUMP_V2 RIB snapshots. MRT recording is experimental. The MRT guide also describes tools to inspect and replay recorded data.

Standalone tools include ze bgp decode, ze bgp encode and ze config validate. They are useful for protocol debugging and offline configuration checks, even when you do not run Ze as the router.

Reasons to choose another implementation

Your deployment requires a released, operationally established NOS

Ze has no published release. Its test suites and interoperability labs provide evidence about specific behavior, but they do not establish a history of production operation. A network that requires an established release and support process needs an implementation that already meets those requirements.

The distinction applies across the network OS. OSPFv2, OSPFv3 and IS-IS exist, and the code includes BFD, MPLS, IPsec and subscriber access functions. OSPF, IS-IS and PPPoE remain experimental and partial. Their presence in the binary is a reason to evaluate the documented behavior in a lab, rather than assume that the whole routing suite is ready for your network.

You need a feature Ze does not provide

The feature inventory records what each feature implements and the evidence behind its maturity. The comparison identifies gaps such as BGP confederation support and PIM multicast routing. Check the behavior your deployment depends on, including the selected dataplane, rather than infer support from a protocol name.

The standards coverage pages describe what has been tested and what is missing. They list tests that still need checking separately from behavior Ze does not implement. A feature label or a large test count alone does not tell you whether Ze meets your network's requirements.

Your project requires a different license or maintenance model

Ze is licensed under AGPL-3.0-only. If your project requires a permissive license, Ze does not meet that requirement. The license and contribution policy describe the project terms and contribution requirements.

Ze is developed with AI coding assistants, with Thomas Mangin directing the architecture and development decisions. Specifications, tests and independent review constrain that process. If your organization requires a larger maintainer team or a contracted support arrangement, evaluate those requirements separately from the feature list.

Engineering tradeoffs

Plugins share a contract, with a choice of process boundary

Ze separates BGP functions such as RIB storage and route-server behavior into plugins. Internal plugins run inside the daemon and use DirectBridge for typed calls after startup. External plugins run in separate processes and communicate through the process protocol. The separation lets a plugin be replaced without moving its policy into the BGP engine.

Internal plugins share the daemon's address space. External processes provide a process boundary, with transport and serialization costs. Both forms still need correct lifecycle handling and event ordering.

Performance depends on the workload

Ze is written in Go and uses pooled data and lazy wire parsing to reduce allocation and decoding costs. WireUpdate retains the supplied payload and parses sections when needed. These techniques reduce particular costs, and their effect on throughput depends on the workload.

The performance results describe measured scenarios, with their dates and environments. They cannot establish a general percentage cost for Go, a plugin boundary or another implementation. For a deployment decision, use the benchmarking guide to test your route counts, policies and peer topology, and check that all expected routes arrive.

Process IPC and management APIs serve different callers

External plugins use a multiplexed text protocol, while operators and automation can use REST, gRPC or MCP. A custom plugin therefore needs to implement the plugin contract even if its application already uses a management API. The process protocol reference describes that contract, and the API guide describes daemon management.
