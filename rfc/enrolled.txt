# RFC requirement enrolment -- the gate's scope.
#
# columns: <rfc-stem>\t<why this RFC is enrolled>
#
# An enrolled RFC has EVERY MUST-level requirement in rfc/short/<stem>.md either
#   (a) covered by a positive AND a negative test tagged `RFC requirement: <ID> <polarity>`, or
#   (b) annotated in the summary with a reason: {not-applicable: why} / {gap: why} /
#       {single-polarity: <polarity>; why}
# `make ze-rfc-check` enforces this. See ai/skills/ze-rfc.md.
#
# This file GROWS ONLY. Un-enrolling an RFC fails the gate: obligations that were once
# proven cannot quietly stop being proven. Adding a row is a deliberate act taken once the
# tests exist -- writing a summary does NOT enroll it.
#
# The un-enrolled remainder is NOT hidden: every summary appears in ai/RFC-REQUIREMENTS.md
# marked "not enrolled", which is the explicit tracked backlog required by
# ai/rules/testing.md ("Back-Fill New Test Types"). An empty file fails the gate rather
# than reporting clean -- clean must mean "I compared things and found nothing", never
# "I compared nothing" (ai/rules/fail-closed-guards.md).

rfc7606	Revised UPDATE error handling: the error-handling contract for every UPDATE Ze parses. Pilot for this system -- ~60 near-1:1 tests already exist and the one real divergence (5.1 MP ordering, docs/architecture/wire/mp-nlri-ordering.md) proves the {gap} path is honest rather than an escape hatch.
rfc792	ICMP Echo/Echo Reply, the only part of ICMP ze exercises (ping, show ping, ping-monitor). Gated obligations are the echo request's Type/Code/Checksum, which internal/core/probe BuildICMPEcho emits and the probe tests pin; the responder-only obligations (data returned unchanged, reply formation) are {not-applicable} because ze is the echo requester, never the echoer.
rfc8671	Support for Adj-RIB-Out in BMP: three MUSTs over the BMP Per-Peer Header (internal/component/bgp/plugins/bmp). RFC8671-x-1 (O flag is bit 4) both polarities: PeerFlagO == 1<<4 and a flags byte with bit 4 set decodes as Adj-RIB-Out while bit 3 does not (TestRFC8671OFlagBit4). RFC8671-x-2 (when O=1 the L flag is also set) both polarities: the sent direction sets O and L (TestPeerHeaderFromEventAdjRIBOut), the received direction sets neither (TestPeerHeaderFromEventAdjRIBIn). RFC8671-x-3 (Adj-RIB-Out Peer Up carries the same OPENs as Adj-RIB-In) is {single-polarity: positive}: ze sources both OPENs from the per-peer openCache (bmp.go:757-772) independent of the O flag, proven round-tripping in TestBMPPeerUpRoundTrip. Ledger row unchanged (no gap).
rfc6608	Subcodes for BGP Finite State Machine Error: three MUSTs requiring a code-5 FSM Error NOTIFICATION with subcode 1/2/3 (plus the 1-octet message type) on an unexpected message in OpenSent/OpenConfirm/Established. Disclosed in the docs/features/rfc-status.md RFC 6608 row (Partial).

rfc8203	Administrative Shutdown Communication: five MUST-level requirements over the Cease NOTIFICATION shutdown message, all bound to the message codec (internal/component/bgp/message/notification.go). RFC8203-2-1 (subcode 2/4) is proven by ShutdownMessage extracting for Admin Shutdown/Reset and returning empty for any other subcode; RFC8203-2-3 (UTF-8) and RFC8203-2-4 (MUST NOT interpret invalid UTF-8) by a valid message round-tripping while an invalid sequence is rejected; RFC8203-6-1 (shortest form) by an overlong 0xC0 0xAF encoding being rejected where the canonical form is accepted (Go utf8.Valid enforces shortest form).
