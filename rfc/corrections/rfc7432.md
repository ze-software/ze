# RFC 7432 corrections

Retired 2026-09-26: `RFC7432-9.2.1-5` states no obligation RFC 7432 carries. The row said
a PE creating MAC forwarding state from received MAC/IP routes MUST enable forwarding to
remote destinations. Read §9.2.1, §9.2.2, §4, §10.1, §13.2 and §14.1, then the whole text:
§9.2.1 says the opposite, that "this document does not require PEs to create forwarding
state for remote MACs when they are learned in the control plane", and §4 leaves the
contents of the Layer 2 forwarding table a local decision. The only MUST about creating
MAC forwarding state is the default-gateway one in §10.1, which RFC7432-10.1-5 already
carries, and the conditions on installing it are §9.2.2, carried by RFC7432-9.2.2-1 and
RFC7432-9.2.2-2. The row carried no tag, so no tag moved; its id leaves the §9.2.1
`unsourced-ids` of rfc/extraction/rfc7432.json.

Correction 2026-10-03: `RFC7432-8.2.1-9` retains §8.2.1, "Support of this
route is REQUIRED." Owner ruling 2026-10-02 permits positive-only
evidence for route support. Configuration, route-command encoding and session
ingress exercise that support in Ze's documented BGP control-plane role.
The nonzero-label claims now name `RFC7432-8.2.1-2`: "The MPLS label in the
NLRI MUST be set to 0." The malformed-width ingress test remains a framing
calibration, with its assertions unchanged, not a negative of route support.
These claims do not establish every per-ES obligation or full EVPN PE conformance.

The support summary distinguishes source-backed origination guards from
unverified row-specific proof and absent redundancy or forwarding procedures.
`RFC7432-9.2.1-2` no longer describes a zero-address fallback:
`message.BuildEVPN` refuses a missing, unspecified or multicast next hop.
Explicit next-hop ownership remains unverified, so that row retains its gap.
The neighboring MAC/IP, per-EVI and IMET rows now distinguish configured
community transport from missing guards or unverified assignment proof.
They no longer claim `l2vpnRouteToEVPNParams` drops configured communities.
The `RFC7432-10-1` sender test retains the mandatory first label from §7.2
while checking the §10 bit lengths and exact IPv4 and IPv6 address bytes.
This correction records source and test changes, not a new execution result.
