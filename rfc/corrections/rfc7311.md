# RFC 7311 corrections

Why a requirement row of `rfc/short/rfc7311.md` changed level, text, or citation.
The summary is the working document; this file is the record the level
ratchet reads (`checkLevelRatchet`, `internal/le/rfc/check_ratchets.go`).

Correction 2026-09-21: `RFC7311-3.1-1` was extracted as "A BGP speaker MAY attach an AIGP
attribute to a connected route, a route learned from an IGP, or a route already carrying
AIGP", cited Section 3.1. Section 3.1, Applicability Restrictions and Cautions, carries no
RFC 2119 keyword at all; it states the applicability restriction the row now quotes. The
origination list the row used to carry is in Section 3.4.1 and now stands as
`RFC7311-3.4.1-4`. `RFC7311-3.2-2` was corrected the same way: it cited Section 3.2 while
carrying the AIGP_SESSION default, which Section 3.3 states, so the row now carries
Section 3.2's own remaining obligation ("If an AIGP attribute is received and its first
AIGP TLV contains the maximum value 0xffffffffffffffff, the attribute SHOULD be considered
to be malformed and SHOULD be discarded as specified in this section") and the AIGP_SESSION
default stands as `RFC7311-3.3-5`. Both ids keep their anchors, because an id is permanent
and is parsed from the section its line cites.

Correction 2026-09-27: `RFC7311-3-3` read "Unknown TLV types MUST be preserved and not discarded", cited Section 3. No sentence of RFC 7311 obliges an implementation to preserve TLVs of unknown types: Section 3 says "Use of other TLV types is outside the scope of this document", and the one statement about unknown types, Section 3.2's "Note that an AIGP attribute MUST NOT be considered to be malformed because it contains more than one TLV of a given type or because it contains TLVs of unknown types", stands as `RFC7311-3.2-6`. The signed-off extraction maps the Section 3 MUST that states preservation to this id, so the row now quotes it: "Any other AIGP TLVs in the AIGP attribute MUST be passed along unchanged if the AIGP attribute is passed along." That sentence binds the AIGP TLVs (Type 1) after the first, the term Section 3 defines, not TLVs of unknown types. The level stays MUST.

Correction 2026-10-08: `RFC7311-3-2` was listed for retirement when interpreted as an invented independent total-length mandate. The current row instead quotes §3: "The value field of the AIGP attribute is defined here to be a set of elements encoded as \"Type/Length/Value\" (i.e., a set of TLVs)." Under owner D-3 retain that format definition at MUST, its identity, §3 reverse mapping and existing format verdict. AIGPMetricOffset validates complete TLV boundaries; this reconciliation invents no independent total-length or error-action obligation and requires no mechanical rejudgment of the unchanged row.
