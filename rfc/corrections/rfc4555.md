# RFC 4555 corrections

Why a requirement row of `rfc/short/rfc4555.md` changed level, text, or citation, or why a
sentence of the RFC gained a row. The summary is the working document; this file is the
record the level ratchet reads (`checkLevelRatchet`, `internal/le/rfc/check_ratchets.go`).

Correction 2026-10-11: `RFC4555-x-4` quotes the §3.4 permission to advertise additional
addresses in IKE_AUTH, and no row carried the later advertisement. Read §3.6: "This
information can be updated by sending an INFORMATIONAL exchange request message that
contains either one or more ADDITIONAL_IP4_ADDRESS/ADDITIONAL_IP6_ADDRESS notifications or
the NO_ADDITIONAL_ADDRESSES notification." is now `RFC4555-3.6-2`, and "The initiator MAY
include these notifications in the same request as UPDATE_SA_ADDRESSES." is now
`RFC4555-3.6-3`. The -x-4 row is unchanged.

Correction 2026-10-11: `RFC4555-3.9-1` obliges the address-updating messages to carry
NO_NATS_ALLOWED, and no row carried what that notification holds. Read §4.2.6: "The
notification data contains the IP addresses and ports from/to which the packet was sent."
That obligation is now `RFC4555-4.2.6-1`, levelled MUST under D-3, because the §3.9
responder check, `RFC4555-3.9-3`, compares exactly these fields. The -3.9-1 row is
unchanged.
