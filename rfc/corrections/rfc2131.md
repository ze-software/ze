# RFC 2131 corrections

Correction 2026-09-29: `RFC2131-4.1-15` is a new row. The narrowing audit found that `RFC2131-4.1-7` drops the §4.1 sentence "The 'file' field MUST be interpreted next (if the 'option overload' option indicates that the 'file' field contains DHCP options), followed by the 'sname' field." Extraction site 4.1:9 excluded it as a duplicate of 4.1:8, which states a different obligation; the site now maps to the new row. The server honors no received option overload, so the row carries a gap.

Correction 2026-09-29: `RFC2131-4.1-7` changes from not-applicable to a gap. The row binds the receiver of client messages, a role the server fills, and its not-applicable reason rested on the absence of option overload handling, which `ai/rules/rfc-compliance.md` does not accept for a role Ze fills. The server reads only the options field and never interprets an option overload (52) found there, so the row carries the same gap as `RFC2131-4.1-15`.
