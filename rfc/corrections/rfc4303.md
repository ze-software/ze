# RFC 4303 corrections

Correction 2026-09-30: `RFC4303-1-1` quoted the whole §1 sentence, which states two ways
integrity-only ESP is offered, and ze provides one of them. The sentence is split on the
main thread's ruling R3: "Integrity-only ESP MUST be offered as a service selection option,
e.g., it must be negotiable in SA management protocols" is now `RFC4303-1-2`, a gap row, and
-1 keeps "MUST be configurable via management interfaces" with its tests. Same level for
both rows.

Correction 2026-10-11: `RFC4303-3.4.4.1-1` quotes steps 1 and 2 of the receive processing
list and stops before step 3. Read §3.4.4.1, step 3: "If the default padding scheme (see
Section 2.4) has been employed, the receiver SHOULD inspect the Padding field before
removing the padding prior to passing the decrypted data to the next layer." That obligation
is now `RFC4303-3.4.4.1-2`, at SHOULD, as a gap: Ze's Go does no ESP packet processing, and
nothing in this repository shows that Linux XFRM inspects the Padding bytes.
