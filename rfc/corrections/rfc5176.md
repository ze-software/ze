# RFC 5176 corrections

Why a requirement row of `rfc/short/rfc5176.md` changed level, text, or citation,
or was retired. The summary is the working document; this file is the record the
ratchets read (`checkLevelRatchet`, `checkRetiredRequirements`,
`internal/le/rfc/check_ratchets.go`).

Correction 2026-09-30: `RFC5176-2.3-7` states the §2.3 rule for a NAS without multi-session support, "A NAS that does not support dynamic authorization changes applying to multiple sessions MUST send a CoA-NAK or Disconnect-NAK in reply; an Error-Cause Attribute with value 508 (Multiple Session Selection Unsupported) SHOULD be included." The narrowing audit of 2026-09-28 named the §3 sentence the row does not state, "If all NAS identification attributes match, and more than one session matches all of the session identification attributes, then a CoA-Request or Disconnect- Request MUST apply to all matching sessions." No row is added for it. Read together with §2.3, the §3 sentence binds a NAS that supports changes applying to multiple sessions, and Ze does not: a request matching more than one session is answered with a NAK carrying Error-Cause 508 (coa.go, the multi-session branch; TestRFC5176MultipleMatchingSessionsNAKed and TestRFC5176CoAMatchingSeveralSessionsIsNAKed, both tagged RFC5176-2.3-7). The extraction maps site 3:2 to this row. The row's text, level and id are unchanged.

Correction 2026-09-30: `RFC5176-3.2-1` states the §3.2 "Authorize Only" rule, "A NAS MUST respond to a CoA-Request including a Service-Type Attribute with value "Authorize Only" with a CoA-NAK; a CoA-ACK MUST NOT be sent." and the NAK owed by a NAS that does not support that value. The narrowing audit of 2026-09-28 named two further sentences. §3.2, "If other attributes are included in such a CoA-Request, a CoA-NAK MUST be sent; an Error-Cause Attribute with value 401 (Unsupported Attribute) SHOULD be included." and §3.3, "A NAS receiving a CoA-Request containing a Service-Type Attribute with a value of "Authorize Only" but lacking a State Attribute MUST send a CoA-NAK and SHOULD include an Error-Cause Attribute with a value of 402 (Missing Attribute)." No row is added for either. Each MUST names a CoA-Request carrying Service-Type "Authorize Only", and the row's first sentence already requires a CoA-NAK for every such request, whatever else it carries or lacks, so each is a narrower case of the row's obligation. Their SHOULD clauses choose the Error-Cause for a NAS that processes "Authorize Only"; Ze supports no Service-Type value in a CoA-Request, so the row's second sentence governs it and Ze sends 405 (coa.go, the Service-Type branch, which runs before the attribute and State checks). The extraction maps sites 3.2:5 and 3.3:6 to this row. The row's text, level and id are unchanged.

Retired 2026-09-29: `RFC5176-3.5-2` quoted the same §6.1 sentence as RFC5176-6.1-1, "A Dynamic Authorization Server MUST silently discard Disconnect-Request or CoA-Request packets from untrusted sources." Read §2.3, §3.5 and §6.1: the sentence appears once, in §6.1, so the two rows were one obligation, and RFC5176-6.1-1 keeps it with its own positive and negative tags. The retired row's two tags, on TestCoAListenerInvalidAuth and TestCoAListenerUnknownSession (internal/component/l2tp/plugins/authradius/rfc5176_coa_listener_test.go), proved the discard of a packet whose Request Authenticator is wrong. The RFC5176-3.5-1 tags on the same two units already state that claim, so the tags were dropped and the tests stay.
