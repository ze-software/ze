# RFC 2865 corrections

Why a requirement row of `rfc/short/rfc2865.md` changed level, text, or citation,
or was retired. The summary is the working document; this file is the record the
ratchets read (`checkLevelRatchet`, `checkRetiredRequirements`,
`internal/le/rfc/check_ratchets.go`).

Retired 2026-09-26: `RFC2865-x-1` said to "use constant-time comparison for authenticator
verification", cited to "Implementation Constraints", which is not a section of RFC 2865.
Read §3 (the Response Authenticator), §4.2, §4.4 and §8 Security Considerations, then the
whole text: no sentence mentions timing or constant-time comparison, and §3 only defines
the MD5 value the NAS compares. The row stated a Ze implementation choice at SHOULD level,
not an RFC obligation. It carried no test tag, no extraction mapping and no audit verdict,
so nothing moved.

Retired 2026-09-27: `RFC2865-2.5-2` states an obligation RFC 2865 does not carry. Read §2.5 and the whole text: RFC 2865 says nothing about backing off between retransmissions. RFC 5080 §2.2.1 states it: "implementations SHOULD support congestive backoff." RFC 5080 has no summary in rfc/short, so under owner decision D-10 the row is retired, and a journal row asks for it to be enrolled. The row carried no tag.

Retired 2026-09-27: `RFC2865-3-5` states no obligation RFC 2865 carries (owner decision D-2). Read §3, then the whole text for every sentence about a source address: each one binds the server, "A RADIUS server MUST use the source IP address of the RADIUS UDP packet to decide which shared secret to use" among them, and none tells a client to drop a response from another address. RFC 5080 §2.2.1 and §2.2.2 were read too: a client processes the first response with a valid Response Authenticator, and no source-address rule appears. Its three tags, on TestRFC2865ResponseSourceAddress in internal/component/radius/rfc2865_test.go and TestClientExchangeAccept in internal/component/radius/client_test.go, were removed; the tests stay.
