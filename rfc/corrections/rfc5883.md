# rfc5883 corrections

Why a requirement row of `rfc/short/rfc5883.md` changed level, text, or
citation, or was retired. The summary is the working document; this file is the
record the ratchets read (`internal/le/rfc/check_ratchets.go`).

Retired 2026-09-27: `RFC5883-7-1` states no obligation RFC 5883 carries. Read §2,
§3, §5, §6 and §8, then the whole text: the only congestion sentence is §2's,
addressed to the operator, who must provision the transmit rates. The
implementation-side rule is RFC 5880 §7, which rfc/short/rfc5880.md carries as
RFC5880-7-1 with the same gap. No test tagged this row, so no tag moved.

Retired 2026-09-27: `RFC5883-7-2` states no obligation RFC 5883 carries. Read §2,
§3, §5, §6 and §8, then the whole text: no sentence tells a BFD implementation to
reduce its transmit rate when it detects congestion. RFC 5880 §7 does, and
rfc/short/rfc5880.md carries it as RFC5880-7-2 with the same gap. No test tagged
this row, so no tag moved.

Retired 2026-09-30: `RFC5883-5-2` duplicated the obligation of `RFC5883-5-1`.
Read §5, which holds one normative sentence, "the UDP destination port MUST have
a value of 4784", and one explanatory sentence ("This can aid in the
demultiplexing and internal routing of incoming BFD packets.") that obliges
nothing; §5's only extraction site already maps to `RFC5883-5-1`, and the
parent's narrowing audit of 2026-09-28 called this row for retirement. Its two
tags, on TestRFC5883SingleHopControlPort and TestRFC5883SeparatePortsPerMode in
internal/component/bfd/rfc5883_test.go, were deleted rather than moved: they
assert the bound local ports, and `RFC5883-5-1` is proven on the wire by
TestRFC5883MultiHopControlSentToPort4784OnTheWire and
TestRFC5883SingleHopControlNeverAddressesPort4784. This is the third
retirement in the 7-row stem (D-7: reported).
