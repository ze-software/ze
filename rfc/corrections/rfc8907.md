# RFC 8907 corrections

Why a requirement row of `rfc/short/rfc8907.md` changed level, text, or citation,
or was retired. The summary is the working document; this file is the record the
ratchets read (`checkLevelRatchet`, `checkRetiredRequirements`,
`internal/le/rfc/check_ratchets.go`).

Correction 2026-09-28: `RFC8907-4-4` dropped its `{single-polarity: positive}` marker. The marker said a single-exchange client has no constancy violation to test, but the client does hold a refusal path for "This field does not change for the duration of the TACACS+ session": trySend in internal/component/tacacs/client.go refuses a reply whose session_id differs from the request's. The row now carries a positive and a negative tag in internal/component/tacacs/rfc8907_header_test.go. Same id, same text and level.

Correction 2026-09-28: `RFC8907-5.4.2.6-2` is narrowed to its own sentence, "It MUST NOT be set to this value when requesting any other operation." The row also quoted the preceding sentence, which `RFC8907-5.4.2.6-1` already carries with its `{feature-declined}` annotation, so the row claimed an obligation it could not be tested for. rfc/extraction/rfc8907.json maps site 5.4.2.6:2 to this row with exactly the narrowed text. "This value" is TAC_PLUS_AUTHEN_SVC_ENABLE, named by the sentence before it. Same id and level.

Correction 2026-09-28: `RFC8907-x-1` keeps its text. The narrowing audit named §4.3, "For example, a server MUST be configured to time out a Single Connection Mode TCP connection after a specific period of inactivity to preserve its resources.", as an obligation the row dropped. It binds the TACACS+ server, a role Ze does not fill: internal/component/tacacs only dials out as a client. rfc/extraction/rfc8907.json already records the sentence as site 4.3:3, excluded as binds-another-role, so no row is owed for it.
