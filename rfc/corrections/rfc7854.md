# RFC 7854 corrections

Why a requirement row of `rfc/short/rfc7854.md` changed level, text, or citation.
The summary is the working document; this file is the record the level
ratchet reads (`checkLevelRatchet`, `internal/le/rfc/check_ratchets.go`).

Correction 2026-09-21: `RFC7854-x-11` was published [MUST]. Section 3.3, Lifecycle of a
BMP Session, states the Termination message at permission strength: "The router MAY send
a Termination message prior to closing the session." The MUST that section 4.5 carries is
a different obligation, on what a router does AFTER it sends one, so it does not raise
this row. The row is corrected to [MAY].

Retired 2026-09-29: `RFC7854-5-3` binds a router that monitors both pre-policy and
post-policy Adj-RIB-In for one peer, which Ze does not implement. Read §5 and §4.2,
then the whole text. The row quoted the whole §5 sentence, and its second clause
("if the route in question was previously announced with L flag both clear and set,
the withdraw MUST similarly be sent twice") needs one received route announced with
L clear and again with L set. `peerHeaderFromEvent` sets L only on the sent
direction, together with the O flag of RFC 8671, so a received route is announced
with L clear alone and the twice-sent withdraw has no input. The first clause holds
for Ze and has its own row, `RFC7854-5-4`, quoting it verbatim. Both tags moved
there with the same polarity: the positive tag of TestRFC7854LFlagFollowsPolicy and
the negative tag of TestRFC7854LFlagNotDecidedByBody
(internal/component/bgp/plugins/bmp). Extraction site 5:5 (5:4 under the rfc2119
register) now maps to `RFC7854-5-4`. The second clause gets no `{gap}` row: it is
conditional on a route announced with the L flag both clear and set, and only the
optional post-policy Adj-RIB-In view, which §5 leaves to the implementation ("A BMP
speaker may send pre-policy routes, post-policy routes, or both"), produces that
route. Ze does not offer that view, so the condition never holds and Ze owes no
twice-sent withdraw. The summary's `Support remaining` row discloses the absent view.
