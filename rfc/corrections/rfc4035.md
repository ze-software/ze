# rfc4035 corrections

Why a requirement row of `rfc/short/rfc4035.md` changed level, text, or citation,
or was retired, and why an obligation the parent's narrowing audit found dropped
has no row of its own. The summary is the working document; this file is the
record the ratchets read (`internal/le/rfc/check_ratchets.go`).

Correction 2026-09-30: `RFC4035-2.2-1` quotes the lead-in of §2.2's list, and the
narrowing audit of spec-rfc-verdict-test-fix-pass found the list item "The RRSIG
Algorithm, Signer's Name, and Key Tag fields identify a zone key DNSKEY record at the
zone apex." dropped. It gets no row of its own: every item of that list constrains the
RRSIG records of a signed zone, and Ze signs no zone. No Go code under internal/,
pkg/ or cmd/ creates a DNSKEY, RRSIG, NSEC or DS record, and geodns synthesizes
A, AAAA, SRV, SOA and NS answers only. The row's {not-applicable} finding covers the
item, and the row keeps its text.

Correction 2026-09-30: `RFC4035-3.1.1-4` quotes §3.1.1's TC rule for RRSIG records,
and the narrowing audit found §3.1.4's parallel sentence "If space does not permit
inclusion of the DS or NSEC RRset and associated RRSIG RRs, the name server MUST set
the TC bit" dropped. It gets no row: it binds a security-aware name server answering
from a signed zone that holds DS or NSEC RRsets, and neither geodns nor as112 holds a
DS, NSEC or RRSIG record to include, so the condition never arises. The row's
{not-applicable} finding is the same one, and the row keeps its text.

Correction 2026-09-30: `RFC4035-4.3-1` quotes "A security-aware resolver MUST be able
to determine whether it should expect a particular RRset to be signed." The narrowing
audit found the next sentence, "More precisely, a security-aware resolver must be able
to distinguish between four cases:", dropped. It gets no row: it is the lead-in of the
Secure, Insecure, Bogus and Indeterminate list that restates the same obligation of
the same security-aware resolver, and Ze runs no validating resolver. The resolver's
whole DNSSEC surface is dnssecDecision in internal/component/resolve/dns/resolver.go,
which reads the rcode alone. The row's {not-applicable} finding covers it.
