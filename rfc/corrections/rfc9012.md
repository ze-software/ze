# RFC 9012 corrections

Retired 2026-09-30: `RFC9012-13-7` binds the speaker that interprets the single-instance sub-TLVs of a Tunnel TLV to build a tunnel, which Ze does not implement. It quoted §13, "If a Tunnel TLV has more than one of any of these sub-TLVs, all but the first occurrence of each such sub-TLV type MUST be disregarded." Read §13 and the whole text: the sub-TLVs it names are Tunnel Egress Endpoint, Encapsulation, DS, UDP Destination Port, Embedded Label Handling, MPLS Label Stack and Prefix-SID, and disregarding one is an act of the party that reads them to encapsulate traffic. Ze reads none of them: it decides whether the attribute is malformed and passes it along, and `TunnelTLV.Preference` (an RFC 9830 sub-TLV, not one of the seven) has no caller outside `internal/test/decode`. The carrier's part of the same paragraph stays as `RFC9012-13-8` (not malformed) and `RFC9012-13-9` (all sub-TLVs propagated). Its two tags, on `TestRFC9012DuplicateSingleInstanceSubTLVs` in `internal/core/bgp/attribute/rfc9012_test.go`, proved the RFC 9830 Preference rule that the same lines tag as `RFC9830-2.4-1`, so they were dropped under ruling R2; the test stays. Extraction site 13:7 is now excluded as binds-another-role.
