# RFC 2516 corrections

Why a requirement row of `rfc/short/rfc2516.md` changed level, text, or citation.
The summary is the working document; this file is the record the level
ratchet reads (`checkLevelRatchet`, `internal/le/rfc/check_ratchets.go`).

Correction 2026-09-21: `RFC2516-7-1` was extracted as "AC MUST verify SESSION_ID + source
MAC pair on every Session and PADT packet", cited "(Security, §7)". Section 7 is LCP
Considerations and states no such rule; Section 9, Security Considerations, states only
the AC-Cookie and Service-Name advice. The document does state the obligation this row
carries, in two places. Section 4, of the SESSION_ID field: "The value is fixed for a
given PPP session and, in fact, defines a PPP session along with the Ethernet SOURCE_ADDR
and DESTINATION_ADDR." Section 6: "The SESSION_ID MUST NOT change for that PPPoE session
and MUST be the value assigned in the Discovery stage." Same requirement id, same MUST
level, corrected text, and the tests bound to it in
internal/component/l2tp/pppoe/server_test.go prove exactly that pairing. The id keeps its
Section 7 anchor, because an id is permanent and is parsed from the section its line
cites.
