# RFC 9085 corrections

Why a requirement row of `rfc/short/rfc9085.md` changed level, text, or citation.
The summary is the working document; this file is the record the level
ratchet reads (`checkLevelRatchet`, `internal/le/rfc/check_ratchets.go`).

Correction 2026-09-21: `RFC9085-2.1-1` was published [MUST]. Section 2.1 states the
placement rule at lowercase should: "These TLVs should only be added to the BGP-LS
Attribute associated" with the Node NLRI that originates the corresponding IGP
TLV/sub-TLV. Sections 2.2 and 2.3 repeat the same sentence for Link and Prefix NLRI.
Section 1.1 puts RFC 2119 force on the keywords only "when, and only when, they appear in
all capitals", so the lowercase should is not a MUST. The row is corrected to [SHOULD].

Retired 2026-09-30: `RFC9085-2.1.2-3` duplicated `RFC9085-2.1.2-2`. Read §2.1.2: it states
the SR Capabilities TLV's Reserved rule once, "Reserved:  1 octet that MUST be set to 0 and
ignored on receipt.", and both rows quoted that span at the same level. The row is merged
into `RFC9085-2.1.2-2`, which keeps its text and level. Its tags moved to
`RFC9085-2.1.2-2`: the positive on TestRFC9085SRCapabilitiesIgnoresReservedAndUndefinedFlags
in internal/component/bgp/plugins/nlri/ls/attr_test.go became a `RFC9085-2.1.2-2` tag,
and the positive and negative on the IS-IS units TestRFC9085ISISOriginatedCapabilitiesReservedZero
and TestRFC9085ISISAllOnesSourceNeverReachesReserved (internal/plugins/isis/rfc9085_bgpls_export_test.go)
and the OSPF units TestRFC9085OSPFOriginatedCapabilitiesFlagsReservedZero and
TestRFC9085OSPFSourceReservedNeverOriginated (internal/plugins/ospf/rfc9085_bgpls_export_test.go)
fold into the `RFC9085-2.1.2-2` tags those units already carried with the same claim.

Correction 2026-10-08: `RFC9085-2.2-1` records the separate §2.2 recommendation: "These TLVs should only be added to the BGP-LS Attribute associated with the Link NLRI that describes the link of the IGP node that is originating the corresponding IGP TLV/sub-TLV described below." Retain the existing Node identity and its 2026-09-21 level correction. Native IS-IS and OSPFv2/v3 fixtures now distinguish parallel links by complete IDs or interface addresses and exclude Link attributes from populated wrong-class objects; separate exporter assertions preserve exact descriptors, SID values and multiplicity. Independent judgment and native bindings establish this conditional placement duty for implemented producers. Native IS-IS 1172 remains absent; RFC 9085 defines no corresponding OSPF bundle feature. This is composed native derivation and exporter association, not a single integrated daemon run or a receiver-rejection MUST.

Correction 2026-10-08: `RFC9085-2.3-1` records the separate §2.3 recommendation: "These TLVs should only be added to the BGP-LS Attribute associated with the Prefix NLRI that describes the prefix of the IGP node that is originating the corresponding IGP TLV/sub-TLV described below." Native IS-IS fixtures cover emitted 1158/1159/1170/1171; OSPFv2/v3 fixtures cover emitted 1158/1159/1170. Exact origin, prefix, topology, value and populated wrong-class assertions now accompany exporter checks for competing same-prefix OSPF route classes 1/2/3/5, their descriptor 264 and distinct SIDs. Independent judgment and native bindings establish the conditional association duty, not absent OSPF 1171/1174 support; 1174 is OSPF-only, not an IS-IS gap. Generic encoding and the Node verdict alone remain insufficient evidence for this occurrence.
