# RFC 1195 corrections

Why a requirement row of `rfc/short/rfc1195.md` changed level, text, or citation,
or was retired. The summary is the working document; this file is the record the
ratchets read (`checkLevelRatchet`, `checkRetiredRequirements`,
`internal/le/rfc/check_ratchets.go`).

Correction 2026-09-29: `RFC1195-5.3.4-3` quoted the DEFAULT METRIC sentence of
Section 5.3.4, "Bit 8 of this field is reserved, and must be set to zero on
tranmission and ignored on reception.", while its tagged units encode and decode
bit 7 of the DELAY, EXPENSE and ERROR metric octets. RFC 2966 Section 2, which
updates RFC 1195, reassigns default-metric bit 8 of TLVs 128 and 130 to the up/down
bit: "L1L2 routers must set this bit to one for prefixes that are derived from L2
routing and are advertised into L1 LSPs." That obligation is RFC2966-2-1's, so the
bit-8 sentence no longer binds as reserved. The row now quotes the Section 5.3.4
sentence its units prove, "Bit 7 of this field is reserved, and must be set to zero
on transmission and ignored on reception.", which the RFC states once for each of
the delay, expense and error metrics. Extraction site 5.3.4:6 is mapped to the row,
sites 5.3.4:8 and 5.3.4:10 stay its duplicates, and site 5.3.4:3 is excluded as
cross-document to RFC 2966.
