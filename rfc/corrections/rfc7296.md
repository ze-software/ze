# RFC 7296 corrections

Why a requirement row of `rfc/short/rfc7296.md` changed level, text, or citation.
The summary is the working document; this file is the record the level
ratchet reads (`checkLevelRatchet`, `internal/le/rfc/check_ratchets.go`).

Correction 2026-08-15: `RFC7296-2.8-1` was extracted at MUST strength. §2.8.1 states the
collision rule as a recommendation: the redundant SA "SHOULD be closed by the endpoint that
created it". Same requirement id, corrected text and level. §2.8.1 defines "lowest" in the
same paragraph, and the definition is part of the rule: an octet-by-octet comparison, "start
by comparing the first octet; if they're equal, move to the next octet, and so on. If you
reach the end of one nonce, that nonce is the lower one."

Correction 2026-08-15: `RFC7296-1.7-2` cited §1.7 and §2.13. Only §1.7 carries the sentence:
"This document adds the restriction in Section 2.13 that all pseudorandom functions (PRFs)
used with IKEv2 MUST take variable-sized keys." §2.13 states the same property as an
assumption, "It is assumed that PRFs accept keys of any length, but have a preferred key
size". §2.13 does carry MUSTs of its own, each already extracted as `RFC7296-2.13-1` to
`RFC7296-2.13-4`, but none of them is this obligation. `RFC7296-2.13-1`'s "a fixed key size
MUST be specified" sits in the paragraph opening "We assume that each encryption algorithm
and integrity protection algorithm uses a fixed-size key", so it governs those algorithms
rather than the PRF's acceptance of variable-sized keys. The citation now names §1.7 alone.

Retired 2026-09-27: `RFC7296-2.1-1` states an obligation RFC 7296 does not carry. Read §2.1 and the whole text: RFC 7296 predates IKE fragmentation and never mentions it. RFC 7383 §2.4 states it: "that peer SHOULD use IKE fragmentation." RFC 7383 has no summary in rfc/short, so under owner decision D-10 the row is retired, and a journal row asks for it to be enrolled. The row carried no tag.

Retired 2026-09-27: `RFC7296-3.8-1` states an obligation RFC 7296 does not carry. Read §3.8 and the whole text: RFC 7296 lists authentication methods 1, 2 and 3 and predates the Digital Signature method. RFC 8247 §3.1 grades method 14, Digital Signature, at SHOULD in its table, and says "Digital Signature [RFC7427] is expected to be promoted". RFC 8247 has no summary in rfc/short, so under owner decision D-10 the row is retired, and a journal row asks for it to be enrolled. The row carried no tag.

Retired 2026-09-29: `RFC7296-3.3.6-1` duplicated `RFC7296-3.3.2-1`. Correction 2026-09-30: `RFC7296-2.21.4-7` quoted two sentences of the last §2.21.4 paragraph that bind two different nodes: "A node receiving a suspicious message from an IP address (and port, if NAT traversal is used) with which it has an IKE SA SHOULD send an IKE Notify payload in an IKE INFORMATIONAL exchange over that SA." binds the node that saw the suspicious message, and "The recipient MUST NOT change the state of any SAs as a result, but may wish to audit the event to aid in diagnosing malfunctions." binds the peer that receives that protected Notify. Extraction site 2.21.4:5 maps the second. The row now quotes the second sentence, same id and level [MUST NOT], and keeps its tagged units, which assert that a protected INFORMATIONAL notify changes no SA state. The SHOULD send clause is the new row `RFC7296-2.21.4-8` [SHOULD], recorded as a {gap}: no path in Ze sends a protected Notify over an existing IKE SA in answer to a suspicious message.

Retired 2026-09-30: `RFC7296-2.13-2` binds the specification of a cryptographic transform, which Ze does not implement. Read §2.13: "For algorithms for which not all values are valid keys (such as DES or 3DES with key parity), the algorithm by which keys are derived from arbitrary values MUST be specified by the cryptographic transform." The subject is the transform's defining document, which must state a derivation, and no implementation fills that role. Ze also implements no transform the condition names: every cipher in encryptionRegistry (internal/component/ike/crypto/transform.go) is AES CBC, GCM or CCM, for which every value of the fixed size is a valid key. The row's two tags, on TestSKKeyLengthsComeFromTransforms in internal/component/ike/crypto/rfc7296_test.go, asserted SK_* key sizing, which is `RFC7296-2.13-3` and carried by the same unit's own tags, so they were dropped and that unit keeps its `RFC7296-2.13-3` tags.
