# RFC 4360 corrections

Why a requirement row of `rfc/short/rfc4360.md` changed level, text, or citation,
or was retired. The summary is the working document; this file is the record the
ratchets read (`internal/le/rfc/check_ratchets.go`).

Retired 2026-09-27: `RFC4360-x-2` states no obligation RFC 4360 carries. Read §1,
§2, §3, §4, §5 and §6, then the whole text: RFC 4360 classifies the attribute as
"a transitive optional BGP attribute" (§2) and says nothing about what a speaker
that does not support it does. That pass-through is RFC 4271's rule for every
unrecognized transitive optional attribute, and row RFC4271-5-3 of
`rfc/short/rfc4271.md` already states it. No test tagged the retired row, so no
tag moved.

Correction 2026-10-08: `RFC4360-x-1` keeps the §2 wire format "Each Extended Community is encoded as an 8-octet quantity" at its existing MUST level under owner D-3. The historical non-zero-length malformed-attribute claim belongs to RFC7606 §7.14, already rowed as RFC7606-7.14-1: "The Extended Community attribute SHALL be considered malformed if its length is not a non-zero multiple of 8." Retain the current RFC4360 format identity, §2 reverse entry and existing format evidence. An eight-octet codec is not proof of nonzero cardinality plus treat-as-withdraw; no separate error-action obligation or verdict is created by this reconciliation.
