# RFC 8669 corrections

Correction 2026-10-08: `RFC8669-6-4` records the separate §6 sentence "When discarding an attribute, a BGP speaker SHOULD log an error for further analysis." Keep `RFC8669-4-2` for the §4 EBGP/SR-boundary recommendation. The new occurrence covers malformed/invalid labeled-unicast Prefix-SID discard and is unverified: observable malformed-discard diagnostics and a clean control through enforceRFC7606 remain owed; invalid-state triggering is absent. AttributeDiscard classification alone is not logging proof, and the word error prescribes no particular slog enum. No missing SR-MPLS implementation is commissioned.

Correction 2026-10-08: `RFC8669-4.1-15` records the separate §4.1 sentence "A BGP speaker SHOULD log an error for further analysis." Its governing condition is: "In the case of an \"invalid\" BGP Prefix-SID attribute, a BGP speaker MUST follow the error-handling rules specified in Section 6." Do not confuse this occurrence with the following conflicting-attribute warning or the existing §4 boundary recommendation. validatePrefixSIDAttr does not compute the invalid state or its logging trigger; preserve this absent-feature gap and obtain a first unimplemented judgment with the validator in the code map. No missing SR-MPLS semantics are commissioned.

superseded by actual receive-enforcement diagnostic proof. Isolated TLV
