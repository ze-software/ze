# RFC 2869 corrections

Retired 2026-09-27: `RFC2869-x-1` states no obligation RFC 2869 carries. The row said an
accounting server MUST handle the absence of the Gigaword attributes for backward
compatibility, citing an "Implementation Constraints" section the RFC does not have.
Read §5.1, §5.2, §5.19 and §2.1, then the whole text: §5.19 lets an Accounting-Request
carry 0-1 instances of Acct-Input-Gigawords and Acct-Output-Gigawords, and no sentence
places an obligation on the receiving server. The row carried no tag.

Retired 2026-09-27: `RFC2869-x-3` states no obligation RFC 2869 carries. The row said the
Gigaword attributes MUST only be included when the counter has wrapped at least once,
citing a "Presence Rules" section the RFC does not have. Read §5.1, §5.2 and §5.19, then
the whole text: §5.1 and §5.2 define the value as the number of times the octet counter
has wrapped around 2^32 and restrict the attributes to Stop and Interim-Update records,
and §5.19 allows 0-1 instances; nothing forbids sending a zero. Its positive tag, on
TestBuildAcctPacketGigawords, moved to RFC2869-x-5, which quotes the §5.1 definition
the test proves (the attribute holds the wrap count). Its negative tag, on
TestBuildAcctPacketWithCounters, was deleted, because its only claim was this row.

Retired 2026-09-27: `RFC2869-x-4` states no obligation RFC 2869 carries beyond the one
RFC2869-x-5 already quotes. The row said a total byte count MUST be reconstructed as
Gigawords * 2^32 + Octets. Read §5.1, §5.2 and §5.19, then the whole text: the only
sentence behind it is the §5.1 definition that the attribute "indicates how many times
the Acct-Input-Octets counter has wrapped around 2^32", which RFC2869-x-5 carries. The
row carried no tag.

Retired 2026-09-27: `RFC2869-x-6` states no obligation RFC 2869 carries. The row said the
State attribute (type 24) MAY be maintained between Access-Challenge and Access-Request.
Read §2.2 and §5, then the whole text: RFC 2869 names State only in the §2.2 ARAP
exchange, and the general rule is RFC 2865 §5.24, which RFC2865-5.24-1 already carries
("MUST be sent unmodified from the client to the server in the new Access-Request reply
to that challenge"). The row carried no tag.

Retired 2026-09-30: `RFC2869-x-5` states no obligation RFC 2869 carries beyond the one `RFC2869-x-2` already quotes. It quoted §5.1, "This attribute indicates how many times the Acct-Input-Octets counter has wrapped around 2^32 over the course of this service being provided", and its annotation claimed that Ze derives the value from the 64-bit byte counter rather than from a tracked wrap event. Read §5.1, §5.2 and the whole text: no sentence says how the counter is computed, and the quoted clause is the first half of the sentence `RFC2869-x-2` quotes whole. The narrowing audit of 2026-09-28 called the row retire. Its two positive tags were dropped under a D-15 approval: TestSplitGigawords (internal/component/l2tp/plugins/authradius/rfc2869_acct_test.go) proved the derivation, which no sentence requires, and stays as an untagged test; on TestBuildAcctPacketGigawords the wrap-count assertion now sits in that unit's `RFC2869-x-2` claim, re-recorded. Section 5.1 of rfc/extraction/rfc2869.json no longer declares `RFC2869-x-5` unsourced.
