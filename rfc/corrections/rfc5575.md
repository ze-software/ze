# RFC 5575 corrections

Why a requirement row of `rfc/short/rfc5575.md` changed level, text, or citation,
or was retired. The summary is the working document; this file is the record the
level ratchet and the retirement check read (`internal/le/rfc/check_ratchets.go`).

Retired 2026-09-27: `RFC5575-4-5` states no obligation RFC 5575 carries in words.
Read §4 (the numeric operator figure, whose bit 4 is drawn as a literal 0), then the
whole text, §1 to §11: no sentence says the bit must be 0 or names it reserved. RFC
8955 §4.2.1.1 states it, and its row RFC8955-4.2.1.1-3 already carries that
obligation with its own positive and negative tags. The one tag, a positive on
TestFlowSpecNumericOperatorReservedBitZero, was deleted rather than moved, because
the RFC 8955 row's stamped verdict already covers encoding with its own test.

Retired 2026-09-27: `RFC5575-4-6` states no obligation RFC 5575 carries in words.
Read §4 (the bitmask operator figure, whose bits 4 and 5 are drawn as literal 0s),
then the whole text, §1 to §11: no sentence says those bits must be 0. RFC 8955
§4.2.1.2 states it as row RFC8955-4.2.1.2-1. The one tag sat on
TestFlowSpecBitmaskOperatorReservedBitsZero, which already carries the RFC 8955
row's positive tag, so it was deleted.

Retired 2026-09-27: `RFC5575-4-7` states no obligation RFC 5575 carries in words.
Read §4 (the Type 12 Fragment figure, whose high nibble is labelled Reserved), then
the whole text, §1 to §11: no sentence says the reserved bits must be 0. RFC 8955
§4.2.2.12 states it as row RFC8955-4.2.2.12-2. The one tag sat on
TestFlowSpecFragmentReservedHighNibbleZero, which already carries the RFC 8955 row's
positive tag, so it was deleted.
