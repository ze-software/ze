# RFC 9582 corrections

The rows retired below were written against RTR version 2, not against RFC 9582.
RFC 9582 is "A Profile for Route Origin Authorizations (ROAs)": its §5 is ROA
Validation with no subsections, so it has no §5.12, and its §7 is IANA
Considerations. Each row was read against the whole text (Abstract, §1 to §8 and
Appendix A, the example payload) and no sentence states it: the text never names
ASPA, a provider AS, an RTR PDU or a protocol version. Its obligation is stated by `draft-ietf-sidrops-8210bis`
revision 27, whose summary already carries a row for it. No test tagged any of
these ids: commit `af76a2ad56` had already moved every tag to the destination rows
named below, so none moved here.

Retired 2026-09-26: `RFC9582-5.12-1` states no obligation RFC 9582 carries. Read
§1 to §8 as above. Its obligation, an ASPA announcement carries at least one
provider, is draft-ietf-sidrops-8210bis §5.12, "For an announcement, the PDU MUST
contain at least one Provider Autonomous System Number.", row
`DRAFT-IETF-SIDROPS-8210BIS-5.12-1`, which carries both of its tags.

Retired 2026-09-26: `RFC9582-5.12-3` states no obligation RFC 9582 carries. Read
§1 to §8 as above. Its obligation, providers in ascending order, is
draft-ietf-sidrops-8210bis §5.12, "There are zero or more 32-bit Provider
Autonomous System Number fields in increasing numeric order.", row
`DRAFT-IETF-SIDROPS-8210BIS-5.12-3`, which carries both of its tags.

Retired 2026-09-26: `RFC9582-5.12-4` states no obligation RFC 9582 carries. Read
§1 to §8 as above. Its obligation, one ASPA per customer, is
draft-ietf-sidrops-8210bis §5.12, "The router MUST see at most one ASPA from a
particular cache for a particular Customer Autonomous System Number active at any
time.", row `DRAFT-IETF-SIDROPS-8210BIS-5.12-4`. Revision 27 has no AFI, so the
row's per-AFI key has no destination. It had no tags.

Retired 2026-09-26: `RFC9582-5.12-5` states no obligation RFC 9582 carries. Read
§1 to §8 as above. Its obligation, a withdrawal matches the customer's record, is
draft-ietf-sidrops-8210bis §5.12, "A router receiving this type of ASPA PDU (i.e.,
a withdrawal) MUST remove the entire ASPA record from that cache for that Customer
AS.", row `DRAFT-IETF-SIDROPS-8210BIS-5.12-5`. Revision 27 has no AFI, so the row's
per-AFI key has no destination. It had no tags.

Retired 2026-09-26: `RFC9582-5.12-8` states no obligation RFC 9582 carries. Read
§1 to §8 as above. Its obligation, providers sorted ascending, is the same
draft-ietf-sidrops-8210bis §5.12 sentence as `RFC9582-5.12-3`, row
`DRAFT-IETF-SIDROPS-8210BIS-5.12-3`. Revision 27 states no separate router SHOULD
for verifying the order. It had no tags.

Retired 2026-09-26: `RFC9582-7-1` states no obligation RFC 9582 carries. Read §1
to §8 as above; its §7 is IANA Considerations. Its obligation, the first query
carries version 2, is draft-ietf-sidrops-8210bis §7, which says the router "MUST
attempt to open an RPKI-Router 'session' by issuing either a Reset Query Section
5.4) or a Serial Query (Section 5.3) with the highest version of this protocol the
router implements", row `DRAFT-IETF-SIDROPS-8210BIS-7-1`, which carries its tag.

Retired 2026-09-26: `RFC9582-7-2` states no obligation RFC 9582 carries. Read §1
to §8 as above. Its obligation, downgrade or disconnect on an unsupported version,
is draft-ietf-sidrops-8210bis §7, "it MUST either downgrade to a known version or
terminate the connection", row `DRAFT-IETF-SIDROPS-8210BIS-7-2`, which carries both
of its tags.

Retired 2026-09-26: `RFC9582-7-3` states no obligation RFC 9582 carries. Read §1
to §8 as above. Its obligation, a cache answers an unsupported version with Error
Code 4, is draft-ietf-sidrops-8210bis §7, "the cache MUST send an Error Report PDU
with Protocol Version C and Error Code 4.", row `DRAFT-IETF-SIDROPS-8210BIS-7-3`.
It had no tags.

Retired 2026-09-26: `RFC9582-7-4` states no obligation RFC 9582 carries. Read §1
to §8 as above. Its obligation, start at the highest supported version, is the same
draft-ietf-sidrops-8210bis §7 sentence as `RFC9582-7-1`, at MUST rather than
SHOULD, row `DRAFT-IETF-SIDROPS-8210BIS-7-4`, whose level governs. It had no tags.

Retired 2026-09-27: `RFC9582-5.12-2` states an obligation RFC 9582 does not carry. RFC 9582 is the ROA profile and has no ASPA text: read the whole text, §1 to §8, and no sentence names a provider. draft-ietf-sidrops-aspa-profile §3.3 states it: "The customerASID value MUST NOT appear in any PAS in the providers field." That draft has no summary in rfc/short, so under owner decision D-10 the row is retired rather than moved, and a journal row asks for the draft to be enrolled. The row carried no tag.

Retired 2026-09-27: `RFC9582-5.12-7` states an obligation RFC 9582 does not carry. Read the whole text, §1 to §8: RFC 9582 is the ROA profile and says nothing of an ASPA customer. draft-ietf-sidrops-aspa-profile §3 and §3.2 state it, through "CAS ::= INTEGER (1..4294967295)" and "The customerASID field contains a positive integer". That draft has no summary in rfc/short, so under owner decision D-10 the row is retired, and a journal row asks for the draft to be enrolled. The row carried no tag.
