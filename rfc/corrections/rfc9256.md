# rfc9256 correction records

Correction 2026-10-06: `RFC9256-4-2` remains the Type B permission for SID behavior and structure, and `RFC9256-4-3` remains the Types C/D permission for SR Algorithm. They do not cover Types I, J and K. §4 states under each of those three types: "The SR Algorithm (refer to Section 3.1.1 of [RFC8402]), the SRv6 SID behavior (as defined in [RFC8986] or other SRv6 specifications), and structure (as defined in [RFC8986]) MAY also be provided." New row `RFC9256-4-7` quotes this common sentence once and records all three types and all three optional fields. `parseSegmentList` in `internal/component/bgp/plugins/nlri/srpolicy/config.go` accepts only Types A/B; its default rejects I/J/K, and `buildSegmentSubSubTLV` dispatches only A/B. The Type B endpoint-behavior encoder does not implement these I/J/K permissions. This is an explicit optional implementation gap, not conformance and not approval to add segment types. The two original rows and their evidence remain unchanged.
