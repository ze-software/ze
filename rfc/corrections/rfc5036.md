# RFC 5036 corrections

Why a requirement row of `rfc/short/rfc5036.md` changed level, text, or citation.
The summary is the working document; this file is the record the level
ratchet reads (`checkLevelRatchet`, `internal/le/rfc/check_ratchets.go`).

Correction 2026-09-21: The row `RFC5036-3.5.1-1` published [MUST NOT] over a sentence the RFC does not contain. RFC 5036 states the obligation at SHOULD and about terminating the session, not about processing further messages: "If the condition is one that is a fatal error, the Status Code carried in the Notification will indicate that. In this case, after sending the Notification message the LSR SHOULD terminate the LDP session by closing the session TCP connection and discard all state associated with the session, including all label-FEC bindings learned via the session." The row now carries [SHOULD] and the sentence's own words.

Correction 2026-09-21: The row `RFC5036-2.9-1` published [SHOULD] where the RFC states a MUST, and the row now carries [MUST]: "The use of this mechanism MUST be supported as a configurable option."

Correction 2026-09-21: The row `RFC5036-2.6.1.1-1` published [SHOULD] over a sentence the RFC does not contain. The cited section grants a permission: "When operating in independent Downstream Unsolicited mode, an LSR may advertise a label mapping for a FEC to its neighbors whenever it is prepared to label-switch that FEC." The row now carries [MAY].

Correction 2026-09-21: The row `RFC5036-2.7-1` published a prohibition on sending labeled packets before MPLS forwarding is enabled on an interface. No sentence of RFC 5036 states it. The cited section states instead: "To enable LSRs to map between a peer LDP Identifier and the peer's addresses, LSRs advertise their addresses using LDP Address and Withdraw Address messages." The row now carries that obligation.

Correction 2026-10-02: Add `RFC5036-2.5.3-8` and `RFC5036-2.5.3-9` for the active role's previously unrowed items 2.c and 2.d in §2.5.3: "If LSR1 receives a KeepAlive message, LSR2 has accepted its proposed session parameters." and "When LSR1 has received both an acceptable Initialization message and a KeepAlive message, the session is operational from LSR1's point of view." Both describe mandatory session-state semantics without capitalized keywords, so extraction lists them as unsourced ids, not invented normative sites.

Correction 2026-10-02: Add `RFC5036-2.5.4-1` for the complete OPENREC row in the §2.5.4 state table, including "Receive Any other LDP msg NON EXISTENT Action: Transmit Error Notification msg (NAK) and close transport connection". This is an implemented active-session defect, not an absent feature or exclusion: `Session.processMessages` previously dispatched other messages while waiting for the peer's KeepAlive. The row includes the KeepAlive transition to retain its subject and both branches. §3.5.1.1 explicitly includes an initialization Shutdown: "When an LSR receives a Shutdown message during session initialization, it SHOULD transmit a Shutdown message and then close the transport connection." The table has no extractor keyword site; its row is an unsourced id. The existing 87 sites, dispositions and sign-off are unchanged. The separate keepalive-expiry spec explicitly excludes other Notification causes.

Correction 2026-10-02: Add `RFC5036-2.5.4-2` for the complete OPENSENT row of the §2.5.4 state table (full text lines 929–935), from "OPENSENT Receive acceptable OPENREC Initialization msg Action: Transmit KeepAlive msg" through "Receive Any other LDP msg NON EXISTENT Action: Transmit Error Notification msg (NAK) and close transport connection". The quote preserves the source's column order: OPENREC appears on the first printed line, before "Initialization msg" on the next. The table imposes these transitions without an uppercase keyword, so the row uses MUST under D-3. This repairs the implemented active FSM, not an absent capability: non-Initialization messages previously bypassed the OPENREC-only guard. The row retains the acceptable-Initialization control and records an unsourced id because the extractor does not enumerate this table. §3.5.1.1 requires a Shutdown reply during initialization; operational fatal-Notification handling is unchanged. General Notification gap disclosures now name both initialization state checks without claiming expiry or other decoding errors are fixed.
