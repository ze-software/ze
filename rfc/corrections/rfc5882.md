# rfc5882 corrections

Why a requirement row of `rfc/short/rfc5882.md` changed level, text, or
citation, or was retired. The summary is the working document; this file is the
record the ratchets read (`internal/le/rfc/check_ratchets.go`).

Correction 2026-09-30: `RFC5882-4.2.1-1` quotes the §4.2.1 sentence for a control protocol with a single data protocol, while §4.2.2.1 and §4.2.2.2 state the same action for a control protocol that carries several, in sentences of their own, and §4.2.2.1 adds the timeout emulation. No row quoted them. Read §4.2.2, §4.2.2.1 and §4.2.2.2. They are now three rows, verbatim: `RFC5882-4.2.2.1-1` ("... signal the lack of connectivity for the path in the topology corresponding to the BFD session."), `RFC5882-4.2.2.1-2` ("If this cannot be signaled otherwise, a control protocol timeout SHOULD be emulated for the associated neighbor.") and `RFC5882-4.2.2.2-1` ("... for the path in the topology over which BFD is running."). `RFC5882-4.2.1-1` keeps its text and its tags. All three are SHOULD, so none is gated, and they sit in their sections' unsourced-ids.

Correction 2026-09-30: `RFC5882-10.1.3-2` carries the §10.1.3 authentication SHOULD for OSPF Virtual Links, while §10.2 states the same sentence for EBGP sessions, "BFD authentication SHOULD be used and is strongly encouraged.", and no row quoted it. It is now `RFC5882-10.2-1`, in the unsourced-ids of section 10.2. `RFC5882-10.1.3-2` is unchanged.
