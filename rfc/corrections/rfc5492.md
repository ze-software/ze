# RFC 5492 corrections

Why a requirement row of `rfc/short/rfc5492.md` changed level, text, or citation,
or was retired. The summary is the working document; this file records the
correction.

Correction 2026-10-08: `RFC5492-5-1` retained only the causing-capability-set
sentence and omitted the immediately following encoding sentence in Section 5:

> The Data field in the NOTIFICATION message MUST list the set of capabilities
> that causes the speaker to send the message. Each such capability is encoded
> in the same way as it would be encoded in the OPEN message.

Both sentences now remain under the existing identity and MUST level. Extraction
site `5:1` stays mapped to this row; its keyword-derived quote is unchanged. The
extraction explanation had claimed the row already included the second sentence.
This correction restores that scope rather than creating a duplicate identity.

The earlier Supported/no-tracked-gap claim overstated the evidence: tests of
zero-length Route Refresh and Extended Message tuples did not establish values
for ASN4 or variable-length capabilities. Actual OPEN-path regressions exposed
missing values and, subsequently, oversized notifications caused by expanding
repeated ADD-PATH entries into separate capability tuples. The serializers are
repaired; both OPEN paths now pass exact-value, original-side, noncausing-family
and repeated-grouping assertions. Fresh native discrimination and independent
judgment of the complete row remain separate obligations; the summary records
that remaining proof instead of awarding conformance from this correction.
