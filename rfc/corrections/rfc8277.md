# rfc8277 correction records

Correction 2026-10-02: `RFC8277-2.2-1`, `RFC8277-2.3-1` and `RFC8277-2.3-2` drop their `{single-polarity: positive}` markers. The markers said no transmission input could carry a wrong S bit, but LabeledUnicast.WriteTo takes label stack ENTRIES, the form a relayed stack arrives in, and nlri.WriteLabelStack rewrites their S bit rather than copying it: §2.2 reads "S: This 1-bit field MUST be set to one on transmission", and §2.3 reads "In all labels except the last (i.e., in all labels except the one immediately preceding the prefix), the S bit MUST be 0." TestRFC8277RelayedStackSBitRewritten (internal/component/bgp/plugins/nlri/labeled/rfc8277_sbit_relay_test.go) hands it entries with the S bit wrong and asserts the octets transmitted, so each row now carries a negative. The second transmitter, nlri.WriteLabelValues through UpdateBuilder.BuildLabeledUnicastNLRIBytes and buildVPNNLRIBytes, is proven by TestRFC8277BuilderLabelLayout (internal/component/bgp/message/rfc8277_label_layout_test.go). Quote, id and level unchanged.

Correction 2026-10-02: the `{single-polarity: positive}` reason of `RFC8277-2-2` named LabeledUnicast.WriteTo as the only transmitter. Two more write the label field: UpdateBuilder.BuildLabeledUnicastNLRIBytes and buildVPNNLRIBytes, both through nlri.WriteLabelValues. The reason now names all three; §2 reads "when advertising the binding of a single label to a prefix, the BGP speaker MUST use the encoding specified in Section 2.2", and each of the three emits that layout for any one-label input. Quote, id and level unchanged.
