# RFC 905 corrections

Why a requirement row of `rfc/short/rfc905.md` changed level, text, or citation,
or was retired. The summary is the working document; this file is the record the
ratchets read (`checkLevelRatchet`, `checkRetiredRequirements`,
`internal/le/rfc/check_ratchets.go`).

Retired 2026-09-27: `RFC905-x-6` states an obligation of RFC 2328, not of RFC 905,
and cited "(RFC 2328 Section 12.1.7)". Read §6.17, §13.2.3.1 and §B.1 to §B.4, then
the whole text: RFC 905 is the ISO transport protocol and never mentions an LSA,
OSPF or an LS Age field. RFC 2328 §12.1.7 states the obligation, and its row
RFC2328-12.1.7-1 already quotes it ("the checksum of the complete contents of the
LSA, excepting the LS age field"). Its tags moved there: the positive tags of
TestFletcherRFC905Vectors and TestFletcherIgnoresLSAge (internal/plugins/ospf/types)
and the negative tag of TestOSPFLSAChecksumExcludesAge (internal/plugins/ospf/packet)
now name RFC2328-12.1.7-1 with the same polarity. The positive tag of
TestOSPFLSAChecksum was dropped, because that unit already carries an
RFC2328-12.1.7-1 positive tag stating the same claim.

Retired 2026-09-27: `RFC905-x-7` states no obligation any RFC carries. It read "Test
BOTH encode (X,Y placement) and decode (verify-to-zero) against vectors", which is
advice to a tester, not a requirement on an implementation. Read §6.17, §13.2.3.1
and §B.1 to §B.4, then the whole text: no sentence mentions test vectors or
interoperability testing. Its round-trip tags moved to the rows that state what they
prove: the positive tags of TestOSPFLSAChecksum (internal/plugins/ospf/packet) and
TestFletcherRFC905Vectors (internal/plugins/ospf/types) now name RFC905-x-3, the
generation of X and Y (§B.3.4). The positive tag of TestISISChecksumVectors and the
negative tag of TestOSPFLSAChecksumExcludesAge were dropped, because each unit
already carries RFC905-x-3 positive and RFC905-x-4 negative respectively, stating the
same claim.

Retired 2026-09-27: `RFC905-x-5` states an obligation RFC 905 does not carry. Read §6.17 and Annex §B.1 to §B.4, then the whole text: §B.2 states only the opposite mapping, a variable of minus zero "shall be regarded as though it was plus zero (i.e. 0)", and no sentence turns a computed 0 into 255. The rule comes from RFC 1008 §7.2.1, whose C algorithm writes "if (iq <= 0) iq = iq + 255", and from ISO 8473, whose text is not in this repository. Neither has a summary in rfc/short, so under owner decision D-10 the row is retired, and a journal row asks for RFC 1008 to be enrolled. The row carried no tag.
