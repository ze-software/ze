# RFC 5301 corrections

Why a requirement row of `rfc/short/rfc5301.md` changed level, text, or citation,
or was retired. The summary is the working document; this file is the record the
ratchets read (`checkLevelRatchet`, `checkRetiredRequirements`,
`internal/le/rfc/check_ratchets.go`).

Correction 2026-09-30: `RFC5301-3-8` carries [MUST NOT] over a sentence with no BCP 14
keyword, "The string is not null-terminated.", and was reviewed under owner decision
D-3 rather than demoted by rule. Read §3 and §4. The sentence sits in the §3
definition of the TLV 137 Value field, beside "Value - a string of 1 to 255 bytes"
(`RFC5301-3-6`) and the 7-bit ASCII encoding (`RFC5301-3-7`): it fixes the wire format
of the field, so a sender that appends a NUL octet emits a Value the RFC does not
define and a receiver would read the NUL as part of the name. A format definition
binds the encoder as firmly as a keyword would, so the level stays [MUST NOT], the id
and text are unchanged, and the row is gated. The quote is verbatim; the row's
"null- terminated" keeps the RFC's own line-break hyphen.
