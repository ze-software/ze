# RFC 3787 corrections

Why a requirement row of `rfc/short/rfc3787.md` changed level, text, or citation,
or was retired. The summary is the working document; this file is the record the
ratchets read (`checkLevelRatchet`, `checkRetiredRequirements`,
`internal/le/rfc/check_ratchets.go`).

Correction 2026-09-30: `RFC3787-x-2` keeps its Section 9 text, "IP capable routers
MUST generate a Protocol Supported TLV, and MUST include the IP protocol as a
supported protocol.", while extraction site 10:1 had also been mapped to it. That
Section 10 sentence, "For an implementation to interoperate in a such mixed
environment, it MUST include an IP Interface address (TLV 132) in its IIH PDUs.", is
a separate obligation and is now its own row, `RFC3787-10-1` (main-thread ruling
R44). The negative tag on `TestISISHelloTLV132RequiresInterfaceAddr`, which proves
the TLV 132 clause, now tags `RFC3787-10-1`. The same unit keeps a narrowed
`RFC3787-x-2` negative (no address still advertises the IPv4 NLPID), because the
coverage ratchet refuses to drop the negative held at HEAD and refuses a
single-polarity marker beside a negative tag.
