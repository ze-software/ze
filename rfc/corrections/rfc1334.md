# RFC 1334 corrections

Why a requirement row of `rfc/short/rfc1334.md` changed level, text, or citation.
The summary is the working document; this file is the record the level
ratchet reads (`checkLevelRatchet`, `internal/le/rfc/check_ratchets.go`).

Correction 2026-09-21: the six ids `RFC1334-2.3-1` through `RFC1334-2.3-6` are anchored
to a section number this document does not have. RFC 1334 runs 2.1 Configuration Option
Format, 2.2 Packet Format, 2.2.1 Authenticate-Request, 2.2.2 Authenticate-Ack and
Authenticate-Nak, then 3. The sentences those six rows carry are in Section 2.2.2, at
rfc/full/rfc1334.txt line 363, and the prose of this summary cites 2.2.2 for them: "If the
id/password pair received in an Authenticate-Request is both recognizable and acceptable,
then the authenticator MUST transmit a PAP packet with the Code field set to 2
(Authenticate-Ack)." The two ids `RFC1334-2.2-1` and `RFC1334-2.2-2` carry sentences from
2.2.1, which is inside the Section 2.2 they cite. The ids keep their anchors, because an
id is permanent and is parsed from the section its line cites; renumbering them would
retire six obligations and orphan the eight `RFC requirement:` tags in
internal/component/l2tp/ppp/pap_test.go and
internal/component/l2tp/pppoeclient/rfc1334_pap_message_test.go.
