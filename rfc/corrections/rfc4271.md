# RFC 4271 row corrections

Retired 2026-10-01: `RFC4271-8.2.2-18` repeats `RFC4271-8.2.2-8`. Read §8.2.2, the OpenSent state, and the ManualStop paragraphs of the Idle, Connect, Active, OpenConfirm and Established states: the row's text is the first four items of the one OpenSent ManualStop sentence that `RFC4271-8.2.2-8` already quotes in full, with the ConnectRetryCounter item cut, so it states no obligation the other row does not (owner decision D-2, main-thread ruling of 2026-09-30). Its tags moved to `RFC4271-8.2.2-8`: the positive on `TestShutdownNotifySendsCeaseFromEveryConnectedState` and the one on `test/reload/signal-stop-cease.ci`, each re-recorded. The positive on `TestRFC4271OpenSentManualStopReleasesTheConnection` and the negative on `TestRFC4271OpenSentWellFormedOpenKeepsTheConnection` were dropped, because both units already carry the `RFC4271-8.2.2-8` tag. The negative on `TestRFC4271NoCeaseWithoutAManualStop` was dropped: it drives an Established session, which neither row covers.

Correction 2026-10-01: `RFC4271-6.1-3` quoted only the tail of its sentence. §6.1 lists five Length conditions before "then the Error Subcode MUST be set to Bad Message Length", and the next sentence, "The Data field MUST contain the erroneous Length field", belongs to the same obligation (extraction site 6.1:4 is excluded as its duplicate). The row now quotes the whole sentence and the Data sentence. Same id, same level.

Correction 2026-10-01: `RFC4271-6.1-4` carried a false {gap} annotation, published as a gap in the Support text. It said an unknown message type is answered with subcode 0 and a text string. Since commit fc9c8bcaae, handleUnknownType (internal/component/bgp/reactor/session_handlers.go) sends Message Header Error with subcode 3 and the one erroneous Type octet, as §6.1 asks: "If the Type field of the message header is not recognized, then the Error Subcode MUST be set to Bad Message Type." The gap figure had counted a behavior Ze no longer had. The annotation and the Support clause are removed, and TestRFC4271UnknownMessageTypeIsReported proves the answer through a running Peer's read path.

Correction 2026-10-01: `RFC4271-8.2.2-20` is a new row, split from `RFC4271-8.2.2-7` under main-thread ruling R45. §8.2.2, Idle state, reads "In response to a ManualStart event (Event 1) or an AutomaticStart event (Event 3), the local system:". Ze has no Event 3, so the AutomaticStart clause is a {gap} row of its own, and `RFC4271-8.2.2-7` keeps its tests for the ManualStart clause.
