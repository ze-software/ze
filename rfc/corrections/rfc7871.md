# RFC 7871 row corrections

Retired 2026-09-30: `RFC7871-7.2.2-1` binds an Intermediate Nameserver, which Ze does not implement. §7.2.2 opens "When an Intermediate Nameserver uses ECS, whether it passes an ECS option in its own response to its client is predicated on whether the client originally included the option", and the row's sentence is the next one. geodns is an Authoritative Nameserver and forwards no query. Its one tag, on `TestRFC7871_NoECSQueryNoECSResponse`, sat on a byte-identical repeat of the `RFC7871-7.2.1-7` assertion, which is where the authoritative obligation is proved, so the tag and its duplicate assertion were dropped and no coverage moves. Extraction site 7.2.2:1 is now excluded as binds-another-role.

Retired 2026-09-30: `RFC7871-7.2.2-2` binds an Intermediate Nameserver, which Ze does not implement. It is the third sentence of the same §7.2.2 paragraph, whose "the server" is the Intermediate Nameserver the paragraph opens with, and §4 defines that role as "Any nameserver in between the Stub Resolver and the Authoritative Nameserver, such as a Recursive Resolver or a Forwarding Resolver." geodns is an Authoritative Nameserver and forwards no query, and the resolver is a stub that sends no ECS option. The row carried no tag. It was a {gap}, so the rfc7871 gap count falls from six to five, and the missing behaviour stays counted: an authoritative server that receives an ECS option and omits it from the response is the {gap} row `RFC7871-7.2.1-5`. Extraction site 7.2.2:2 is now excluded as binds-another-role.
