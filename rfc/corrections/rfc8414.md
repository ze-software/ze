# RFC 8414 corrections

Why a requirement row of `rfc/short/rfc8414.md` changed level, text, or citation.
The summary is the working document; this file is the record the level
ratchet reads (`checkLevelRatchet`, `internal/le/rfc/check_ratchets.go`).

Correction 2026-09-29: `RFC8414-4-1` quoted only the lead-in of §4, "comparisons
between JSON strings and other Unicode strings MUST be performed as specified
below", a pointer to a list whose steps 2 and 3 are rowed as `RFC8414-4-2` and
`RFC8414-4-3`. Step 1, "Remove any JSON-applied escaping to produce an array of
Unicode code points.", was rowed nowhere. The row now quotes the lead-in and
step 1, the same shape as `RFC9728-6-3`. The level stays [MUST]. Read §4.

Correction 2026-09-29: `RFC8414-3.3-1` was published before 2026-09-27 as "The
metadata path MUST use the "https" scheme, and confidentiality protection MUST be
applied using TLS with a ciphersuite that provides confidentiality and integrity
protection (§3, §6.1)". The verbatim-quote pass kept only the §3 sentence, and
the §6.1 obligation lost its row while extraction site 6.1:4 still mapped to
`RFC8414-3.3-1`. The §6.1 sentence "To protect against information disclosure
and tampering, confidentiality protection MUST be applied using TLS with a
ciphersuite that provides confidentiality and integrity protection." is now its
own row, `RFC8414-6.1-4` at [MUST], and site 6.1:4 maps to it. `RFC8414-3.3-1`
keeps its §3 quote and its tags. Read §3 and §6.1.
