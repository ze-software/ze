# RFC 2328 corrections

Why a requirement row of `rfc/short/rfc2328.md` changed level, text, or citation, or
was retired, and why an obligation a split audit named has no row of its own. The
summary is the working document; this file is the record the ratchets read
(`checkLevelRatchet`, `checkRetiredRequirements`, `internal/le/rfc/check_ratchets.go`).

Correction 2026-10-21: `RFC2328-12.2-1` was listed as having dropped the obligation that
a network-LSA is looked up on its Link State ID alone (§16.1). No sentence of RFC 2328
states that. §12.2 says the lookup "is based on an LSA's LS type, Link State ID and
Advertising Router", which the row already quotes, and §16.1 says only that for a transit
vertex "the LSA's Link State ID is always equal to the above Vertex ID". The claim is a
reading of the Dijkstra procedure, not a sentence a row could quote, so no row is added.

Correction 2026-10-21: `RFC2328-D.3-2` was listed as having dropped two obligations of
§D.3: the cryptographic sequence number is non-decreasing, and it is reset to zero when
the neighbor goes Down. The first is now `RFC2328-D.3-4`, quoting "a non-decreasing
sequence number is included in each OSPF protocol packet to protect against replay
attacks". The second cannot be a row: its sentence starts "This field is initialized to
zero, and is also set to zero" on page 228 and ends with the transition to Down after
Figure 18 on page 229, so no verbatim span of the section
carries the whole sentence, and either half alone states a different rule.
