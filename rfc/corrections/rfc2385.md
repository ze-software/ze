# RFC 2385 requirement corrections

Retired 2026-10-02: `RFC2385-4.3-1` quoted §4.3: "As with other options that are added to every segment, the size of the MD5 option must be factored into the MSS offered to the other side during connection negotiation." RFC 6691 §3.2 explicitly corrects that passage: "This is incorrect. The value for the MSS option is only adjusted by the fixed IP and TCP headers." RFC 9293 §3.7.1 retains fixed-header advertised MSS and requires the sender to reduce data length for the options it sends. Thomas authorized retirement, removal of the audit entry and orphan records, and removal of misleading tags in the 2026-10-02 "MSS retirement and EVPN polarity" ruling. This is a superseded obligation, not an implementation gap or permission to omit MD5. The real namespace/veth packet carrier retains untagged assertions for advertised MSS 1460 on IPv4 MTU 1500 and signed packet lengths no greater than 1500. The old loopback transfer never read an MSS option and cannot prove either calculation. Extraction site 4.3:1 records the correction; the 60-byte header obligation in §4.3 remains mapped to `RFC2385-4.3-2`.
