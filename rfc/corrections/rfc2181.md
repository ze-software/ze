# RFC 2181 row corrections

Why a requirement row of `rfc/short/rfc2181.md` changed level, text, or citation,
or why a sentence an audit named carries no row of its own. The summary is the

Correction 2026-11-14: `RFC2181-10.3-1` already carries the obligation of the last sentence of §10.3, so that sentence gets no row of its own. The 2026-09-28 narrowing audit called the row "dropped" over 'It can also have other RRs, but never a CNAME RR.' Read §10.3 whole and §10.1: the subject of that sentence is the domain name that is the value of an NS record or part of an MX record ('This domain name must have as its value one or more address records', `RFC2181-10.3-2`), and §10.1 writes 'An alias name (label of a CNAME record)'. A name that owns a CNAME RR is therefore an alias, and 'never a CNAME RR' restates 'The domain name used as the value of a NS resource record, or part of the value of a MX resource record must not be an alias.', which `RFC2181-10.3-1` quotes. The sentence carries no modal keyword, so the extraction raises no site for it, and a second row would split one obligation in two. The RFC text here is in single quotes on purpose: a double-quoted span would authorize a later level demotion of either row, and this record lowers nothing. Ze's authoritative servers hold the role: `TestRFC2181NSTargetIsNotAnAlias` (internal/plugins/geodns/rfc2181_clarifications_test.go) queries each NS target for CNAME and asserts that none is answered, which is this sentence's content. Same id, text and level.
