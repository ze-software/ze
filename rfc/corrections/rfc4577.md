# RFC 4577 corrections

Why a requirement row of `rfc/short/rfc4577.md` changed level, text, or citation, or
was retired. The summary is the working document; this file is the record the
ratchets read (`checkLevelRatchet`, `checkRetiredRequirements`,
`internal/le/rfc/check_ratchets.go`).

Retired 2026-10-02: `RFC4577-4.2.6-5` binds the VPN PE role, which Ze does not implement.
It quoted §4.2.6, "Routes that a PE receives in type 4 LSAs MUST NOT be redistributed to
BGP." Read §1, §4.2.6 and the whole text: §4.2.6 specifies "the way in which a PE router
handles the OSPF LSAs it receives from a CE router", where the PE installs the routes in
a VRF and "must create a VPN-IPv4 route in BGP". The 2026-09-21 owner decision recorded
in the summary (`ospf_pe = "Keep ordinary OSPF role"`) does not select that role, and §1
says "No special procedures are needed in the CE router though; CE routers just run
whatever OSPF implementations they may have." Ze's OSPF to BGP export
(internal/plugins/ospf/redistribute/source.go) is plain ipv4/unicast redistribution with
no VRF and no VPN-IPv4 route, so no Ze function acts as the PE this sentence addresses.
Retired on the main thread's ruling R2. The tags on
`TestRFC4577Type3SummaryBecomesRedistributableRoute` and
`TestRFC4577Type4SummaryNotRedistributed` (internal/plugins/ospf/spf/rfc4577_test.go)
were dropped: they check that ComputeInterArea turns a Type 3 summary into a route entry
and a Type 4 summary into an ASBR border-router entry, the RFC 2328 §16.2 inter-area
calculation, which no RFC 4577 row states and no RFC 2328 row carries. The tests stay.
They held no discrimination record. Extraction site 4.2.6:9 is now excluded as
binds-another-role.
