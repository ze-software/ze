# RFC 3031 corrections

Why a requirement row of `rfc/short/rfc3031.md` changed level, text, or citation,
or was retired. The summary is the working document; this file is the record the
ratchets read (`checkLevelRatchet`, `checkRetiredRequirements`,
`internal/le/rfc/check_ratchets.go`).

Retired 2026-09-26: `RFC3031-3.15-1` ("An LSR SHOULD be able to support both liberal
and conservative label retention modes") states no obligation RFC 3031 carries. Read
§3.8, §3.15, §3.26.2 and §5.1, then searched the whole text for "retention": §3.8 defines
the two modes, §5.1.2 and §5.1.4 name the procedures each mode uses, and item 4 of the
§5.2.3 combinations says the choice between them belongs to Ru. No sentence asks an LSR to
support both. The row carried no tag, no extraction mapping and no audit verdict.

Retired 2026-09-26: `RFC3031-3.24-1` ("TTL decremented at each LSR", level MUST) states no
obligation RFC 3031 carries. Read §3.23 and §3.24, then searched the whole text for "TTL"
and "decrement": the only sentence saying a TTL "gets decremented by 1" is the §3.23
description of conventional IP forwarding, which obliges nobody, and the label-stack
decrement RFC 3031 does state is the SHOULD already carried by row RFC3031-3.23-1. §3.24
does not mention TTL. The MPLS obligation lives in RFC 3032 §2.4.1 and §2.4.2, whose
outgoing TTL is one less than the incoming TTL and MUST be written into the top label
stack entry: `RFC3032-2.4.2-3` states it. The row carried no tag and no audit verdict; its
id is dropped from the §3.24 `unsourced-ids` of `rfc/extraction/rfc3031.json`.

Retired 2026-09-26: `RFC3031-3.24-2` ("discard at TTL 0", level MUST) states no obligation
RFC 3031 carries. Read §3.23 and §3.24, then the whole text for "TTL": the only sentence
about discarding at TTL 0 is the same §3.23 description of conventional IP forwarding.
RFC 3032 §2.4.2 states the MPLS obligation ("If the outgoing TTL of a labeled packet is 0,
then the labeled packet MUST NOT be further forwarded"), carried by `RFC3032-2.4.2-1` and
`RFC3032-2.4.2-2`. The row carried no tag and no audit verdict; its id is dropped from the
§3.24 `unsourced-ids` of `rfc/extraction/rfc3031.json`.
