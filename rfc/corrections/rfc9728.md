# RFC 9728 corrections

Why a requirement row of `rfc/short/rfc9728.md` changed level, text, or citation.
The summary is the working document; this file is the record the level
ratchet reads (`checkLevelRatchet`, `internal/le/rfc/check_ratchets.go`).

Correction 2026-09-21: `RFC9728-2-2` was published [MUST]. Section 2 marks the parameter
optional in its own definition: "OPTIONAL. JSON array containing a list of OAuth
authorization server issuer identifiers", and the same paragraph lets a protected
resource withhold servers it supports. Only `resource` is REQUIRED there. The row is
corrected to [MAY].

Correction 2026-09-21: `RFC9728-5.1-1` was published [MUST]. The whole WWW-Authenticate
route is a permission: section 5 states that "A protected resource MAY use the
WWW-Authenticate HTTP response header field" to return the metadata URL, and section 5.1
states the extension this row cites at the same strength, because "This parameter MAY
also be used in WWW-Authenticate responses using" schemes other than Bearer. The row is
corrected to [MAY].

Retired 2026-09-29: `RFC9728-3.1-2` binds the protected-resource metadata client,
which Ze does not implement. Its §3.1 sentence, "A protected resource metadata
document MUST be queried using an HTTP GET request at the previously specified URL.",
obliges the party that queries the document, and Thomas's 2026-09-21 scope decision
excludes protected-resource discovery clients. Ze publishes the document and never
queries one. The row's two tags on `TestRFC9728MetadataQueriedWithGET` proved the
publisher's method handling (GET answered 200, POST and PUT refused with 405), which
no RFC 9728 sentence obliges, so they were deleted rather than moved; the test stays
as an untagged regression test. Extraction site 3.1:1 is now excluded as
`binds-another-role`. Read §3, §3.1 and §3.2.
