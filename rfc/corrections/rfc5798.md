# RFC 5798 corrections

Correction 2026-09-29: `RFC5798-7.1-4` keeps its text and its level, and its scope is
narrowed by a later erratum. §7.1 lists, among "the above checks", "MUST verify that
the VRID is configured on the receiving interface and the local router is not the
IPvX address owner", so under RFC 5798 an advertisement received by the address
owner fails a check and the receiver MUST discard it. RFC 9568, which obsoletes RFC
5798 and restates this row as RFC9568-7.1-6, carries Verified Technical erratum 8298
(rfc/errata/rfc9568/8298.txt) against its §7.1. Its Corrected Text reads: "It MUST
verify that the VRID is configured on the receiving interface." and "It SHOULD verify
that the local router is not the IPvX address owner (Priority = 255 (decimal)) and
log the event (subject to rate-limiting) and MAY indicate via network management that
a misconfiguration was detected." Ze's VRRPv3 receiver follows the erratum: the
owner test is a SHOULD-log outside the discard list, and the tests tagged for this
row assert the discard for every other check of the list. A v3 owner that keeps
an advertisement it received is therefore not counted as a failure of this row.

Correction 2026-09-30: `RFC5798-8.1.1-2` and `RFC5798-8.2.1-2` are new rows. Sites 8.1.1:1
and 8.2.1:1, "then it must determine which virtual router the packet was sent to when
selecting the redirect source address", were mapped to 8.1.1-1 and 8.2.1-1, whose quotes
are the neighbouring "should be the address that the end-host used" sentence, so the
lowercase must had no row. Each site now maps to its own row, and 8.1.1-1 and 8.2.1-1
become unsourced ids of their sections. Both rows are superseded as unextracted, because
RFC 9568 §8.1.1 and §8.2.1 restate the sentence and rfc/short/rfc9568.md declares no row
for it. The IPv4 row carries the wire test that also proves RFC3768-8.1-1. The IPv6 row is
a gap: ze sets nothing that selects an ICMPv6 redirect source.

Correction 2026-09-30: `RFC5798-8.1.2-6` and `RFC5798-8.2.2-8` are new rows, restated as
RFC9568-8.1.2-6 and RFC9568-8.2.2-8. Sites 8.1.2:1 ("the Virtual Router Master MUST
respond to the ARP request with an ARP response that indicates the virtual MAC address
for the virtual router") and 8.2.2:1 were excluded as duplicates of 6.4.3-1 and 6.4.3-3,
whose quotes do not say what the answer carries. The parent narrowing audit named this
drop for RFC 3768 and RFC 9568, and the same sentence stood unrowed here.

Correction 2026-09-30: `RFC5798-A.2-3` is a new row for the lowercase should "VRRP
advertisements sent to 224.0.0.18 should be encapsulated as described in [RFC1469]",
an unsourced id of §A.2. It is superseded as dropped: RFC 9568 §1.2 change 6 removed
the legacy-media appendices. The Meta counts now read 85 requirements, 59 MUST-level.
