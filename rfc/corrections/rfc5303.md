# RFC 5303 corrections

Retired 2026-09-30: `RFC5303-3.1-6` quoted a framing sentence, not an obligation of its own. Read §3.1: "Any system that is able to process this option SHALL follow the procedures below." The procedures it points at are §3.2 Elements of Procedure, and each is a requirement in its own §3.2 row: the reported state in `RFC5303-3.2-1` and `RFC5303-3.2-2`, the Extended Local Circuit ID in `RFC5303-3.2-3` and `RFC5303-3.2-4`, the neighbor fields in `RFC5303-3.2-5` and `RFC5303-3.2-6`, the invalid-state discard in `RFC5303-3.2-7`, the neighbor examination and mismatch discard in `RFC5303-3.2-8` and `RFC5303-3.2-9`, and the state table and its actions in `RFC5303-3.2-10` to `RFC5303-3.2-13` (main-thread ruling R22 shape). The procedures Ze does not yet follow stay recorded as gaps on those rows. Its extraction site 3.1:4 is excluded as `not-a-requirement`. Its positive tag, on TestISISThreeWayProceduresEngagedByOption, moved to `RFC5303-3.2-11`, the table action it proves (a new adjacency receiving Up takes the action "Down"). Its negative tag asserted that with no TLV 240 the legacy ISO 10589 two-way adjacency forms, which no RFC 5303 row obliges, so it was dropped rather than moved. rfc5303 has 19 rows, below the D-7 20-row threshold, so this retirement is reported to the owner.
