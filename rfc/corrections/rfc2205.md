# RFC 2205 corrections

Why a requirement row of `rfc/short/rfc2205.md` changed level, text, or citation,
or was retired. The summary is the working document; this file is the record the
level ratchet reads (`checkLevelRatchet`, `internal/le/rfc/check_ratchets.go`).

Retired 2026-09-29: `RFC2205-3.1-3` states no obligation RFC 2205 carries. The row
quoted the Appendix B list of message formatting errors a node "may detect and log
locally", which the sentence itself calls implementation-specific, and published it
[MUST]. Read §B, §3.1.1 and §3.10, then the whole text for the checksum: no sentence
obliges a node to detect or log any listed error. The row carried no tag. The one
checksum rule the text states is §3.1.1, that an all-zero checksum means no checksum
was transmitted, and it is the new row `RFC2205-3.1.1-1`. The sentence carries no
RFC 2119 keyword; it defines how a receiver reads the field, so the row is published
[MUST] under D-3.
