# BGP RFC Reference

Text versions of RFCs relevant to ZeBGP implementation.

Best-practice and Informational documents that must not create requirements live in
`reference/ietf/`, not here. See `reference/README.md`.

RFCs and Internet-Drafts that Ze will never implement live in `rfc/declined/`
(`texts/` and `short/`), outside `rfc/full/`, `rfc/drafts/`, and `rfc/short/`,
so they never enter the dependency graph or conformance ledger. See
`rfc/declined/README.md`.

## Profiles and the priority tree

`rfc/profiles/` holds one file per profile: a use-case profile (its roots and
the RFCs it needs that the corpus lacks, under `Absent`; `Release: yes` marks
a release profile) or a technology aggregate. `rfc/graph.tsv` is the
dependency graph between the texts here, generated by `./le rfc update` and
never edited. A summary's `| Aggregate tier | optional |` row lists it in its
aggregate's optional tier, counted only in that tier's own figures.
`./le rfc tree profile <name>` prints a profile's closure roots
to leaves with both coverage figures, and `./le rfc next` names the next gap
across the release profiles. The format and the rules are in
`docs/contributing/rfc-conformance-gates.md` ("Profiles and aggregates", "The
dependency graph", "The priority tree").

## Error Handling

| RFC | Title | Status | Notes |
|-----|-------|--------|-------|
| [7606](full/rfc7606.txt) | Revised Error Handling for BGP UPDATE Messages | Implemented | **Supersedes RFC 4271 §6 for error handling** |

> ⚠️ **Important:** RFC 7606 updates RFC 4271's strict "session reset" error handling with recovery tactics: treat-as-withdraw, attribute discard, AFI/SAFI disable. New implementations SHOULD follow RFC 7606.
