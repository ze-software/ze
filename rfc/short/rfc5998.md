**Purpose:** Lets an IKEv2 initiator ask the responder to skip its public-key AUTH and CERT payloads when the EAP method itself provides mutual authentication and a shared key, signalled by the EAP_ONLY_AUTHENTICATION status notify in message 3.

**Ze context:** Ze's remote-access responder authenticates itself with a certificate signature and then runs EAP. A client sending EAP_ONLY_AUTHENTICATION today gets the normal RFC 7296 path, which Section 3 permits for a responder that does not support the notify.

## Notify (Section 3)

| Field | Value |
|-------|-------|
| Notify Message Type | EAP_ONLY_AUTHENTICATION, 16417 (status) |
| Protocol ID | 0 |
| SPI Size | 0 |
| Notification Data | none |

Sent by the initiator in IKE_AUTH message 3. A responder that supports and accepts it omits AUTH and CERT from message 4.

## Exchange (Section 3)

```
     -----------                 -----------

            N(NAT_DETECTION_DESTINATION_IP)]  -->
                            <--   HDR, SAr1, KEr, Nr, [CERTREQ],
                                       [N(NAT_DETECTION_SOURCE_IP),
                                        N(NAT_DETECTION_DESTINATION_IP)]
      HDR, SK { IDi, [IDr], SAi2, TSi, TSr,
                N(EAP_ONLY_AUTHENTICATION),
                [CP(CFG_REQUEST)] }  -->
                            <--   HDR, SK { IDr, EAP(Request) }
      HDR, SK { EAP(Response) }  -->
                            <--   HDR, SK { EAP(Request) }
      HDR, SK { EAP(Response) }  -->
                            <--   HDR, SK { EAP(Success) }
      HDR, SK { AUTH }  -->
                            <--   HDR, SK { AUTH, SAr2, TSi, TSr,
                                            [CP(CFG_REPLY] }
```

## Safe EAP Methods (Section 4)

A method used with the extension provides mutual authentication, is key-generating, and resists dictionary attacks. Listed as safe: EAP-SIM, EAP-AKA, EAP-AKA', EAP-GPSK, EAP-pwd, EAP-EKE, EAP-PAX, EAP-SAKE, EAP-SRP, EAP-POTP (mutual), EAP-TLS, EAP-FAST, EAP-TTLS.

## Pitfalls

- Without a safe-method filter, EAP-only mode lets an EAP-MD5 style method authenticate an unauthenticated responder (Section 6.1).
- Session resumption (RFC 5723) keeps the original authentication method, so the notify is never re-sent (Section 3).
