**Purpose:** Standardizes a discovery document the authorization server publishes so clients and resource servers can learn endpoint URLs, supported algorithms, and the `jwks_uri` where signing keys live. Ze consumes `issuer` and `jwks_uri` as an OAuth resource server.

## Well-Known Endpoint (Section 3)

| Item | Value |
|------|-------|
| Path | `/.well-known/oauth-authorization-server` |
| Method | GET |
| Publication | "Authorization servers supporting metadata MUST make a JSON document containing metadata as specified in Section 2 available at a path formed by inserting a well-known URI string into the authorization server's issuer identifier between the host component and the path component, if any." (§3) |
| Content-Type | `application/json` |

Ze uses the RFC 8414 suffix only. It does not query OpenID Connect's older appended discovery path or accept a separate concrete metadata URL.

## Required Fields (Section 2)

Ze trusts these fields from the document:

| Field | Required? | Ze use |
|-------|-----------|--------|
| `issuer` | MUST | Compared exact-match against JWT `iss` claim on every token |
| `jwks_uri` | OPTIONAL | Fetched once at startup + refreshed on cache TTL to obtain verification keys |
| `authorization_endpoint` | MUST (for clients) | Not used by resource server |
| `token_endpoint` | MUST (for clients) | Not used by resource server |
| `scopes_supported` | RECOMMENDED | Not used; operator declares required scopes separately |
| `response_types_supported` | MUST | Not used by resource server |
| `grant_types_supported` | OPTIONAL | Not used |
| `token_endpoint_auth_methods_supported` | OPTIONAL | Not used |
| `id_token_signing_alg_values_supported` | OPTIONAL | Not used (Ze's JWT verifier has its own allow-list) |

## Security Properties (Sections 3, 3.3, and 6.1)

| Requirement | Detail |
|-------------|--------|
| TLS | Both the metadata and JWKS fetch URLs require HTTPS, and redirects cannot downgrade to HTTP. The Go HTTP transport checks server certificates. |
| Issuer validation | The metadata `issuer` must equal the configured issuer string after JSON unescaping. URL canonicalization and Unicode normalization are forbidden. |
| Content integrity | Metadata changes only when the operator updates AS configuration; document is cacheable. Ze refreshes JWKS on TTL, not the metadata document itself. |

## Ze Implementation

- Fetcher: `internal/component/mcp/as_metadata.go` `fetchASMetadata` -- single HTTP GET, bounded body size, JSON decode via `map[string]any` (avoids snake_case struct tags).
- Consumption: `internal/component/mcp/streamable_auth.go` `buildAuthForMode` fetches metadata at startup and constructs a `jwksCache` around the validated `jwks_uri`.
- Failure mode: `cmd/ze/hub/service_mcp.go` `startMCPServer` does not start the MCP listener if metadata or key loading fails.
