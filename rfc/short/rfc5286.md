**Purpose:** Defines loop-free alternates (LFAs), a set of precomputed backup
next-hops that a router installs alongside its primary next-hops so it can
locally repair unicast traffic the instant a single failure (link, node, or
local SRLG) is detected, before the IGP reconverges. LFA selection is a
per-destination, per-primary-next-hop computation layered on top of the normal
SPF; it changes no protocol packets on the wire.

**Scope for Ze:** This is an algorithm/control-plane specification, not a wire
protocol. It applies on top of a link-state IGP (OSPFv2 RFC 2328, OSPFv3
RFC 2740 / RFC 5340, or IS-IS RFC 1195 / RFC 2966) and feeds a backup next-hop
into the FIB. Inputs are reverse/forward SPF distances already computed by the
IGP plus per-neighbor SPTs; output is a backup next-hop per primary next-hop
per prefix that is installed into the forwarding pipeline (Loc-RIB / sysrib /
fibkernel). Intra-domain only; BGP inter-domain Fast Reroute is explicitly out
of scope (§2). Multicast is out of scope (§4, §6.5).

## No Wire Formats

RFC 5286 defines no packet, message, attribute, capability, or NLRI format. It
adds no fields to any IGP or LDP message and introduces no new TLVs. The only
data structures it defines are computation-local (per-candidate alternate
state), reproduced under Algorithms below. There are therefore no ASCII wire
diagrams or Field/Offset/Size tables to capture; inventing any would be wrong.

The one on-the-wire requirement (§5) is a configuration constraint on existing
LDP behavior (liberal label retention, downstream-unsolicited, advertise to all
neighbors), not a new format.

## Terminology and Notation (§1, §3)

| Symbol | Meaning |
|--------|---------|
| `S` | The computing (calculating) router |
| `D` | The destination router/prefix under consideration |
| `E` | `S`'s primary neighbor (next-hop) being protected |
| `N`, `N_i` | A neighbor of `S` offering a candidate alternate |
| `PN` | Pseudo-node representing a broadcast / NBMA segment |
| `Distance_opt(X,Y)` / `D_opt(X,Y)` | Shortest distance from X to Y per the IGP |
| `SPT(S)` / `SPT(N)` | Shortest-path tree rooted at S, or rooted at neighbor N |
| `SRLG_local(S)` | Set of SRLGs that include a link directly connected to S |
| `SRLG_set(N,D)` | Set of SRLGs crossed if traffic to D is forwarded through N |
| `LSInfinity` | OSPF max metric; IS-IS uses "the maximum cost" |

Required inputs to compute LFAs for destination D (§3):
`D_opt(S,D)` (from normal SPF), `D_opt(N_i,D)`, `D_opt(N_i,S)`, and
`D_opt(N_i,N_j)`. The neighbor distances come from running an additional SPF
rooted at each IGP neighbor (`SPT(N)`).

## Loop-Free Inequalities (the load-bearing math)

### Inequality 1 - Loop-Free Criterion (§1, §3.1)

A neighbor N can provide a loop-free alternate (LFA) if and only if:

```
Distance_opt(N, D) < Distance_opt(N, S) + Distance_opt(S, D)
```

Meaning: N's optimal path to D does not come back through S, so forwarding to N
after a link failure cannot loop. Every alternate produced by an implementation
MUST satisfy at least this (§3.1).

### Inequality 2 - Downstream Path Criterion (§1, §1.1)

A stricter subset; a downstream path satisfies:

```
Distance_opt(N, D) < Distance_opt(S, D)
```

Meaning: N is strictly closer to D than S is. Every router on a downstream path
is closer to D than its predecessor, so a downstream alternate cannot create a
micro-loop *involving S* even under a more extensive failure than planned
(e.g., node failure when only link protection was computed). All downstream
paths are LFAs; not all LFAs are downstream paths.

### Inequality 3 - Node-Protecting Criterion (§3.2)

For alternate N to protect against node failure of primary neighbor E for
destination D, N's path to D must avoid E:

```
Distance_opt(N, D) < Distance_opt(N, E) + Distance_opt(E, D)
```

If `Distance_opt(N,D) = Distance_opt(N,E) + Distance_opt(E,D)` (equality), N may
have an ECMP path that goes through E and S cannot influence N's choice;
therefore the implementation SHOULD assume no node protection when Inequality 3
is not strictly met (§3.2).

The companion test for "does a downstream path to the protected node E exist"
(§1.1):

```
Distance_opt(N, E) < Distance_opt(S, E)
```

### Inequality 4 - Loop-Free Link-Protecting Criterion for Broadcast Links (§3.3)

When the primary next-hop is across a broadcast / NBMA link, the alternate must
be loop-free with respect to the pseudo-node PN:

```
D_opt(N, D) < D_opt(N, PN) + D_opt(PN, D)
```

Plus a second condition unique to non-point-to-point links: the link S uses to
*reach* the alternate neighbor N must itself not be the protected link / not
traverse PN. Consequences (§3.3):
- On point-to-point links, a node-protecting LFA is always link-protecting.
- On broadcast/NBMA links, a node-protecting LFA is NOT automatically
  link-protecting, because S's own path to N may cross the same PN. S must find
  a next-hop to N that avoids PN to get link protection.
- The same "avoid the link S uses to reach N" reasoning applies to SRLG
  protection.

## Protection Classification (§3.6)

Each candidate next-hop carries non-mutually-exclusive characteristics:

| Class | Satisfies | Notes |
|-------|-----------|-------|
| Primary Path | (is a primary next-hop) | All primary next-hops are downstream paths |
| Loop-Free Node-Protecting Alternate | Ineq. 1 AND Ineq. 3 | Path avoids S, E, and the S->E link |
| Loop-Free Link-Protecting Alternate | Ineq. 1, NOT Ineq. 3 | If primary uses a broadcast link, also Ineq. 4 |
| Downstream Alternate | Ineq. 2 | Stricter LFA; cannot micro-loop via S |
| SRLG-Protecting (SP) | path avoids the SRLG set | May be partial (avoids G1 not G2) |

Abbreviations (§3.7): LP = link-protecting, NP = node-protecting,
SP = SRLG-protecting.

## SRLG Handling (§3, §3.3)

- Only `SRLG_local(S)` (SRLGs that include a link directly attached to S) is of
  interest; only those can cause a local failure. Local link SRLG membership is
  manually configured; remote membership may come from RFC 4205 / RFC 4203
  (§3).
- `SRLG_set(N,D)` is built during `SPT(N)`: initialize `SRLG_set(N,N)` empty;
  when a vertex V is added, `SRLG_set(N,V)` = union of parents' SRLG sets and
  the `SRLG_local(S)` SRLGs on the links from V's parents to V (§3).
- A "local-SRLG" is a set of links all sharing one end at the same router
  (VLANs on one Ethernet port, channelized sub-interfaces, same line card).
  S can pick an alternate that avoids the primary's local-SRLG; failures of E's
  local-SRLGs are covered by node protection (§1.1).
- SRLG protection is per-area; an SRLG spanning multiple areas needs a separate
  SRLG-protecting alternate in each traversed area (§1.1).

## ECMP (§3.4, §3.8)

- A prefix with ECMP primaries computes alternates per primary next-hop
  separately. An alternate MAY itself be one of the other primaries, but other
  primaries are not guaranteed to protect against the failure of interest.
- Per-next-hop simplification (§3.8): when only link protection is wanted,
  compute a single link-protecting LFA per next-hop and share it across all
  prefixes using that next-hop. This reduces coverage (may miss an LFA that a
  per-prefix computation would find, and limits multi-homed-prefix protection).

## Costed-Out / Overloaded Links (§3.5, §3.5.1)

- A link is unusable as an alternate if its cost or reverse cost is LSInfinity
  (OSPF) / maximum cost (IS-IS), or the next-hop has the IS-IS overload bit set
  (§3.5).
- Reverse cost on a broadcast link = cost toward the pseudo-node advertised by
  the next-hop router. For point-to-point links where a specific link cannot be
  associated, use the minimum-cost link from the next-hop router back to S
  (§3.5).
- IS-IS link attributes (RFC 5029): a router SHOULD NOT advertise the "local
  protection available" flag merely because it has LFAs; SHOULD NOT use an
  alternate on a link advertised "link excluded from local protection path" or
  "local maintenance required" (§3.5.1).

## OSPF Multi-Area Constraints (§2, §6.3, Appendix A)

OSPF traffic can leave and re-enter an area, so the local-area SPF may not
reflect the real path. LFAs should not be used where any of these apply
(advisory, lowercase in RFC; §2 a-d, §6.3 a-d):

- Backbone area with virtual links configured, unless every transit area has a
  full mesh of virtual links between all its ABRs (§2a, §6.3a).
- Inter-area routes in an area containing more than one alternate ABR (RFC 3509)
  (§2b, §6.3b).
- AS-External / ASBR routes in a non-backbone area when an ABR is announced as
  an ASBR in multiple non-backbone areas and another ABR shares at least two of
  those areas (§2c, §6.3c, Appendix A).
- AS-External routes in a non-backbone area advertised by multiple ASBRs in
  different non-backbone areas with the same external metric type and forwarding
  address 0.0.0.0 (or with forwarding addresses spanning multiple non-backbone
  areas) where a single ABR sits in two or more of those areas (§2d, §6.3d).

OSPF external routing with a nonzero forwarding address: compute the alternate
toward the forwarding address(es), not toward the ASBR (§6.3.1). Multi-topology
IS-IS (RFC 5120) and multi-topology OSPF (RFC 4915) are out of scope (§6.2,
§6.3.2).

## Multi-Homed Prefixes (§6.1)

- Run an SPF-like computation per topology (per OSPF area / IS-IS level).
- Model a multi-homed prefix as a node with unidirectional links into it from
  each advertising router; the node has no outgoing links and is never explored.
- Prefixes sharing identical attachment/metric sets can share one computed
  alternate.
- A router SHOULD compute the MHP alternate by considering paths via all routers
  advertising the prefix (§6.1).
- A router MAY simplify by assuming the MHP is attached only at its pre-failure
  optimal attachment point, at the cost of possibly missing a viable repair
  (§6.1).

## BGP and LDP (§5, §6.4)

- **LDP (§5):** to let LDP follow LFAs, the LSR must distribute FEC labels to
  all neighbors (even non-upstream), run liberal label retention mode, and run
  downstream-unsolicited mode, so backup out-segments exist before failure. No
  targeted sessions or signaling extensions needed.
- **BGP (§6.4):** BGP inherits the IGP alternate next-hop for its resolved
  next-hop automatically; the BGP decision process is unchanged. MBGP routes do
  not copy alternate next-hops. ASBR protection via treating BGP next-hops as a
  multi-homed prefix is left for future study.

## Using and Terminating an Alternate (§4, §4.1)

On detecting a primary next-hop failure (local interface down or other
detection per the IPFRR framework), the router SHOULD (§4):
1. Remove the primary next-hop associated with the failure.
2. Install the precomputed LFA for the failed next-hop if not already installed.

The router MAY also remove other next-hops it believes share the failure via
SRLG analysis (§4). The alternate MUST be used only for shortest-path-routed
traffic; multicast is out of scope (§4).

Termination (§4.1): a router MUST bound how long an alternate is used so it
returns to the new primaries. An implementation SHOULD continue using the
alternate even after new routing info is available, and SHOULD stop when (§4.1):
- a. the new primary next-hop was loop-free prior to the topology change, or
- b. a configured hold-down (worst-case convergence bound) expires, or
- c. notification of an unrelated topological change is received.

If the implementation follows RFC-draft micro-loop avoidance schemes
([MICROLOOP] or [ORDERED-FIB]), it SHOULD use those schemes' termination rules
instead (§4.1).

## Algorithms

### Per-prefix LFA selection (§3.6, informational reference algorithm)

The RFC states the algorithm is informational; any algorithm satisfying the §3.6
rules is conformant. Per-router alternates also serve prefixes singly attached
to that router; multi-homed prefixes use the §6.1 transformation.

Setup: S's candidate next-hops are `H_1 .. H_k` (each `H_h.link`,
`H_h.neighbor`, link must be bidirectional). For destination D, S has precomputed
`D_opt(S,D)`, and per neighbor `D_opt(N_i,D)`, `D_opt(N_i,S)`, `D_opt(N_i,N_j)`,
plus the SRLG set on each `D_opt(N_i,D)`. Run the procedure for every primary
next-hop `P_i` (set `P_1 .. P_p`).

Initialize per primary:
```
P_i.alt_next_hops   = {}
P_i.alt_type        = NONE
P_i.alt_link-protect = FALSE
P_i.alt_node-protect = FALSE
P_i.alt_srlg-protect = {}
```

For each candidate `H_h`:
```
 1. cand_type=NONE; cand_link-protect=FALSE; cand_node-protect=FALSE; cand_srlg-protect={}
 2. If H_h is P_i, skip.
 3. Usable as alternate only if: H_h.link admin-allowed AND cost(H_h.link)<max
    AND reverse-cost(H_h)<max AND H_h.neighbor not overloaded (IS-IS)
    AND H_h.link bidirectional. Else skip.            [§3.5 cost/overload gate]
 4. If D_opt(H_h.neighbor,D) >= D_opt(H_h.neighbor,S) + D_opt(S,D): not
    loop-free (fails Inequality 1). Skip.              [Inequality 1]
 5. cand_type = LOOP-FREE.
 6. If H_h is a primary next-hop, cand_type = PRIMARY.
 7. If H_h.link != P_i.link: cand_link-protect = TRUE.
 8. If D_opt(H_h.neighbor,D) < D_opt(H_h.neighbor,P_i.neighbor)
       + D_opt(P_i.neighbor,D): cand_node-protect = TRUE.   [Inequality 3]
 9. SRLG (if considered): cand_srlg-protect = SRLGs on S->P_i.link->P_i.neighbor;
    remove SRLGs of H_h; remove SRLGs on H_h.neighbor->D path. Result = SRLGs P_i
    belongs to that are NOT crossed via H_h to D.
10. If cand_type==PRIMARY AND router prefers primaries AND P_i.alt_type!=PRIMARY: goto 20.
11. If cand_type!=PRIMARY AND P_i.alt_type==PRIMARY AND router prefers primaries: next candidate.
12. If cand_node-protect AND NOT P_i.alt_node-protect: goto 20.
13. If cand_link-protect AND NOT P_i.alt_link-protect: goto 20.
14. If cand_srlg-protect better than P_i.alt_srlg-protect: goto 20.
15. If cand_srlg-protect differs from P_i.alt_srlg-protect: tie-break (distance,
    IP, router-local). Prefer H_h -> goto 20; prefer P_i.alt -> next candidate.
16. If D_opt(H_h.neighbor,D) < D_opt(S,D) AND
       D_opt(P_i.alt_next_hops,D) >= D_opt(S,D): H_h is a downstream alternate
    and P_i.alt is merely an LFA. Prefer H_h, goto 20.   [ERRATA 2323 - see below]
17. Tie-break on type/distance/IP: if H_h preferred, goto 20.
18. If P_i.alt preferred, next candidate.
19. Add H_h to P_i.alt_next_hops; set P_i.alt_type to better of the two. Next candidate.
20. Replace: P_i.alt_next_hops={H_h}; copy cand_type / cand_link-protect /
    cand_node-protect / cand_srlg-protect into P_i.*. Next candidate.
```

### Selection rules (§3.6, normative ordering the algorithm encodes)

1. SHOULD prefer a node-protecting LFA; if none, MAY use a link-protecting LFA.
2. Between link-and-node-protecting and node-protecting-only, SHOULD prefer
   link-and-node-protecting.
3. With multiple primaries, SHOULD prefer another primary or a node-protecting
   LFA; failing both, SHOULD use a link-protecting LFA.
4. SHOULD support a mode preferring primaries (satisfying basic loop-free + at
   least link or node protection) over non-primary alternates (preserves ECMP
   patterns).
5. MAY use SRLG protection to declare a node/link-protecting alternate
   unavailable.

## Errata

One verified erratum.

| Errata ID | Status | Type | Section | Effect |
|-----------|--------|------|---------|--------|
| 2323 | Verified | Technical | §3.6 step 16 | Corrects the downstream-alternate test |

Step 16 as published reads:
```
16. If D_opt(H_h.neighbor, D) < D_opt(P_i.neighbor, D) and
    D_opt(P_i.alt_next_hops, D) >= D_opt(P_i.neighbor, D), then H_h
    is a downstream alternate and P_i.alt_next_hops is simply an LFA.
```
It SHOULD read (corrected, reported by Andras Csaszar, verified by Stewart
Bryant 2011-08-12):
```
16. If D_opt(H_h.neighbor, D) < D_opt(S, D) and
    D_opt(P_i.alt_next_hops, D) >= D_opt(S, D), then H_h
    is a downstream alternate and P_i.alt_next_hops is simply an LFA.
```
A "downstream" alternate is defined by the Downstream Path Criterion
(Inequality 2: `D_opt(N,D) < D_opt(S,D)`), i.e., distance is measured against
the computing router S, not against the primary neighbor `P_i.neighbor`. The
reference algorithm in §3.6 step 16 must compare against `D_opt(S, D)`. The
algorithm block above already reflects the corrected text.

## Pitfalls

- **Inequality 1 uses strict `<`.** Equality means N's optimal path can come
  back through S; treat as not loop-free.
- **Node protection needs strict Inequality 3.** On equality, assume no node
  protection (§3.2) - N may have an ECMP path through E that S cannot influence.
- **Node-protecting != link-protecting on broadcast/NBMA.** S's own path to the
  alternate neighbor may cross the same pseudo-node; you must also verify the
  S->N link avoids PN (Inequality 4 plus the second condition, §3.3). On
  point-to-point links node-protecting implies link-protecting.
- **Errata 2323.** Downstream test in step 16 is against `D_opt(S,D)`, not
  `D_opt(P_i.neighbor,D)`. Implementing the uncorrected text misclassifies
  alternates.
- **Reverse cost matters.** A link with reverse cost = LSInfinity / max is
  unusable even if forward cost is fine (§3.5); for broadcast use the cost
  toward the PN, for point-to-point use the min-cost link back to S.
- **IS-IS overload bit / RFC 3137 stub.** Never route an alternate through an
  overloaded or costed-out transit node (§3.5).
- **Per-next-hop simplification loses coverage.** Sharing one LFA per next-hop
  (§3.8) can fail to find an LFA that exists per-prefix (the Figure 4 E1 case).
- **Premature reversion micro-loops.** Switching to a new primary before
  neighbors install theirs can loop; keep using the alternate until §4.1 (a/b/c)
  holds. Immediate switch is safe only if the new primary was loop-free before
  the failure.
- **Multicast.** Do not apply alternates to multicast RPF (§6.5); out of scope.
- **OSPF multi-area path leakage.** Local-area SPF can misjudge inter-area
  paths; honor the §2 / §6.3 area constraints or risk micro-loops.

## TI-LFA (out of scope here, for orientation)

Topology Independent LFA (`draft-ietf-rtgwg-segment-routing-ti-lfa`, a separate
IETF document, not part of RFC 5286) extends this work: where RFC 5286 only
installs a directly-connected loop-free neighbor and gives topology-dependent
coverage, TI-LFA uses Segment Routing to build an explicit repair tunnel to the
post-convergence "P-Q" path, achieving 100% coverage and matching the
post-convergence path. This summary covers RFC 5286 only; TI-LFA's repair-tunnel
and SR-label mechanics are not specified here.

## Compatibility

- No protocol changes; an LFA-capable router interoperates with non-LFA routers
  with no negotiation. Coverage depends purely on topology (§1, abstract).
- LDP requires the §5 configuration (liberal retention, downstream-unsolicited,
  advertise to all neighbors) to follow LFAs; otherwise IP forwarding still uses
  LFAs but LDP traffic does not get the backup label.
- Assumes a single failure and that all other routers forward on the shortest
  path; correlated failures beyond the protected scope may micro-loop until the
  next full SPF (§1.1).
- Both primary and alternate paths must be in the same routing area (§1).
