# RFC 5340 - OSPF for IPv6

## Meta

| Field | Value |
|-------|-------|
| RFC | 5340 |
| Title | OSPF for IPv6 |
| Status | Standards Track |
| Date | July 2008 |
| Authors | R. Coltun, D. Ferguson, J. Moy, A. Lindem |
| Obsoletes | RFC 2740 |
| Updates | None |
| Updated by | RFC 6845, RFC 6860, RFC 7503, RFC 8362, RFC 9454 |

**Purpose:** Defines OSPFv3, the IPv6 version of OSPF. The flooding,
DR election, areas, neighbor FSM, and SPF concepts remain OSPF, but the
packet header, LSA registry, addressing model, checksum, and prefix
carriage change for IPv6.

**Scope for Ze:** This is the base protocol for an `ospfv3` edge plugin.
It is not an extension to the OSPFv2 wire codec. Copy the proven OSPFv2
engine shape, but keep packet, LSA, LSDB, and auth code separate.

## Major Differences from OSPFv2

| Area | RFC 5340 rule | Implementation consequence |
|------|---------------|----------------------------|
| Link model | OSPFv3 runs per link, not per IP subnet (§2.1) | Interface enrollment is keyed by link and Instance ID, not by IPv4 subnet |
| Addressing | Addresses are removed from OSPF packets and basic topology LSAs | Router-LSA and Network-LSA describe graph only; prefixes live in prefix LSAs |
| Transport | IPv6 protocol 89, link-local source, multicast `ff02::5` and `ff02::6` (§2.9) | Raw IPv6 socket must bind the interface and join both multicast groups as needed |
| Header | 16-byte common header, no AuType and no Authentication field (§A.3.1) | OSPFv2 auth code cannot be shared; use RFC 7166 trailer for auth |
| Instance ID | 8-bit field with link-local significance (§A.3.1) | Drop received packets whose Instance ID does not match the interface |
| Interface ID | 32-bit identifier for each local interface (§A.3.2, §A.4.3) | Hello, Router-LSA, Network-LSA, and SPF use Interface IDs, not link-local addresses as graph identifiers |
| Flooding scope | LS type high bits encode link-local, area, or AS scope (§A.4.2.1) | LSDB keys and flood queues must carry scope explicitly |
| Prefix encoding | PrefixLength, PrefixOptions, and padded 32-bit words (§A.4.1) | Prefix byte length is `((PrefixLength + 31) / 32) * 4`; reject overrun and non-zero padding bits |
| Authentication | Header authentication was removed | RFC 7166 trailer is the preferred non-IPsec auth path for Ze |

## Packet Header (§A.3.1)

Every OSPFv3 packet starts with a 16-byte header:

| Field | Width | Rule |
|-------|-------|------|
| Version | 8 bits | Must be 3 |
| Type | 8 bits | 1 Hello, 2 Database Description, 3 Link State Request, 4 Link State Update, 5 Link State Acknowledgment |
| Packet length | 16 bits | Length of the OSPF packet starting at the OSPF header |
| Router ID | 32 bits | Source router identifier, still IPv4-shaped |
| Area ID | 32 bits | Area for this packet; backbone is 0 |
| Checksum | 16 bits | IPv6 upper-layer checksum over the OSPF packet plus IPv6 pseudo-header, Next Header 89 |
| Instance ID | 8 bits | Link-local OSPF instance selector |
| Reserved | 8 bits | Send zero, ignore on receive |

Checksum uses the OSPF packet length as the IPv6 pseudo-header upper-layer
packet length. The checksum field is zeroed before calculation. RFC 7166
changes this when the authentication trailer is used.

## Packet Types (§A.3.2 through §A.3.6)

| Type | Name | OSPFv3 differences to preserve |
|------|------|--------------------------------|
| 1 | Hello | Contains Interface ID, router priority, Options, intervals, DR/BDR Router IDs, and neighbor Router IDs. There is no network mask field |
| 2 | Database Description | Carries Options, Interface MTU, I/M/MS bits, DD sequence, and LSA headers |
| 3 | Link State Request | Each request item is LS Type, Link State ID, Advertising Router |
| 4 | Link State Update | Carries a count and full LSAs |
| 5 | Link State Acknowledgment | Carries LSA headers for explicit or implicit flood acknowledgments |

## LSA Header and LSA Type (§A.4.2)

All LSAs start with a 20-byte LSA header: LS Age, LS Type, Link State ID,
Advertising Router, LS Sequence Number, LS Checksum, Length. The LS Type
high bits encode handling and flooding scope:

| Bits | Meaning |
|------|---------|
| U | Unknown LSA handling. 0 means treat as link-local, 1 means store and flood as if understood |
| S2/S1 | Scope. 00 link-local, 01 area, 10 AS, 11 reserved |
| Function code | LSA function within the chosen scope |

Ze must key the LSDB by scope plus LS Type, Link State ID, and Advertising
Router, and must never flood a link-local LSA beyond its originating link.

## Base LSA Types (§A.4)

| LS Type | Name | Flooding scope | Role |
|---------|------|----------------|------|
| `0x2001` | Router-LSA | Area | Router topology links, options, V/E/B/Nt/R bits |
| `0x2002` | Network-LSA | Area | DR-originated list of routers attached to a broadcast or NBMA link |
| `0x2003` | Inter-Area-Prefix-LSA | Area | ABR-originated IPv6 prefix summary into another area |
| `0x2004` | Inter-Area-Router-LSA | Area | ABR-originated reachability to an ASBR in another area |
| `0x4005` | AS-External-LSA | AS | External IPv6 prefixes |
| `0x2007` | NSSA-LSA | Area | NSSA external prefixes before Type 5 translation |
| `0x0008` | Link-LSA | Link-local | Router link-local address, link-local options, prefixes for the link |
| `0x2009` | Intra-Area-Prefix-LSA | Area | IPv6 prefixes attached to a Router-LSA or Network-LSA |

## Prefix Encoding (§A.4.1)

IPv6 prefixes are encoded as `PrefixLength`, `PrefixOptions`, and an address
prefix padded to a multiple of 32-bit words. The number of 32-bit words is
`(PrefixLength + 31) / 32`. Prefix length 0 represents the default route.

The NU bit excludes a prefix from unicast calculation. The LA bit marks a
local interface address. The P bit controls NSSA propagation. The DN bit is
used for VPN re-advertisement control. Deprecated or reserved bits must be
sent zero and ignored unless an extension spec claims them.

## SPF and Route Install

SPF builds the topology from Router-LSAs and Network-LSAs, then attaches
IPv6 prefixes from Intra-Area-Prefix-LSAs. Inter-area routes use
Inter-Area-Prefix-LSAs and Inter-Area-Router-LSAs. External routes use
AS-External-LSAs and NSSA-LSAs. Ze should install IPv6 `locrib.Path` entries
through the existing Loc-RIB, sysrib, and fibkernel pipeline.
