# RFC 2782 — A DNS RR for specifying the location of services (DNS SRV)

Implementation-relevant summary. Full text: https://www.rfc-editor.org/rfc/rfc2782

## Purpose

Defines the SRV resource record, which lets a client discover the host(s) and
port offering a given service in a domain, with priority/weight load balancing.

## Owner name

`_Service._Proto.Name` (e.g. `_kerberos._tcp.example.`). `_Service` is the
symbolic service name, `_Proto` is usually `_tcp` or `_udp`, `Name` is the
domain the record refers to.

## RDATA format

```
Priority  Weight  Port  Target
```

- **Priority** — unsigned 16-bit (0..65535). Lower priority is tried first.
- **Weight** — unsigned 16-bit (0..65535). Relative weight among records of the
  same priority (load balancing). Weight 0 means no special weighting.
- **Port** — unsigned 16-bit (0..65535). The port the service runs on.
- **Target** — the canonical hostname of the machine providing the service. A
  domain name; MUST NOT be a name alias (no CNAME). A Target of `.` means the
  service is decidedly not available at this domain.

## How geodns applies this

- A host record of `type SRV` carries a `srv { priority; weight; port; target }`
  block. `priority`, `weight`, `port` are parsed as uint16 (0..65535); `target`
  is FQDN-normalised. All four are required — a missing field rejects the record
  (`parseSRV` in `internal/plugins/geodns/config.go`).
- geodns serves SRV answers verbatim; it does not perform the client-side
  priority/weight selection (that is the resolver/client's job).
