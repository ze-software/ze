**Purpose:** Defines two TFTP options: "timeout" (retransmission interval) and
"tsize" (transfer size). Uses the OACK mechanism from RFC 2347.

**Scope:** Two independent option definitions.

## Timeout Option (Timeout Interval Option Specification section)

| Field | Value |
|-------|-------|
| Option name | `timeout` (case-insensitive) |
| Option value | ASCII decimal, seconds before retransmit |
| Valid range | 1 to 255, inclusive |

- Server's acknowledged value MUST match the client's requested value
  (no counter-proposal).

## Transfer Size Option (Transfer Size Option Specification section)

| Field | Value |
|-------|-------|
| Option name | `tsize` (case-insensitive) |
| Option value | ASCII decimal, file size in octets |

### Read Request behavior

- Client sends `tsize` with value `0` in the RRQ.
- Server determines the file size and returns it in the OACK.
- "In Read Request packets, a size of '0' is specified in the request
  and the size of the file, in octets, is returned in the OACK."
- If the file is too large for the client, it aborts with ERROR code 3
  (disk full / allocation exceeded).

### Write Request behavior

- Client sends `tsize` with the actual file size in the WRQ.
- Server echoes the size back in the OACK.
- If the file is too large for the server, it aborts with ERROR code 3.

## Wire Format in RRQ/WRQ

```
    2 bytes    string   1B   string   1B  string  1B  string  1B
    -------------------------------------------------------------
   | opc   | filename |  0 |  mode  |  0 | tsize |  0 |  size |  0 |
    -------------------------------------------------------------
```

## MUST Requirements

- Timeout: server's value MUST match client's value exactly.
- Tsize in RRQ: client's value MUST be "0"; server returns actual size.
- Tsize in WRQ: server's OACK value MUST echo client's value.

## Constants

| Name | Value | Usage |
|------|-------|-------|
| TIMEOUT_MIN | 1 | Minimum timeout in seconds |
| TIMEOUT_MAX | 255 | Maximum timeout in seconds |

## Pitfalls

- **tsize=0 is a query, not "zero-byte file":** In a Read Request,
  `tsize` value `0` means "tell me the file size." The server stats the
  file and returns the real size in the OACK. This is the standard UEFI
  PXE probe before download.

- **tsize requires stat, not transfer:** The server must be able to
  determine file size (e.g., via stat/fstat) without reading the entire
  file, since this is a pre-transfer query.
