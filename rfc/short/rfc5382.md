**Related:** RFC 4787 (the UDP requirements, whose terminology this document reuses)

## Purpose

Applies the RFC 4787 behavioral vocabulary to TCP: mapping and filtering of
TCP connections, the handling of internally and externally initiated
connections (including simultaneous open), idle timeouts, port assignment,
hairpinning and ICMP.

## Timers

| Name | RFC floor | Linux default (ze sets none) |
|------|-----------|------------------------------|
| Established connection idle-timeout | 2 hours 4 minutes | nf_conntrack_tcp_timeout_established 432000 s |
| Transitory connection idle-timeout | 4 minutes | syn_sent 120 s, syn_recv 60 s, fin_wait 120 s, close_wait 60 s, last_ack 30 s, time_wait 120 s, close 10 s |
| Unsolicited inbound SYN hold | at least 6 seconds | none |

## Compliance Checklist

- [ ] [RFC5382-4.1-1] [MUST] REQ-1: A NAT MUST have an "Endpoint-Independent Mapping" behavior for TCP. (§4.1) {gap: nf_nat preserves the internal source port only while the translated 5-tuple is unique and otherwise allocates another port for that destination, the masquerade random and fully-random flags ze lowers randomize per connection, and VPP NAT44-ED maps per endpoint; internal/plugins/firewall/nft/lower_linux.go lowerMasquerade}
- [ ] [RFC5382-4.2-1] [MUST] REQ-2: A NAT MUST support all valid sequences of TCP packets (defined in [RFC0793]) for connections initiated both internally as well as externally when the connection is permitted by the NAT. (§4.2) {lower-layer: Linux nf_conntrack TCP tracker; internal/plugins/firewall/nft/lower_linux.go::lowerMasquerade installs the NAT rule and the tracker follows every RFC 793 state transition of the translated connection}
- [ ] [RFC5382-4.2-2] [MUST] In addition to handling the TCP 3-way handshake mode of connection initiation, A NAT MUST handle the TCP simultaneous- open mode of connection initiation. (§4.2) {lower-layer: Linux nf_conntrack TCP tracker; internal/plugins/firewall/nft/lower_linux.go::lowerMasquerade installs the NAT rule and the tracker accepts a SYN answered by a SYN as a simultaneous open}
- [ ] [RFC5382-4.3-1] [MUST NOT] REQ-4: A NAT MUST NOT respond to an unsolicited inbound SYN packet for at least 6 seconds after the packet is received. (§4.3) {gap: ze installs nothing that holds an unsolicited inbound SYN; one addressed to the NAT's external address matches no conntrack entry, reaches the NAT's own Linux TCP stack and is answered with a RST at once unless an operator input filter drops it}
- [ ] [RFC5382-4.3-2] [MUST] If during this interval the NAT receives and translates an outbound SYN for the connection the NAT MUST silently drop the original unsolicited inbound SYN packet. (§4.3) {gap: no unsolicited SYN is held (RFC5382-4.3-1), so a later outbound SYN cannot cause it to be dropped}
- [ ] [RFC5382-4.3-3] [MUST] The NAT MUST silently drop the original SYN packet if sending a response violates the security policy of the NAT. (§4.3) {gap: whether the NAT's own TCP stack answers with a RST or an operator filter drops the SYN is decided by the input ruleset, and ze ties no NAT security policy to that choice}
- [ ] [RFC5382-5-1] [MUST NOT] In such cases, the value of the "established connection idle-timeout" MUST NOT be less than 2 hours 4 minutes. (§5) {lower-layer: Linux nf_conntrack; internal/plugins/firewall/nft/lower_linux.go::lowerMasquerade installs the NAT rule and no timeout policy, so an established connection keeps nf_conntrack_tcp_timeout_established, 432000 seconds}
- [ ] [RFC5382-5-2] [MUST NOT] The value of the "transitory connection idle-timeout" MUST NOT be less than 4 minutes. (§5) {gap: ze installs no conntrack timeout policy, so Linux's transitory TCP timeouts apply, from 10 seconds (close) to 120 seconds (syn_sent, time_wait)}
- [ ] [RFC5382-7.1-1] [MUST NOT] REQ-7: A NAT MUST NOT have a "Port assignment" behavior of "Port overloading" for TCP. (§7.1) {lower-layer: Linux nf_nat; internal/plugins/firewall/nft/lower_linux.go::lowerMasquerade installs the masquerade expression and nf_nat's unique-tuple allocation never gives two internal endpoints one external tuple}
- [ ] [RFC5382-7.2-1] [MUST] REQ-8: A NAT MUST support "hairpinning" for TCP. a) A NAT's hairpinning behavior MUST be of type "External source IP address and port". (§7.2) {gap: ze generates no hairpin rule, and a SYN from an internal host to another internal host's external mapping matches no conntrack reply tuple and is delivered to the NAT itself, so no hairpin exists and no hairpin source is translated}
- [ ] [RFC5382-7.3-1] [MUST NOT] REQ-10: Receipt of any sort of ICMP message MUST NOT terminate the NAT mapping or TCP connection for which the ICMP was generated. (§7.3) {lower-layer: Linux nf_conntrack; internal/plugins/firewall/nft/lower_linux.go::lowerMasquerade installs the NAT rule and nf_conntrack classifies an ICMP error as RELATED to the connection without deleting it}
- [ ] [RFC5382-4.3-4] [RECOMMENDED] REQ-3: If application transparency is most important, it is RECOMMENDED that a NAT have an "Endpoint-Independent Filtering" behavior for TCP. (§4.3)
- [ ] [RFC5382-4.3-5] [RECOMMENDED] If a more stringent filtering behavior is most important, it is RECOMMENDED that a NAT have an "Address-Dependent Filtering" behavior. (§4.3)
- [ ] [RFC5382-4.3-6] [SHOULD] Otherwise, the NAT SHOULD send an ICMP Port Unreachable error (Type 3, Code 3) for the original SYN, unless REQ-4a applies. (§4.3)
- [ ] [RFC5382-6-1] [RECOMMENDED] REQ-6: If a NAT includes ALGs that affect TCP, it is RECOMMENDED that all of those ALGs (except for FTP [RFC0959]) be disabled by default. (§6)
- [ ] [RFC5382-7.3-2] [SHOULD] REQ-9: If a NAT translates TCP, it SHOULD translate ICMP Destination Unreachable (Type 3) messages. (§7.3)
- [ ] [RFC5382-4.3-7] [MAY] a) The filtering behavior MAY be an option configurable by the administrator of the NAT. (§4.3)
- [ ] [RFC5382-4.3-8] [MAY] b) The filtering behavior for TCP MAY be independent of the filtering behavior for UDP. (§4.3)
- [ ] [RFC5382-5-3] [MAY] REQ-5: If a NAT cannot determine whether the endpoints of a TCP connection are active, it MAY abandon the session if it has been idle for some time. (§5)
- [ ] [RFC5382-5-4] [MAY] a) The value of the NAT idle-timeouts MAY be configurable. (§5)
- [ ] [RFC5382-5-5] [MAY] A NAT MAY hold state for a connection in TIME_WAIT state to accommodate retransmissions of the last ACK. (§5)
- [ ] [RFC5382-5-6] [MAY] When a NAT abandons a live connection, for example due to a timeout expiring, the NAT MAY either send TCP RST packets to the endpoints or MAY silently abandon the connection. (§5)
