## Purpose

Applies the RFC 4787 behavioral vocabulary to TCP: mapping and filtering of
TCP connections, the handling of internally and externally initiated
connections (including simultaneous open), idle timeouts, port assignment,
hairpinning and ICMP.

## Timers

| Name | RFC floor | Linux default (ze sets none) |
|------|-----------|------------------------------|
| Established connection idle-timeout | 2 hours 4 minutes | nf_conntrack_tcp_timeout_established 432000 s |
| Transitory connection idle-timeout | 4 minutes | syn_sent 120 s, syn_recv 60 s, fin_wait 120 s, close_wait 60 s, last_ack 30 s, time_wait 120 s, close 10 s |
| Unsolicited inbound SYN hold | at least 6 seconds | none |

## Compliance Checklist

- [ ] [RFC5382-4.1-1] [MUST] REQ-1: A NAT MUST have an "Endpoint-Independent Mapping" behavior for TCP. (§4.1) {gap: nf_nat preserves the internal source port only while the translated 5-tuple is unique and otherwise allocates another port for that destination, the masquerade random and fully-random flags ze lowers randomize per connection, and VPP NAT44-ED maps per endpoint; internal/plugins/firewall/nft/lower_linux.go lowerMasquerade}
- [ ] [RFC5382-4.2-1] [MUST] REQ-2: A NAT MUST support all valid sequences of TCP packets (defined in [RFC0793]) for connections initiated both internally as well as externally when the connection is permitted by the NAT. (§4.2) {gap: on the nft backend the kernel performs it: internal/plugins/firewall/nft/lower_linux.go::lowerMasquerade (with lowerSNAT and lowerDNAT) installs the NAT rule and the Linux nf_conntrack TCP tracker (nf_conntrack_proto_tcp.c, linux:CONFIG_NF_CONNTRACK) follows every RFC 793 state transition of the translated connection in nf_conntrack_tcp_packet over its tcp_conntracks table; the be_liberal and loose values internal/component/config/system/conntrack.go::addTCPBehavior can write widen what the tracker accepts and remove no transition; the firewall backend leaf is operator-set, and on the vpp backend internal/plugins/firewall/vpp/nat_linux.go::applyMasquerade (with applySNAT and applyDNAT) programs VPP NAT44-ED instead, whose TCP state tracking no test or source reading has verified}
- [ ] [RFC5382-4.2-2] [MUST] In addition to handling the TCP 3-way handshake mode of connection initiation, A NAT MUST handle the TCP simultaneous- open mode of connection initiation. (§4.2) {gap: on the nft backend the kernel performs it: internal/plugins/firewall/nft/lower_linux.go::lowerMasquerade (with lowerSNAT and lowerDNAT) installs the NAT rule and the Linux nf_conntrack TCP tracker (nf_conntrack_proto_tcp.c, linux:CONFIG_NF_CONNTRACK) accepts a SYN answered by a SYN as a simultaneous open, the TCP_CONNTRACK_SYN_SENT2 state of its tcp_conntracks table; the firewall backend leaf is operator-set, and on the vpp backend internal/plugins/firewall/vpp/nat_linux.go::applyMasquerade (with applySNAT and applyDNAT) programs VPP NAT44-ED instead, whose handling of a simultaneous open no test or source reading has verified}
- [ ] [RFC5382-4.3-1] [MUST NOT] REQ-4: A NAT MUST NOT respond to an unsolicited inbound SYN packet for at least 6 seconds after the packet is received. (§4.3) {gap: ze installs nothing that holds an unsolicited inbound SYN; one addressed to the NAT's external address matches no conntrack entry, reaches the NAT's own Linux TCP stack and is answered with a RST at once unless an operator input filter drops it}
- [ ] [RFC5382-4.3-2] [MUST] If during this interval the NAT receives and translates an outbound SYN for the connection the NAT MUST silently drop the original unsolicited inbound SYN packet. (§4.3) {gap: no unsolicited SYN is held (RFC5382-4.3-1), so a later outbound SYN cannot cause it to be dropped}
- [ ] [RFC5382-4.3-3] [MUST] The NAT MUST silently drop the original SYN packet if sending a response violates the security policy of the NAT. (§4.3) {gap: whether the NAT's own TCP stack answers with a RST or an operator filter drops the SYN is decided by the input ruleset, and ze ties no NAT security policy to that choice}
- [ ] [RFC5382-5-1] [MUST NOT] In such cases, the value of the "established connection idle-timeout" MUST NOT be less than 2 hours 4 minutes. (§5) {gap: the established idle timeout is a value Ze writes: the `system conntrack timeout tcp established` leaf accepts 1 to 604800 seconds and internal/component/config/system/conntrack.go::addTCPTimeouts writes it to net.netfilter.nf_conntrack_tcp_timeout_established, so an operator value below 7440 seconds breaks this MUST NOT and nothing refuses it; the Linux default of five days holds only while the leaf is unset}
- [ ] [RFC5382-5-2] [MUST NOT] The value of the "transitory connection idle-timeout" MUST NOT be less than 4 minutes. (§5) {gap: Ze writes a transitory TCP conntrack timeout only when the operator sets one under `system conntrack timeout tcp`, which internal/component/config/system/conntrack.go::addTCPTimeouts writes to the net.netfilter.nf_conntrack_tcp_timeout_* sysctls from leaves that accept values down to 1 second; with the leaves unset Linux's transitory TCP timeouts apply, from 10 seconds (close) to 120 seconds (syn_sent, time_wait), and an operator value below 4 minutes is not refused; on the vpp backend the NAT44-ED transitory timeout is unverified}
- [ ] [RFC5382-7.1-1] [MUST NOT] REQ-7: A NAT MUST NOT have a "Port assignment" behavior of "Port overloading" for TCP. (§7.1) {gap: nf_nat checks a candidate translation for collision on the full reply tuple (net/netfilter/nf_nat_core.c nf_nat_used_tuple inverts the tuple and asks nf_conntrack_tuple_taken), so two internal endpoints can be given one external address and port toward different remote endpoints, which is the port overloading RFC 4787 Section 4.2.1 describes and this section forbids for TCP; internal/plugins/firewall/nft/lower_linux.go::lowerMasquerade and lowerSNAT install no option that keeps an external port to one internal endpoint, and the firewall backend leaf is operator-set, and on the vpp backend internal/plugins/firewall/vpp/nat_linux.go::applyMasquerade (with applySNAT and applyDNAT) programs VPP NAT44-ED instead, whose port assignment no test or source reading has verified}
- [ ] [RFC5382-7.2-1] [MUST] REQ-8: A NAT MUST support "hairpinning" for TCP. a) A NAT's hairpinning behavior MUST be of type "External source IP address and port".
