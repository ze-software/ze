**Purpose:** Adds a `resource` parameter to OAuth authorization and token requests. Section 2 recommends audience-restricted tokens and permits the authorization server to map a resource value to a broader URI or abstract identifier.

**Scope:** Partial implementation. No authorization/token request producer or
AS token issuer is offered under the 2026-09-21 scope decision. Local audience
verification remains implemented and testable; its retained historical IDs are
not evidence of normative text in RFC 8707 §5.

The absolute-URI constraint is recorded as RFC8707-2-6. Producing OAuth
authorization or token requests remains an absent feature; the source mapping
does not claim that Ze implements or has verified that request parameter.

## Client Behavior (Section 2)

| Requirement | Item |
|-------------|------|
| `resource` parameter on authorization request | An absolute URI identifying the target resource. |
| MAY appear on token endpoint | When present, the AS uses it to select the audience. |
| Multiple `resource` values | MAY appear; AS policy decides. |

## Authorization Server Behavior (Sections 2 and 2.1)

| Requirement | Item |
|-------------|------|
| Validate `resource` against registered metadata | AS decides which values it issues tokens for. |
| Set the token audience | The AS SHOULD audience-restrict tokens to the indicated resources (§2). |
| Reject unacceptable resources | Section 2.1 recommends the `invalid_target` error. |

## Resource Server Behavior (RFC 7519 Sections 2 and 4.1.3)

This is the rule the MCP resource server enforces:

| Requirement | Item |
|-------------|------|
| Verify `aud` on every token | Reject a token whose audience does not identify this resource server. |
| String equality | Compare case-sensitive strings with no transformations or canonicalization (RFC 7519 §2). |
| Multiple audiences | RFC 7519 §4.1.3 permits a string or an array of strings. At least one must identify this resource server. |

RFC 8707 does not define URL canonicalization for JWT audience comparison.
Distinct trailing slashes, queries, escaped path segments and Unicode spellings
remain distinct audience identifiers. Section 2 prohibits fragments in the
`resource` request parameter and recommends omitting queries, but explicitly
allows useful query components.

## Ze Implementation

- Audience comparison: `internal/component/mcp/jwt.go` `audClaim.Matches` exact-match on string or array-form `aud`.
- Operator config: `environment.mcp.oauth.audience` is the exact audience identifier. It must be set explicitly and never comes from `r.Host`.
- Rejection path: `oauthAuthenticator.mapVerifyError` maps `errJWTAudienceMismatch` to `error="invalid_token", error_description="invalid audience"` per RFC 6750 vocabulary.

## Key Security Property

Audience restriction prevents a token intended only for resource A from being
accepted by resource B. RFC 8707 communicates requested resource targets to an
authorization server; RFC 7519 defines how a JWT recipient checks `aud`. A JWT
audience can be assigned and checked even when no RFC 8707 `resource` request
parameter was used.
