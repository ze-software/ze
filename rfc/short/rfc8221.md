**Purpose:** Grades the ESP and AH encryption, integrity and compression algorithms for implementers, replacing RFC 7321, with the same MUST-/SHOULD+ terms as RFC 8247.

**Ze context:** The grades bind the algorithms ze can negotiate for a Child SA and install into the datapath. Ze offers no AH for IKE-negotiated SAs.

## Encryption (Section 5)

| Name | Status | AEAD | ze |
|------|--------|------|----|
| ENCR_DES_IV64, ENCR_DES, ENCR_BLOWFISH, ENCR_3IDEA, ENCR_DES_IV32 | MUST NOT | No | no |
| ENCR_3DES | SHOULD NOT | No | ESP |
| ENCR_NULL | MUST | No | ESP |
| ENCR_AES_CBC | MUST (128, 256) | No | yes |
| ENCR_AES_CCM_8 | SHOULD | Yes | IKE SA only |
| ENCR_AES_GCM_16 | MUST (128, 256) | Yes | yes |
| ENCR_CHACHA20_POLY1305 | SHOULD | Yes | ESP |

## Integrity (Section 6)

| Name | Status | ze |
|------|--------|----|
| AUTH_NONE | MUST with AEAD only, MUST NOT otherwise | AEAD only |
| AUTH_HMAC_MD5_96, AUTH_KPDK_MD5, AUTH_DES_MAC | MUST NOT | no |
| AUTH_HMAC_SHA1_96 | MUST- | ESP |
| AUTH_AES_XCBC_96 | SHOULD (IoT) / MAY | no |
| AUTH_AES_128_GMAC, AUTH_AES_256_GMAC | MAY | no |
| AUTH_HMAC_SHA2_256_128 | MUST | yes |
| AUTH_HMAC_SHA2_512_256 | SHOULD | yes |

## Compression (Section 7)

IPCOMP_OUI MUST NOT; IPCOMP_DEFLATE, IPCOMP_LZS, IPCOMP_LZJH MAY. Ze offers none.

## Compliance Checklist

- [ ] [RFC8221-3-1] [MUST NOT] If manual keying is used regardless, Counter Mode algorithms such as ENCR_AES_CTR, ENCR_AES_CCM, ENCR_AES_GCM, and ENCR_CHACHA20_POLY1305 MUST NOT be used, as it is incompatible with a secure and persistent handling of the counter (as explained in the Security Considerations section of [RFC3686]). (§3)
- [ ] [RFC8221-4-1] [MUST NOT] Encryption without authentication is not effective and MUST NOT be used. (§4)
- [ ] [RFC8221-5-1] [MUST] For that purpose, the requirement level for 128-bit keys and 256-bit keys is MUST (when applicable). (§5)
- [ ] [RFC8221-5-2] [MUST NOT] These algorithms were not mentioned in [RFC7321], and this document clarifies that such algorithms MUST NOT be implemented for IPsec communications. (§5)
- [ ] [RFC8221-5-3] [MUST NOT] As a result, these algorithms MUST NOT be implemented. (§5)
- [ ] [RFC8221-5-4] [MUST NOT] Various ciphers that are older, not well tested, and never widely implemented have been changed to MUST NOT. (§5)
- [ ] [RFC8221-5-5] [MUST NOT] ENCR_BLOWFISH has been downgraded to MUST NOT as it has been deprecated for years by TWOFISH, which is not standardized for ESP and therefore not listed in this document. (§5)
- [ ] [RFC8221-5-6] [MUST] ENCR_NULL status was set to MUST in [RFC7321] and remains a MUST to enable the use of ESP with only authentication, which is preferred over AH due to NAT traversal. (§5)
- [ ] [RFC8221-5-7] [MUST] ENCR_AES_CBC MUST be implemented in order to enable interoperability between implementations that followed [RFC7321]. (§5)
- [ ] [RFC8221-5-8] [MUST] ENCR_AES_GCM_16 status has been updated from SHOULD+ to MUST in order to favor the use of authenticated encryption and AEAD algorithms. (§5)
- [ ] [RFC8221-6-1] [MUST NOT] AUTH_NONE has been downgraded from MAY in [RFC7321] to MUST NOT. (§6)
- [ ] [RFC8221-6-2] [MUST NOT] In all other cases, AUTH_NONE MUST NOT be selected. (§6)
- [ ] [RFC8221-6-3] [MUST NOT] As MD5 is known to be vulnerable to collisions, these algorithms MUST NOT be used. (§6)
- [ ] [RFC8221-6-4] [MUST] AUTH_HMAC_SHA1_96 has been downgraded from MUST in [RFC7321] to MUST- as there is an industry-wide trend to deprecate its usage. (§6)
- [ ] [RFC8221-6-5] [MUST NOT] As DES is known to be vulnerable, it MUST NOT be used. (§6)
- [ ] [RFC8221-6-6] [MUST] AUTH_HMAC_SHA2_256_128 MUST be implemented in order to replace AUTH_HMAC_SHA1_96. (§6)
- [ ] [RFC8221-5-9] [SHOULD] Its status has been set to SHOULD and is expected to become MUST in the long term. (§5)
- [ ] [RFC8221-6-7] [SHOULD] AUTH_HMAC_SHA2_512_256 SHOULD be implemented as a future replacement of AUTH_HMAC_SHA2_256_128 or when stronger security is required. (§6)
- [ ] [RFC8221-7-1] [MAY] As it is not widely deployed, it remains optional and at the MAY level. (§7)

## Pitfalls

- AUTH_NONE is correct only beside an AEAD cipher; ENCR_NULL with AUTH_NONE protects nothing (Section 6).
- Counter-mode ciphers under manual keys reuse counters across restarts (Section 3), so a manually keyed SA must use AES-CBC or NULL.
