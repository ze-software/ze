# RFC 7999: BLACKHOLE Community

**Status:** Informational
**Date:** October 2016
**Authors:** T. King, C. Dietzel, J. Snijders, G. Doering, G. Hankins

## Overview

Defines the BLACKHOLE well-known community (0xFFFF029A = 65535:666).
Provides a standardized mechanism for remotely triggered blackhole (RTBH)
filtering. A network under DDoS attack tags victim prefixes with this
community and announces them to upstream providers, who then null-route
traffic destined for those prefixes at their edge.

Before this RFC, operators used ad-hoc per-network communities for
blackholing, requiring bilateral agreements. The well-known community
enables automatic blackholing across any BLACKHOLE-aware network.

## Well-Known Community

| Community | Value | Hex | Decimal |
|-----------|-------|-----|---------|
| BLACKHOLE | 65535:666 | 0xFFFF029A | 4294967962 |

## Operation

### Signaling

1. Victim network identifies prefix under attack (e.g., 203.0.113.1/32)
2. Originates or re-tags the prefix with the BLACKHOLE community
3. Announces to upstream provider(s) via BGP

### Receiving

1. Provider recognizes BLACKHOLE community on incoming route
2. Sets next-hop to a null-route/discard interface
3. Traffic to the victim prefix is dropped at the provider edge
4. Provider SHOULD NOT propagate BLACKHOLE routes further upstream

## Key Requirements

| Requirement | Detail |
|-------------|--------|
| Prefix length | SHOULD be /32 (IPv4) or /128 (IPv6) for precision |
| Propagation | Receiver SHOULD NOT propagate blackholed routes to peers/upstream |
| Scope | Local to the receiving network by default |
| Verification | Receiver SHOULD validate the origin of BLACKHOLE-tagged routes |
| Filtering | Receiver SHOULD accept BLACKHOLE only from customers, not peers |

## Deployment Considerations

- Blackholing drops ALL traffic to the prefix, including legitimate traffic
- More-specific prefixes (/32, /128) limit collateral damage
- Providers should filter: only accept BLACKHOLE from direct customers
  whose prefix is covered by a less-specific the customer legitimately
  originates
- Can be combined with FlowSpec (RFC 8955) for surgical filtering

## Interaction with Route Servers

- IXP route servers MAY support BLACKHOLE community
- Route server distributes the blackhole route to all IXP participants
- Each participant decides locally whether to honor the blackhole
