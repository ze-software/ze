**Purpose:** Defines the `ietf-ospf` YANG data model used to configure and manage OSPF. It augments the routing control-plane-protocol tree from RFC 8349, references the key-chain model from RFC 8177, and supports **both OSPFv2 (RFC 2328) and OSPFv3 (RFC 5340)** under one module (§2.3, "OSPFv2 and OSPFv3").

**Scope:** This summary captures the high-level shape of the model (containers, lists, key leaves) as a reference for shaping Ze's own schema and for future gNMI/YANG conformance. It is NOT a full transcription of the module. **Ze does not adopt `ietf-ospf` verbatim:** Ze ships its own `ze-ospf-conf.yang` with kebab-case leaves and a per-interface area binding (interface declares its `area`), rather than nesting interfaces under each area as RFC 9129 does. Use this document to align leaf semantics and defaults, not to copy structure.

## Where It Lives (§2.2, §2.5)

The module augments the base routing tree (RFC 8349). The protocol instance hangs off a named `control-plane-protocol` entry; everything OSPF lives under one `ospf` container.

| Path | Meaning |
|------|---------|
| `/routing/control-plane-protocols/control-plane-protocol` (RFC 8349) | Generic per-protocol anchor |
| `.../control-plane-protocol/ospf` | The OSPF instance container (augment) |

## Instance Container (§2.5)

The `ospf` container carries router-wide config plus the `areas` subtree.

| Leaf / container | Type | Notes |
|------------------|------|-------|
| `address-family` | identityref | ipv4 / ipv6 (selects OSPFv2 vs OSPFv3 plane) |
| `enabled` | boolean | Enable/disable the instance |
| `explicit-router-id` | router-id | Optional, feature-gated (`explicit-router-id`) |
| `router-id` (ro) | router-id | Operational, configured or derived |
| `spf-control` | container | `paths` (max-ECMP), IETF SPF delay timers (§2.5) |
| `graceful-restart` | container | `enabled`, `helper-enabled`, `restart-interval`, `helper-strict-lsa-checking` (§2.5) |
| `fast-reroute` | container | LFA config, feature-gated (`fast-reroute`/`lfa`) (§2.5) |
| `areas` | container | Holds the per-area list (below) |

## Model Tree (indented, key leaves only)

The model is config (`rw`) and operational state (`ro`) interleaved in one tree. Sections cited inline.

```
ospf  (§2.5)
  address-family            identityref      af selector
  enabled                   boolean
  explicit-router-id        router-id        feature explicit-router-id
  router-id (ro)            router-id        operational
  spf-control               container        paths (max-ecmp), ietf-spf-delay
  graceful-restart          container        enabled / helper-enabled / restart-interval
  fast-reroute              container         feature fast-reroute -> lfa
  areas                                                              (§2.6)
    area* [area-id]
      area-id               area-id-type     LIST KEY
      area-type             identityref      normal-area | stub-area | nssa-area | stub-nssa-area
      summary               boolean          inject summary LSAs into stub/NSSA
      default-cost          ospf-metric      default-summary metric for stub/NSSA
      ranges                                                         (§2.6)
        range* [prefix]
          prefix            inet:ip-prefix   LIST KEY (area-range)
          advertise         boolean          advertise vs suppress the aggregate
          cost              ospf-metric      override metric for the range
      interfaces                                                     (§2.7)
        interface* [name]
          name              if:interface-ref LIST KEY (the area binding)
          interface-type    enumeration      broadcast | point-to-point | non-broadcast(nbma) | point-to-multipoint
          enabled           boolean
          passive           boolean          advertise but form no adjacency
          priority          uint8            DR/BDR election
          cost              ospf-link-metric
          hello-interval    uint16
          dead-interval     uint32
          retransmit-interval uint16
          transmit-delay    uint16
          mtu-ignore        boolean          feature mtu-ignore
          prefix-suppression boolean         feature prefix-suppression
          ttl-security      container        feature ttl-security (enabled, hops)
          bfd               container        feature bfd (enabled, local-multiplier)
          authentication    container        see Authentication below   (§2.7)
          neighbors (ro)                                              (§2.5/§2.6)
            neighbor* [neighbor-router-id]
              neighbor-router-id  router-id  LIST KEY
              address       inet:ip-address
              state         nbr-state-type   down|attempt|init|2-way|exstart|exchange|loading|full
              statistics    container        nbr-event-count, nbr-retrans-qlen
          database (ro)     container        link-scope LSAs for this interface (§2.6)
      statistics (ro)       container        area-scope LSA counts/chksum (§2.6)
  database (ro)             container        as-scope + area-scope LSAs (LSDB)   (§2.5)
  statistics (ro)          container         router-wide LSA counters           (§2.5)
```

## Per-Area List (§2.6)

| Leaf | Type | Notes |
|------|------|-------|
| `area-id` | area-id-type | List key (dotted-quad or uint32) |
| `area-type` | identityref | `normal-area`, `stub-area`, `nssa-area`, `stub-nssa-area` |
| `summary` | boolean | Whether summary LSAs are injected (stub/NSSA) |
| `default-cost` | ospf-metric | Metric of the default summary LSA into a stub/NSSA |
| `ranges/range* [prefix]` | list | Inter-area aggregation: `prefix` (key), `advertise`, `cost` |

Interfaces are nested **inside** the area (`areas/area/interfaces/interface`), so the RFC encodes the area binding by containment. Ze inverts this: the interface names its `area`.

## Per-Interface Config (§2.7)

| Leaf | Type | Default semantics |
|------|------|-------------------|
| `name` | if:interface-ref | List key; the area binding in RFC 9129 |
| `interface-type` | enumeration | `broadcast` / `point-to-point` / `non-broadcast` (NBMA) / `point-to-multipoint` |
| `cost` | ospf-link-metric | Output interface metric |
| `hello-interval` | uint16 | Seconds between Hellos |
| `dead-interval` | uint32 | Router-dead interval (typically 4x hello) |
| `retransmit-interval` | uint16 | LSA retransmit timer |
| `transmit-delay` | uint16 | Estimated LSA transit delay |
| `priority` | uint8 | DR/BDR election priority |
| `passive` | boolean | Advertise prefix, suppress adjacency |
| `mtu-ignore` | boolean | Skip MTU match in DBD exchange (feature `mtu-ignore`) |
| `prefix-suppression` | boolean | Suppress prefix advertisement (feature) |
| `ttl-security` | container | GTSM: `enabled`, `hops` (feature) |
| `bfd` | container | `enabled`, `local-multiplier` (feature `bfd`) |
| `authentication` | container | See below |

## Authentication Model (§2.7)

Authentication is a choice keyed by protocol version. Both versions support a **key-chain reference** (RFC 8177) or an explicit inline key with a crypto-algorithm identity.

| Branch | Key leaves |
|--------|-----------|
| `ospfv2-auth` | `ospfv2-auth-trailer-rfc` (feature `ospfv2-authentication-trailer`) |
| ` -> auth-key-chain` | `ospfv2-key-chain` -> `key-chain:key-chain-ref` (feature `key-chain`) |
| ` -> auth-key-explicit` | `ospfv2-key-id` (uint32), `ospfv2-key` (string), `ospfv2-crypto-algorithm` (identityref) |
| `ospfv3-auth-ipsec` | `sa` (string), feature `ospfv3-authentication-ipsec` |
| `ospfv3-auth-trailer` | feature `ospfv3-authentication-trailer` |
| ` -> auth-key-chain` | `ospfv3-key-chain` -> `key-chain:key-chain-ref` |
| ` -> auth-key-explicit` | `ospfv3-sa-id` (uint16), `ospfv3-key` (string), `ospfv3-crypto-algorithm` (identityref) |

The same `authentication` grouping is reused on virtual-links and sham-links.

## Operational State (§2.5, §2.6)

The state tree is read-only (`ro`) and shares the area/interface containment of config.

| Subtree | Key contents |
|---------|--------------|
| `neighbors/neighbor* [neighbor-router-id]` | `address`, `state` (down/attempt/init/2-way/exstart/exchange/loading/full), per-neighbor `statistics` |
| `database` (LSDB) | Scoped lists: `as-scope-lsa-type*`, `area-scope-lsa-type*`, `link-scope-lsa-type*`; each LSA keyed by `[lsa-id adv-router]` with `raw-data` and a version choice (`ospfv2` / `ospfv3`) |
| `statistics` | `discontinuity-time`, `originate-new-lsa-count`, `rx-new-lsas-count`, per-scope LSA `lsa-count` / `lsa-cksum-sum` |

## Redistribution and Fast-Reroute (§2.5)

- **Fast-reroute:** `fast-reroute/lfa` config plus a `protected-routes` state list (feature `fast-reroute`). §2.5.
- **Redistribution:** RFC 9129 does **not** define a native redistribution container; it expects vendor/augment modules to add route-import policy. Ze handles redistribution through its own plugin path, not via this model.

## Compliance Checklist

This is a YANG data-model RFC (configuration/management surface), so "compliance" here means schema-shape alignment, not on-the-wire bits. Ze's `ze-ospf-conf.yang` is the canonical schema; these items track where it should track or deliberately diverge from RFC 9129.

- [ ] [RFC9129-2.5-1] [SHOULD] Instance carries `address-family` / `router-id` semantics equivalent to §2.5
- [ ] [RFC9129-2.6-1] [SHOULD] Area list keyed by `area-id` with `area-type` covering normal/stub/nssa (§2.6)
- [ ] [RFC9129-2.6-2] [SHOULD] Area `ranges/range` aggregation with `advertise` + `cost`, and stub/NSSA `default-cost` (§2.6)
- [ ] [RFC9129-2.7-1] [SHOULD] Interface carries `interface-type` (broadcast/point-to-point/nbma/point-to-multipoint), `cost`, `hello-interval`, `dead-interval`, `retransmit-interval`, `transmit-delay`, `priority`, `passive`, `mtu-ignore` (§2.7)
- [ ] [RFC9129-2.7-2] [SHOULD] Authentication supports a key-chain reference per RFC 8177 plus explicit key + crypto-algorithm (§2.7)
- [ ] [RFC9129-2.5-2] [SHOULD] Operational state exposes neighbors (with adjacency state), LSDB by scope, and statistics (§2.5, §2.6)
- [ ] [RFC9129-2.9-1] [MAY] Provide `clear-neighbor` / `clear-database` RPC equivalents (§2.9)
- [ ] [NOTE] Ze diverges: kebab-case leaves and per-interface `area` binding instead of interfaces nested under each area
- [ ] [NOTE] Ze diverges: redistribution handled outside this model (RFC 9129 leaves it to augments)
