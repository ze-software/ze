# RFC 8484 — DNS Queries over HTTPS (DoH)

**Status:** Proposed Standard
**Date:** October 2018
**Authors:** P. Hoffman, P. McManus

## Purpose

Specifies sending DNS queries and receiving DNS responses over HTTPS. Each
DNS query-response is mapped onto an HTTP request-response using the
`application/dns-message` media type, so DNS rides on the same encrypted,
authenticated, cache-aware HTTP infrastructure as web traffic.

## Media type and framing (§4.1)

| Property | Value |
|----------|-------|
| Media type | **application/dns-message** (both request and response bodies) |
| Body | The wire-format DNS message exactly as RFC 1035 §4.1 (no 2-octet length prefix, unlike DoT) |
| Transport | HTTP over TLS; servers **MUST** support HTTP/2 (§5.2) |
| URI | A URI Template chosen by the server; `/dns-query` is the common default path |

## HTTP methods (§4.1)

| Method | Query carried as | Cacheable |
|--------|------------------|-----------|
| **GET** | `?dns=<base64url>` — the wire query base64url-encoded (RFC 4648 §5) **without padding** | Yes (HTTP caching applies) |
| **POST** | request body = raw wire-format DNS message, `Content-Type: application/dns-message` | No (bodies are not cached) |

A server **MUST** support both GET and POST. The response body is the
wire-format DNS message with `Content-Type: application/dns-message`.

## How ze applies this

- The authoritative DNS harness (`internal/core/dnsserver`) binds an optional
  DoH listener: a standard `net/http` server over a `crypto/tls` listener. Its
  handler decodes the `application/dns-message` body (POST) or the `?dns=`
  base64url parameter (GET), unpacks it into a `*dns.Msg`, feeds it to the same
  `dns.Handler` used for cleartext DNS and DoT via an in-memory
  `dns.ResponseWriter`, and writes the packed response back with
  `Content-Type: application/dns-message`.
- The in-memory response writer reports the HTTP peer address as the query's
  `RemoteAddr`, so source-based policy (as112 `allow-from`, geodns client-IP
  selection) applies identically to DoH clients.
- The DoH port defaults to **443** and is operator-configurable per listener
  (`doh { listen-port }`); the request path defaults to `/dns-query`.
- HTTP status is always 200 for a well-formed query the handler answered,
  carrying the DNS RCODE inside the response body (§4.2.1). Malformed bodies /
  parameters return 400; unsupported methods return 405.
- ze reuses the same operator PEM or `selfcert` self-signed certificate as DoT,
  and the same `ze doctor` certificate-validity check covers both.

## Notes

- Unlike DoT, DoH bodies carry NO 2-octet length prefix — the HTTP
  `Content-Length` / framing delimits the message.
- ze answers authoritatively (as112, geodns) and is not a recursive resolver,
  so it does not itself act as a DoH client. DoH here is a server transport.
