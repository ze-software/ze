# RFC 2205: Resource ReSerVation Protocol (RSVP)

## Meta

| Field | Value |
|-------|-------|
| RFC | 2205 |
| Title | Resource ReSerVation Protocol (RSVP) -- Version 1 Functional Specification |
| Status | Standards Track |
| Date | September 1997 |
| Authors | R. Braden (ISI), L. Zhang (UCLA), S. Berson (ISI), S. Herzog (ISI), S. Jamin (Univ. of Michigan) |
| Obsoletes | None |
| Updated-by | RFC 2750, RFC 3936, RFC 4495, RFC 5765, RFC 6437, RFC 6780 |

**Purpose:** Defines RSVP, a signaling protocol for reserving network resources along a data path. RSVP operates on IP (protocol 46) and uses a soft-state model where reservations must be periodically refreshed.

## Message Types

| Type | Value | Direction | Purpose |
|------|-------|-----------|---------|
| Path | 1 | Downstream | Carries sender info and route |
| Resv | 2 | Upstream | Carries reservation request |
| PathErr | 3 | Upstream | Error in PATH processing |
| ResvErr | 4 | Downstream | Error in RESV processing |
| PathTear | 5 | Downstream | Removes PATH state |
| ResvTear | 6 | Upstream | Removes RESV state |

| 11 | SENDER_TEMPLATE | Identifies sender in PATH messages |
| 12 | SENDER_TSPEC | Sender traffic specification |

## Soft-State Model

RSVP uses soft-state: all reservation state is created and periodically refreshed by PATH and RESV messages.

| Parameter | Default | Constraints |
|-----------|---------|-------------|
| Refresh period (R) | 30 seconds | Configurable |
| Cleanup timeout | (K+0.5) * 1.5 * R | K = number of allowed losses, typically 3 |
| State lifetime | ~3.5 * R with K=3 | State removed if no refresh within this window |

**Refresh rules:**
- Each PATH/RESV message refreshes the corresponding state
- Missing K consecutive refreshes triggers state cleanup
- PathTear/ResvTear provide explicit teardown (faster than timeout)
- Jitter: SHOULD randomize refresh timing by +/- 50% of R

## Reservation Styles

| Style | Senders | Reservations | Use Case |
|-------|---------|--------------|----------|
| Wildcard Filter (WF) | All | Shared | Multicast with uniform QoS |
| Fixed Filter (FF) | Named | Distinct per sender | Unicast or selective multicast |
| Shared Explicit (SE) | Named | Shared among named | RSVP-TE make-before-break |

**SE style** is critical for RSVP-TE: allows old and new LSPs to share bandwidth during make-before-break rerouting.

## Processing Rules

### PATH Processing (RFC 2205 Section 3.1.3)
1. Validate message integrity
2. Create or update Path State Block (PSB) for (SESSION, SENDER_TEMPLATE)
3. Set cleanup timer to state lifetime
4. Forward PATH downstream (toward destination)

### RESV Processing (RFC 2205 Section 3.1.4)
1. Validate message integrity
2. Perform admission control (check bandwidth availability)
3. Create or update Reservation State Block (RSB)
4. Install reservation in packet classifier
5. Forward RESV upstream (toward sender)

### Teardown Processing
- PathTear: remove PSB and all dependent RSBs, forward downstream
- ResvTear: remove RSB, forward upstream
- Teardown is immediate; no refresh needed

## Error Handling

### ERROR_SPEC Object

| Field | Size | Purpose |
|-------|------|---------|
| Error Node | 4 bytes | IPv4 address of node detecting error |
| Flags | 1 byte | InPlace (0x01), NotGuilty (0x02) |
| Error Code | 1 byte | Error category |
| Error Value | 2 bytes | Error-specific detail |

### Error Codes

| Code | Name | Meaning |
|------|------|---------|
| 1 | Admission Control | Insufficient bandwidth |
| 2 | Policy Control | Administrative rejection |
| 3 | No Path Information | PATH state missing for RESV |
| 4 | No Sender Information | Sender not in PATH state |
| 24 | Routing Problem | Next hop unreachable |

## Transport

- IP protocol number 46 (not TCP or UDP)
- IP Router Alert option (RFC 2113) MUST be set in PATH messages
- Router Alert causes intermediate routers to examine the packet
- Raw IP socket required (CAP_NET_RAW on Linux)

## Implementation Constraints

| Constraint | Section | Enforcement |
|------------|---------|-------------|
| Version MUST be 1 | 3.1 | Reject messages with other versions |
| Object lengths MUST be multiple of 4 | 3.1.2 | Reject malformed objects |
| Unknown Class-Num of the form 0bbbbbbb: reject entire message | 3.10 | Return an "Unknown Object Class" error |
| Unknown Class-Num of the form 10bbbbbb: ignore object | 3.10 | Neither forward it nor send an error |
| Unknown Class-Num of the form 11bbbbbb: ignore object, forward it | 3.10 | Forward unexamined and unmodified in every resulting message |
| Checksum MUST be verified on receipt | 3.1 | Drop messages with bad checksum |
| Refresh period SHOULD be jittered | 3.7 | Prevent synchronization |
