## Purpose

Describes how to install and operate an AS112 node: an anycast DNS
nameserver that sinks misdirected reverse-DNS ("reverse lookup") queries
for private-use address space (RFC 1918, link-local) so that the
IN-ADDR.ARPA infrastructure is not burdened by them. Named after the
Autonomous System Number (112) assigned to the project.

## Two Service Modes (§2.1)

| Mode | Description |
|------|--------------|
| Direct Delegation | Zones for RFC 1918 / link-local reverse space are delegated directly to AS112 nameservers, which are manually configured to answer for them. |
| DNAME Redirection | Any zone administrator redirects queries to a shared EMPTY.AS112.ARPA zone via a DNAME record (RFC 7535), without AS112-operator coordination. |

## Zones Served (§2.2)

| Zone | Mode | Origin |
|------|------|--------|
| 10.IN-ADDR.ARPA | Direct Delegation | RFC 1918 |
| 16.172.IN-ADDR.ARPA … 31.172.IN-ADDR.ARPA (16 zones) | Direct Delegation | RFC 1918 |
| 168.192.IN-ADDR.ARPA | Direct Delegation | RFC 1918 |
| 254.169.IN-ADDR.ARPA | Direct Delegation | link-local, 169.254.0.0/16 (RFC 6890) |
| EMPTY.AS112.ARPA | DNAME Redirection | RFC 7535 |
| HOSTNAME.AS112.NET, HOSTNAME.AS112.ARPA | Operational (node identification) | — |

Zone content rule: SOA + NS records only. "There should be no other
resource records included in this zone." Records relating to RFC 1918
resources within the hosting site itself must not be hosted on the
AS112 nameserver.

## Anycast Addressing (§2.3)

| Service | Nameserver | IPv4 | IPv6 |
|---------|-----------|------|------|
| Direct Delegation (NS for IN-ADDR.ARPA zones) | BLACKHOLE-1.IANA.ORG | 192.175.48.6 | 2620:4f:8000::6 |
| Direct Delegation | BLACKHOLE-2.IANA.ORG | 192.175.48.42 | 2620:4f:8000::42 |
| Direct Delegation (SOA MNAME, dynamic-update target) | PRISONER.IANA.ORG | 192.175.48.1 | 2620:4f:8000::1 |
| DNAME Redirection | BLACKHOLE.AS112.ARPA | 192.31.196.1 | 2001:4:112::1 |

Covering prefixes: Direct Delegation 192.175.48.0/24 and
2620:4f:8000::/48 (ARIN-assigned); DNAME Redirection 192.31.196.0/24 and
2001:4:112::/48 (IANA-assigned per RFC 7535). An IPv4-only node
configures only the IPv4 addresses; an IPv6-only node configures only
the IPv6 addresses — single-stack operation is supported.

## Host and Routing Requirements (§3.3–3.4)

- Platform must support either cloned loopback interfaces or multiple
  addresses bound to one loopback interface — all AS112 nameserver
  addresses are configured on this interface.
- A host running an AS112 node should be dedicated to that purpose.
- Startup ordering: loopback interface configuration → DNS software →
  routing software (BGP), so the BGP announcement never precedes DNS
  readiness.
- BGP origination: AS 112 originates 192.175.48.0/24 and 2620:4f:8000::/48
  (Direct Delegation) and 192.31.196.0/24 and 2001:4:112::/48 (DNAME
  Redirection) to its peers.
- Recommended outbound BGP filtering at the AS112 node: a prefix filter
  permitting only the service prefixes, and an AS_PATH filter matching
  only locally-originated routes (`^$`) — together these prevent the
  node becoming a transit point for adjacent ASes.
- Wrapper/orchestration should ensure the service prefixes are not
  advertised while the anycast addresses are unconfigured or the DNS
  software is not running.

## DNS Software Requirements (§3.5)

- AS112 nodes are fully functional, standards-compliant authoritative
  DNS servers (RFC 1034) — recursion is disabled (authoritative-only).
- Listens on the local/global address plus all configured AS112 anycast
  addresses (both UDP and TCP).
- Each zone's SOA: serial, refresh 1W, retry 1M, expire 1W, negative
  cache (minimum) TTL 1W, $TTL 1W. NS record(s) point at the canonical
  AS112 nameserver name(s) for that service.
- HOSTNAME.AS112.NET / HOSTNAME.AS112.ARPA TXT answers (facility/city
  identification) must fit a 512-octet UDP datagram without requiring
  EDNS0.

## Operations (§4)

- Monitor the node like any production DNS service.
- On planned downtime or DNS-software failure, withdraw the AS112
  service-prefix BGP announcement (or stop the routing daemon) — do not
  leave the prefix announced with the DNS service down, since that
  blackholes query traffic.
- Operators should measure traffic for capacity planning and anomaly
  detection.

## Security Considerations (§8)

- Queries reaching AS112 indicate a misconfiguration upstream of the
  AS112 node; hosts should answer RFC 1918 reverse queries locally
  rather than letting them escape to the public DNS.
- Traffic reaching AS112 servers may leak private-infrastructure
  information and can trigger IDS/firewall alerts on the querying side
  — this is expected, not an attack.
- AS112 zones are not DNSSEC-signed: the loosely-coordinated, anycast
  nature of the deployment means private key material would have to be
  shared so widely it would be effectively public.

## Compliance Checklist

- [ ] [RFC7534-3.5-1] [MUST] AS112 nameservers answer authoritatively for each zone delegated to them (§3.5, also restated in RFC 7535 §1)
- [ ] [RFC7534-3.5-2] [MUST] Direct Delegation zones contain no resource records beyond SOA and NS (§3.5, db.dd-empty)
- [ ] [RFC7534-3.5-3] [MUST] Records relating to RFC 1918 resources within the hosting site are not hosted on the AS112 nameserver itself (§3.5) {single-polarity: positive; ze's AS112 nameserver serves only empty SOA/NS Direct-Delegation zones (internal/plugins/as112/zones.go), which hold their records at the apex and nothing below it, so every RFC 1918 reverse name draws a name error and no RFC 1918 record is ever hosted -- there is no "RFC 1918 record is hosted" case to assert as a negative. The positive (an RFC 1918 reverse PTR yields NXDOMAIN, with no PTR anywhere in the reply) is proven in TestZoneAnswer_ResponseCodeByNamePosition}
- [ ] [RFC7534-3.3-1] [SHOULD] The chosen platform supports cloned loopback interfaces or multiple addresses on one loopback interface (§3.3)
- [ ] [RFC7534-3.3-2] [SHOULD] A host running an AS112 node is dedicated to that purpose, not shared with other services (§3.3)
- [ ] [RFC7534-3.3-3] [SHOULD] Startup order is: loopback interface configuration, then DNS software, then routing software (§3.3)
- [ ] [RFC7534-3.3-4] [SHOULD] The AS112 service prefix is not advertised while anycast addresses are unconfigured or DNS software is not running (§3.3)
- [ ] [RFC7534-3.4-1] [SHOULD] Outbound BGP advertisement is restricted by a prefix filter permitting only the AS112 service prefixes (§3.4)
- [ ] [RFC7534-3.4-2] [SHOULD] Outbound BGP advertisement is restricted by an AS_PATH filter matching only locally-originated routes (§3.4)
- [ ] [RFC7534-3.5-4] [SHOULD] AS112 nodes run as authoritative-only DNS servers with recursion disabled (§3.5)
- [ ] [RFC7534-3.5-5] [SHOULD] HOSTNAME.AS112.NET / HOSTNAME.AS112.ARPA TXT responses fit within a 512-octet UDP datagram without requiring EDNS0 (§3.5)
- [ ] [RFC7534-4.1-1] [SHOULD] AS112 nodes are monitored as a production service (§4.1)
- [ ] [RFC7534-4.2-1] [SHOULD] An AS112 node going off-line for maintenance withdraws its service-prefix BGP announcement first (§4.2)
- [ ] [RFC7534-4.3-1] [SHOULD] Usage is measured for long-term trend and anomaly tracking (§4.3)
- [ ] [RFC7534-3.2-1] [SHOULD] New AS112 node operators notify the local community (e.g. IXP mailing list) before installation; globally-reachable nodes coordinate with other AS112 operators (§3.2, §5)
- [ ] [RFC7534-3.4-3] [MAY] An IPv4-only node configures only the IPv4 anycast addresses; an IPv6-only node configures only the IPv6 anycast addresses (§3.4)
