**Purpose:** Defines the L2TP PPP Disconnect Cause Code AVP (Attribute Type
46), carried in a Call-Disconnect-Notify to report why PPP ended: a
disconnect code, the PPP control protocol number, the direction, and an
optional UTF-8 message.

## PPP Disconnect Cause Code AVP (Section 2)

| Field | Constraints |
|-------|-------------|
| M bit | 0; the AVP is valid in a Call-Disconnect-Notify only |
| Length | at least 11; octets past 11 are a UTF-8 message |
| Control Protocol Number | 0 for global errors (Section 3.1), C021 for LCP errors (3.2), the authentication protocol's number for authentication errors (3.3) |

## Compliance Checklist

- [ ] [RFC3145-2-1] [MUST NOT] The AVP is valid in the L2TP Call-Disconnect-Notify (CDN) message only, and it MUST NOT be marked Mandatory. (§2)
- [ ] [RFC3145-2-2] [MUST] The length of the Value field MUST be at least 11 octets. (§2)
- [ ] [RFC3145-2-3] [MUST] If the length is more than 11 octets, the additional octets MUST contain a descriptive text in UTF-8 [3] format that can be displayed to the user or in a log file. (§2)
- [ ] [RFC3145-2-4] [MUST] Mandatory (M) bit: MUST be 0. (§2)
- [ ] [RFC3145-2-5] [MUST] The length MUST be at least 11. (§2)
- [ ] [RFC3145-3.1-1] [MUST] The Control Protocol Number for these errors thus MUST be set to 0. (§3.1)
- [ ] [RFC3145-3.2-1] [MUST] The Control Protocol Number for these errors MUST be set to C021 hexadecimal (LCP). (§3.2)
- [ ] [RFC3145-3.3-1] [MUST] The Control Protocol Number for such errors MUST correspond to the PPP Control Protocol number for the authentication protocol in use. (§3.3)
- [ ] [RFC3145-2-7] [SHOULD] The valid values of this field are: 0: global error 1: at peer 2: at local 3-255: Reserved This field SHOULD be 0 unless documented otherwise in the description of the specific Disconnect Code. (§2)
- [ ] [RFC3145-3-1] [SHOULD] Unless documented otherwise for a specific Disconnect Code, the Direction value SHOULD be 0. (§3)
- [ ] [RFC3145-3.4-1] [SHOULD] The Control Protocol Number for such errors SHOULD correspond to the PPP Network Control Protocol number in use. (§3.4)
- [ ] [RFC3145-3.4-3] [SHOULD] Otherwise, if only one copy of the AVP is given, the Control Protocol Number SHOULD correspond to the last (most recent) failing NCP. 17 FSM Timeout error. 18 No NCPs available (all disabled or rejected); no NCPs went to Opened state. (§3.4)
- [ ] [RFC3145-4-2] [SHOULD NOT] Implementations MAY accept AVPs with these values as equivalent to the message described in this document, but SHOULD NOT transmit an AVP using these values. (§4)
- [ ] [RFC3145-1-1] [MAY] This document provides an additional Attribute Value Pair (AVP), called PPP Disconnect Cause Code, that MAY be used by an L2TP host to provide PPP-specific disconnect information to its peer. (§1)
- [ ] [RFC3145-2-6] [MAY] Hidden (H) bit: MAY be 1 if the attribute is hidden. (§2)
- [ ] [RFC3145-3.4-2] [MAY] Where multiple network protocols are in use, multiple copies of this AVP MAY be given to indicate failure reasons for each NCP. (§3.4)
- [ ] [RFC3145-4-1] [MAY] This AVP MAY may be sent by either the LNS or LAC. (§4)
- [ ] [RFC3145-5-1] [MAY] It is intended for logging and diagnostic purposes in the event of PPP link failure and should not pose a threat to system security, but the AVP MAY be hidden as described in section 4.3 of RFC 2661. (§5)
