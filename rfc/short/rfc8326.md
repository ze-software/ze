## Overview

Defines the GRACEFUL_SHUTDOWN well-known community (0xFFFF0000) and a
procedure (GSHUT) to drain traffic from a BGP session or link before
taking it down for planned maintenance. Routes carrying this community
are de-preferenced by receivers so traffic shifts to alternative paths
before the actual shutdown, preventing packet loss during the transition.

## Well-Known Community

| Community | Value | Hex |
|-----------|-------|-----|
| GRACEFUL_SHUTDOWN | 65535:0 | 0xFFFF0000 |

## GSHUT Procedure

### Initiator (router about to go down)

1. Tag all routes advertised over the target session with GRACEFUL_SHUTDOWN
2. Re-advertise the tagged routes to the peer
3. Wait for convergence (implementation-specific timer or manual trigger)
4. Shut down the session or disable the link

### Receiver

1. Detect GRACEFUL_SHUTDOWN community on incoming routes
2. Set LOCAL_PREF to a low value (e.g., 0) for those routes
3. Re-run best-path selection: alternative paths become preferred
4. Re-advertise new best paths to other peers
5. Traffic naturally shifts away from the soon-to-be-down path

## Key Requirements

| Requirement | Detail |
|-------------|--------|
| LOCAL_PREF | Receiver SHOULD set to lowest configured value |
| iBGP | GSHUT community SHOULD be propagated to iBGP peers |
| eBGP outbound | Initiator SHOULD strip GSHUT before advertising to eBGP (unless the peer is the target) |
| Route selection | Standard BGP decision process applies; lower LOCAL_PREF naturally deprioritizes |

## Operation Timeline

```
1. Initiator tags routes with GRACEFUL_SHUTDOWN
2. Receiver lowers LOCAL_PREF, re-runs best path
3. Network converges to alternative paths
4. Initiator shuts down session/link
5. No packet loss (traffic already rerouted)
```

## Without GSHUT (comparison)

```
1. Session/link goes down abruptly
2. Peer detects failure (hold timer: 90s default)
3. Peer withdraws routes, re-runs best path
4. Convergence takes seconds to minutes
5. Packet loss during convergence window
```

## Interaction with Other Communities

- GRACEFUL_SHUTDOWN and NO_EXPORT can coexist on the same route
- If a route also carries LLGR_STALE (RFC 9494), GSHUT takes precedence
  for the LOCAL_PREF reduction

## Partial Deployment

- Works even if not all routers in the path support it
- Non-supporting routers propagate the community unchanged (transitive)
- Effectiveness degrades: some routers won't lower LOCAL_PREF
- Still better than cold shutdown for the supporting portion

## Implementation Notes (Ze context)

- Constant to be added as `CommunityGracefulShutdown` (0xFFFF0000) in
  `attribute/community.go`
- Parse/display as `graceful-shutdown` in text format
- The GR plugin (`bgp-gr`) handles restart/LLGR but not GSHUT; GSHUT
  is a pre-shutdown signal, not a post-failure mechanism
- Filter plugins can match on GRACEFUL_SHUTDOWN to implement the
  LOCAL_PREF reduction policy
