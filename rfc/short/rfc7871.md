# RFC 7871 — Client Subnet in DNS Queries (EDNS0 ECS)

Implementation-relevant summary. Full text: https://www.rfc-editor.org/rfc/rfc7871

## Meta

- RFC 7871, "Client Subnet in DNS Queries", Informational, May 2016.
- Contavalli, van der Gaast, Lawrence, Kumari. Documents deployed behaviour; a
  revision was expected to follow. ECS is defined only for the Internet (IN) class.

## Purpose

Lets a recursive resolver (or forwarder) tell an authoritative server part of
the *original client's* IP, as an EDNS0 option, so the server can return a
locality-tailored answer even though the query reaches it from the resolver's
address. This is exactly what geodns needs: the answer depends on the end
client, not on the CoreDNS forwarder in front of it.

## Option format (OPTION-CODE 8)

```
FAMILY (2)  SOURCE PREFIX-LENGTH (1)  SCOPE PREFIX-LENGTH (1)  ADDRESS (variable)
```

- **FAMILY** — address family: 1 = IPv4, 2 = IPv6.
- **SOURCE PREFIX-LENGTH** — number of significant bits of ADDRESS the resolver
  is supplying (the client network). The remaining bits are zero.
- **SCOPE PREFIX-LENGTH** — in a *query* it is 0; in a *response* the
  authoritative server sets it to the prefix length of the network for which
  this answer is valid (how much of the address actually influenced the answer).
- **ADDRESS** — the (truncated) client network, only enough octets to hold
  SOURCE PREFIX-LENGTH bits.

All fields are in network byte order.

## How geodns applies this

- On a query, when `client-ip-source` allows it, geodns reads the ECS option's
  ADDRESS as the client network and selects the host-set by longest-prefix match
  against it (`clientIP` in `internal/plugins/geodns/server.go`). The miekg/dns
  `*dns.EDNS0_SUBNET` exposes `Family`, `SourceNetmask`, `SourceScope`,
  `Address`.
- CoreDNS in front rewrites ECS to the real client `/32` (`rewrite edns0 subnet
  set 32 128`), so in the typical deployment the network is the full client IP.
- `client-ip-source` modes: `edns0` (ECS only, no answer without it), `packet`
  (ignore ECS, use the socket source), `edns0-then-packet` (ECS, else socket).

## Privacy / scope note

RFC 7871 §11 cautions ECS leaks client network information and recommends
truncation and SCOPE handling. geodns is an internal SurfProtect component
behind a trusted CoreDNS, so it consumes the ECS network as provided.
