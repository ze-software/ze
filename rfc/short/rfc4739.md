**Purpose:** Lets an IKEv2 peer authenticate more than one set of credentials (for example a machine certificate and then a user EAP method) in a chain of IKE_AUTH exchanges, announced by MULTIPLE_AUTH_SUPPORTED and continued by ANOTHER_AUTH_FOLLOWS.

**Ze context:** `internal/component/ike/wire/payload_notify.go` lists the status Notify types Ze knows; 16404 and 16405 are not among them, and the IKE_AUTH handling in `internal/component/ike/engine/` completes after a single authentication per side.

## Protocol Overview (Section 2.1)

- Support is announced with MULTIPLE_AUTH_SUPPORTED in the IKE_SA_INIT response (responder) and the first IKE_AUTH request (initiator).
- When both support it, either peer may put ANOTHER_AUTH_FOLLOWS in any IKE_AUTH message carrying an AUTH payload; its next IKE_AUTH message carries a new IDi or IDr and starts another authentication.
- IKE_AUTH succeeds only when every individual authentication succeeds.
- AUTH is computed per RFC 7296 Sections 2.15 and 2.16, with IDi' and IDr' the latest identity payloads sent.
