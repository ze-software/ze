**Purpose:** Grades every IKEv2 transform and authentication algorithm as MUST, SHOULD+, SHOULD, MUST-, MAY, SHOULD NOT or MUST NOT for implementers, replacing RFC 4307.

**Ze context:** The levels apply to what ze implements, not to what an operator configures. They bind the IKE transform registries and the AUTH payload code.

## Level Terms (Section 1.1)

| Term | Meaning |
|------|---------|
| SHOULD+ | SHOULD now, likely MUST later |
| MUST- | same as MUST now, likely lowered later |
| SHOULD- | SHOULD now, likely lowered later |

## Authentication (Section 3)

| Method | Status | ze |
|--------|--------|----|
| 1 RSA Digital Signature | MUST | verified, never sent |
| 2 Shared Key MIC | MUST | yes |
| 3 DSS | SHOULD NOT | no |
| 9, 10, 11 ECDSA | SHOULD | no (ECDSA goes through method 14) |
| 14 Digital Signature | SHOULD | yes |

Section 3.2 hash and signature levels: SHA1 MUST NOT, SHA2-256 MUST, SHA2-384 MAY, SHA2-512 SHOULD; RSASSA-PSS with SHA-256 MUST, ecdsa-with-sha256 SHOULD, sha1WithRSAEncryption, dsa-with-sha1, ecdsa-with-sha1 and RSASSA-PSS with empty or default parameters MUST NOT.

## Pitfalls

- A table row graded MUST- is a MUST today (Section 1.1); dropping SHA-1 from the IKE SA early is the gap recorded above.
- RSA Digital Signature (method 1) is RSASSA-PKCS1-v1.5; RSASSA-PSS is reachable only through method 14 (RFC 7427).
