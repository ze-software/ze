**Purpose:** Describes destination-based Remote Triggered Black Hole (RTBH) filtering and extends it to source-based filtering by combining a discard route with unicast Reverse Path Forwarding (uRPF), so that a BGP announcement can drop traffic from an attacking source at the network edge.

**Scope:** Operational technique, Informational. No wire format. Uses BGP communities and next-hop rewriting to point a prefix at a discard route, and loose or strict uRPF to drop packets whose source address resolves to that route.

**Errata:** None affecting implementation.

## Destination-Based RTBH (§3)

| Step | Action |
|------|--------|
| 1 | Choose discard addresses (often from 192.0.2.0/24), one per incident if telemetry is wanted |
| 2 | Install a discard route (next-hop to the null interface) on every edge router |
| 3 | Configure a BGP policy: a route carrying the RTBH community gets its next-hop set to the discard address; accept only narrow prefixes (typically /32) |
| 4 | Egress safety filters: deny prefixes longer than expected, deny the RTBH trigger communities |
| 5 | Trigger router: announces the target with NO_EXPORT, typically an iBGP route-reflector client |

Variants (§3.2): community-per-scope ("XXX:600" family), and customer-triggered RTBH, where customers announce the blackhole themselves. The customer-triggered variant carries the document's only MUST.

## Source-Based RTBH (§4)

Traffic whose source address matches a route pointing at the discard interface fails the uRPF check and is dropped. Loose mode checks that a route exists for the source; strict mode also checks the arrival interface. The trigger announcements must not leave the local AS and should carry NO_EXPORT.
