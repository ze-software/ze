# RFC 1035 — Domain Names: Implementation and Specification

Implementation-relevant summary (the parts geodns uses). Full text:
https://www.rfc-editor.org/rfc/rfc1035

## Message structure (§4.1)

A DNS message has five sections: Header, Question, Answer, Authority (NS in the
header's terminology / the "NS" section), Additional. geodns fills:

- **Answer** — the records that answer the query (A/AAAA/SRV, or SOA/NS for apex
  queries).
- **Authority (Ns)** — the SOA record for a negative answer, or the zone NS set.
- **Additional (Extra)** — glue A records for the nameservers, and the OPT
  pseudo-record.

## Resource records (§3.2)

`NAME TTL CLASS TYPE RDATA`. CLASS is IN (1). TTL is a 32-bit field (further
bounded by RFC 2181 §8). Types geodns emits:

- **A (1)** — 4-octet IPv4 address (§3.4.1).
- **AAAA** — 16-octet IPv6 address (RFC 3596).
- **SRV** — service location (RFC 2782).
- **SOA (6)** — `MNAME RNAME SERIAL REFRESH RETRY EXPIRE MINIMUM` (§3.3.13).
  MNAME is the primary nameserver; RNAME is the responsible mailbox with the
  `@` replaced by `.` (hostmaster@zone -> hostmaster.zone.).
- **NS (2)** — an authoritative nameserver name (§3.3.11).

## Negative answers (§4.1.1, and RFC 2308)

A name that exists in the zone but has no record of the requested type is a
NOERROR response with an empty Answer and the zone SOA in the Authority section
(a "NODATA"/negative answer), not NXDOMAIN. A name outside every authoritative
zone is NXDOMAIN (RcodeNameError).

## How geodns applies this

- `answerQuestions` (`internal/plugins/geodns/server.go`) builds A/AAAA/SRV
  answers, synthesizes SOA/NS plus glue for apex SOA/NS queries, and returns a
  NOERROR + SOA-in-Authority negative answer when an in-zone name has no record.
- A query name not matching any configured zone yields NXDOMAIN.
- `ns1..nsN.<zone>` glue addresses are synthesized from the configured
  nameserver list, never stored as host records.
