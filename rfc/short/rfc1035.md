# RFC 1035 — Domain Names: Implementation and Specification

Implementation-relevant summary (the parts geodns uses). Full text:
https://www.rfc-editor.org/rfc/rfc1035

## Message structure (§4.1)

A DNS message has five sections: Header, Question, Answer, Authority (NS in the
header's terminology / the "NS" section), Additional. geodns fills:

- **Answer** — the records that answer the query (A/AAAA/SRV, or SOA/NS for apex
  queries).
- **Authority (Ns)** — the SOA record for a negative answer, or the zone NS set.
- **Additional (Extra)** — glue A records for the nameservers, and the OPT
  pseudo-record.

## Resource records (§3.2)

`NAME TTL CLASS TYPE RDATA`. CLASS is IN (1). TTL is a 32-bit field (further
bounded by RFC 2181 §8). Types geodns emits:

- **A (1)** — 4-octet IPv4 address (§3.4.1).
- **AAAA** — 16-octet IPv6 address (RFC 3596).
- **SRV** — service location (RFC 2782).
- **SOA (6)** — `MNAME RNAME SERIAL REFRESH RETRY EXPIRE MINIMUM` (§3.3.13).
  MNAME is the primary nameserver; RNAME is the responsible mailbox with the
  `@` replaced by `.` (hostmaster@zone -> hostmaster.zone.).
- **NS (2)** — an authoritative nameserver name (§3.3.11).

## Negative answers (§4.1.1, and RFC 2308)

A name that exists in the zone but has no record of the requested type is a
NOERROR response with an empty Answer and the zone SOA in the Authority section
(a "NODATA"/negative answer), not NXDOMAIN. A name outside every authoritative
zone is NXDOMAIN (RcodeNameError).

## How geodns applies this

- `answerQuestions` (`internal/plugins/geodns/server.go`) builds A/AAAA/SRV
  answers, synthesizes SOA/NS plus glue for apex SOA/NS queries, and returns a
  NOERROR + SOA-in-Authority negative answer when an in-zone name has no record.
- A query name not matching any configured zone yields NXDOMAIN.
- `ns1..nsN.<zone>` glue addresses are synthesized from the configured
  nameserver list, never stored as host records.

## Normative reading: RFC 1035 predates RFC 2119

RFC 1035 was published in November 1987, ten years before RFC 2119. It contains
**zero capitalised RFC 2119 keywords** and no requirements-terminology section. Its
obligations are written as lowercase indicative prose -- "labels must be 63
characters or less", "the high order two bits of every length octet must be zero",
"Longer messages are truncated and the TC bit is set in the header" -- and as
declarative statements of the wire format.

A capitalised-keyword scan of `rfc/full/rfc1035.txt` therefore returns nothing, and
extracting under that scan would declare the DNS wire format free of obligations.
The checklist below reads the indicative prose as normative, which is the only
reading under which this document constrains an implementation at all.

**Extraction scope (declared, not silent).** This summary is scoped to the
authoritative-server surface geodns implements: name encoding and its size limits,
case-insensitive comparison, message compression, the header fields and RCODEs
geodns sets, the RR and SOA fields it emits, and the UDP/TCP transport rules. The
checklist covers every MUST-level obligation in that scope.

RFC 1035's other halves (§5 master files, §6 name-server internals, §7 resolver
algorithms, and the zone-transfer paths) bind roles Ze does not play, and the
full-document walk recorded in `rfc/extraction/rfc1035.json` says so site by
site. That walk found ONE obligation outside the declared scope that binds Ze
anyway, and it is captured below rather than left out: §6.4 makes the error
response to an unsupported inverse query mandatory for *all* name servers, not
only for ones that implement inverse queries. An unextracted obligation is still
an obligation.

## Compliance Checklist

- [ ] [RFC1035-2.3.3-1] [MUST] For all parts of the DNS that are part of the official protocol, all comparisons between character strings (e.g., labels, domain names, etc.) are done in a case-insensitive manner (§2.3.3)
- [ ] [RFC1035-2.3.3-2] [MUST] Loss of case sensitive data must be minimized (§2.3.3)
- [ ] [RFC1035-2.3.4-1] [MUST] Size limit -- TTL: positive values of a signed 32 bit number (§2.3.4)
- [ ] [RFC1035-2.3.4-2] [MUST] Size limit -- UDP messages: 512 octets or less (§2.3.4)
- [ ] [RFC1035-3.1-1] [MUST] Each label is represented as a one octet length field followed by that number of octets (§3.1)
- [ ] [RFC1035-3.1-2] [MUST] Since every domain name ends with the null label of the root, a domain name is terminated by a length byte of zero (§3.1)
- [ ] [RFC1035-3.1-3] [MUST] The high order two bits of every length octet must be zero, and the remaining six bits of the length field limit the label to 63 octets or less (§3.1)
- [ ] [RFC1035-3.1-4] [MUST] The total length of a domain name (i.e., label octets and label length octets) is restricted to 255 octets or less (§3.1)
- [ ] [RFC1035-3.1-5] [MUST] Name servers and resolvers must compare labels in a case-insensitive manner (i.e., A=a), assuming ASCII with zero parity (§3.1)
- [ ] [RFC1035-3.1-6] [MUST] Non-alphabetic codes must match exactly (§3.1)
- [ ] [RFC1035-3.3.13-1] [MUST] Whenever a RR is sent in a response to a query, the TTL field is set to the maximum of the TTL field from the RR and the MINIMUM field in the appropriate SOA (§3.3.13)
- [ ] [RFC1035-4.1.1-1] [MUST] Z is reserved for future use and must be zero in all queries and responses (§4.1.1)
- [ ] [RFC1035-4.1.1-2] [MUST] AA (Authoritative Answer) is valid in responses and specifies that the responding name server is an authority for the domain name in question section (§4.1.1)
- [ ] [RFC1035-4.1.1-3] [MUST] RCODE 3 (Name Error), meaningful only for responses from an authoritative name server, signifies that the domain name referenced in the query does not exist (§4.1.1)
- [ ] [RFC1035-4.1.3-1] [MUST] TTL is a 32 bit unsigned integer that specifies the time interval in seconds that the resource record may be cached (§4.1.3)
- [ ] [RFC1035-4.1.3-2] [MUST] RDLENGTH is an unsigned 16 bit integer that specifies the length in octets of the RDATA field (§4.1.3)
- [ ] [RFC1035-4.1.4-1] [MUST] A compression pointer takes the form of a two octet sequence whose first two bits are ones, distinguishing it from a label, which must begin with two zero bits (§4.1.4)
- [ ] [RFC1035-4.1.4-2] [MUST] The OFFSET field specifies an offset from the start of the message, i.e. the first octet of the ID field in the domain header (§4.1.4)
- [ ] [RFC1035-4.1.4-3] [MUST] Pointers can only be used for occurances of a domain name where the format is not class specific (§4.1.4)
- [ ] [RFC1035-4.1.4-4] [MUST] If a domain name is contained in a part of the message subject to a length field, such as the RDATA section of an RR, and compression is used, the length of the compressed name is used in the length calculation, rather than the length of the expanded name (§4.1.4)
- [ ] [RFC1035-4.1.4-5] [REQUIRED] All programs are required to understand arriving messages that contain pointers (§4.1.4)
- [ ] [RFC1035-4.2-1] [MUST] Zone refresh activities must use virtual circuits because of the need for reliable transfer (§4.2)
- [ ] [RFC1035-4.2.1-1] [MUST] Messages carried by UDP are restricted to 512 bytes, not counting the IP or UDP headers (§4.2.1)
- [ ] [RFC1035-4.2.1-2] [MUST] Longer messages are truncated and the TC bit is set in the header (§4.2.1)
- [ ] [RFC1035-4.2.1-3] [MUST] Messages sent using UDP user server port 53 (decimal) (§4.2.1) <!-- "user" is verbatim: RFC 1035 rfc/full/rfc1035.txt:1754 has a typo for "use", and the id contract pins the quoted text, so it is reproduced rather than silently corrected. Compare :1783, which reads "use server port 53" for TCP. -->

- [ ] [RFC1035-4.2.2-1] [MUST] Messages sent over TCP connections use server port 53 decimal, and the message is prefixed with a two byte length field which gives the message length (§4.2.2)
- [ ] [RFC1035-6.4-1] [MUST] While inverse query support is optional, all name servers must be at least able to return the error response (§6.4)
- [ ] [RFC1035-2.3.1-1] [SHOULD] Preferred name syntax: labels must start with a letter, end with a letter or digit, and have as interior characters only letters, digits, and hyphen (§2.3.1)
- [ ] [RFC1035-2.3.3-3] [SHOULD] When data enters the domain system, its original case should be preserved whenever possible (§2.3.3)
- [ ] [RFC1035-2.3.3-4] [SHOULD NOT] Attempts to store domain names in 7-bit ASCII or use of special bytes to terminate labels, etc., should be avoided (§2.3.3)
- [ ] [RFC1035-3.1-7] [RECOMMENDED] Although labels can contain any 8 bit values in octets that make up a label, it is strongly recommended that labels follow the preferred syntax described elsewhere in this memo (§3.1)
- [ ] [RFC1035-3.3.13-2] [SHOULD] This use of MINIMUM should occur when the RRs are copied into the response and not when the zone is loaded from a master file or via a zone transfer (§3.3.13)
- [ ] [RFC1035-4.1.3-3] [SHOULD NOT] Zero TTL values are interpreted to mean that the RR can only be used for the transaction in progress, and should not be cached (§4.1.3)
