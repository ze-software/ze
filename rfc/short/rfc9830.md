**Purpose:** Defines the BGP encoding for advertising SR Policies: SAFI 73 assignment, SR Policy NLRI wire format, and Tunnel Encapsulation attribute sub-TLVs for SR Policy (Tunnel Type 15).

**Scope:** BGP advertisement and reception of SR Policies over AFI 1 (IPv4) and AFI 2 (IPv6) with SAFI 73. Architecture is in RFC 9256; segment types C-K are in RFC 9831.

## Wire Formats

### SR Policy NLRI (Section 2.1)

Carried in MP_REACH_NLRI (code 14) and MP_UNREACH_NLRI (code 15) with SAFI 73.

```
+---------------------------------------------------------+
| NLRI Length (1 octet, in bits)                          |
+---------------------------------------------------------+
| Distinguisher (4 octets)                                |
+---------------------------------------------------------+
| Color (4 octets)                                        |
+---------------------------------------------------------+
| Endpoint (4 octets for AFI 1, 16 octets for AFI 2)     |
+---------------------------------------------------------+
```

| Field | Offset | Size | Type | Constraints |
|-------|--------|------|------|-------------|
| Length | 0 | 1 | uint8 | Bit count: 96 for AFI 1, 192 for AFI 2 |
| Distinguisher | 1 | 4 | uint32 | Arbitrary; for uniqueness when multiple CPs share color+endpoint |
| Color | 5 | 4 | uint32 | Matches BGP Color Extended Community |
| Endpoint | 9 | 4 or 16 | IP addr | IPv4 or IPv6; 0.0.0.0 / :: means "any endpoint" |

**Fixed sizes per AFI:**
- AFI 1 (IPv4): Length=96, body=12 bytes (4+4+4)
- AFI 2 (IPv6): Length=192, body=24 bytes (4+4+16)

**Length field is in BITS, not bytes.** This differs from CIDR NLRI where the length is also in bits but represents prefix length. Here the length covers the entire NLRI body.

### Next-Hop Encoding (Section 2.1)

The next-hop in MP_REACH_NLRI for SAFI 73 follows standard RFC 4760 encoding:

| NH Length | Meaning |
|-----------|---------|
| 4 | IPv4 next-hop |
| 16 | IPv6 global next-hop |
| 32 | IPv6 global + link-local next-hop |

The next-hop AFI is independent of the SR Policy AFI. An IPv4 SR Policy (AFI 1) can have an IPv6 next-hop and vice versa.

### Tunnel Encapsulation Attribute (Section 2.2)

SR Policy candidate path content is encoded in the Tunnel Encapsulation Attribute (code 23, RFC 9012) using Tunnel Type 15 (SR Policy).

**Restriction:** Tunnel Type 15 is ONLY valid with SAFI 73. Any other tunnel type in a SAFI 73 UPDATE triggers treat-as-withdraw (RFC 7606).

Outer TLV structure (per RFC 9012):

```
+---------------------------------------------------------+
| Tunnel Type = 15 (2 octets)                             |
+---------------------------------------------------------+
| Length (2 octets)                                       |
+---------------------------------------------------------+
| SR Policy Sub-TLVs (variable)                           |
+---------------------------------------------------------+
```

### SR Policy Sub-TLVs (Section 2.4)

Sub-TLV length encoding per RFC 9012: types 0-127 use 1-byte length, types 128-255 use 2-byte length.

| Type | Name | Length field | Section |
|------|------|-------------|---------|
| 12 | Preference | 1 byte | 2.4.1 |
| 13 | Binding SID | 1 byte | 2.4.2 |
| 14 | Explicit NULL Label Policy (ENLP) | 1 byte | 2.4.5 |
| 15 | Priority | 1 byte | 2.4.6 |
| 20 | SRv6 Binding SID | 1 byte | 2.4.3 |
| 128 | Segment List | 2 bytes | 2.4.4 |
| 129 | SR Policy Candidate Path Name | 2 bytes | 2.4.7 |
| 130 | SR Policy Name | 2 bytes | 2.4.8 |

#### Preference Sub-TLV (Type 12)

```
+---------------------------------------------------------+
| Flags (1 octet, reserved)                               |
+---------------------------------------------------------+
| RESERVED (1 octet)                                      |
+---------------------------------------------------------+
| Preference (4 octets, uint32)                           |
+---------------------------------------------------------+
```

Value length: 6 bytes. Higher preference wins candidate path selection.

#### Binding SID Sub-TLV (Type 13, MPLS)

```
+---------------------------------------------------------+
| Flags (1 octet)                                         |
+---------------------------------------------------------+
| Reserved (1 octet)                                      |
+---------------------------------------------------------+
| MPLS Label (4 octets, label in top 20 bits)             |
+---------------------------------------------------------+
```

Value length (§2.4.2): 2 bytes when no BSID is present, 6 bytes when an
SR-MPLS BSID is present, 18 bytes when an SRv6 BSID is present.

Flags: S bit (bit 0, 0x80) = Specified-BSID-Only; I bit (bit 1, 0x40) = Drop-Upon-Invalid.
Every other bit is unassigned and MUST be zero on transmission.

#### SRv6 Binding SID Sub-TLV (Type 20)

```
+---------------------------------------------------------+
| Flags (1 octet)                                         |
+---------------------------------------------------------+
| Reserved (1 octet)                                      |
+---------------------------------------------------------+
| SRv6 SID (16 octets)                                    |
+---------------------------------------------------------+
```

Value length: 18 bytes, or 26 bytes when the SRv6 Endpoint Behavior and SID
Structure is appended.

Flags: S bit (bit 0, 0x80), I bit (bit 1, 0x40), B bit (bit 2, 0x20: SRv6
Endpoint Behavior and SID Structure present).

#### Priority Sub-TLV (Type 15)

```
+---------------------------------------------------------+
| Priority (1 octet, uint8)                               |
+---------------------------------------------------------+
| Reserved (1 octet)                                      |
+---------------------------------------------------------+
```

Value length: 2 bytes.

#### Segment List Sub-TLV (Type 128)

Contains sub-sub-TLVs: Weight (type 9) and one or more Segment entries. Multiple Segment List sub-TLVs per tunnel TLV enable ECMP.

##### Weight Sub-Sub-TLV (Type 9)

```
+---------------------------------------------------------+
| Flags (1 octet)                                         |
+---------------------------------------------------------+
| RESERVED (1 octet)                                      |
+---------------------------------------------------------+
| Weight (4 octets, uint32)                               |
+---------------------------------------------------------+
```

Value length: 6 bytes.

##### Segment Type A (Type 1, MPLS Label)

```
+---------------------------------------------------------+
| Flags (1 octet)                                         |
+---------------------------------------------------------+
| Reserved (1 octet)                                      |
+---------------------------------------------------------+
| MPLS Label Stack Entry (4 octets)                       |
+---------------------------------------------------------+
```

Value length: 6 bytes. Label in top 20 bits of the 4-byte entry; TC, S and TTL
occupy the remaining 12 bits and the S bit MUST be zero on transmission.

Segment Flags (Section 2.4.4.2.3): V bit (bit 0, 0x80) = SID verification;
B bit (bit 3, 0x10) = SRv6 Endpoint Behavior and SID Structure present, which
applies to Segment Type B and MUST be ignored on Segment Type A.

##### Segment Type B (Type 13, SRv6 SID)

```
+---------------------------------------------------------+
| Flags (1 octet)                                         |
+---------------------------------------------------------+
| Reserved (1 octet)                                      |
+---------------------------------------------------------+
| SRv6 SID (16 octets)                                    |
+---------------------------------------------------------+
| [SRv6 Endpoint Behavior sub-sub-TLV, optional]          |
+---------------------------------------------------------+
```

Value length: 18 bytes without the endpoint behavior, 26 bytes with it.

##### SRv6 Endpoint Behavior and SID Structure (Section 2.4.4.2.4)

```
+---------------------------------------------------------+
| Endpoint Behavior (2 octets)                            |
+---------------------------------------------------------+
| Reserved (2 octets)                                     |
+---------------------------------------------------------+
| LB Length | LN Length | Fun. Length | Arg. Length       |
+---------------------------------------------------------+
```

8 bytes, appended inside the Segment Type sub-TLV (B, I, J, K) and inside the
SRv6 Binding SID sub-TLV; it is not a sub-TLV of its own. The four lengths MUST
total 128 or less.

#### SR Policy Candidate Path Name Sub-TLV (Type 129)

```
+---------------------------------------------------------+
| RESERVED (1 octet)                                      |
+---------------------------------------------------------+
| Candidate Path Name (variable, no NULL terminator)      |
+---------------------------------------------------------+
```

#### SR Policy Name Sub-TLV (Type 130)

```
+---------------------------------------------------------+
| RESERVED (1 octet)                                      |
+---------------------------------------------------------+
| SR Policy Name (variable, no NULL terminator)           |
+---------------------------------------------------------+
```

## Error Handling (Section 5)

All malformed SR Policy updates use treat-as-withdraw (RFC 7606):
- Wrong tunnel type with SAFI 73
- Malformed sub-TLV lengths
- Invalid NLRI length field

Unknown sub-TLVs within the SR Policy tunnel are silently ignored but preserved for propagation.
