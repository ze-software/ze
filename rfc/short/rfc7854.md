## Purpose

BMP enables routers to stream BGP routing state to external monitoring
stations over TCP. Unidirectional: router to collector. Covers Adj-RIB-In,
peer state changes, and statistics.

## Wire Format

### Common Header (6 bytes, all messages)

| Offset | Size | Field |
|--------|------|-------|
| 0 | 1 | Version (must be 3) |
| 1 | 4 | Message Length (total including header) |
| 5 | 1 | Message Type (0-6) |

### Per-Peer Header (42 bytes, types 0-3 and 6)

| Offset | Size | Field |
|--------|------|-------|
| 0 | 1 | Peer Type: 0=Global, 1=L3VPN, 2=Local, 3=Loc-RIB |
| 1 | 1 | Flags: bit7=V(IPv6), bit6=L(post-policy), bit5=A(2-byte-AS), bit4=O(Adj-RIB-Out) |
| 2 | 8 | Peer Distinguisher (RD for VRF peers) |
| 10 | 16 | Peer Address (IPv4 as ::ffff:x.x.x.x) |
| 26 | 4 | Peer AS (always 4-byte) |
| 30 | 4 | Peer BGP ID |
| 34 | 4 | Timestamp seconds |
| 38 | 4 | Timestamp microseconds |

### TLV Format (4-byte header)

Type (2) + Length (2) + Value (variable).

## Message Types

| Type | Name | Per-Peer Header | Content |
|------|------|-----------------|---------|
| 0 | Route Monitoring | Yes | BGP UPDATE message |
| 1 | Statistics Report | Yes | Count (4) + stat TLVs |
| 2 | Peer Down | Yes | Reason (1) + optional NOTIFICATION/FSM |
| 3 | Peer Up | Yes | Local addr (16) + ports (4) + sent OPEN + recv OPEN + optional TLVs |
| 4 | Initiation | No | TLVs: sysName (2), sysDescr (1), string (0) |
| 5 | Termination | No | TLVs: string (0), reason (1) |
| 6 | Route Mirroring | Yes | TLVs: BGP message (0), messages lost (1) |

## Peer Down Reasons

| Code | Meaning | Data |
|------|---------|------|
| 1 | Local closed, NOTIFICATION sent | BGP NOTIFICATION PDU |
| 2 | Local closed, no NOTIFICATION | 2-byte FSM event code |
| 3 | Remote closed, NOTIFICATION recv | BGP NOTIFICATION PDU |
| 4 | Remote closed, no data | None |
| 5 | Peer de-configured | None |

## Statistics Types (Section 4.8)

Types 0-13 defined. Types 0-6 are 64-bit counters for policy rejections,
duplicates, and loop detection. Types 7-8 are Adj-RIB-In and Loc-RIB route
counts. Types 9-10 are per-AFI/SAFI variants (11-byte: AFI(2)+SAFI(1)+value(8)).
Types 11-13 cover treat-as-withdraw and duplicate updates.

## Session Lifecycle

1. TCP connection established (IANA port 11019)
2. Initiation message with sysName/sysDescr
3. For each established peer: Peer Up with OPEN messages
4. Route Monitoring: initial RIB dump then incremental updates
5. Periodic Statistics Reports
6. Peer Down on session loss
7. Termination on BMP session close

## Reconnection

RFC suggests minimum 30 seconds, maximum 720 seconds between reconnection
attempts with exponential backoff.

## Related RFCs

- RFC 8671: Adj-RIB-Out support (O flag in per-peer header)
- RFC 9069: Local RIB support (peer type 3, F flag)
- RFC 9736: Peer Up TLV namespace clarification

## Ze Implementation

- Receiver: `internal/component/bgp/plugins/bmp/` -- accepts TCP, parses all 7 types
- Sender: same package -- connects to collectors, streams peer state + updates
- YANG config: `ze-bmp-conf.yang` under `bgp { bmp { receiver { ... } sender { ... } } }`

## Compliance Checklist

- [ ] [RFC7854-x-1] [MUST] Common Header Version field must be 3 (Wire Format)
- [ ] [RFC7854-x-2] [MUST] Common Header must be 6 bytes: Version (1) + Message Length (4) + Message Type (1) (Wire Format)
- [ ] [RFC7854-x-3] [MUST] Per-Peer Header must be present for message types 0-3 and 6 (Wire Format)
- [ ] [RFC7854-x-4] [MUST] Peer AS field must always be encoded as 4-byte AS number (Wire Format) {single-polarity: positive; the Peer AS is unconditionally a 4-octet field on every encode and decode, so there is no shorter-AS variant to reject and no negative case to construct}
- [ ] [RFC7854-x-5] [MUST] IPv4 Peer Address must be encoded as IPv4-mapped IPv6 (::ffff:x.x.x.x) in 16-byte field (Wire Format)
- [ ] [RFC7854-x-6] [MUST] Initiation message must be sent immediately after TCP connection establishment (Session Lifecycle) {single-polarity: positive; the sender always emits Initiation as the first message on a fresh connection, so there is no valid session in which another message precedes it to reject}
- [ ] [RFC7854-x-7] [MUST] Initiation message must include sysName TLV (type 2) (Session Lifecycle) {single-polarity: positive; the Initiation the sender builds always includes the sysName TLV, so there is no valid Initiation omitting it to assert against}
- [ ] [RFC7854-x-8] [MUST] Peer Up message must include both sent and received OPEN messages (Message Types)
- [ ] [RFC7854-x-9] [MUST] Route Monitoring messages must contain a BGP UPDATE message (Message Types) {single-polarity: positive; Route Monitoring is only ever constructed around a complete BGP UPDATE PDU, so there is no valid Route Monitoring lacking one to reject}
- [ ] [RFC7854-x-10] [MUST] Peer Down must include the reason code (1 byte) (Message Types) {single-polarity: positive; Peer Down is always written with a reason byte, so there is no valid Peer Down without one to assert against}
- [ ] [RFC7854-x-11] [MUST] Termination message must be sent when BMP session is being closed (Session Lifecycle) {single-polarity: positive; Termination is produced unconditionally when the session is torn down, so there is no valid shutdown that omits it to reject}

- [ ] [RFC7854-4.5-2] [MUST] The monitoring station must close the TCP session after receiving a termination message (§4.5, Termination Message)
- [ ] [RFC7854-x-13] [SHOULD] Minimum 30 seconds between reconnection attempts (Reconnection)
- [ ] [RFC7854-x-14] [SHOULD] Maximum 720 seconds between reconnection attempts with exponential backoff (Reconnection)
- [ ] [RFC7854-x-15] [SHOULD] Statistics Reports should be sent periodically (Session Lifecycle)
- [ ] [RFC7854-x-16] [SHOULD] Peer Up message should be sent for each established peer (Session Lifecycle)
- [ ] [RFC7854-x-17] [SHOULD] Initial RIB dump via Route Monitoring should follow Peer Up (Session Lifecycle)
