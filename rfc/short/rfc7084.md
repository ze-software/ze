## Purpose

States the baseline an IPv6 customer edge router meets so it works in common
residential and small-office access networks: how it provisions its WAN
interface (SLAAC, DHCPv6 addresses and prefix delegation, router discovery),
how it serves its LAN (Router Advertisements, DHCPv6, DNS information, ULA),
6rd and DS-Lite transition support, and baseline security filtering.

Section 1.1 notes that the requirement keywords are not used strictly as RFC
2119 defines them: they set an industry baseline rather than interoperability
rules. The rows below keep the RFC's own level.

## Wire Formats

RFC 7084 defines no message, option or field. Every format it relies on
belongs to the RFC it cites: Router Advertisement and Prefix Information
(RFC 4861), Route Information Option (RFC 4191), RDNSS and DNSSL (RFC 8106,
which obsoletes the cited RFC 6106), DHCPv6 IA_NA, IA_PD and Reconfigure
Accept (RFC 9915, which obsoletes the cited RFC 3315 and RFC 3633),
SOL_MAX_RT (RFC 7083, folded into RFC 9915), the 6rd DHCPv4 option 212
(RFC 5969) and the DS-Lite AFTR-Name option 64 (RFC 6334).

## Pitfalls

- **Router Lifetime is CE state, not configuration.** G-4, G-5, L-4 and ULA-5
  each make the Router Lifetime on the LAN depend on what the WAN side holds.
  A fixed configured lifetime meets none of them.
- **Prefix delegation is two halves.** Requesting the IA_PD (WPD-1) is the
  client; carving a /64 per LAN interface and advertising it (L-2, L-3) is the
  CE glue, and without it a delegated prefix reaches no host.
- **Linux router mode ignores RAs.** With forwarding enabled the kernel
  processes Router Advertisements only when accept_ra is 2, which is what W-1
  and W-3 need on the WAN.
