**Purpose:** Defines three DHCP options (93, 94, 97) used by PXE and EFI
clients to identify their system architecture, network interface revision,
and machine identity so the DHCP/PXE boot server can return the correct
OS bootstrap image for the client's platform.

**Errata 4624 (Verified, Section 2.1):** In practice, UEFI x86-64
implementations send architecture type 7 (listed as "EFI BC" in the RFC).
The IANA registry reflects the practical assignment. Match type 7 for
UEFI x86-64 bootfile selection.

## Wire Formats

### Option 93: Client System Architecture Type (Section 2.1)

```
          Code  Len  16-bit Type
         +----+-----+-----+-----+
         | 93 |  n  | n1  | n2  |
         +----+-----+-----+-----+
```

| Field | Offset | Size | Type | Constraints |
|-------|--------|------|------|-------------|
| Code | 0 | 1 | uint8 | 93 |
| Len | 1 | 1 | uint8 | "MUST be an even number greater than zero" (Section 2.1) |
| Type(s) | 2 | 2*k | uint16 | Big-endian, k = Len/2 architecture type identifiers |

Multiple architecture types MAY be listed; Len = 2 * count.

#### Architecture Type Values (Section 2.1)

| Type | Architecture Name |
|------|-------------------|
| 0 | Intel x86PC |
| 1 | NEC/PC98 |
| 2 | EFI Itanium |
| 3 | DEC Alpha |
| 4 | Arc x86 |
| 5 | Intel Lean Client |
| 6 | EFI IA32 |
| 7 | EFI BC |
| 8 | EFI Xscale |
| 9 | EFI x86-64 |

Post-RFC IANA additions (not in RFC text):

| Type | Architecture Name |
|------|-------------------|
| 10 | EFI ARM 32-bit |
| 11 | EFI ARM 64-bit |

### Option 94: Client Network Interface Identifier (Section 2.2)

```
              Code  Len  Type Major Minor
             +----+-----+----+-----+-----+
             | 94 |  3  |  t |  M  |  m  |
             +----+-----+----+-----+-----+
```

| Field | Offset | Size | Type | Constraints |
|-------|--------|------|------|-------------|
| Code | 0 | 1 | uint8 | 94 |
| Len | 1 | 1 | uint8 | 3 (fixed) |
| Type | 2 | 1 | uint8 | 1 = UNDI (only defined value) |
| Major | 3 | 1 | uint8 | Major revision |
| Minor | 4 | 1 | uint8 | Minor revision (e.g., 11 = 0x0B for rev 2.11) |

#### UNDI Revision Values (Section 2.2)

| Revision | Description |
|----------|-------------|
| < 2.00 | LANDesk service agent boot ROMs. No PXE APIs. |
| 2.00 | First generation PXE boot ROMs. (PXENV+) |
| 2.01 | Second generation PXE boot ROMs. (!PXE) |
| 3.00 | 32/64-bit UNDI specification. (Alpha). EFI boot services driver only. No EFI runtime support. |
| 3.10 | 32/64-bit UNDI specification. (Beta). First generation EFI runtime driver support. |
| 3.20 | 32/64-bit UNDI specification. (Release). Second generation EFI runtime driver support. |

### Option 97: Client Machine Identifier (Section 2.3)

```
              Code  Len  Type  Machine Identifier
             +----+-----+----+-----+ . . . +-----+
             | 97 |  n  |  t |     | . . . |     |
             +----+-----+----+-----+ . . . +-----+
```

| Field | Offset | Size | Type | Constraints |
|-------|--------|------|------|-------------|
| Code | 0 | 1 | uint8 | 97 |
| Len | 1 | 1 | uint8 | 17 for type 0 |
| Type | 2 | 1 | uint8 | 0 = GUID (only defined value) |
| GUID | 3 | 16 | bytes | 16-octet Globally Unique Identifier |

## Encoding Rules

- All multi-byte fields are big-endian (network byte order).
- Option 93 length field counts only the type octets, not code or len.
- Option 93 can encode multiple architecture types as consecutive
  uint16 values within a single option instance.

## Decoding Rules

- Parse option 93 by reading Len/2 consecutive uint16 values.
  First value is the primary architecture type.
- Option 94 is fixed 3 bytes: type + major + minor.
- Option 97 type field determines interpretation of remaining bytes.
  Only type 0 (GUID) is currently defined; other values are undefined.

## Validation

| Check | Valid | Invalid Action |
|-------|-------|----------------|
| Option 93 Len | Even, > 0 | Ignore option |
| Option 93 Type value | 0-9 (RFC), 0-11 (IANA) | Unknown type; select default bootfile or reject |
| Option 94 Len | 3 | Ignore option |
| Option 94 Type | 1 (UNDI) | Unknown interface type |
| Option 97 Len | 17 for type 0 | Ignore option |
| Option 97 Type | 0 (GUID) | Unknown identifier type |

## MUST Requirements

### Tx
- "This option [93] MUST be present in all DHCP and PXE packets sent
  by PXE-compliant clients and servers." (Section 2.1)
- "This option [94] MUST be present in all DHCP and PXE packets sent
  by PXE-compliant clients and servers." (Section 2.2)
- "This option [97] MUST be present in all DHCP and PXE packets sent
  by PXE-compliant clients and servers." (Section 2.3)
- "All compliant PXE clients MUST include a request for DHCP options
  128 through 135 in all DHCP and PXE packets." (Section 2.4)

### Validation
- Option 93 Len "MUST be an even number greater than zero." (Section 2.1)

## SHOULD/MAY

- [MAY] "Clients that support more than one architecture type MAY
  include a list of these types in their initial DHCP and PXE boot
  server packets." (Section 2.1)
- [MAY] "The list of supported architecture types MAY be reduced in
  any packet exchange between the client and server(s)." (Section 2.1)
- [MAY] Options 128-135 "MAY be present in the DHCP and PXE boot
  server replies and are meant for use by the downloaded network
  bootstrap programs. These options are NOT used by the PXE boot
  ROMs." (Section 2.4)

## Pitfalls

- **Type 7 vs 9 (Errata 4624, Verified):** The RFC lists type 7 as
  "EFI BC" and type 9 as "EFI x86-64". In practice, UEFI x86-64
  implementations send type 7. The IANA registry reflects this. A PXE
  server selecting bootfiles MUST match type 7 for UEFI x86-64 clients.
  Matching only type 9 will miss all real UEFI x86-64 boot requests.

- **Options 128-135 conflict (Section 2.4):** "As options 128-135 are
  not officially assigned for PXE use (before November 2004 they were
  considered site-specific options), use of these option values for PXE
  may conflict with other uses of the same options on the same networks."

- **Multiple architecture types:** Option 93 can list multiple types.
  A naive implementation checking only for a single 2-byte value will
  break when a client lists multiple architectures. Parse Len/2 entries,
  use the first as the primary selection criterion.

## Security Considerations (Section 5)

| Concern | Description |
|---------|-------------|
| Wrong platform code | "By specifying incorrect values for some of these options, a client may get access to, and possibly attempt to execute, code intended for another platform or client." |
| Information disclosure | "These options contain information about a client's system architecture and pre-OS runtime environment that is revealed to anyone who is able to listen in on DHCP messages sent by the client." |
