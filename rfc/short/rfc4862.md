# RFC 4862 — IPv6 Stateless Address Autoconfiguration (SLAAC)

**Status:** Draft Standard
**Date:** September 2007
**Authors:** S. Thomson, T. Narten, T. Jinmei
**Obsoletes:** RFC 2462

## Purpose

Defines how an IPv6 host configures its own addresses without a stateful server:
it forms a link-local address, then, on receiving a Router Advertisement (RA)
carrying a Prefix Information Option with the Autonomous flag set, forms one or
more global addresses by combining the advertised /64 prefix with an
interface identifier. Each autoconfigured address carries the RA's preferred and
valid lifetimes and is refreshed or expired as the router re-advertises.

## Address lifecycle (§5.5, §5.5.3, §5.5.4)

| State | Meaning |
|-------|---------|
| Tentative | Address is undergoing Duplicate Address Detection (DAD); not yet usable (kernel IFA_F_TENTATIVE). |
| Preferred | Within its *preferred lifetime*: freely used for new connections. |
| Deprecated | Preferred lifetime elapsed but valid lifetime remains: used only for existing connections. |
| Invalid | Valid lifetime elapsed: the address is removed. |

A host **MUST** perform DAD on every unicast autoconfigured address before use
(§5.4). Preferred/valid lifetimes come from the RA's Prefix Information Option
(§5.5.3); a valid lifetime of 0xFFFFFFFF is infinity.

## Relation to other mechanisms

- **RFC 4941** adds *temporary* (privacy) addresses: additional SLAAC addresses
  with randomized interface identifiers and shorter lifetimes, marked by the
  kernel with IFA_F_TEMPORARY.
- **DHCPv6** (RFC 8415) is the stateful alternative; the RA's M/O flags tell a
  host whether to use it. DHCPv6-assigned addresses are also non-permanent but
  are not SLAAC.
- A *manually configured* (static) address has an infinite lifetime and is
  marked IFA_F_PERMANENT by the kernel.

## How ze applies this (kernel-cooperating tracking)

ze does **not** run a userspace RA client or form SLAAC addresses itself — the
Linux kernel does that. ze *observes* the addresses the kernel autoconfigures
and classifies them so status/CLI can distinguish them from static ones
(`internal/plugins/iface/netlink`, spec followup-subsystem AC-6):

- `addrOrigin(isIPv6, IFA_F_*)` -> `static` (IFA_F_PERMANENT), `temporary`
  (IFA_F_TEMPORARY, RFC 4941), `slaac` (non-permanent IPv6), or `dynamic`
  (non-permanent IPv4 / DHCP).
- `AddrInfo.Origin` plus the normalized valid/preferred lifetimes ride the
  interface listing (`show interface`, web) and the netlink addr-event stream.
- Address churn is observed through the existing coalesced netlink monitor
  (RTM_NEWADDR/RTM_DELADDR), so a high-RA network needs no extra observer.
- IFA_F_TENTATIVE IPv6 addresses are dropped from the event stream until DAD
  completes (existing behavior), matching the Tentative state above.
