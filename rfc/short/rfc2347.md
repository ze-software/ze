**Purpose:** Extends TFTP (RFC 1350) with a backward-compatible option negotiation
mechanism. Options are appended to RRQ/WRQ packets; the server acknowledges
accepted options with a new OACK packet (opcode 6).

**Scope:** General-purpose option negotiation framework. Specific options (blksize,
tsize, timeout, windowsize) are defined in companion RFCs 2348, 2349, 7440.

## Wire Formats

### RRQ/WRQ with Options (Packet Formats section)

```
    2 bytes    string   1 byte  string  1 byte  string  1 byte  string  1 byte
    ---------------------------------------------------------------------------
   | opc   | filename |   0  |  mode  |   0  |  opt1  |   0  | value1 |   0  | ...
    ---------------------------------------------------------------------------
```

Options are NUL-terminated key/value pairs appended after the mode field.
Multiple options may be appended; order is not significant. Each option
may only appear once. All option names and values are case-insensitive ASCII.
Maximum request packet size is 512 octets.

### OACK Packet (Packet Formats section)

```
    2 bytes    string   1 byte  string  1 byte
    -------------------------------------------
   | 06    |  opt1  |   0  | value1 |   0  | ...
    -------------------------------------------
```

| Field | Offset | Size | Type | Constraints |
|-------|--------|------|------|-------------|
| Opcode | 0 | 2 | uint16 | 6, big-endian |
| Options | 2 | variable | NUL-terminated pairs | Only options the client requested |

## Negotiation Protocol

### Server behavior (Negotiation Protocol section)

1. Server receives RRQ/WRQ with options appended after mode.
2. For each recognized option with an acceptable value: include in OACK.
3. Unrecognized options: omit from OACK (do NOT send ERROR).
4. Invalid option values: per-option spec defines whether to omit, propose
   alternate value, or send ERROR code 8.
5. Server MUST NOT include options the client did not request.

### Client acknowledgment of OACK (Negotiation Protocol section)

- **Read Request:** Client sends ACK with block number 0 to confirm OACK.
- **Write Request:** Client begins transfer with DATA block 1.
- **Rejection:** Client sends ERROR code 8 to terminate.

### Fallback (Negotiation Protocol section)

If a server does not support option negotiation, it ignores the appended
options and returns DATA (for RRQ) or ACK (for WRQ) as normal RFC 1350.
The client then proceeds with default parameters.

## MUST Requirements

### Tx
- "The server must not include in the OACK any option which had not been
  specifically requested by the client" (Negotiation Protocol)

### State
- "If multiple options were requested, the client must use those options
  which were acknowledged by the server and must not use those options
  which were not acknowledged by the server." (Negotiation Protocol)

## Error Handling

| Condition | Response | Code |
|-----------|----------|------|
| Option negotiation failure | ERROR packet | 8 |
| Client receives unrequested option in OACK | ERROR packet | 8 |
| Server does not support options | Ignore options, proceed with DATA/ACK | N/A |

Error code 8 is defined by this RFC for option-negotiation-related termination.

## State Machine

### Read Transfer with Options

| State | Event | Action | Next |
|-------|-------|--------|------|
| IDLE | RRQ with options | Parse options, build OACK | WAIT_OACK_ACK |
| IDLE | RRQ with options, no recognized options | Send DATA block 1 (RFC 1350) | SEND_DATA |
| WAIT_OACK_ACK | ACK block 0 | Send DATA block 1 with negotiated params | SEND_DATA |
| WAIT_OACK_ACK | ERROR | Terminate | DONE |
| WAIT_OACK_ACK | Timeout | Retransmit OACK | WAIT_OACK_ACK |

## Pitfalls

- **Request packet size limit:** Maximum RRQ/WRQ with options is 512 octets.
  Servers should handle up to this limit.

- **Case insensitivity:** Option names and values are case-insensitive.
  Comparison must be case-folded.

- **OACK before DATA:** For a read with options, the server sends OACK
  instead of DATA block 1. The client ACKs with block 0. Only then does
  DATA block 1 follow with negotiated parameters. Sending DATA directly
  (skipping OACK) tells the client the server does not support options.

- **Unrecognized options are silently dropped:** Do not send ERROR for
  options the server does not implement. Simply omit them from the OACK.
