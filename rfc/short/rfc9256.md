# RFC 9256: Segment Routing Policy Architecture

## Meta

| Field | Value |
|-------|-------|
| RFC | 9256 |
| Title | Segment Routing Policy Architecture |
| Status | Standards Track |
| Date | July 2022 |
| Authors | C. Filsfils, K. Talaulikar, D. Voyer, A. Bogdanov, P. Mattes |

**Purpose:** Defines the architecture for Segment Routing (SR) Policies, including policy identification, candidate path selection, segment list structure, and traffic steering. This is the conceptual architecture document; BGP encoding is in RFC 9830.

**Scope:** SR-MPLS and SRv6 data planes. Defines the <Headend, Color, Endpoint> identification tuple and the segment type taxonomy (Types A through K).

## Key Concepts

### SR Policy Identification (Section 2.1)

An SR Policy is identified by the tuple:
- **Headend:** the node where the policy is instantiated
- **Color:** a 32-bit value used with BGP Color Extended Community for steering
- **Endpoint:** the destination of the policy (IPv4 or IPv6 address, or unspecified 0.0.0.0/::)

### Candidate Paths (Section 2.9)

An SR Policy has one or more candidate paths. Each is identified by:
- **Protocol origin:** LOCAL (10), PCEP (20), BGP (30)
- **Originator:** ASN + node address of the source
- **Discriminator:** 32-bit value for uniqueness

Selection uses: preference (highest wins), then protocol origin tiebreak.

### Segment Types (Section 4)

| Type | Code | Description |
|------|------|-------------|
| A | 1 | SR-MPLS label |
| B | 13 | SRv6 SID |
| C | 3 | IPv4 Node + SR Algorithm (+ optional MPLS SID) |
| D | 4 | IPv6 Node + SR Algorithm (+ optional MPLS SID) |
| E | 5 | IPv4 Node + Local Interface ID (+ optional MPLS SID) |
| F | 6 | IPv4 Adjacency (+ optional MPLS SID) |
| G | 7 | IPv6 Link-local Adjacency + Interface IDs (+ optional MPLS SID) |
| H | 8 | IPv6 Adjacency (+ optional MPLS SID) |
| I | 14 | IPv6 Node + SR Algorithm (+ optional SRv6 SID + Endpoint Behavior) |
| J | 15 | IPv6 Link-local Adjacency + Interface IDs + Algorithm (+ optional SRv6 SID + EB) |
| K | 16 | IPv6 Adjacency + SR Algorithm (+ optional SRv6 SID + EB) |

Types C-K are defined in RFC 9831.

### Binding SID (Section 6)

A Binding SID (BSID) is bound to an SR Policy. Packets arriving with the BSID as top label/SRv6 SID are steered into the policy. BSID can be:
- SR-MPLS label (20-bit)
- SRv6 SID (128-bit)

### Weight-Based ECMP (Section 2.10)

Multiple segment lists within a candidate path can carry a weight for ECMP distribution.

## Ze-Relevant Notes

- The NLRI and attribute wire formats are NOT in this RFC; see RFC 9830.
- Tunnel Encapsulation attribute (code 23) carries SR Policy sub-TLVs; see RFC 9012 for the attribute frame and RFC 9830 for SR Policy sub-TLV encoding.
- Segment types C-K wire encoding is in RFC 9831.
- SAFI 73 is assigned in RFC 9830, not here.
