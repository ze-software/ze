**Purpose:** Extends RADIUS to allow a RADIUS server to initiate
changes to active sessions on the NAS. Two new message types:
Change-of-Authorization (CoA) for modifying session parameters, and
Disconnect-Message (DM) for terminating sessions.

**Scope:** The NAS listens on UDP port 3799 for incoming requests from
the RADIUS server. This reverses the normal client-server direction:
the RADIUS server sends requests, and the NAS responds. The same
shared secret, authenticator computation, and TLV attribute encoding
from RFC 2865 apply.

| 44 | CoA-ACK | NAS -> Server |
| 45 | CoA-NAK | NAS -> Server |

## Request Authenticator (Section 2.3)

The Request Authenticator in CoA-Request and Disconnect-Request is
computed the same way as Accounting-Request (RFC 2866 Section 3):

```
MD5(Code + Identifier + Length + 16-zero-octets + Attributes + Secret)
```

RFC 5176 states no receive-side rule for this field: Section 2.3 says only
that the Authenticator "MUST be calculated in the same way as is specified for
an Accounting-Request in [RFC2866]". Ze verifies it before it reads any
attribute, and discards a packet whose value does not match without answering,
because a sender that cannot compute the value holds no shared secret and
Section 6.1 makes such a source untrusted.

## Response Authenticator (Section 2.3)

Response packets (ACK/NAK) use the standard Response Authenticator
from RFC 2865 Section 3:

```
MD5(Code + Identifier + Length + Request-Authenticator + Attributes + Secret)
```

## Session Identification (Section 3)

The RADIUS server identifies the target session using one or more of:

| Attribute | Type | Purpose |
|-----------|------|---------|
| Acct-Session-Id (44) | String | Unique session identifier from Accounting-Start |
| User-Name (1) | String | PPP authenticated identity |
| NAS-Port (5) | Integer | Port number on the NAS |
| Calling-Station-Id (31) | String | Subscriber phone/MAC |
| NAS-IP-Address (4) | IPv4 | NAS identification |
| NAS-Identifier (32) | String | NAS identification |

Multiple identification attributes narrow the match. Section 3 says the
combination "MUST match at least one session in order for a Request to be
successful; otherwise a Disconnect-NAK or CoA-NAK MUST be sent". The presence
of User-Name or Chargeable-User-Identity is a SHOULD, not a MUST.

## CoA Use Cases (Section 2)

- **Bandwidth change:** Update Filter-Id or vendor-specific rate
  attributes on an active session. The NAS applies new TC/QoS rules
  without disconnecting the subscriber.

- **Session disconnect:** Force-terminate a session (e.g., prepaid
  credit exhausted, administrative action).

- **Authorization change:** Modify any RADIUS-provisioned session
  attribute (VLAN, ACL, idle timeout).

## Message-Authenticator (Section 3.4)

Optional in the RFC, and optional in ze by default. The
`require-message-authenticator` leaf turns an absent attribute into a discard.
The HMAC-MD5 is computed with the Request Authenticator field AND the
Message-Authenticator value each taken as sixteen octets of zero, and the
attribute is inserted before the Request Authenticator is computed. Both fields matter: hashing the Request
Authenticator would make each of the two authenticators depend on the other,
and RFC 3579 Section 3.2's Access-Request rule does not apply here.

## Ze Implementation Notes

- The NAS listens on a configurable UDP port. Unset keeps the listener off, and
  a listener with no resolved server address does not start (RFC 5176 §6.1).
- The shared secret is chosen by the source address, and the RADIUS auth/acct
  server config supplies it.
- The identification attributes ze evaluates are Acct-Session-Id, User-Name and
  NAS-Port, and they narrow the match together rather than each opening its own
  route to a session.
- A match of more than one session is answered with Error-Cause 508, because ze
  does not apply one request to several sessions (RFC 5176 §2.3).
- CoA with a Filter-Id carrying a rate string ("10mbit") or a MikroTik VSA emits
  the SessionRateChange event; a Filter-Id naming a CoS profile emits
  SessionCoSChange. A CoA-ACK is sent only after the event was emitted.
- Disconnect-Request calls TeardownSession on the L2TP subsystem.
- Event-Timestamp is required, which is stricter than the RFC and is the answer
  to a port that takes unsolicited teardowns. Message-Authenticator is optional
  by default, and the `require-message-authenticator` leaf makes its absence a
  discard.
- Proxy-State and State are echoed unmodified and are never read.

**Known deviation, owner decision owed.** Five ids are anchored to sections
their obligations do not live in: `RFC5176-3.5-1`, `-3.5-2`, `-3.5-3` and
`-3.5-4` state Section 2.3 obligations, and `RFC5176-3.3-1` states a Section 3
one. An id is anchored to the section its line cites and `checkRetiredRequirements`
refuses a vanishing id, so correcting an anchor means retiring five ids and that
is not a walk's decision to take. Each of the three lines whose TEXT was also
wrong now names its true section: `-3.5-1` and `-3.5-2` quoted sentences that
appear nowhere in RFC 5176, and `-3.3-1` stated a Section 3 SHOULD as a MUST.
