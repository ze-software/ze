**Purpose:** Defines additional attributes for RADIUS (RFC 2865/2866)
to support EAP, ARAP, and accounting extensions including Gigaword
counters for sessions exceeding 4GB.

**Scope:** Extends the base RADIUS attribute set. Relevant to BNG:
the Gigaword attributes allow accurate accounting for high-bandwidth
subscriber sessions.

## Service Scope (Section 1.1)

Section 1.1 scopes the rest of the document to the services the NAS offers. Ze's
NAS offers one: PPP over L2TP, authenticated with PAP, CHAP-MD5 or MS-CHAPv2
(`internal/component/l2tp/ppp`). It offers no ARAP and no EAP, so it declares no
RADIUS attribute for either: `internal/component/radius/dict.go` names no
attribute in the 70-74 or 84 range and none for EAP-Message (type 79).

Every Access-Request the NAS builds names Service-Type Framed and
Framed-Protocol PPP (`buildAuthAttrs`,
`internal/component/l2tp/plugins/authradius/handler.go`), so it never requests a
service it cannot provide.

## Interim Accounting Interval (Section 2.1)

A RADIUS server that wants interim accounting records puts an
Acct-Interim-Interval attribute (type 85, Section 5.16) in its Access-Accept.
The NAS can also carry an interval of its own, and Section 2.1 settles which of
the two wins: "Note that a locally configured value on the NAS MUST override the
value found in an Access-Accept."

Ze's local value is the `acct-interval` leaf
(`internal/component/l2tp/plugins/authradius/yang/ze-l2tp-auth-radius-conf.yang`).
The leaf carries no YANG default, so an operator who sets nothing is
distinguishable from one who set 300, and `acctInterval`
(`internal/component/l2tp/plugins/authradius/acct.go`) reads the two cases apart:
a configured value is the session's cadence, an absent one leaves the
Access-Accept in charge, and a session neither side gave an interval runs at 300
seconds. A value read from an Access-Accept is clamped to 60..3600 seconds first.

## Gigaword Accounting Attributes (Section 5.1-5.2)

32-bit RADIUS counters (Acct-Input-Octets, Acct-Output-Octets) wrap
at 2^32 bytes (~4.3GB). Gigaword attributes track the number of times
each counter has wrapped.

| Type | Name | Format | Notes |
|------|------|--------|-------|
| 52 | Acct-Input-Gigawords | Integer | Times Acct-Input-Octets wrapped 2^32 |
| 53 | Acct-Output-Gigawords | Integer | Times Acct-Output-Octets wrapped 2^32 |

**Reconstruction:** Total bytes = (Gigawords * 2^32) + Octets.

**Presence rules:**
- Present only in Accounting-Request records where Acct-Status-Type
  is Stop or Interim-Update.
- Only included when the counter value is non-zero (i.e., when the
  32-bit octet counter has wrapped at least once).

## NAS-Port-Id (Section 5.17)

Type 87. The value is UTF-8 text naming the port of the NAS that is
authenticating the user, in the sense of a physical connection rather than a
TCP or UDP port number. Length is 3 or more, so the text is never empty.

The attribute is used only in Access-Request and Accounting-Request packets.
It exists for a NAS that cannot conveniently number its ports: such a NAS names
them instead. Section 5.19's table allows 0-1 instances in an Access-Request,
and Section 5.19 also allows 0-1 in an Accounting-Request.

## Message-Authenticator (Section 5.14)

Type 80, length 18. The value is an HMAC-MD5 keyed by the shared secret. In an
Access-Request it covers Type, Identifier, Length, the Request Authenticator and
the Attributes, with the Message-Authenticator value itself read as sixteen
octets of zero.

An Access-Accept, Access-Reject or Access-Challenge uses the same formula, but
substitutes the Request Authenticator of the Access-Request it answers for the
Response Authenticator the datagram carries. Section 5.14 computes the
Message-Authenticator first and the Response Authenticator over the finished
packet, so a receiver reverses that order.

The attribute is optional in a reply, and Section 5.19 Note 1 makes it mandatory
only for a packet that also carries an EAP-Message attribute. A client that
receives one anyway MUST verify it and discard the packet on a mismatch. A
Response Authenticator alone does not stand in for it: RFC 2865 computes that
value with MD5 over a concatenation, while the Message-Authenticator is a keyed
HMAC over the same packet.

## Implementation Constraints

- Gigaword computation: `gigawords = total_bytes >> 32`,
  `octets = total_bytes & 0xFFFFFFFF`.
- Accounting servers MUST handle the absence of Gigaword attributes
  (backward compatibility with RFC 2866-only implementations).
- The NAS computes Gigawords from the actual byte count; it does not
  independently track wrap events.
