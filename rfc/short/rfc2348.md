# RFC 2348 - TFTP Blocksize Option

## Meta

| Field | Value |
|-------|-------|
| RFC | 2348 |
| Title | TFTP Blocksize Option |
| Status | Standards Track |
| Date | May 1998 |
| Author | G. Malkin (Bay Networks), A. Harkin (Hewlett Packard) |
| Updates | 1350 |
| Obsoletes | 1783 |

**Purpose:** Defines the "blksize" option for TFTP option negotiation (RFC 2347),
allowing client and server to negotiate a data block size other than the
default 512 octets.

**Scope:** Single option definition. Uses the OACK mechanism from RFC 2347.

## Option Specification (Blocksize Option Specification section)

| Field | Value |
|-------|-------|
| Option name | `blksize` (case-insensitive) |
| Option value | ASCII decimal, number of data octets per block |
| Valid range | 8 to 65464, inclusive |
| Default (no negotiation) | 512 (RFC 1350) |

The blocksize refers to the number of data octets only; it does not include
the 4-byte TFTP header (opcode + block number).

### Wire Format in RRQ/WRQ

```
    2 bytes    string   1B   string   1B   string    1B   string   1B
    -----------------------------------------------------------------
   | opc   | filename |  0 |  mode  |  0 | blksize |  0 | #octets |  0 |
    -----------------------------------------------------------------
```

## Negotiation (Blocksize Option Specification section)

- Server responds with OACK containing the accepted blksize.
- "The specified value must be less than or equal to the value specified
  by the client."
- Client must use the OACK value or send ERROR code 8 to terminate.

## MUST Requirements

### Tx
- Server's acknowledged blksize MUST be <= client's requested value.
- Final block rules unchanged from RFC 1350: a data block shorter than
  the negotiated blksize signals end of transfer.

### State
- "If the blocksize is greater than the amount of data to be transferred,
  the first packet is the final packet."
- "If the amount of data to be transferred is an integral multiple of the
  blocksize, an extra data packet containing no data is sent to end the
  transfer."

## Constants

| Name | Value | Usage |
|------|-------|-------|
| BLKSIZE_MIN | 8 | Minimum negotiable block size |
| BLKSIZE_MAX | 65464 | Maximum negotiable block size |
| BLKSIZE_DEFAULT | 512 | RFC 1350 default, used when option not negotiated |

## Pitfalls

- **65464, not 65535:** The maximum is 65464 because the IP datagram
  maximum is 65535, minus 20 bytes IP header, minus 8 bytes UDP header,
  minus 4 bytes TFTP header = 65503. The RFC states 65464, which accounts
  for typical headers.

- **MTU fragmentation:** Practical blocksizes should stay within one
  Ethernet frame: 1468 (1500 MTU - 20 IP - 8 UDP - 4 TFTP) for
  untagged Ethernet, or 1428 for typical environments. Exceeding the
  path MTU causes IP fragmentation.

- **Zero-length final block:** Same rule as RFC 1350. When file size is
  an exact multiple of the negotiated blocksize, a final zero-length
  DATA must be sent.
