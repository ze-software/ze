**Purpose:** Lets IKEv2 run up to seven additional key exchanges after the initial one, typically post-quantum methods alongside classical (EC)DH, each mixed into the key material. For the IKE SA they run in IKE_INTERMEDIATE exchanges; for a Child SA or rekey they run in IKE_FOLLOWUP_KE exchanges after CREATE_CHILD_SA.

**Ze context:** `internal/component/ike/wire/header.go` declares IKE_SA_INIT (34), IKE_AUTH (35), CREATE_CHILD_SA (36) and INFORMATIONAL (37) only. `internal/component/ike/crypto/proposal.go::TransformTypeUnderstoodIKE` reads Transform Types 6 to 12 as not understood, so a proposal carrying one is unacceptable and skipped under RFC 7296 Section 3.3.6.

## Negotiation (Section 2.2.1)

- Transform Type 4 is renamed Key Exchange Method (KE); Transform Types 6 to 12 are ADDKE1 to ADDKE7.
- The initiator lists ADDKE transforms in the IKE_SA_INIT or CREATE_CHILD_SA SA payload; Transform ID NONE marks an optional additional exchange.
- The responder picks one algorithm per ADDKE type, never duplicating a non-NONE choice; omitted ADDKE types count as NONE.
- ADDKE transforms in IKE_SA_INIT require INTERMEDIATE_EXCHANGE_SUPPORTED in both IKE_SA_INIT messages. Without it, ADDKE types are unknown transform types and their proposals are skipped.

## Additional Exchanges

| Phase | Exchange | Order |
|-------|----------|-------|
| Initial IKE SA | IKE_INTERMEDIATE (43, RFC 9242), one per additional key exchange | Ascending Transform Type |
| Child SA create or rekey | CREATE_CHILD_SA, then IKE_FOLLOWUP_KE (44) per additional exchange | Ascending Transform Type |

Each additional key exchange completes before the next starts. The KE payload's Key Exchange Method field matches the n-th negotiated additional exchange.

### ADDITIONAL_KEY_EXCHANGE Notify (Section 2.2.4)

| Field | Value |
|-------|-------|
| Notify Message Type | 16441 |
| Data | Opaque link value chosen by the responder, returned intact by the initiator in the next IKE_FOLLOWUP_KE request |

### Errors

| Condition | Response |
|-----------|----------|
| Responder cannot pick non-duplicated algorithms | NO_PROPOSAL_CHOSEN |
| Responder's choice duplicates an algorithm | Initiator treats the exchange as failed |
| IKE_FOLLOWUP_KE with no matching key exchange state | STATE_NOT_FOUND (47) |
| Repeated STATE_NOT_FOUND after retries | Initiator deletes the IKE SA |
| Simultaneous rekey, losing side receives IKE_FOLLOWUP_KE | TEMPORARY_FAILURE |

## Constants (Section 3)

| Name | Value |
|------|-------|
| ADDKE1 to ADDKE7 | Transform Types 6 to 12 |
| IKE_FOLLOWUP_KE | Exchange Type 44 |
| ADDITIONAL_KEY_EXCHANGE | Notify Message Type 16441 |
| STATE_NOT_FOUND | Error Notify Type 47 |

## Pitfalls

- A peer that does not negotiate IKE_INTERMEDIATE must still skip proposals carrying ADDKE types, not reject the whole SA payload.
- Simultaneous Child SA rekey with additional exchanges: the side whose exchange used the smallest nonce stops rekeying and must not start IKE_FOLLOWUP_KE.
