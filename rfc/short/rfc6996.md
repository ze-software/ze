**Purpose:** Reserves Autonomous System Numbers for Private Use and adds a four-octet Private Use ASN range.

**Scope:** Private Use ASN ranges and operational guidance for using them in BGP AS path attributes.

## Private Use ASN Ranges

RFC 6996 reserves two Private Use ASN ranges:

| Registry | Range | Inclusive |
|----------|-------|-----------|
| 16-bit Autonomous System Numbers | 64512 - 65534 | Yes |
| 32-bit Autonomous System Numbers | 4200000000 - 4294967294 | Yes |

## Operational Requirements

RFC 6996 Section 4 states:

> If Private Use ASNs are used and prefixes originate from these ASNs, Private Use ASNs MUST be removed from AS path attributes (including AS4_PATH if utilizing a four-octet AS number space) before being advertised to the global Internet.

RFC 6996 Section 4 also states:

> Operators SHOULD ensure that all External Border Gateway Protocol (EBGP) speakers support the extensions described in [RFC6793] and that implementation-specific features that recognize Private Use ASNs have been updated to recognize both ranges prior to making use of the newer, numerically higher range of Private Use ASNs in the four-octet AS number space.

RFC 6996 Section 4 notes that some implementations only remove Private Use ASNs when the path does not mix Private Use and Non-Private Use ASNs. Operators should not rely on that behavior for Internet advertisement safety.

RFC 6996 Section 4 states:

> Normal AS path filtering MAY also be used to prevent prefixes originating from Private Use ASNs from being advertised to the global Internet.

## Security Considerations

Private Use ASNs do not raise unique security concerns. Inappropriate use outside a single organization can cause loss of connectivity because Private Use ASNs are not globally unique.
