# ISO/IEC 10589 - Intermediate System to Intermediate System (IS-IS)

## Meta

| Field | Value |
|-------|-------|
| Standard | ISO/IEC 10589:2002 (second edition) |
| Title | Information technology -- Telecommunications and information exchange between systems -- Intermediate System to Intermediate System intra-domain routeing information exchange protocol |
| Publisher | ISO/IEC (NOT the IETF; there is no "RFC 10589") |
| IP support | Added by IETF RFC 1195 (Integrated / Dual IS-IS) |
| Freely redistributable | No -- this file is a clean-room summary, never the standard text |

**Purpose:** IS-IS is a link-state interior gateway protocol originally
defined by ISO for routeing CLNP (ISO 8473). RFC 1195 extended it to carry
IPv4 (and the model later extended to IPv6 via RFC 5308). It runs **directly
over the data link layer** (IEEE 802.3 with LLC, not over IP/TCP/UDP), uses
TLV-encoded PDUs, and computes shortest paths with Dijkstra over a flooded
link-state database.

**Clause numbering note:** ISO/IEC 10589 uses clause numbers (for example
clause 7.3 for the update process, clause 8.2 for adjacencies). Earlier
internal drafts referred to these as "RFC 10589 sections"; that citation is
incorrect. Cite as `ISO/IEC 10589 clause X`.

## Addressing (clause 7.1, 8.x)

| Term | Definition |
|------|------------|
| System ID | 6-octet identifier of an IS, unique within the routeing domain |
| NET (Network Entity Title) | Area address (1..13 octets) + System ID (6) + SEL (1, = 0x00 for an IS). Total 8..20 octets |
| Area address | Variable-length prefix shared by all L1 ISs in an area |
| Source ID | System ID (6) + pseudonode ID (1) = 7 octets |
| LSP ID | Source ID (7) + LSP number (1) = 8 octets. LSP number 0..255 (256 fragments; fragment 0 is valid and carries the non-fragmentable fields) |

## Levels (clause 7.1, 8.2)

- **Level 1 (L1):** intra-area. L1 adjacencies require a matching area address (clause 8.2.2).
- **Level 2 (L2):** inter-area backbone.
- An IS may be L1, L2, or L1L2. Domain-wide prefix leaking between levels uses the up/down bit (RFC 2966).

## PDU Types (clause 9)

Nine PDU types, identified by a 5-bit type field in the common header. The
correct type-code octet values are:

| PDU | Code |
|-----|------|
| Level 1 LAN IIH | 0x0f (15) |
| Level 2 LAN IIH | 0x10 (16) |
| Point-to-Point IIH | 0x11 (17) |
| Level 1 LSP | 0x12 (18) |
| Level 2 LSP | 0x14 (20) |
| Level 1 CSNP | 0x18 (24) |
| Level 2 CSNP | 0x19 (25) |
| Level 1 PSNP | 0x1a (26) |
| Level 2 PSNP | 0x1b (27) |

All PDUs share an 8-octet common header: intra-domain routeing protocol
discriminator (0x83), length indicator, version/protocol-ID extension (0x01),
ID length, PDU type, version (0x01), reserved (0x00), maximum area addresses.

## Core TLVs (clause 9)

TLVs use Type (1) + Length (1) + Value. ISO/IEC 10589 base TLVs:

| TLV | Name | Used in |
|-----|------|---------|
| 1 | Area Addresses | IIH, LSP |
| 2 | IS Reachability (narrow metric, 6-bit) | LSP (obsoleted for new use by RFC 5305 TLV 22) |
| 6 | IS Neighbours (lists neighbour SNPA/MAC) | LAN IIH (required for LAN adjacency three-way detection) |
| 8 | Padding | IIH (pad to interface MTU for MTU-mismatch detection, clause 8.2.3) |
| 9 | LSP Entries (LSP ID + seq + checksum + lifetime) | CSNP, PSNP |
| 10 | Authentication | all PDUs; MUST be the first TLV (RFC 5304 clause 1) |
| 14 | LSP Buffer Size | IIH |

IP support TLVs are defined by RFC 1195 (128 IP Internal Reach, 129 Protocols
Supported, 130 IP External Reach, 132 IP Interface Address), wide-metric TLVs by
RFC 5305 (22 Extended IS Reach, 135 Extended IP Reach), and IPv6 TLVs by RFC
5308 (232 IPv6 Interface Address, 236 IPv6 Reachability). An IS MUST accept and
re-flood unknown TLVs verbatim (clause 7.3.14).

## Adjacency state machine (clause 8.2)

States Down, Initialising, Up. On broadcast circuits adjacency is detected via
the IS Neighbours TLV (TLV 6) listing SNPAs heard. On point-to-point circuits
the three-way handshake is carried by the Point-to-Point Adjacency State TLV
(TLV 240, RFC 5303); legacy peers without it fall back to two-way. Hold time =
hello interval * hold multiplier; loss of hellos times the adjacency out.

## Designated IS (DIS) and pseudonodes (clause 8.4.5)

On broadcast circuits one IS per level is elected DIS by highest priority
(0..127), MAC address as tiebreaker. The DIS originates a pseudonode LSP (LSP ID
with a non-zero pseudonode octet) listing all ISs on the LAN at metric 0; each
IS reports only the pseudonode as its neighbour, turning the mesh into a star.

## Update process: flooding (clause 7.3)

- Each LSP in the LSDB carries per-circuit **SRM** (Send Routeing Message, "send this LSP on this circuit") and **SSN** (Send Sequence Number, "acknowledge / request via PSNP on this circuit") flags.
- On receipt, compare by (sequence number, then remaining lifetime, then checksum). Newer replaces local and sets SRM on all other circuits + SSN on the incoming circuit (clause 7.3.15, 7.3.16).
- CSNPs summarise the LSDB (periodically on LANs from the DIS; once at P2P bring-up). A receiver missing an LSP listed in a CSNP requests it via PSNP; requesting an LSP the receiver does not yet hold needs a request entry that is not an SRM/SSN flag on an existing LSDB entry.
- Purge: an LSP with remaining lifetime 0 is re-flooded then retained for ZeroAgeLifetime before deletion (not deleted immediately).

## LSP origination, ageing, sequence numbers (clause 7.3.4, 7.3.7, 7.3.16.1)

- Sequence numbers are 32-bit, start at 1; 0 is reserved. On reaching 0xFFFFFFFF the IS purges and waits MaxAge + ZeroAgeLifetime before re-originating.
- Remaining lifetime (16-bit seconds) decrements once per second; the originator refreshes before expiry. MaxAge default 1200 s.
- The overload (LSPDBOL) bit marks an IS as transit-only (RFC 3787 clarifies usage).

## Checksum (clause 7.3.11)

LSPs carry an ISO 8473 Fletcher checksum computed from the octet after the
Remaining Lifetime field to the end. The checksum field participates in its own
computation, so a two-step adjustment is required; verify against known vectors.

## Forwarding

SPF (Dijkstra) runs per level over the graph formed by IS Reachability edges
(including pseudonodes), producing prefixes with next-hops and metrics. Wide
metrics (RFC 5305, 24-bit) are preferred over the legacy 6-bit narrow metrics.
