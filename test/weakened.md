| Test | Reason |
|------|--------|
| TestRunTreeJSON | Deleted with the flag it covered. It drove `ze yang tree --json` and asserted the JSON that command encoded itself. That flag is gone: `show yang tree` is registered through `MustRegisterLocalData`, so the json operator renders the same payload and `ai/rules/cli.md` bans the second spelling. The payload itself is still asserted, by the `dataTree` cases in `yang_data_test.go`, which is what the flag was printing |
| TestRunCompletionJSON | Deleted with the flag it covered, for the same reason as `TestRunTreeJSON`. `ze yang completion --json` no longer exists; `show yang completion` renders the same answer through the pipe layer and `dataCompletion`'s own cases assert it |
| TestLocalDataRejectsPrintedRenderingFlag | Deleted with the guard it covered. It proved the data handlers refused a `--json` token passed through the pipe path, which existed only while the flag and the operator both reached the same handler. With the flag gone there is no second route for the token to arrive by, so the guard it asserted over is deleted too and the test asserts nothing |
| captureJSONOutput | Deleted with its only callers. It was a helper that captured stdout for the three tests above; no test in the package writes JSON to stdout any more, because the pipe layer renders it |
