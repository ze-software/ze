| TestInitLocksTheExecutable | RENAMED, not removed: it is `TestTheRecordedLockIsALockTheKernelHolds` in the same file, and it makes the same assertion for the same reason. It compares the octet count the module claims to have pinned against `VmLck` in `/proc/self/status`, which the kernel maintains and this package never writes, so a call that returned a number and locked nothing still cannot pass. Only its SOURCE moved: the count now comes from the registry record rather than from a package variable this package alone could read, which is the point of the commit. Coverage went UP, not down: `TestMemlockRecordsItsOutcome` and `TestMemlockNeverRecordsAHardFailure` are new, and the second pins the owner's classification that memlock is the soft exemplar and must never stop a daemon. |
| TestCheckExecutableLockedSaysNothingWhenLocked | REMOVED with the code it tested. This commit deletes memlock's doctor check, because `ze doctor` re-probes the environment in its own process and answered for the operator's shell rather than the daemon, and the owner ruled that tier out for this fact. A test whose subject no longer exists cannot be kept. Its assertion survives in a truer place: `TestMemlockRecordsItsOutcome` asserts that a successful lock records `SetupSucceeded` and carries no reason, which is the same "a healthy module raises nothing" property, now read from the process that did the locking. |
| TestCheckExecutableLockedReportsTheFailure | REMOVED with the same doctor check, and its assertion is the half that mattered. It checked that a failed lock produced one warning carrying the cause and the remedy. `TestMemlockRecordsItsOutcome` now asserts the soft-failure branch carries `RLIMIT_MEMLOCK` and `LimitMEMLOCK=infinity` in the recorded reason, so the operator still gets the cause and the fix; `show module list` is where they read it instead of `ze doctor`. The diagnostic code `doctor-memlock-not-locked` is deleted in the same commit, so nothing is left advertising a check that no longer runs. |
| setLockOutcome | Helper, not a test. It swapped the two package variables `lockedOctets` and `lockErr` so the doctor check could be driven over both outcomes. Both variables are deleted by this commit: the outcome lives in the registry now. Its replacement is `recordedOutcome`, which reads the real record rather than installing a fake one, so the tests that used to run against a substituted value now run against what `init()` actually wrote. No assertion left the suite through it. |
