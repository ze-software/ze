The rename is the point of the commit. RFC 5176 Section 3.4 opens "The Message-Authenticator Attribute MAY be used", so discarding unconditionally refused a conformant Dynamic Authorization Client, and the behaviour now sits behind the `require-message-authenticator` leaf. The old name asserted a rule; the new name asserts the rule an operator opted into. Coverage went UP rather than down: the renamed test constructs its listener with `RequireMessageAuthenticator: true`, and a new paired test asserts the same packet is ACCEPTED at the leaf's default, so the pair proves the leaf and not the code decides. A third case asserts that a request carrying a WRONG Message-Authenticator is still discarded with the leaf off, which is the case that proves the presence check was gated and the verification was not. |
