# Test weakenings this commit accepts

One row, and it is a restatement rather than a loss.

The stored-route replay used to emit one UPDATE per stored prefix. It now
rebuilds the message framing the source sent, coalescing the prefixes that share
an attribute block back into one UPDATE. That is what makes an egress policy
reach the same decision on the replay rail as on the live forward, which is the
defect this commit fixes.

A test that counted DISPATCHES was therefore counting the framing, not the
behavior. The requirement it exists for is untouched and is still asserted.

## The ExaBGP compatibility commit

Seven more rows, and every one is a RENAME or a rewrite in place. No assertion
left the suite: each row names where its subject is asserted now, and each of
those files is in the same commit.

The pattern behind six of them is one change. A function that used to take
20-bit label VALUES now takes RFC 3032 Section 2.1 stack ENTRIES, and a
function that used to turn operator text into wire bytes was named `Parse*` in
a package where `Parse*` means wire-to-type everywhere else. Both were renamed
so the name says which of the two jobs it does, and a test named after the old
function is renamed with it.

| Test | Reason |
|---|---|
| TestResolvedNextHopIsASubsetOfBest | A RENAME, following the field it is named after. The `resolvedNH` map became `installed` and its value became an `installedPath` carrying the PROOF the install was made under beside the next hop, because a gateway inside a connected covering route resolves to itself and the address therefore cannot say which rule programmed it. The test is `TestInstalledIsASubsetOfBest` in the same file, asserting the same invariant over the renamed map, with no assertion added or removed |


## The unwired-feature class pass

Four rows, and all four are one deletion: `archive.ValidateTrigger` had no
non-test caller and no entry point could reach it. `system/archive/trigger` is a
YANG `enumeration`, and the schema validator refuses an out-of-set value with
`ErrTypeEnum` before `ExtractConfigs` runs, so the Go switch was a second gate
behind a closed door. Wiring it would have added a branch no input can take.

What left the suite is the coverage of that unreachable branch, and nothing
else. The property an operator depends on -- that a trigger word outside the
model is refused -- is asserted where it is actually enforced. The four rows are
in the table above, which is the one this gate reads.

## The PPP refusals pass

One row, and it is a SPLIT that leaves more coverage than it found, not a loss.

`TestLCPReplyLargerThanAFrameIsNotSent` drove the bound from the wire, with a
Configure-Request repeating one Magic-Number option 700 times. That request can
no longer build an oversized reply: RFC 1661 Section 6 allows none of its own
options more than once, so `NegotiatePeerOptions` now names each Type once and
700 repetitions earn one Nak entry. The old input stopped exercising the thing
the test exists for.

It became three tests rather than one, and all three are in this commit:

- `TestLCPReplyLargerThanAFrameIsNotSent` keeps the bound as a direct assertion
  over `WriteLCPOptions`, because that writer also serves the PPPoE client and
  `LCPNakOrReject`, and a writer with no bound is one caller away from the
  panic again.
- `TestLCPReplyLargerThanAFrameIsNotSentFromTheWire` restores the ENTRY-POINT
  drive with 200 DISTINCT unrecognized Types. Distinct Types are not
  deduplicated and cannot be, because Section 5.4 requires every unrecognizable
  option to appear in the Configure-Reject, so the wire still reaches the bound.
- `TestRFC1661RepeatedOptionDrawsOneNakEntry` asserts the new behaviour the old
  input now produces, tagged `RFC1661-5.3-3`.
