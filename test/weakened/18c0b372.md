# Test weakenings this commit accepts

Nothing left the suite. Seven names leave `pkg/plugin/sdk/sdk_test.go` and all
seven arrive in `pkg/plugin/sdk/dial_chain_test.go`, in the same package
directory, with their bodies unchanged. The gate reads one file and sees a
deletion, because it cannot see the file that received them.

They had to move. `sdk_test.go` is `package sdk`, and it imported
`internal/component/pki`. That package's closure returns to `pkg/plugin/sdk`
through `internal/component/pki/show.go`, `internal/component/plugin/server`
and `internal/component/iface`. An in-package test file may not close an import
cycle, so the whole test binary failed to build and NONE of the SDK's 83 tests
ran. The external test package is the remedy Go provides for this exact shape:
`package sdk_test` may import a package that imports the package under test.

The three tests reach the unexported dial through `sdk.DialAndAuth`
(`pkg/plugin/sdk/export_test.go`), which is a name for `dialAndAuth` and
nothing else. No product code changed, and the tests still need
`internal/component/pki` for the certificate authority they issue the hub's
leaf from.

Evidence that the move preserved them: `go test ./pkg/plugin/sdk/` builds and
passes in 4.2s where it previously reported `[setup failed]`, and the three
moved tests each pass by name under `-run TestPluginDial`.
