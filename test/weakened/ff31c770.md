# Test weakenings this commit accepts

Every row below is one test whose ASSERTION was inverted by an owner decision,
not a test that lost coverage. Thomas ruled on 2026-09-09 that a
`reference-bandwidth` commit must not tear down established adjacencies. Four
tests existed to prove the teardown. A test that pins behavior the owner has
just reversed is not evidence to preserve: it is the old behavior with a green
bar, and `ai/rules/rfc-compliance.md` names that shape as the violation rather
than the proof.

Nothing left the suite. `internal/plugins/ospf/interface_cost_test.go` grows in
this commit: `TestReferenceBandwidthReloadKeepsNeighborAndReprices` replaces the
teardown test with a stronger claim, and the Router-LSA assertions it adds read
the decoded link metric out of both address families, which the removed test
never did.

| Test | Reason |
|------|--------|
| TestInterfaceGlobalParamsChangedReferenceBandwidth | Renamed to `TestInterfaceGlobalParamsChangedIgnoresReferenceBandwidth` and its assertions inverted. It asserted that a reference-bandwidth change whose derived cost moves RESTARTS the interface. That is the behavior the owner reversed, so the arm it tested no longer exists in `interfaceGlobalParamsChanged`: the predicate now keeps only the Router ID and area-type arms, and the new test asserts both of those still restart, plus that a reference-bandwidth change does not. The link-speed read-count assertion went with it because `interfaceCostAtSpeed`, which existed only for that comparison, is folded back into `interfaceCost`. |
| TestReferenceBandwidthReloadDropsAdjacencyAndReprices | Renamed to `TestReferenceBandwidthReloadKeepsNeighborAndReprices`, asserting the opposite outcome on the same path. Its setup is unchanged and its 2-Way precondition is unchanged; what changed is what the reload is allowed to do to the neighbor. The replacement asserts strictly more: the neighbor stays 2-Way, the interface runtime is not replaced, the Router-LSA link metric moves from 100 to 10, and `show ospf interface` reports the new cost. |
| TestReferenceBandwidthReloadRepricesEveryAddressFamily | One `t.Fatalf` became a `t.Errorf` on the reconcile-journal assertion. It was fatal because the old test could not continue once the interface it expected to be restarted was not; the new assertion is that NO interface was restarted, and every later assertion in the test is still meaningful when it fails, so stopping there would hide the Router-LSA and snapshot results a reader needs to diagnose it. The count moved 7 to 6; no assertion was deleted. |
| TestOSPFTopologyCostFollowsReferenceBandwidth | Its two reconcile-journal expectations become one, so the assertion count moves 10 to 9. It asserted that the auto-costed interface was restarted and the explicitly-costed one was not; it now asserts that neither is. The explicit-cost half is unchanged in meaning, and the auto-cost half changed side because of the owner's decision. Nothing about the costs themselves was dropped: the same test still reads eth0 at 100, eth1 at the explicit 10, eth0 at 10 after the reload, and the runtime snapshot at each step, which is what the test exists for. |
