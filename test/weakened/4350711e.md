# Test weakenings this commit accepts

Four entries. Three are the same property asserted under a new name, against the
model instead of against a rendered page, and the fourth is an assertion count
that follows the one real deletion. Nothing about surviving behavior stopped
being asserted.

| Test | Reason |
|------|--------|
| TestHandEditedStatusPageReportsStale | It asserted that hand-editing `docs/features/rfc-status.md` makes `rfcFreshnessStage` report stale. That stage is deleted with the byte comparison behind it: the page is derived and untracked, so there is no committed copy for a hand edit to diverge from, and a hand edit is discarded by the next rebuild rather than reported. `TestTheDocVerifyStageNoLongerJudgesTheRFCLedger` is its successor and asserts the stage is gone, so the deletion itself is covered. |
| TestTheLedgerRollupIsReadFromItsAnnotatedAndNoTestColumns | Renamed, not dropped. It pinned that the rollup is summed from the ledger's own `Annotated` and `No test` COLUMNS, parsed out of the rendered page. `TestTheModelRollupIsReadFromItsAnnotatedAndNoTestCounts` makes the identical claim about the same two figures, read from `rfc.CoverageRows` rather than from a regex over markdown. The property under test is unchanged; only the source of the numbers moved, which is what this commit is for. |
| TestTheLedgerRollupReadsItsOnePolarityColumn | Renamed, not dropped, for the same reason. `TestTheModelRollupReadsItsOnePolarityCount` is the successor and asserts the one-polarity figure against the model. |
| docverify_test | The file's assertion count falls because `TestHandEditedStatusPageReportsStale` is deleted. Every dropped assertion sits inside that one test, and no surviving stage lost one. |
