# Test weakenings this commit accepts

One test is REMOVED, and it is removed because it asserted the defect.

`TestOwningPackageIsNotAFinding` pinned the rule that the enumeration gate
excludes an entire package DIRECTORY from a corpus it declares. That rule is
the defect this commit fixes. Under it, a second declaration living inside the
registry's own package was invisible to the gate, and that is not hypothetical:
`readOnlyVerbs` sat in `internal/component/command`, restated three of the verb
spellings `command.Verbs` declares, disagreed with it about `resolve`, and made
`ze help ai` publish five roots to agents as daemon-mode. The gate could not
have reported it, because the package owning the corpus was excused wholesale.

Keeping the test would have pinned the blind spot in place. Its fixture is NOT
removed: `testdata/owner/` stays, and it now pins the corrected answer, that the
DECLARATION is excused and everything else in the same package is judged.

Two tests replace it and both were observed red against the unfixed producer:
`TestASecondDeclarationInTheDeclaringPackageIsReported` and
`TestALiteralInTheRegistrysPackageIsReported`. Two more guard the other
direction, so the narrowed exclusion cannot start reporting the declarations
themselves: `TestTheDeclarationIsNotAFinding`, and
`TestTheLiveDeclarationsAreNotFindings`, which walks the real
`internal/component/command` and `internal/core/diagnostic` behind a 20-file
floor rather than a fixture.

Net: one assertion about the old rule leaves, four assertions about the correct
rule arrive, and the population the gate judges grows rather than shrinks.
