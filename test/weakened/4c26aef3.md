# Test weakenings this commit accepts

One test is RENAMED and rewritten, and nothing left the suite. Half of what it
asserted was the branch this commit deletes, so keeping it unchanged would
have required the product to keep behavior that is wrong.

`TestOrchestratorAppliesParticipantThatYieldedNoOperations` made two claims.
The first is the one that matters: a participant whose root yields no
operations still gets its change applied, so nothing is silently dropped. The
second is the one this commit deletes: it required BOTH participants to
receive a section apply and required `operationEvents` to be empty, which is
the fallback itself. It asserted that a decomposed root loses its ordering
whenever an uncovered root joins the transaction.

`TestExecuteMixedRootTakesOperationPath` keeps the first claim in the same
words. The uncovered participant must receive exactly one section apply, which
is the old `want 1` on `iface` unchanged. The second claim is inverted, on
purpose: the decomposed root must now receive zero section applies and must
appear in `operationEvents`. That inversion is the defect being fixed, not
coverage being reduced.

The assertion still discriminates. Reverting the coarse-node synthesis
(`for _, name := range uncovered` to `uncovered[:0]`) leaves the uncovered
participant with no section apply, which the kept `want 1` rejects. The same
revert was observed turning `test/reload/config-apply-ordering-coarse-root.ci`
red at step 5, and green again after restore.


## Phase 3: the rules these tests drove are deleted

Three tests asserted the behavior of constraint rules this commit removes.
Each one's subject is gone, so none could be kept: a test of a deleted rule
either fails to compile or asserts nothing.

`TestDependencyGraphSimple` built a graph from two rules whose relations,
`ResourceRelationInterfaceAddress` and `ResourceRelationAddressUsedBy`, are
both deleted here. It made three claims, and all three survive:
an interface is created before its address, and an address exists before a
peer uses it, are now asserted by
`TestBuildOperationGraphDerivesProducerBeforeConsumer` and by the `iface-create`
and `bgp-peer-local-address-change` cases of
`TestBuildOperationGraphDerivedEdgesMatchDeletedRules`; the third claim, that
no transitive edge appears, is asserted more strictly than before, because
that test compares the WHOLE edge set with `ElementsMatch` rather than
checking one absent pair.

`TestBGPConstraintRulesOrderPeerAgainstAddress` and
`TestBGPListenerConstraintRules` asserted the four `bgp` constraint rules,
all four deleted here. For the two PEER rules the claim is replaced:
`TestBGPOperationsDeclareConsumeAddress` asserts what the decomposer declares,
and `TestBGPOperationsOrderAgainstAnAddressOnAnyInterface` asserts the ordering
that declaration earns. The replacement is wider: the deleted rules selected
the `add-peer` label, so a `modify-peer` rebinding the same address got no
edge, and the derivation gives it one.

The two LISTENER rules are replaced by nothing, and the coverage that goes with
them is not replaced either. `decomposeBGPOperations` emitted no listener
operation before this commit and emits none after it (checked at
`a6ea1ad0b~1`), so both rules selected an operation that never existed, and
`TestBGPListenerConstraintRules` asserted the rule registry rather than any
ordering the daemon can produce. Nothing declares a listener's address
consumption today: `internal/core/bgp/configop` carries `add-peer`,
`remove-peer` and `modify-peer` and no listener label. The listener's ordering
is owed when a listener operation is emitted, and it is owed a test then.

## Review round 2: the deadline stops being a per-tier max

Two deadline tests asserted the tier computation that review finding I-1
deletes. `computeTieredDeadline` took the max budget within a dependency tier
and summed the tiers, on the premise that a tier applied concurrently. Nothing
applies concurrently: an engine handler fires inside the emitter's goroutine
and the bridge performs the plugin RPC inside that handler, so a publish
returns only when the plugin has answered, and the ordered path then applies
one node at a time under one absolute deadline.

`TestOrchestratorDependencyGraphDeadline` asserted 13s for four participants
budgeted 10, 5, 3 and 2. The answer is now 20s, and the test is
`TestApplyDeadlineSumsEveryParticipantBudget` over the same four participants
and the same budgets. The claim is not reduced, it is corrected: the old
expectation would have aborted a transaction in which the third and fourth
participants applied correctly.

`TestOrchestratorTieredDeadlineCycleFallback` made `tierFn` return an error to
reach the flat-max fallback branch. The deadline calls `tierFn` never, so that
branch has no code and the test has no subject. What it protected beyond the
branch was "a zero deadline is an instant timeout", and
`TestApplyDeadlineDefaultsWhenNoParticipantDeclaresABudget` keeps exactly that,
asserting the 30-second default for a participant set that declares nothing.

Both replacements discriminate. The sum test was observed RED against the
per-tier max at `apply deadline = 10s, want 20s`
(`tmp/session/2026-09-08-cbc36cee-41ac-4afd-8b71-1bae841964d9/scratch/cao2-i1-deadline-red.log`).
The default test fences a value no revert in this change moves, so it has no
red phase, and it is recorded as a kept claim rather than as proof.

| Test | Reason |
|------|--------|
| TestOrchestratorDependencyGraphDeadline | Renamed to TestApplyDeadlineSumsEveryParticipantBudget over the same participants and budgets. Its 13s expectation was the per-tier max this change deletes; 20s is the sum the serialized phase can cost |
| TestOrchestratorTieredDeadlineCycleFallback | Its subject is deleted: the deadline no longer calls tierFn, so the flat-max fallback branch does not exist. TestApplyDeadlineDefaultsWhenNoParticipantDeclaresABudget keeps its surviving claim, that a zero deadline never reaches the apply |
