# Argument binding tests move with the validator

`validateCommandArgs` and its helpers moved from `plugin/server` to the
`command` package as `command.ValidateArgs` (`argbind.go`), so the local-data
route and the daemon dispatcher call one validator. The tests that called the
unexported helpers moved with them, unchanged apart from the package qualifier,
to `internal/component/command/argbind_test.go`. Nothing left the suite.

| Test | Reason |
|------|--------|
| TestLocalDataPlainHandlerJudgesArguments | Moved, not dropped: C-T2c moved `RegisterLocalData` and its plain handler from `command/registry` into `command`, so the test moved with the code to `internal/component/command/local_data_args_test.go` under the same name. It now drives the real judgment (`ValidateModelArgs` over a declared 1..4 leaf) instead of an injected check: an over-long value exits 1, no definition source exits 1, and the handler never runs on either. That the handler runs on the judged value is asserted by `TestHandlerTypesTakeValidatedArguments/LocalDataHandler` in the same file, on both R2 and R3 |
| local_data_args_test | The file keeps only `TestValidateLocalArgsAnswersTheJudgedTokens`, the R6/R7 judgment the registry still owns; its assertion count fell because `TestLocalDataPlainHandlerJudgesArguments` moved to `command/local_data_args_test.go` (row above) |
