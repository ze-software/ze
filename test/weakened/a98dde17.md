# Test weakenings this commit accepts

Two tests left `internal/le/docvalid/helpshape_schema_test.go`. Each one
asserted a behavior this commit REMOVES, and every assertion it carried that
still holds is carried by a named test in the same file.

Every other row is a RENAME: the Go field that holds a command's long
explanation was `LongHelp` and is now `Description`, the field that holds its
one-line summary was `Description` and is now `ShortHelp`, and each test that
named the old field in its own name now names the new one. The body, the
fixture and the assertion of each one are the same function under the new
name, in the same file, in this commit.

| Test | Reason |
|------|--------|
| TestHelpShapeIgnoresAnEnumThatKeysNoList | Deleted. It asserted that an enum which keys no list is NOT judged; AC-7 judges every rendered enum value, so the assertion is now false. `TestHelpShapeJudgesEveryRenderedEnum` (`internal/le/docvalid/helpshape_schema_test.go`) asserts the replacement: every value `yang.EnumValueNames` renders is counted and capped, list key or not. |
| TestHelpShapeIgnoresALeafInACommandModuleButCapsOneInAConfigModule | Deleted. Its first half asserted that a `-cmd` module leaf is NOT judged; the gate now judges command arguments and rpc and notification leaves, so that assertion is false and `TestHelpShapeCapsACommandArgumentSummary`, `TestHelpShapeJudgesAnInheritedArgumentOnce` and `TestHelpShapeCapsAnRPCAndNotificationLeafSummary` assert the replacement. Its second half, that an over-cap `ze:help` on a CONFIG leaf is refused under `char-cap`, still holds and is carried by `TestHelpShapeCapsAConfigLeafSummary` (same file). |
