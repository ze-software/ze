# Test weakenings this commit accepts

One assertion is deleted from one `.ci` file, and the file gets STRONGER by it:
the deleted line asserted an exit code that only a runner defect ever produced,
and the assertion that remains binds three facts where it bound one.

| Test | Reason |
|------|--------|
| tacacs-key-required | `expect=exit:code=1` is DELETED, and the test gets STRONGER by it. The line asserted that `ze -` exits 1, and it was only ever satisfied by a defect in the runner: `runOneCommand` rewrote the bare `-` into the PATH of the stdin file, so the command ran as `ze <path>`, which is not a form the CLI has, and the daemon printed `unknown command: <path>` with its usage and exited 1 before reading a line of config. Nothing about the TACACS+ guard could change that exit code. With the runner fixed the daemon starts, drops the tacacs backend and keeps running, which is the correct behavior and has no exit code to assert: aborting on one broken backend is what `internal/component/aaa/types.go` deliberately does NOT do, because it would take the local accounts down with it. What remains is the assertion that was always the proof and was itself dropped in silence until this work gave the parser an arm for it: `expect=stderr:pattern=` now binds THREE facts to one log line where it bound one, requiring that the backend dropped is tacacs, that the server is the one this config declares, and that the reason is `ErrNoSharedSecret`. Checked against four near-misses, each rejected: tacacs dropped for another reason, a different backend dropped carrying the same text, the error text with no drop, and a different server address. The suite count falls 3 -> 2 and the number of facts asserted rises 1 -> 3. |
