| Test | Reason |
|------|--------|
| TestSAInfoCountersAreNotNarrowed | The hard-limit assertion left this test because the behavior it pinned is now wrong: the kernel's `XFRM_INF` sentinel maps to zero, which is the public contract for unlimited (`hardLimitFromKernel`, `internal/component/ike/dataplane/xfrm_linux.go`). The same boundary is asserted harder in `TestSAInfoHardLimitSentinel`, which pins the sentinel in both directions and proves the largest FINITE limit survives the read without saturation. The current-counter assertion this test exists for is unchanged. |

It stopped the initiator BEFORE the foreground responder ran the inspection steps, so the fixture measured a peer that was already gone. The runner now waits for the foreground daemon to self-exit and tears the background peer down after (`terminateAfterSelfExit`, `internal/test/runner/runner_exec.go`). Every `expect=` and `reject=` line is unchanged, and the fixture fails with an emptied `ListSAs` (`EXPECTED_RED:1`). |
| ipsec-show-sa-counters | The same `cmd=stop:seq=3` teardown step, removed for the same reason and covered by the same runner change. Its counter assertions are unchanged and it goes red with `ListSAs` emptied. |
