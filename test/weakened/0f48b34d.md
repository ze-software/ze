# Test weakenings this commit accepts

`TestNATKeepalive` (`internal/component/ike/transport/keepalive_test.go`) lost
one `t.Fatal` and none of its wire assertions. The client side of the pair used
to be a bare `net.UDPConn` opened in two steps, `net.ResolveUDPAddr` then
`net.ListenUDP`, each with its own error check. `Keepalive` now writes through
`UDPTransport.Send`, under the transport's lock, so a keepalive never leaves
while `SendDF` holds the socket's DF option toggled (spec-ike-padded-path-probe),
and the test opens the client with `NewNATTTransport("127.0.0.1:0", log)` in one
step with one error check. The check that left the suite guarded the address
resolution that no longer happens. The two `RFC requirement:` claims the test
carries (RFC3948-2.3-2, RFC3948-4-1) are asserted exactly as before: the server
socket reads one octet and it is `0xFF`.

| Test | Reason |
|------|--------|
| TestNATKeepalive | the `t.Fatal` on `net.ResolveUDPAddr` for the client address; the client is now opened by `NewNATTTransport`, whose one error check replaces both setup checks, and every assertion about the keepalive octet on the wire is unchanged |
