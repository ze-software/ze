# Test weakenings this commit accepts

One test loses two directives, and neither of them tested BFD. `test/bfd/
bfd-detection-interval.ci` carried a `bgp` peer block, a `ze-peer` background
command and an `expect=bgp` end-of-rib expectation. None of the three appears in
what the file says it validates: the RFC 5880 detection time and slow-start
transmit interval an operator reads back through `show bfd session address`. The
one assertion that carries that claim, `expect=stderr:contains=OK: bfd session
publishes detection-interval 600ms and tx-interval 1s`, is untouched and still
passes.

The BGP peer was there to make the daemon stoppable, and it was there because
`request shutdown` could not stop a daemon with no BGP reactor during startup.
That is the defect this commit fixes in `cmd/ze/hub/main.go`. With it fixed, the
scaffolding has no job left, and its removal is not a loss of coverage but the
proof of the fix: the file now stops a BFD-only daemon and would time out at 15s
if the reactorless shutdown path broke again. Observed both ways on 2026-09-07,
15.0s timeout before the fix and 6.3s pass after.

The removed `expect=bgp` could not pass in any case. The fixture answers 60ms
after the BFD plugin reports running and then asks the daemon to stop, so the
BGP session never reached Established and never emitted the end-of-rib UPDATE
the peer waited for. It asserted a message this file's own lifecycle makes
unreachable, which is why `./le functional bfd` was 0/1 twice in a row.

| Test | Reason |
|------|--------|
| bfd-detection-interval | The `bgp` config block, the `ze-peer` background command and its `expect=bgp` end-of-rib expectation leave the file. All three were scaffolding for a daemon that could not otherwise be stopped, the expectation was unreachable under this file's lifecycle, and none of them asserted anything about BFD. The claim in the file's own header is unchanged and still asserted by `expect=stderr:contains=OK: bfd session publishes detection-interval 600ms and tx-interval 1s`, plus `expect=exit:code=0`, which now depends on the reactorless `request shutdown` path this commit repairs. |
