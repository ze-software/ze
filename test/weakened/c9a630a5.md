# Test weakenings this commit accepts

The CoPP integration tests are REWRITTEN, not removed. At HEAD both tests
dialed from goroutines, and a network namespace belongs to a thread, so every
dial ran in the host namespace: `TestCoPPOverLimitDropStopsNewConnectionsToTheProtectedPort`
and its accept twin both failed at HEAD ("the control port accepted 0 of 120"),
unseen because no gate named the package. The rewrite puts every socket on the
locked thread and asks the kernel what it accepted, so the assertions can now be
reached at all.

| Test | Reason |
|------|--------|
| TestCoPPOverLimitDropStopsNewConnectionsToTheProtectedPort | Replaced by `TestCoPPOverLimitDropPolicesTheProtectedPortAndNothingElse`, which floods the protected port and a control port from inside the namespace and asserts the accepted count sits inside the token-bucket bounds (burst, then rate over the measured window) while the control port accepts every SYN. The old test could not observe the namespace and failed at HEAD |
| TestCoPPOverLimitAcceptKeepsTheProtectedPortReachable | The assertion moved into `assertAcceptedWhole`, which fails the test unless all 120 SYNs are accepted. The body carries one call rather than an inline compare; nothing it proved left the suite |
| floodPort | Replaced by `offer` and `flood`: non-blocking raw sockets on the locked thread, so the flood reaches the namespace the policy is applied in |
| acceptUntilClosed | Replaced by the raw-socket accept loop in `offer`; the goroutine version ran in the host namespace |
| dialOnce | Replaced by the raw connect in `flood`; the goroutine version ran in the host namespace |
