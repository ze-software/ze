# Test weakenings this commit accepts

One test leaves `internal/component/plugin/server/restart_test.go`, and it
leaves because the behavior it pinned is the defect this commit closes.

`TestRestartPluginRefusesWhenRespawnIsNotEnabled` asserted that
`(*Server).restartPlugin` refuses with `process.ErrRespawnNotEnabled` when the
plugin's `PluginConfig` enables no respawn. That guard read
`PluginConfig.Respawn`, and no producer in the tree ever set it:
`ExtractPluginsFromTree` did not read the `respawn` leaf, so the field was false
for every configured plugin. `restartPlugin`'s only non-test caller is the
config-reload rollback, reached when an ack reports `CodeBroken`, so the path
could never restart anything at all. The test proved that a permanently dead
path stayed dead.

The owner replaced the design on 2026-09-06: the plugin declares whether it may
be restarted, and the rollback restart is an ORDER rather than a policy
question, because the orchestrator has already been told the plugin is broken.
`ProcessManager.Respawn` therefore asks nothing about consent, and
`ErrRespawnNotEnabled` is deleted with the field it read.

The replacement in the same file,
`TestRestartPluginRestartsAPluginThatDeclaredNothing`, drives the same
`restartPlugin` entry point over the same two-plugin startup and asserts the
opposite outcome: the process is replaced, the replacement is configured again,
and its command resolves to the new process. The suite loses no coverage of the
rollback path, and gains the polarity that was unreachable while the guard
stood.

The two table-driven cases the detector counts are the two-element
`[]plugin.PluginConfig` slice the removed test passed to `runPluginPhase`. The
replacement passes the same two entries; the count moved with the function name.

The previous content of this shard explained six l2tp shaper tests, and it was
spent by commit 2be6e0b199, where git keeps it. A shard describes the commit
being prepared, so it is rewritten rather than appended to.
