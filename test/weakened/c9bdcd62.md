# Test weakenings this commit accepts

| Test | Reason |
|------|--------|
| TestFlowSpecConfigToPlugin | Deleted with its file, `internal/component/bgp/config/flowspec_legacy_test.go`, on the owner's ruling of 2026-09-13: delete the legacy flow route reader. The test drives `flowSpecConfigToPlugin`, and that function and its whole chain go in this commit, so the test cannot compile and has nothing left to assert. The chain was UNREACHABLE, which is what earned the ruling: there is no `container flow` anywhere in the BGP YANG, so the legacy block is refused at schema validation as "unknown field in", and `extractFlowSpecRoutes` read `tree.GetContainer("flow")`, a container no valid config can carry. `test/parse/flow-block-rejected.ci` proves that refusal and still passes, because the refusal is the schema's and never the reader's. |
| TestFlowSpecConfigToPluginVPN | Deleted with the same file, on the same ruling and the same grounds. It drove the VPN variant of the same dead function, asserting the RD reaches the NLRI (RFC 8955 Section 8). The behavior it covered is not lost: the native `update { nlri { ipv4/flow-vpn add rd ... } }` form reaches the same flowspec plugin parser through `registry.ConfigRouteParserByFamily`, which is the path an operator can type, and `test/plugin/flowspec-fw-add.ci` drives it end to end. |
