# Test weakenings this commit accepts

Three tests are deleted and one is renamed, and all four are about the SUBJECT
this commit removes: the staged-file guard in the generated commit script. A
test whose subject is deleted goes with it, and each row below names the test
that now carries its property. The package does not lose coverage: the five
assertions that leave `commit_test.go` are the guard's own, and
`internal/le/commit/snapshot_test.go` arrives in the same commit with 25.

The replacements are stronger than what they replace. The guard tests drove a
fragment of shell in isolation and asserted a refusal. The new tests run a
script that `./le commit create` actually wrote, against a repository a second
session moves under them, and assert what reached the commit.

| Test | Reason |
|------|--------|
| TestGeneratedBlockQuotesPathsAndGuardsForeignStaging | RENAMED to `TestGeneratedBlockQuotesPathsAndCommitsFromItsOwnIndex`, same file, same fixture. Every quoting assertion is kept verbatim, including the path with a space and the path with an apostrophe, and `parseShellWords(quotePaths(...))` still round-trips. What changed is the emitted shell it looks for: the guard line and `git add -f` are gone from the script, so they are gone from the expectations, and the private index, the index-info heredoc, the force-remove, the commit and the shared-index repair are asserted in their place. |
| TestStagingGuardRefusesForeignIndexAndAcceptsItsOwn | DELETED with `renderStagingGuard`, the function it called. It asserted that a block refuses when the shared index holds a path the block did not name. That refusal cannot happen now and must not: a block commits from an index of its own, so a peer's staged path is not in the population at all. `TestTheCommitCarriesThePreparedContentAndNotAConcurrentSessionsEdit` (`snapshot_test.go`) asserts the stronger thing over a whole prepared script: the peer's staged path is not in the commit, and it is still staged afterwards. |
| TestRefusedBlockLeavesTheIndexAsItFoundIt | DELETED for the same reason: it ran a block that the guard refused, and there is no guard to refuse it. Its property is that a block which does not reach its commit stages nothing of its own, and `TestABlockLeavesTheSharedIndexAloneWhenItsCommitFails` (`snapshot_test.go`) asserts exactly that, over a failure that can still happen: the message file goes missing, `git commit` exits non-zero, and the shared index and HEAD are unchanged. |
| commit_test | The count falls from 105 to 100 because the five assertions belong to the two deleted tests. No surviving test loses an assertion, and the package gains 25 in `snapshot_test.go`, which is committed here. |
