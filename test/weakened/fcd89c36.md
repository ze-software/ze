# Test weakenings this commit accepts

Two AS-path parsers are deleted in this commit, and their tests go with them.
No case leaves the suite: every case of the deleted table is present, by name,
in the test of the parser that survives.

`attribute.(*Builder).ParseASPath` and `route.parseASPath` were second parsers
of a syntax `attribute.ParseASPathText` already read. The `as-path` command word
reached the first of them, so the AS-number reader this spec fixed had no
product caller at all (`plan/spec-bgp-as-notation.md`, Mistake Log A-3). The
word now calls `ParseASPathText`, and the two copies are gone.

| Test | Reason |
|------|--------|
| TestBuilderParseASPath | Its producer, `attribute.(*Builder).ParseASPath`, is deleted. All six cases moved to `TestParseASPathTextForms` (`internal/core/bgp/attribute/text_test.go`) under the same names: `bracketed_spaces`, `bracketed_commas`, `single`, `empty_brackets`, `invalid_asn`, and `space_separated` restated as `unbracketed_stops_at_one`, because the surviving parser takes the command's argument list and answers how many arguments it consumed |
| builder_parse_test | The assertion count falls 23 to 20 and all three belong to the function above. No other test in the file changed |
| TestParseASPathEmptyString | Renamed to `TestParseASPathMissingValue` and re-pointed at the command entry point, `parseCommonAttributeBuilder`. The assertion is STRONGER: the deleted producer read an empty string as a silent no-op, and a bare `as-path` word with no value is now an error. The property the old test protected, that a refused as-path leaves the existing AS_PATH alone, is asserted unchanged |
