**📅 Ze Weekly Update**

This update covers two weeks. An eBGP session with no policy now accepts and sends nothing, and routing policy moved to one tree shared by every protocol, so please read the changes below before upgrading.

The release queue holds 298 required items and 348 nice-to-have, up from 240 and 273. 71 required items joined, most of them from a sweep for errors the code dropped without a word, and 12 left. The counts compare the two ends of the period, so an item added and finished in between is missed, and they count work items rather than readiness: https://ze-software.net/project/roadmap/

**⚠️ Changes to check**
- BGP: an eBGP peer with no import or export policy now takes no routes and sends none (RFC 8212 Section 3). iBGP is unchanged. Add `filter { import { final accept; } export { final accept; } }` where that is what you want. `ze config validate` and the session both warn with the exact command.
- Policy: `bgp { policy { ... } }` is now a top-level `policy { ... }`, shared by BGP, IS-IS, OSPF, static, connected and the RIB. The old form is refused, and `ze config migrate` rewrites it.
- Policy: a chain no longer names a `prefix-list` or other list directly. Wrap it in a `match` instance, as in `policy { match customers { prefix-list CUSTOMERS; } }`, and use `filters [ customers ]`.
- Redistribution: the `family` and `tag` leaves of a redistribute import, and OSPF's redistribute `metric`, `metric-type` and `tag`, are replaced by filters. `ze config migrate` rewrites both.
- ADD-PATH `limit N;` is now `limit { receive N; }`.
- `ze doctor` through the daemon is `show doctor`. `ze help` is served as `show command catalog` and `show command reference`.

**⚠️ More changes to check**
- RADIUS: every request is now signed with a Message-Authenticator, and an answer without one is dropped (CVE-2024-3596, "BlastRADIUS"). A server that cannot sign needs `require-message-authenticator false`, but upgrading it is the better fix.
- IPsec: only Ze may install per-socket IPsec policies now, enforced by `vpn ipsec application-override deny`, the default. It needs Linux 6.10 and CAP_BPF, and the commit fails without them. In a container, grant CAP_BPF or set `allow`.
- Connection tracking helpers are attached only when listed in `system conntrack module [ ... ]`, which is empty by default (RFC 4787).
- L2TP and PPPoE: `auth-method chap-md5` now allows CHAP only. A subscriber could negotiate down to PAP before. List methods with `authentication { allow [ ... ] }` or `pppoe authentication-allow`.
- DHCP, router advertisements and L2TP pools now hand out the DNS servers learned on the WAN when none are configured. `dns-source { source [ configured ]; }` keeps the old behaviour.

**🔒 Security**
- RADIUS: without the signature, anyone on the path to the RADIUS server could forge an Access-Accept for a system login or a subscriber. Configs without RADIUS were not exposed.
- gNMI returned BGP passwords and RADIUS and TACACS+ keys in clear, and a Set echoed them to every subscriber. They are now sent in `$9$` form. Configs without gNMI were not exposed.
- GTSM peers: SYNs below the TTL floor are now dropped by the firewall before they reach BGP (RFC 5082 Section 3), and `ze doctor` checks the rule is in place.

**🏠 Home router**
Ze can now replace the router on a home FTTP line, with PPPoE carried to the LNS over L2TP. The PPPoE client learns DNS (RFC 1877), runs IPv6 and DHCPv6 prefix delegation, and gains `keepalive` and `reconnect`. LAN interfaces take a /64 from the delegated prefix with `ipv6 delegated-prefix <client>`. It was tested against accel-ppp, xl2tpd and strongSwan, and reports from other access networks are welcome.
- `service dns-resolver` is a caching DNS forwarder for the LAN, with `show dns resolver`. It does not validate DNSSEC yet.
- `show system dns` shows which servers each service uses, and where they came from.

**🛰️ Routing**
New:
- `timer { delay-open N; }` delays the OPEN, for peers that need it alongside BFD.
- PATHS-LIMIT is enforced both ways, with `ze_bgp_paths_limit_refused_total`. Tested against FRR and BIRD.
- `show rib candidates` shows the paths a policy hid, and which chain hid them.
- IS-IS `metric-style narrow|transition|wide`, default wide (RFC 3787 Section 5).
- IKEv2 gains Ed25519 and Ed448 signatures (RFC 8420), and second-round authentication (RFC 4739).

Fixed:
- A policy prepend started a new AS_PATH segment instead of joining the first one (RFC 4271 Section 5.1.2).
- A peer with `asn4 disable` and remote AS 23456 was refused with Bad Peer AS (RFC 6793 Section 4.1).
- RPKI cache failover did not honour `preference` as the 14 September update said. It does now (RFC 8210 Section 8.3).
- The 18 May update announced IKE virtual IP pools, but no address was handed out until now.
- OSPFv3 installed no IPv4 next hop (RFC 5838), and IS-IS point-to-point links with FRR failed unless they were FRR's first.

**📚 Closing the RFC gap**
The number of requirements proven by a test that fails when the code is broken went from 1,844 on 11 October to 2,108 on 25 October and 2,388 today.

These two weeks moved the proofs onto Ze's own system in a virtual machine, where suites that never started now run. A requirement Linux meets on Ze's behalf now has a test of the state Ze installs. A requirement the kernel decides alone is listed apart from the proven ones.

Today 2,239 of the 5,367 MUST requirements written down are covered, up from 1,994 of 4,680: https://ze-software.net/quality/rfc-compliance/
