## Task

`plan/journal/<class>.md` holds one file per problem class and one row per
occurrence. On 2026-10-05 it held 197 class files and 2,133 rows. A class with
10 or more rows is DUE for a fix pass, and DUE counts every row the class has
ever collected. No tool reads the Fix cell, so whether an occurrence is fixed is
free prose. Rows are never deleted: the two fix passes so far (`b6a0de6daa`,
`01a1443c76`, both 2026-09-20) rewrote Fix cells and deliberately kept every row
to keep the first-seen dates. A class therefore stays DUE forever, whatever its
fix pass delivered, and the DUE count (49 classes) cannot tell a class nobody
has touched from one that was captured months ago.

A main-thread audit of 60 fully-fixed classes found 34 with no rule or check
capturing the cause, 12 with a rule only, 8 with a check and 6 with a
structural fix, and about 7 classes recorded as fixed whose Fix prose says they
are still open. The passes so far patched instances; none ended with something
that prevents the next one.

The owner approved this direction (2026-10-05):

| # | Direction |
|---|-----------|
| 1 | Each class gets a lifecycle: a machine-readable declaration of what now prevents it (a named check, or a rule as the weaker fallback) and when that capture landed |
| 2 | Rows are kept: history, first-seen dates and citations survive. Rows dated before the capture stop counting toward DUE, so DUE means "recurred after the class was captured" |
| 3 | The Fix cell carries a machine-readable fixed/open marker the tooling reads. Existing rows are backfilled, the misclassified ones included, and a new row without a marker is refused |
| 4 | A fix pass on a DUE class ends with a check, never with per-row patches. This spec defines what a pass must deliver to set the capture |
| 5 | Near-duplicate classes are merged and mixed classes split, judged by reading rows rather than names, with every citation kept valid. A candidate that does not hold is dropped |
| 6 | No layering: no period where old and new counting coexist |
| 7 | (2026-10-05, answering the open question) A class captured by a CHECK is DUE again after one row dated after the capture: "a single repeat means the check has a gap". A class captured by a rule only, or uncaptured, keeps the threshold of 10. The pass that follows a recurrence after a check capture repairs the check |

Also fixed here: the `DueRowsMin` comment in
`internal/le/spec/journal/report.go` attributes "a class that collects rows
earns its fix in a deliberate pass" to `plan/journal/README.md`. The README
does not say it. The sentence is in `ai/rules/rule-precedence.md` (point
`rule-precedence/directives/close-the-work-first-then-ask-about-the-unrelated-defect`).

Out of scope: running a fix pass on any individual DUE class. This spec builds
the lifecycle and defines the pass; each pass is its own piece of work, run
against the definition in AC-17, or AC-21 when a check-captured class recurs.

**Behavior to preserve:**
- Rows are never deleted; every row's Date, Spec, Surface and Symptom cells stay byte-identical through the backfill (only the Fix cell gains its marker)
- The report reads HEAD only, names worktree-only files as `NOT AT HEAD`, refuses malformed and undated classes, omits singletons, and exits 0 when the only news is DUE
- `HeadSpecEvidence` returns the same stems for the same rows
- The 600-character cap applies to the whole row including the marker, and only to rows added or rewritten against HEAD
- The session-start line text and its stderr fallback

**Behavior to change:**
- DUE counts only rows dated strictly after the class's capture date when the class declares a capture
- The DUE threshold depends on the capture kind: 1 counted row for a check capture, 10 for a rule capture or no capture, each declared once in a kind table that the report text, the JSON, `journalWhy` and the session-start line read
- Every row's Fix cell starts with a fixed/open marker, which the report counts and both readers refuse when absent
- The report shows capture and open counts
- Merge and split the candidate classes that hold after reading their rows
- Correct the `DueRowsMin` comment's attribution

## Data Flow (MANDATORY - see `ai/rules/architecture.md`)

### Entry Point
- `./le spec journal report` (text and `| json`), session start, `./le doc verify` journal stage: class files at git HEAD
- `./le spec journal validate file <path>`, the post-write hook and `./le commit create`: one class file in the working tree, compared with HEAD

### Transformation Path
1. `classFilesAtHead` lists `plan/journal/*.md` at HEAD except the README
2. `readClasses` reads each file; new: the capture line is parsed from the pipe-free lines before the rows are parsed
3. `journalRows` parses rows; new: each row's Fix cell yields its marker (fixed, open, or absent)
4. `appendClass` refuses malformed, undated, unmarked or badly captured classes; new: counted rows are the rows dated strictly after the capture date (every row when uncaptured), and `Due` is counted rows at or above the threshold the kind table gives the class's capture kind (`check`: `DueRowsAfterCheck`, 1; `rule` and uncaptured: `DueRowsMin`, 10)
5. Capture references are resolved against HEAD (report) or the working tree (validate)
6. `Report.Text` and JSON render; `DueCount` feeds the session-start line

### Boundaries Crossed
| Boundary | How | Verified |
|----------|-----|----------|
| le report to git | `git ls-tree HEAD` and one `git cat-file --batch` (existing `headFiles`); capture resolution reuses `headFiles` for the named Go directory's files | No |
| le report to hook runtime | `specjournal.Check` returns `Report`; `DueCount` | No |
| le report to doc-verify | `specjournal.Run` exit code | No |

### Integration Points
- `headFiles` / `classFilesAtHead` - reused to read the Go files a capture reference names at HEAD
- `ai/rules/points/` - a `rule` capture names a point id, the same id `// ze point:` bindings use
- `Problem` - three new kinds join `malformed-row` and `unparseable-date`, so every existing consumer fails closed on them without change

### Architectural Verification
| Check | Holds? | Evidence |
|-------|--------|----------|
| No bypassed layers (data flows through the intended path) | Yes | The capture is read by the same `readClasses` pass every consumer already uses |
| No unintended coupling (components stay isolated) | Yes | Resolution reads files at HEAD; it imports no gate, hook or analyzer package |
| No duplicated functionality (extends existing, does not recreate) | Yes | Extends `appendClass`, `Problem` and `ValidateFile`; no second report |
| Zero-copy preserved where applicable (refs, not copies) | N-A | Offline tooling over markdown |
| Registration over hardcoding, outbound | Yes | The capture is declared in the class's own file; no table of captured classes exists in Go |
| Registration over hardcoding, inbound | Yes | Searched `journalWhy`, `Report.Text`, the `docverify.go` stage table and `lifecycle.go`; none learns a class name. Capture kinds are a closed two-value grammar (`check`, `rule`), not a per-class list, and each kind's threshold is declared once in the kind table every surface reads |

## Risks & Assumptions

### Assumptions
| ID | Assumption | Basis (file/doc/user statement) | If wrong | Validated by | Status |
|----|-----------|--------------------------------|----------|--------------|--------|
| A-1 | No prose line in any class file starts with `Captured:` today | Class headers sampled on 2026-10-05 | A prose line becomes a malformed capture and the report goes red at landing | `git grep -n '^Captured:' plan/journal` returns nothing before Phase 1 lands | unvalidated |
| A-2 | Every row's Fix cell can carry a marker inside the 600-character cap | The cap binds added or rewritten rows; the backfill rewrites every row | Long rows refuse the backfill commit | Count rows over 591 characters before the backfill; shorten only the Fix prose of those, never another cell, and name each in the commit body | unvalidated |
| A-3 | A Go function named by directory and function name is enough to resolve a check of every kind in use (hook verdict, le gate, analyzer run function, Go test) | All four are Go functions in a directory at HEAD | A check that is not a Go function (a `.ci` file, a shell stage) cannot be captured | Survey the checks the existing captures name during Phase 5; if one is a `.ci` test, add a `ci` reference kind resolved as a path at HEAD before landing | unvalidated |
| A-4 | Rows dated on the capture day belong to the pass that set it | Passes write their own rows the same day | A genuine same-day recurrence is not counted, which matters more under a check capture's threshold of 1 | Documented in the README; the pass's proof test, not the row count, catches same-day regressions; a row dated the day after is counted | unvalidated |
| A-5 | The preliminary merge and split verdicts in Design Insights hold | 3 to 12 rows sampled per class on 2026-10-05 | A merge joins two causes one check cannot capture | Phase 4 reads every row of every candidate and records a per-row destination before moving anything | unvalidated |
| A-6 | `plan/spec-knowledge-routing.md` (status design) does not land a conflicting change to the report first | Its AC-6 adds an unrouted-age count to the same report | Text and JSON shapes collide | Check its status before Phase 1; build the text format on whatever landed | unvalidated |

### Risks
| ID | Risk | Early signal | Mitigation / fallback |
|----|------|--------------|----------------------|
| R-1 | A capture line is added to silence DUE without a real check | A capture whose proof test does not fail when the check is removed | The capture names a proof test, which must resolve (AC-5); the pass definition (AC-17) requires its recorded red; review of the capturing commit reads both |
| R-2 | The backfill marks an open row fixed | A `fixed:` row whose prose says "still", "partly", "not yet" | Conservative default: a row is `fixed:` only when its prose says the occurrence was repaired; every ambiguous row is `open:`; the 60 "fixed"-lead rows with open phrases are each read |
| R-3 | A merged or split class leaves a dangling citation | `git grep` for the removed class path returns hits | AC-15 and AC-16 require zero hits; `./le doc check links` covers the markdown corpus |
| R-4 | Capture resolution makes session start slower than its budget | `reportDueJournal` exceeds `sessionStartBudget` | Resolution reads only the directories captured classes name, through the existing single cat-file batch; measured in Phase 1 |
| R-5 | Concurrent sessions append unmarked rows while the backfill is in flight | `./le commit create` refuses their commits after landing | The marker requirement lands in the same commit as the backfill; the refusal names the two markers, so the repair is one word; rows appended between the backfill read and the commit are marked before it runs |
| R-6 | Hook probe fixtures and journal test fixtures turn red | `fixtures.go` probes and `journal_test.go` fixtures lack markers | Updated in the same phase as the reader; they are fixtures of the format, not assertions being weakened |
| R-7 | A report that reads the capture date against the wall clock is not byte-stable | Two runs on different days differ | The future-date check compares against the HEAD commit's committer date, never the clock |
| R-8 | A pass sets a `rule` capture where a check could be built, to get the threshold of 10 instead of 1 | A `rule` capture on a class whose rows name a mechanical shape | AC-17 requires a `rule` capture to state in the commit body why no check can be built; the report shows the kind and its threshold; a pass repairing a check capture may not replace it with a `rule` capture (AC-21) |
| R-9 | AC-18 dates a backfilled check capture at the check's introduction, so a class with a row dated after that day is DUE the moment the backfill lands | The DUE list after Phase 5 holds check-captured classes | Expected: each such row is a recurrence the check missed. The Phase 5 commit body names every such class and its recurring rows, so the repair passes start from that list |

## Blast Radius

| Question | Answer |
|----------|--------|
| What breaks if this is wrong? | Nothing a Ze user sees. A wrong count misdirects fix passes; an over-strict reader refuses journal commits across every session |
| How is it reverted? | The reader change and the backfill are one commit; reverting it restores the old counting and the old rows together |
| Who else touches this path? | Every session that appends a row; `plan/spec-knowledge-routing.md` plans a report change |

## Acceptance Criteria

The capture line and marker grammar the ACs refer to:

| Element | Grammar | Example text |
|---------|---------|--------------|
| Capture line, check kind | A line outside the table starting `Captured:`, then a `YYYY-MM-DD` date, the word `check`, a Go function reference (repo-relative directory, a dot, the function name), the word `proof`, a Go test reference of the same shape | Captured: 2026-10-12 check internal/le/spec/journal.ValidateFile proof internal/le/spec/journal.TestValidateFileAcceptsCanonicalJournalShard |
| Capture line, rule kind | `Captured:`, a date, the word `rule`, a point id under `ai/rules/points/` without `.md` | Captured: 2026-10-12 rule completion/directives/fix-a-defect-that-blocks-your-goal |
| Fix marker | The Fix cell's text starts with `fixed:` or `open:`, then a space and the existing prose | open: not fixed. It blocks no acceptance criterion of this spec. |

| AC ID | Input / Condition | Expected Behavior |
|-------|-------------------|-------------------|
| AC-1 | Class with a check capture dated D, 12 rows dated on or before D and none after | Report shows 0 counted rows and 12 total; `due` false; JSON carries `counted-rows: 0`, `rows: 12`, `due-at: 1`, and a `captured` object with `date`, `kind: check`, `check`, `proof` |
| AC-2 | Same class with one row dated D+1 | `due` true with `counted-rows: 1`; listed among due classes ordered by counted rows, largest first |
| AC-2b | Class with a rule capture dated D, 12 rows on or before D and 9 after; then 10 after | 9 after: `due` false, `due-at: 10`; 10 after: `due` true |
| AC-3 | Class with no capture line, 10 rows | `due` true, `counted-rows` equals `rows`, `due-at: 10`; otherwise identical to today |
| AC-3b | The capture-kind table | Exactly three kinds, `check`, `rule` and uncaptured, each with one threshold: `check` reads `DueRowsAfterCheck` (1), `rule` and uncaptured read `DueRowsMin` (10). `Report.Text`, the JSON `due-at` and `thresholds` fields, `journalWhy` and the session-start line take every threshold from the table; `git grep` over `internal/le/spec/journal/`, `internal/le/hookruntime/lifecycle.go` and the completion point finds no other literal of either threshold outside the two constant declarations and tests |
| AC-4 | A line starting `Captured:` that does not match the grammar (bad date, unknown kind, a check without `proof`, a pipe character, a reference with `..`, an absolute path or a NUL) | Report Problem `capture-malformed` naming the file and the line, exit 1; `ValidateFile` problem of the same kind, so post-write warns and `./le commit create` refuses |
| AC-5 | A capture whose check or proof function is declared in no `.go` file of the named directory, or whose point file does not exist | Report (resolving at HEAD) Problem `capture-unresolved` naming the missing reference, exit 1; `ValidateFile` resolves against the working tree and refuses the same way |
| AC-6 | Two capture lines in one file | Problem `capture-duplicated`, exit 1, in both readers |
| AC-7 | A capture date after the HEAD commit's committer date | Problem `capture-malformed` with the reason "dated after HEAD"; the output for one HEAD is identical on every day |
| AC-8 | Any row whose Fix cell does not start with `fixed: ` or `open: ` | Report Problem `unmarked-fix` with the count and the first three row dates, exit 1; `ValidateFile` problem `unmarked-fix` per line, whether the row is new or held at HEAD |
| AC-9 | Report over a class with 5 `open:` rows | Text carries `5 open`; JSON carries `open: 5` |
| AC-10 | Report text | Captured class: `DUE CLASS: N rows since capture DATE (KIND), T total, O open, Sd span (FIRST .. LAST)`; uncaptured: `DUE CLASS: T rows, O open, Sd span (FIRST .. LAST)`; non-due lines the same without `DUE `; one summary line `N classes captured: C by check, R by rule` after the due-count line when N is non-zero; one threshold line, always printed and built from the kind table, `due at: 1 row since a check capture, 10 rows since a rule capture, 10 rows uncaptured`. JSON carries the same as a top-level `thresholds` object keyed by kind, and `due-at` on every class |
| AC-11 | A captured class with zero rows after its capture and 2+ rows in total | Not due, whatever its kind; still listed with its capture shown |
| AC-21 | A fix pass on a class DUE after a check capture (documented in `plan/journal/README.md` beside AC-17) | The pass repairs the check: (a) every row dated after the capture read; (b) a row whose cause the check is not meant to catch is moved to its own class under AC-16 instead, and the class is then re-judged without it; (c) otherwise the check is extended to refuse the shape it missed, and the proof test reproduces the recurring row, cited by date, going red without the extension, the red recorded in the commit body; (d) the recurring rows marked `fixed:` once the repaired check is green over the tree; (e) the capture line rewritten with the repair date, naming the repaired check and proof. A pass may not replace a check capture with a `rule` capture, and per-row patches without (c) leave the capture date unchanged, so the class stays DUE |
| AC-12 | A class file carrying a capture line and prose | `HeadSpecEvidence` returns the same stems as without the capture line |
| AC-13 | After the backfill commit | Every row at HEAD carries a marker; `./le spec journal report` reports no `unmarked-fix`; for every row, Date, Spec, Surface and Symptom equal HEAD^'s cells, and the Fix cell equals HEAD^'s Fix prose with only the marker prefixed (rows shortened under A-2 named in the commit body); the total row count equals HEAD^'s |
| AC-14 | Rows whose prose states the occurrence is not, or only partly, repaired | Marked `open:`, including each of the 60 rows that open with "fixed" and say "still open", "not fixed", "partly", "not yet" or "unfixed", and every row of the misclassified classes the audit named; a class whose rows are all `fixed:` is one whose prose says every occurrence was repaired |
| AC-15 | Each merge candidate | A verdict (merge or drop) recorded in Design Insights with the row dates read; on merge, every row lands unchanged in the surviving class file, the absorbed file is removed, `git grep` for the absorbed path returns nothing, and each dated-row citation names the surviving file with the same date |
| AC-16 | Each split candidate | A per-row destination recorded in Design Insights; moved rows land unchanged in an existing class or a new class file with a prose header; citations of moved rows repointed; the source class keeps its name and its remaining rows |
| AC-17 | `plan/journal/README.md` after landing | Documents the marker, the capture line, the counting rule, the three new problem kinds, and what a fix pass delivers before it may set a capture: (a) every row of the class read, and the class split first when one check cannot cover it; (b) a check that refuses the class's shape on a path that runs before commit or in `./le verify`; (c) a proof test reproducing at least one historical row, cited by date, that goes red when the check is removed, the red recorded in the commit body; (d) the check green over the tree, so every open occurrence it can see is fixed in the pass and marked `fixed:`; (e) the capture line dated the day the check lands. A pass that cannot build a check sets a `rule` capture naming the point it added or tightened, states in the commit body why no check can be built, and the report shows it as the weaker kind with its threshold of 10. Per-row patches without (b) and (c) set no capture. The README also documents the per-kind thresholds by pointing at the report's threshold line rather than restating the numbers, and the repair pass of AC-21 |
| AC-18 | Classes whose Fix prose names a check or rule that already prevents the cause | The backfill sets a capture only where the named check and a proof test that fails without it both exist at HEAD (check kind), or the named point exists (rule kind); the date is the committer date of the commit that introduced that check or point. A class with a check and no proof test gets no capture. The commit body lists every check-captured class that is DUE at landing with its rows dated after the capture (R-9) |
| AC-19 | `DueRowsMin` comment, `journalWhy`, `ai/INDEX.md` rows 28 and 254, the completion point | The comment cites `ai/rules/rule-precedence.md`; `journalWhy` and both index rows describe counted rows and captures; the point reads that a class is due when the report marks it DUE, a check-captured class on its first row after the capture and any other class at the threshold the report prints, with no number in the point; `./le ai rules render-update` and `./le ai rules condensed-update` regenerate the rendered files |
| AC-20 | `plan/learned/RECURRING-PATTERNS.md` after landing | Its intro states it is frozen history and that the live surface is `plan/journal/` with capture lines; every non-retired `###` entry carries one line naming the class file that holds its occurrences; no entry is deleted |

2. **Phase: Backfill the marker**

   - Rows whose Fix starts with "fixed": `fixed:`, except the 60 that also say "still open", "not fixed", "partly", "not yet" or "unfixed", each read and marked by what it says
   - The other 532 rows: each read; `fixed:` only when the prose says the occurrence was repaired, otherwise `open:`
   - The audit's misclassified classes: every row read and marked by its prose

3. **Phase: One landing** -- Phases 1 and 2 are one commit, so no HEAD carries the new reader without markers or markers without the reader
4. **Phase: Merges and splits** -- read every row of each candidate, record verdicts in Design Insights, move rows, repoint citations

## Key Design Decisions
| Decision | Alternatives Considered | Rationale |
|----------|------------------------|-----------|
| The capture is one line in the class file's header | A separate index file mapping class to capture | The class file is where the fact belongs; an index is a second list of class names that drifts on every merge, split and rename (`ai/rules/principles.md`, declared once). The parser already ignores pipe-free lines, so the header is free for it |
| A check capture names a Go function and a proof test, each as directory plus function name | Reuse `// ze point:` bindings; name a gate by its le verb | Bindings exist only for hook checks; gates, analyzers and tests carry none. A Go function at HEAD is resolvable for all four kinds by reading files the report already knows how to read |
| A check capture requires a proof test | Name the check alone | A check never shown red against a historical row is the `green-that-could-not-have-been-red` class (94 rows); the proof is what separates a capture from a label |
| A rule capture is allowed and shown as the weaker kind | Check only | Owner direction; some classes are judgments no check can make. The report shows the kind so a reader can tell |
| Counted rows are strictly after the capture date; the threshold depends on the capture kind: 1 after a check capture (`DueRowsAfterCheck`), 10 after a rule capture or with none (`DueRowsMin`) | One threshold, `DueRowsMin`, for every kind (the earlier default) | Owner decision 2026-10-05: a single repeat after a check means the check has a gap, so it is due at once; a rule is a judgment, so its class keeps the count threshold |
| A capture-kind table in `report.go` is the one declaration of each kind's threshold; the report prints it as a threshold line and a JSON `thresholds` object, and every class carries `due-at` | Literal numbers in `journalWhy`, the README and the completion point beside the constants | `ai/rules/principles.md`: a fact declared once; the README and the point name the report's line instead of copying the numbers, so changing a threshold is a one-line edit |
| A recurrence after a check capture is repaired by extending the check, with the recurring row as its new proof, and the capture re-dated (AC-21) | Count the recurrence and wait for more; downgrade to a `rule` capture; patch the row | The recurrence is evidence of the gap, so the pass closes the gap at the producer; a downgrade would trade the hair trigger for a weaker capture, and a row patch leaves the gap open |
| The Fix marker is a prefix in the existing Fix cell | A sixth Status column | A sixth cell changes the format every reader parses and every statement of the five-cell rule; a prefix keeps five cells |
| Two marker values, `fixed:` and `open:`; partly fixed is `open:` | A third `partial:` value | A half that is still broken is an open defect; a third value is a place to park it |
| The backfill classifier is a scratch script, never committed | A committed migration command | Keeping it would leave a second reader of unmarked rows after the format forbids them |
| The report shows captured classes inline with counted, total and open counts, plus one summary line | A separate section for captured classes | One sorted list and one DUE rule; the summary line answers "how many are captured" without a second view |
| `RECURRING-PATTERNS.md` is frozen history with a per-entry pointer to its class file | Migrate its entries into class headers and delete it; keep it live beside the journal | Live in two places is two declarations; migrating rewrites 1,272 lines cited by policed paths and Go comments. Freezing keeps every citation and names the live surface |
| Merge criterion is "one check captures both", split criterion "the class's check would miss this row" | Similar names or symptoms | It ties class identity to the lifecycle: a class is the population one capture covers |

## Known Limitations
- A same-day recurrence after a capture is not counted (A-4), even under a check capture's threshold of 1.
- A capture proves a check and a proof test exist; it does not prove the check is wired into a gate. Wiring is a pass deliverable (AC-17 b) checked in the review of the capturing commit.
- No individual DUE class is fixed here; each pass is its own work against AC-17, or AC-21 for a check repair.
