## Data Flow (MANDATORY - see `ai/rules/data-flow-tracing.md`)

### Entry Point
- `make ze-verify` runs the gates; or an author adds a new `internal/core/` file with
  an upward import; or an author adds a same-process-effect call in a nested plugin.

### Transformation Path
1. `dep_audit.py --check` parses package imports (it already builds this graph for the engine gate).
2. New rule: any `internal/core/**` file importing `internal/component/**` or `internal/plugins/**` is a violation unless present in the shrink-only baseline.
3. Stale-entry check: a baselined file that no longer has the upward import fails the gate (baseline must shrink).
4. `plugin_process_boundary.go` derives its scan roots from `plugin_imports.go` (or a shared derivation), then scans as today.
5. `make ze-verify` reports violations naming the file, the imported package, and the rule doc.

### Boundaries Crossed
| Boundary | How | Verified |
|----------|-----|----------|
| core <-> component/plugins import direction | new `dep_audit` direction check + shrink-only baseline | [ ] gate selftest |
| checker <-> generator namespace list | boundary checker derives roots from `plugin_imports.go` | [ ] parity test |
| verify pipeline <-> gate | `make ze-verify` runs the extended `dep_audit` check | [ ] planted-violation fixture |

### Integration Points
- `scripts/dev/dep_audit.py --check` - existing `ze-tier-check` gate; gains the direction check.
- `scripts/checks/plugin_process_boundary.go` + its `_test.go` selftest - gains derived scan roots.
- `scripts/codegen/plugin_imports.go` - the plugin-namespace source of truth the checker reads.
