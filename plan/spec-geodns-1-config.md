## Task

Define the geodns YANG configuration surface and the in-memory model it produces:
daemon settings (bind, zones, nameservers, TTL, SOA, client-IP source mode) plus
the per-source host records. Implement the config parser, the offline verifier,
the CIDR longest-prefix source matcher, and record validation. No listener and no
query handling yet — this spec produces a validated, queryable in-memory config
that spec 2 binds to.

**Behavior to preserve:**
- Record grammar: optional TTL (0..2147483647), optional type (A/AAAA/SRV, case-insensitive), A vs AAAA auto-detected by a `:` in the address, SRV = priority weight port target (uint16 ×3 + domain).
- A host name must end in a configured zone or it is rejected.
- Multiple addresses per A/AAAA host (the reference's space-separated list) → a YANG `leaf-list address`.
- Default TTL applies when a host omits its TTL.

**Behavior to change:**
- Source selection is CIDR longest-prefix, not exact-map + string-prefix. `source` entries map a prefix to a named `host-set`; the reference's `internal` (many prefixes, one shared set) is preserved by pointing several prefixes at the same host-set. `external` is the host-set referenced by `0.0.0.0/0`/`::/0`.
- Host records come from YANG `host-set`s, validated at commit, not from a watched folder.
- A/AAAA `type` is optional and auto-detected per address by `:` (mixed v4/v6 under one name allowed), matching the reference; an explicit `type` constrains the family.
- `listen-address` is a leaf-list (IPv4 AND IPv6, multiple addresses) sharing one `listen-port` and all other settings (zones, host-sets, SOA). Defaults to `127.0.0.1` + `::1`. Replaces the reference's single `listen-host`.
- The SOA serial is generated per `serial-mode`: `auto-epoch` (Unix seconds at commit, default), `auto-datetime` (YYYYMMDDnn), or `fixed` (the `serial` leaf). The wire serial is uint32 (RFC 1035 §3.3.13), so a full `YYYYMMDDHHMMSS` literal does not fit.

## Data Flow (MANDATORY - see `ai/rules/data-flow-tracing.md`)

### Entry Point
- `service geodns { ... }` committed; the config subsystem serialises the `service` root to JSON and calls the plugin verifier/configure callback with it.

### Transformation Path
1. JSON `ConfigSection.Data` → `parseConfig` → `geodnsConfig` struct (daemon fields + `[]hostSet` + `[]sourceEntry`, each source carrying a `host-set` name).
2. `geodnsConfig` → `buildMatcher` → a longest-prefix structure keyed by `netip.Prefix`, each prefix resolving to a named host-set; many prefixes may resolve to one set.
3. Each `hostRecord` → `validateRecord` → typed `dnsRecord` (A/AAAA/SRV) or a named rejection error; each `source.host-set` is checked to reference an existing host-set.
4. `verifyConfig` runs steps 1–3 read-only at commit time and returns the first error (commit aborts) without binding anything.

## Proposed YANG Shape (illustrative)

```yang
container service {
  container geodns {
    leaf enabled { type boolean; default false; }
    leaf-list listen-address { type zt:ip-address; }  // one or more v4 AND v6 addrs; defaults 127.0.0.1 + ::1; same settings/port apply to all
    leaf listen-port { type uint16 { range "1..65535"; } default 5300; }
    leaf default-ttl { type uint32 { range "0..2147483647"; } default 300; }
    leaf client-ip-source {
      type enumeration { enum edns0; enum packet; enum edns0-then-packet; }
      default "edns0-then-packet";
    }
    leaf-list zone { type string; }                  // FQDN-normalised by the verifier
    leaf-list nameserver { type zt:ipv4-address; }    // max-elements 9
    container soa {
      leaf mname   { type string; }                  // primary NS; default derived ns1.<first-zone>
      leaf contact { type string; default "hostmaster"; }
      leaf serial-mode {                             // how the 32-bit SOA serial is produced
        type enumeration {
          enum auto-epoch;                           // max(Unix-seconds, prev+1): strictly increases per commit at ANY rate; fits uint32 to ~2106 (RFC 1982 wrap)
          enum auto-datetime;                        // YYYYMMDDnn (RFC 1912): human-readable; capped at 100 revisions/day by uint32 (4-digit year leaves only 2 counter digits)
          enum fixed;                                // use the `serial` leaf verbatim (e.g. EXA's frozen 2018122500)
        }
        default "auto-epoch";
      }
      leaf serial  { type uint32; }                  // used when serial-mode = fixed
      leaf refresh { type uint32; default 3600; }
      leaf retry   { type uint32; default 600; }
      leaf expire  { type uint32; default 300; }
      leaf minimum { type uint32; default 300; }
    }
    list host-set {                                  // named, reusable record sets
      key "name";
      leaf name { type string; }
      list host {
        key "name";
        leaf name { type string; }
        leaf ttl  { type uint32 { range "0..2147483647"; } }
        leaf type { type enumeration { enum A; enum AAAA; enum SRV; } }  // optional; omit to auto-detect
        leaf-list address { type zt:ip-address; }    // A / AAAA; mixed v4/v6 allowed when type omitted
        container srv { leaf priority; leaf weight; leaf port; leaf target; }
      }
    }
    list source {                                    // prefix -> host-set reference
      key "prefix";
      leaf prefix   { type zt:ip-prefix; }           // 0.0.0.0/0 (::/0) == external default
      leaf host-set { type string; }                 // host-set name; verifyConfig checks it references an existing host-set (ze YANG has no leafref)
    }
  }
}
```

## Design Insights
- Modelling `external` as `0.0.0.0/0` means the resolver never needs a special "default file" branch — the matcher always returns the most specific covering prefix, or nothing (negative answer).

## Key Design Decisions
| Decision | Alternatives Considered | Rationale |
|----------|------------------------|-----------|
| Named `host-set`s + `source.host-set` name (verifier-checked) | inline hosts per source | Preserves reference `internal` sharing (many prefixes, one set); avoids duplication. ze YANG has no leafref, so `verifyConfig` enforces the reference |
| Optional `type`, auto-detect A/AAAA per address | strict per-name single type | Matches reference `recordIP` per-address detection; allows dual-stack names |
| `leaf-list listen-address` (v4 + v6, shared port) | single `listen-host` (reference) | One instance answers on several addresses incl. IPv6 with the same settings; best-effort per-address bind |
| SOA `serial-mode` (auto-epoch default; auto-datetime; fixed) | single literal serial (EXA reference = frozen `2018122500`); full YYYYMMDDHHMMSS; a configurable datetime-counter length | Wire serial is uint32 (RFC 1035 §3.3.13): cannot hold a 14-digit datetime, and YYYYMMDDnn cannot widen past 2 counter digits (4-digit year × 1000 overflows). `auto-epoch` = `max(epoch, prev+1)` strictly increases at any rate — it is the >100/day answer, so no counter-length knob is offered |
| Custom `verifyConfig` for zone-suffix + host-set ref + record consistency | rely on YANG only | YANG cannot express "name ends in a configured zone"; leafref backs the host-set reference |

## Known Limitations
- A name may carry mixed A/AAAA via multiple addresses on one host entry (matches reference); only one host entry per name within a host-set (last wins).
- The SOA serial is uint32 (RFC 1035), so it cannot encode a full `YYYYMMDDHHMMSS`, and `auto-datetime` (YYYYMMDDnn) is intrinsically capped at 100 revisions/day: the `YYYYMMDD` prefix consumes 8 digits, leaving only 2 for the counter before overflow (`20261225 × 1000` exceeds the 4.29e9 ceiling). For >100 changes/day use `auto-epoch`, which sets `max(Unix-seconds, prev+1)` and so strictly increases on every commit at any rate (to ~2106; RFC 1982 arithmetic handles wrap). EXA's reference value `2018122500` is the frozen `fixed` case. No counter-length knob is offered because the decimal-date format cannot exceed 100/day within uint32. geodns serves no AXFR, so a stalled serial is only cosmetic.
