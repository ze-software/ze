# A subscriber waits for an event that only another, optional feature produces

| Date | Spec | Surface | Symptom | Fix |
|------|------|---------|---------|-----|
| 2026-10-30 | bgp-unowned-rfc-rows | reactor_iface.go neighbor-changed; iface OnConfigure monitor start | With no `interface` block no netlink monitor runs, so BGP never re-reads the neighbor table: a third-party router resolved after session up stays unpaired and its routes leave in 16 octets. | fixed: the interface component registers a neighbor table watcher beside the reader in internal/core/network, the netlink backend watches with its own subscription, and the reactor starts the watch from StartWithContext with no bus or interface config; a miss from an unwatched table says so. |
| 2026-10-30 | bgp-unowned-rfc-rows | reactor_iface.go addr-added and addr-removed; iface OnConfigure monitor start | Same shape for addresses: with no `interface` block no monitor emits (interface, addr-added/removed), so BGP never refreshes the connected subnets RFC 2545 Section 3 is judged against, nor starts a listener for an address added after start. | fixed: the netlink backend registers a kernel address watcher in internal/core/network; the reactor watches from start and applies each change. |
| 2026-11-13 | single-owner-lifecycle-5-session-end-locals (walked into) | ddos-flowspec `onDetected`, ddos-detect `characterizeFromFlows` | With `characterize-enable false`, a medium or high detection is never announced: `onDetected` acts at once only on blackhole-fallback at critical, else logs "awaiting characterization" at INFO, and `characterizeFromFlows` returns at once, so the event never comes and nothing is mitigated upstream. `ddos-mitigation.md`'s "falls back to the coarse destination drop" is false for ddos-flowspec | open: verify refusal, coarse announce, or doctor warning |
