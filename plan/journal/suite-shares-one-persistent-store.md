# Suite shares one persistent store

Every functional test in a session resolves the same on-disk store, so a test
that writes state into it changes what every LATER test in the session reads.
The defect presents as an order-dependent failure: the test passes alone, passes
first, and fails after the writer has run. Nothing in the failing test names the
writer, so the reader looks for a code regression in the wrong place.

| Date | Spec | Surface | Symptom | Fix |
|------|------|---------|---------|-----|
| 2026-08-20 | - | functional runner | `setupBinShims` (`internal/test/runner/runner.go`) symlinks `ze` into the session tree so `DefaultConfigDir` resolves `<session>/etc/ze`, and every test in the session therefore opens the SAME `database.zefs`. A test that stores a local auth credential leaves `meta/auth/local/username=admin` in it, and `liveLocalUsers` (`cmd/ze/hub/main.go`) then reports one boot user for every later daemon. `main.go` prefers per-user auth over `ze.api-server.token`, so four `test/reload/mgmt-guard-*` tests that configure a boot token, or no auth at all, met an authenticated REST listener they never asked for. Two of them (`mgmt-guard-reload-auth-rebuild`, `mgmt-guard-reload-unbuilt-transport`) fail only with the polluted store and pass with a fresh one; the other two failed for an unrelated reason. Confirmed by moving the store aside and re-running the four | not fixed: recorded. The fix is a per-test config dir, or a runner step that reseeds the store between tests, and either one is a change to the runner's process model rather than to a test |
| 2026-08-22 | fixit-irr-empty-answer-clears-set | `DefaultConfigDir` (`internal/core/paths/paths.go`) under the functional runner | second instance of the row above, and it corrects that row's mechanism. The shared store is not the session's, it is the DEVELOPER's. `DefaultConfigDir` reads `ze.config.dir` first. Otherwise it runs `EvalSymlinks` over the running binary and hands the result to `ConfigDirFromBinary`, so a `ze` at `<repo>/bin/ze` opens `<repo>/etc/ze/database.zefs`. `setupBinShims` (`internal/test/runner/runner.go`) puts a bare-named symlink on PATH. Its own comment states that the EvalSymlinks sees through it, so the shim isolates the NAME and never the config dir. Measured: `firewall-irr-cold-cache-recovers` asserts an empty prefix cache on its first line. It failed alone in a fresh container while the daemon ran from `/repo/bin`, because earlier runs had left `meta/irr/AS-TEST` in the developer's store. Nothing in the failure names the store, and the store outlives the run | not fixed. The repair is a per-test config dir in the runner's process model, which reaches all 690 functional tests and is not this spec's to make. It is recorded where the reader meets it. A HARNESS NOTE in `test/plugin/firewall-irr-cold-cache-recovers.ci` names the two ways out. Run the daemon from a prefix outside the checkout, or move the store aside. The 12 firewall-irr tests now serialize (see gate-excludes-part-of-its-population). That stops a sibling warming the store mid-run, and does nothing about a previous run |
