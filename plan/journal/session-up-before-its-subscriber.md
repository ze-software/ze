# A session reaches Established before the plugin that subscribes to it

| Date | Spec | Surface | Symptom | Fix |
|------|------|---------|---------|-----|
| 2026-09-07 | rfcgate-2-deferred-nonunit-evidence-backfill | `apiServer.SetShutdownFunc` (`cmd/ze/hub/main.go`) against `handleDaemonShutdown` (`internal/component/plugin/server/system.go`) | The reactor-independent shutdown callback was wired beside the `signal.Notify` that reads its channel, near the end of startup. A plugin can dispatch as soon as it handshakes, which is hundreds of milliseconds earlier, so `request shutdown` from a fast fixture reached a handler whose fallback did not exist yet and got `shutdown not available: no reactor and no shutdown function configured`. A BGP reactor hid it, because the handler's first branch stops a real reactor and never reaches the fallback. So the defect was invisible on every daemon with a `bgp` block and fatal on one without: `test/bfd/bfd-detection-interval.ci` ran to its 15s timeout, and the workaround in the tree was a fake BGP peer whose end-of-rib expectation then made the test red for a second reason. Measured: the fixture answered 60ms after the BFD plugin reported running | fixed: FIXED. `sigCh` is created and `SetShutdownFunc` wired immediately after `pluginserver.NewServer`, so the capability exists before anything can ask for it. `signal.Notify` stays where it was, so the operator's first Ctrl-C during startup is not swallowed; the buffered send needs no receiver yet, because `waitLoop` drains it. The `.ci` carries no `bgp` block now, and its absence is what proves the reactorless path |
| 2026-08-15 | fixit-peer-process-event-filter | `internal/component/bgp/reactor` listeners vs plugin startup | ze binds a dynamic group's listener before its plugins finish starting, so a member that connects in that window has its session-up state event delivered to nobody and nothing replays it. A peer ze DIALS cannot hit this, because `StartPeers` runs from `OnPostStartup` after every plugin tier. It is not the delivery filter: the same event reached an empty subscriber list before this spec | open: recorded, not fixed here. It blocks no goal of this spec: the test puts the member's connection after the observer's ready RPC, which is also what a real IXP member does. For an operator it means a member that reconnects during a ze restart is invisible to bgp-rs until its session bounces |
