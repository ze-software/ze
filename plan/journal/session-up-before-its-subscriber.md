# A session reaches Established before the plugin that subscribes to it

| Date | Spec | Surface | Symptom | Fix |
|------|------|---------|---------|-----|
| 2026-08-15 | fixit-peer-process-event-filter | `internal/component/bgp/reactor` listeners vs plugin startup | ze binds a dynamic group's listener before its plugins finish starting, so a member that connects in that window has its session-up state event delivered to nobody and nothing replays it. Measured while writing `test/plugin/attach-process-dynamic-group.ci`: `dynamic peer created addr=127.0.0.2` at 12:28:29.051, `session established` at .066, the observer's ready RPC at .651, and no state event ever arrived. `onPeerStateChange` (`internal/component/bgp/server/events.go`) asks `PeerScopedProcs` at the instant of the event and delivers to whoever is subscribed then; the peer-up barrier holds the End-of-RIB for barrier plugins, it does not replay the event. A peer ze DIALS cannot hit this, because `StartPeers` runs from `OnPostStartup` after every plugin tier. It is not the delivery filter: the same event reached an empty subscriber list before this spec | recorded, not fixed here. It blocks no goal of this spec: the test puts the member's connection after the observer's ready RPC, which is also what a real IXP member does. For an operator it means a member that reconnects during a ze restart is invisible to bgp-rs until its session bounces |
