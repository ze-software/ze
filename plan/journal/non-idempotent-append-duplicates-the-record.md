# Non-Idempotent Append Duplicates The Record

A writer appends a row without testing whether the file already holds it, so a
second run of the same step records the same fact twice.

| Date | Spec | Surface | Symptom | Fix |
|------|------|---------|---------|-----|
| 2026-08-19 | - | commit_helper.py, verification-debt shard | `record_debt` (`scripts/dev/commit_helper.py`) appends one row per owed gate and never tests whether the shard already carries that row, so a second `create` for the same session, subject and gate writes it again. Measured on commit `d0ddef174`: two `create` runs left four rows in `plan/verification-debt/aabf4645.md` where two were owed. The first run was killed at a 2-minute timeout after it had appended, and `--replace` on the same commit would do the same | not fixed. The two duplicate rows were deleted at owner request; the append is still non-idempotent |
| 2026-08-19 | - | commit_helper.py, verification-debt shard | Second occurrence of the row above, the same day, by the route that row predicted. `create --replace` rewrites the script and appends the debt rows a second time. `record_debt` (`scripts/dev/commit_helper.py`) opens the shard with mode `a` and tests nothing. Commit `2f2eb832b` owes 2 gates and `plan/verification-debt/f8bfdd86.md` holds 4 rows. The inflated count reaches the session-start banner. It also refuses `--push` until each duplicate is cleared, which re-runs one gate twice | fixed for the class, both routes. `record_debt` reads the shard under the lock it already takes and skips a row the shard holds OPEN. A cleared row is spent, so a later commit owing the same gate earns a fresh one. The first sizing of this fix was wrong. It called deduplication large because `open_debt_rows` makes the line position a row's identity. That guard is about clearing rows which already exist, not about appending. The two never met. That docstring also claimed one `create` can render two identical rows. `DEBT_FLAGS` and `debt_owed` make it impossible. The false claim made the duplicates look expected. Three tests in `scripts/dev/commit_helper_test.py`, and the duplicate rows already in `plan/verification-debt/f8bfdd86.md` are untouched |
