| 2026-08-14 | - | ike responder EAP round | `handleResponderEAP` (`internal/component/ike/engine/responder_eap.go`) sets `sa.State = StateDead` when `decryptAndParse` returns an error. A datagram that fails to decrypt therefore kills the IKE SA. Mid-EAP the SA is not yet authenticated. The dispatch path reaches this function for any IKE_AUTH whose Message ID is not the cached one. So a spoofed datagram, built by an off-path attacker from one observed header, stops a live handshake. RFC 7296 Section 2.4 states: "an endpoint MUST NOT conclude that the other endpoint has failed based on any routing information (e.g., ICMP messages) or IKE messages that arrive without cryptographic protection". `RFC7296-2.4-12` MUST adds: "Implementations MUST limit the rate at which they take actions based on unprotected messages". Found in review of spec-fixit-ike-responder-natt-port-float. That fix closes the route through the CACHED message id and leaves this one open | not fixed. AC-3 does not depend on it. The spec's goal is that a retransmission at the cached id is replayed and not reprocessed, and that goal holds. The fix is a state-machine decision about what a responder does with an undecryptable datagram mid-handshake. That is wider than a guard and needs its own tests |
