# Validate accepts what start refuses

A config that `ze config validate` passes is refused when the daemon starts,
because a check lives only on the start path.

| Date | Spec | Surface | Symptom | Fix |
|------|------|---------|---------|-----|
| 2026-10-18 | - (VyOS T6304 comparison) | `system archive` location and timeout (`config/archive/archive.go`) | The scheme check ran only in the manual archive command, so `location "ftp://h/"` committed and later archives failed at runtime; a bad `timeout` became a silent 30s | fixed: both leaves carry `ze:validate` (`config/validators_archive.go`), so validate and commit refuse them; test `cli-config-archive-invalid-refused.ci`, red at HEAD |
| 2026-10-17 | - (L2TP dial-source review) | `l2tp.ExtractParameters` (`internal/component/l2tp/config.go`), called only by `registerBNGSubsystems` (`cmd/ze/hub/register_l2tp.go`) | Read, not run: `ze config validate` never calls it, so `validateRelays` (relay to an undeclared remote) and `validateDialSources` (loopback listener with an off-host remote) refuse at start only | open: register the l2tp checks as config validators |
| 2026-10-22 | spec-exabgp-6-api-compatibility | old-command judge `zeRoutes` (`internal/exabgp/bridge/old_commands_test.go`) against `handleUpdateText` (`internal/component/bgp/plugins/cmd/update/update_text.go`) | The judge runs `update.ParseUpdateText` alone, which accepts `watchdog <name>`; the handler then answers "watchdog not yet implemented for update text". About 95 5.0 lines carrying `watchdog` count as behaving as on 5.0 while the daemon refuses them | fixed: afddd8ffe0; now the bridge gives it to bgp-watchdog (`watchdog give`) |
| 2026-10-26 | - | `Approve` (`internal/le/test/weakened/approve.go`) via `rfc.ApproveInto`, against the commit gate's unit key (`filepath.Base(packageDir)`, `testweakened.go`) | Approve accepts a Go package name (`airules.TestX`; 2026-11-01 `bgpconfig.<unit>` three times) with no warning, as `ValidApprovalUnit` checks only the shape; the gate keys by directory (`rules.`, `config.`), so approvals go unused until a commit refuses | open: refuse at approve time a package no test directory carries, naming the directory spelling |
| 2026-10-27 | spec-network-services-one-off-defects | firewall `validateAction` (`internal/component/firewall/validate.go`) | Jump and Goto check only that the target chain exists, so a self-jump, a jump cycle (kernel ELOOP) or a jump to a base chain (EOPNOTSUPP) passes validate and fails only at the nft Apply | open: refuse all three in validate, naming the chain path |
| 2026-10-28 | spec-pppoe-vpp-dataplane, spec-pppoe-refuse-vpp-backend | PPPoE under `interface backend vpp` (`ze-pppoe-conf.yang`, `pppoe/subsystem.go`) | Read, not run: `pppoe` has no `ze:backend` gate, so `interface backend vpp` plus a `pppoe` block commits, then every session fails at IPCP Opened because the VPP backend's `AddAddressP2P` answers "PPP NCP not supported on VPP backend yet" | open: `spec-pppoe-refuse-vpp-backend` refuses the combination at verify until a VPP session dataplane is registered |
| 2026-11-08 | - | port mirror target (`unitEntry.MirrorIngress` and `MirrorEgress`, `config.go`; `mirrorDestination`, `config_mirror.go`) | `mirror ingress` and `egress` are free YANG strings that verify never checks, so a mistyped or deleted target commits and fails or vanishes only at apply. A target naming a VLAN unit of a mac/match or os-name entry is not translated through its parent's selector: `deviceFor` returns that name unchanged. VyOS T9491 (280cb4837), T6393 | open: refuse an unknown target at verify, and bind a unit target through its parent's binding |
| 2026-11-08 | - | tunnel uniqueness (`parseTunnelEntry`, `config.go`; `parseAndVerifyIfaceSections`, `register.go`) | Two tunnels with the same kernel identity (for gre the tuple local, remote, link and key, compared within one encapsulation, as `ip_tunnel_find` does) pass verify, and the second create fails at apply with EEXIST. No verify step compares tunnel pairs, for any tunnel kind. VyOS encoded the kernel rule in T9193 (1a9181807, b3c4828f5, 4bdf9c3a6) | open: refuse a duplicate kernel tunnel identity at verify |
