# command-takes-an-untyped-positional-value

`ai/rules/cli.md` requires a closed keyword before any user-supplied value. A
free-form value therefore never sits in an untyped positional slot, where it can
collide with a keyword. Peer commands are the one stated exception: a peer is
addressed by name or by address with no selector keyword before it, as in
`show bgp peer 192.0.2.1 detail`.

| Date | Spec | Surface | Symptom | Fix |
|------|------|---------|---------|-----|
| 2026-08-24 | cli-show-bgp-answer-shapes | bgp plugin command grammar | Five `show bgp` commands take a free-form value in an untyped positional slot, and none is a peer command. The stated exception does not reach them. `handleShow` (`internal/component/bgp/plugins/healthcheck/healthcheck.go`) reads `args[0]` as a probe NAME. `aspaCommand` (`internal/component/bgp/plugins/rpki/rpki.go`) reads `args[0]` as a customer ASN. `roaCommand` reads `args[0]` as a prefix. `rpfLookup` (`internal/component/bgp/plugins/rib/rib_commands.go`) reads `args[0]` and `args[1]` as a family and an address. `showIRRCheck` (`internal/component/bgp/plugins/filter_irr/command.go`) reads `args[1]` as a prefix. The correct spellings carry a selector keyword: `show bgp healthcheck name <name>`, `show bgp rpki aspa customer <asn>`, `show bgp rpki roa prefix <prefix>`, `show bgp rib rpf family <family> address <addr>`. Two of them also make the answer change SHAPE with the argument, which is what surfaced them. `show bgp healthcheck` and `show bgp rpki aspa` answer a row set with no argument and one object with one argument, so no declared shape can describe either. `CheckSiblings` and `CheckRootNamespace` (`scripts/checks/cli_grammar.go`) both judge NAMESPACE rather than selector typing, so no gate reads this. Whether a gate deliberately excludes plugin-declared `Args` was NOT checked | not fixed. It blocks no acceptance criterion of the spec that found it. `spec-cli-show-bgp-answer-shapes` and `spec-plugin-declares-answer-shape` make each answer one shape, and a one-shape answer is what a declaration needs whatever the argument spelling. Renaming a shipped command path is a dispatch-key change with backward-compatibility and `.ci` sender obligations of its own (`ai/rules/cli.md`, "Migrating a Built-in Command's Path"). That rename therefore needs its own spec rather than a branch inside one about declarations |
