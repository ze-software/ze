# Per-request state is written into an object every request shares

One instance serves all callers, and each call stores its own input on it before
using it, so concurrent calls race and one caller can act on another's data.

| Date | Spec | Surface | Symptom | Fix |
|------|------|---------|---------|-----|
| 2026-10-30 | route-policy-0-umbrella (found, not caused) | web CLI completion: one shared `cli.Completer` (`cmd/ze/hub/service_web.go`), `completeCLIInput` (`web/cli.go`) | Each request called `SetTree` then `Complete` on the shared completer with no lock, so two users completing at once raced and could be offered names from the other's candidate config | fixed: `Complete` and `GhostText` take the tree per call, `SetTree` and `contract.Completer` deleted, the web completes under `EditorManager.ReadTree`; `TestWebCompletionPerUserTree` (-race), `TestCompleterTreePerCall` |
| 2026-10-30 | config-reference-completion (found, not caused) | `EditorManager.Tree` (`web/editor.go`) and its non-completion web callers | `Tree` returns the session's live tree after releasing the session lock, so a handler walking it can race that same user's concurrent edit from another tab; only completion moved to `ReadTree` | fixed: `051d7bf09d` deletes `EditorManager.Tree` and migrates callers to `ReadTree`/`snapshotTree`; `TestEditorManagerConcurrentReadAndMutation` (-race) and web/hub tests pass. |
| 2026-11-14 | bgp-session-write-wedge (review, found) | `Session.writePathHeldReported` (`bgp/reactor/session.go`), read by `reportUnsentNotification` and `leaveCause` | The record that a close reported a held write path belongs to one connection, and it is kept on the Session and never cleared. On a Session used for a second connection an earlier report would silence a later missed-NOTIFICATION line and one `session-dropped`. Reviewed as unreachable past Established today: a Peer runs one Session per run cycle | open: keep the record on the connection's `socketClaim` |
| 2026-11-19 | ssh-editor-authorization | CLI Editor: Update completion versus dispatched commit | Race tests found Update reading the shared tree while commit and confirmed-commit goroutines replace it. dispatchQueue serializes commands, not Update reads. | fixed: `0d3b9e36c7` fences Update-side editor reads on `m.dispatch.busy()` and queues paste load; `TestModelUpdateFencesEditorDuringDispatchedCommit` and `TestModelFinishPasteModeQueuesBehindDispatchedCommit` pass (-race). |
