# Deferrals: fixit-bgp-per-family-prefix-enforcement

Deferral rows for this source. `/ze-status` folds the aggregate live backlog on
read from `plan/deferrals/`. Nothing stores it (`ai/rules/planning.md`).

Evidence for the 2026-08-04 `done` row (closed 2026-08-07). THREE faults were
stacked behind the one `0`, and the row named only the first.

1. **The verb form resolved nothing, for any verb.** `RunCommand`
   (`cmd/ze/internal/cmdutil/cmdutil.go`) walked the tree from
   `cli.BuildVerbCommandTree`, which is RELATIVE to the verb (`bgp rib status`),
   with the argv the shell gave it, which still carried the verb (`show bgp rib
   status`). Measured on the host: 56 of the 63 `ze show` subcommands answered
   `unknown command`, and `clear`, `monitor`, `request`, `set` and `delete` with
   them. The seven survivors were the ones with a local handler or an offline
   fallback. `ze show help` listed everything because help reads the YANG tree,
   not the dispatch tree. Fixed by aligning the words in `ResolveCommand` and
   rebuilding every absolute form with `cli.AbsoluteVerbPath`
   (`internal/component/cli/client/verb_tree.go`). All 63 resolve.
2. **The interop daemon ran no SSH listener,** so no CLI client could reach it
   whatever the verb (`infraSetup`, `cmd/ze/hub/infra_setup.go`, starts one only
   when the config asks). The harness now appends `ZE_CLI_CONFIG` to every
   rendered `ze.conf` and queries through `ze cli -c`, as
   `test/ipsec-interop/lab.py` already did.
3. **`Ze.rib_count` answered 0 on failure,** which is what made 1 and 2 look
   alike and kept them stacked for three days. It raises now.

Scenarios: `05-routes-from-frr` PASS (3 routes), `06-routes-from-bird` PASS (3),
`13-graceful-restart-frr` PASS (1, after its `frr.conf` was given a prefix to
advertise -- its assertion could not pass on any run before). `35-srv6-frr` and
`19-routes-gobgp` are red for causes that are neither the verb nor the helper,
