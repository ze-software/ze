## Second defect (D-8, found by the race gate): RFC4271-8.2.2-17 collision dump leaked the session
Red first: fp-race.log (TestRFC4271OpenSentCollisionDumpReleasesTheConnection, "the Peer releases the session" never true, intermittent). Producer: Session.CloseWithNotification set no close reason and sent no errChan signal; closeConn nils s.conn, and a Run loop that finds conn nil between two reads takes it as "waiting for Accept" and sleeps until a close reason exists, so the session and the Peer's hold on it outlived the connection forever. FIX (session_connection.go): new sentinel ErrCollisionDump; CloseWithNotification sets it before closeConn and signals errChan (the teardown shape), §8.2.2 quote above. It takes the ordinary reconnect backoff (not ErrTeardown's immediate redial). Green: -race -count=20 on the collision tests (job fp-coll). 8.2.2-17 positive re-recorded after the fix: fp-rec4.log.
