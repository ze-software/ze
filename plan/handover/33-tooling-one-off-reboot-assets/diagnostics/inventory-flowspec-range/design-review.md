# Independent ranged scalar projection review

**Verdict: REWORK the guard-only repair.** A narrow scalar capability proof is sufficient in principle; a complete callback-bearing element summary is not required for this case. It needs one retained range-source proof shared with formal provenance. No evaluator changes or runtime operations ran in this review.

## Why another proof is required

`externalrootfields.go` `projectField` correctly proves the actual receiver type and direct member before reading the value union. Its unconditional collection-element obligation then rejects the builtin `string` member in `Family.String`. The capability question for that closed scalar differs from proving an actual callback stored in an element.

There is also a downstream grounding obligation. `externalbindings.go` `readObject` demands the `String` receiver formal `f`. `externalformals.go` `indexFormalCall` gives it the source `fam`. `externalformalproof.go` `object` gives a nonformal object grounding only for a real zero `ValueSpec` or its indexed definitions. `externalrangestores.go` `indexRangeAssignment` indexes only `=` writes, while parser-created fresh `:=` range bindings are not ordinary walked assignments. Thus a projection-only fix appears to expose an ungrounded `fam`/`f` refusal next. This is a source prediction, not an executed new failure.
