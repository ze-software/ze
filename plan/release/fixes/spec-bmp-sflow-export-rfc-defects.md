## Task

The original D1 defect (every close without a NOTIFICATION reported as BMP Peer Down reason 2 with event 0, reason 4 never sent) landed in `4ef90497c6`, `ecba2d9147`, and `b3dc0806e5`: `sessionCloseFor` derives one close per down, `peerDownFor` sends reason 4 for `rpc.ReasonTCPFailure` and reason 2 carrying the observed RFC 4271 event code for `rpc.ReasonLocalClose`, and `RFC7854-x-10` and `RFC7854-4.9-1` are `enforced`.

Four live BMP residuals remain at HEAD (verified at every producer on 2026-11-26):

| ID | Defect at HEAD | Producer | RFC / Rule text |
|----|----------------|----------|-----------------|
| R-1 | A closing NOTIFICATION PDU reaches BMP only via `BMPPlugin.notifyCache`, populated from `rpc.EventKindNotification` events (`cacheNotificationPDU`). On a bus binding that grants `state` without `notification`, `notifyCache` is empty and `peerDownFor` falls through to reason 2 ("No notification message was sent."), which contradicts the delivered NOTIFICATION. | `internal/component/bgp/plugins/bmp/bmp_events.go::peerDownFor`, `cacheNotificationPDU`; `internal/component/bgp/server/events.go::getStructuredStateEvent`; `internal/component/bgp/reactor/peer_stats.go::closingNotification` | RFC 7854 Section 4.9: "Reason 1: The local system closed the session.  Following the Reason is a BGP PDU containing a BGP NOTIFICATION message that would have been sent to the peer." / "Reason 2: The local system closed the session.  No notification message was sent." / "Reason 3: The remote system closed the session with a notification message.  Following the Reason is a BGP PDU containing the BGP NOTIFICATION message as received from the peer." |
| R-2 | `sessionCloseFor` exempts only `ErrCongestionTeardown` on Event 18 (`EventTCPConnectionFails`). Other local closes Ze initiates with no NOTIFICATION that leave on Event 18 — `ErrWriteBudgetExpired` (OD-3), `errRawOwnership` (`finishRawWrite`), and `context.Canceled` (`StopForRestart` / `Peer.Stop`) — return `rpc.ReasonTCPFailure` to every `state` plugin and BMP Peer Down reason 4 ("The remote system closed the session without a notification message.") to collectors. Meanwhile `ErrWritePathHeld` marks how a socket dropped rather than who closed it, and has no `sessionCloseFor` / BMP coverage. | `internal/component/bgp/reactor/peer_close.go::sessionCloseFor`; `internal/component/bgp/reactor/session_write_budget.go::recordWriteFailure`; `internal/component/bgp/reactor/session_connection.go::reportWritePathHeld` | RFC 7854 Section 4.9 reason 2 (local system closed, no notification) vs reason 4 (remote system closed without notification). |
| R-3 | `handleSenderUpdate` and `handleSenderPrePolicyOut` stream Route Monitoring for any peer with no check that a Peer Up was sent (`bp.peerUps[se.PeerAddress] != nil`), even though `cacheAdjUpdate` and `handleSenderState` (Peer Down) both gate on `peerUps`. On a binding without `open`, the collector receives Route Monitoring for a peer it was never told is up. (Owned journal row `message-for-a-peer-never-announced.md`, 2026-10-13.) | `internal/component/bgp/plugins/bmp/bmp_events.go::handleSenderUpdate`, `handleSenderPrePolicyOut` | RFC 7854 Section 3.3: "It subsequently sends a Peer Up message over the BMP session for each of its monitored BGP peers that is in the Established state.  It follows by sending the contents of its Adj-RIBs-In ... encapsulated in Route Monitoring messages." and "If any BGP peers for which Peer Up messages were sent transition out of the Established state, corresponding Peer Down messages are sent." |
| R-4 | No independent collector interop scenario verifies Peer Down reasons 1, 3, and 4 against `pmacct` `pmbmpd` (`ai/rules/interop-and-goal-validation.md`). | `test/interop/scenarios/bmp-peerdown-reason-pmacct/`, `internal/le/interoplab/bgp/checkers.go`, `names.go` | RFC 7854 Section 4.9 reasons 1, 3, and 4 (and absence of reason 2 on transport loss). |

Goal:
1. Carry the closing NOTIFICATION body bytes and direction from `Session` through `sessionClose` -> `PeerInfo` -> `rpc.StructuredEvent` (and optional hex `data` on JSON/text down state events), remove `BMPPlugin.notifyCache` (`ai/rules/no-layering.md`), and drive `peerDownFor` from the down event alone so bindings without `notification` still produce exact reason 1 / reason 3 PDUs (R-1).
2. Classify all local Event 18 closes (`ErrCongestionTeardown`, `ErrWriteBudgetExpired`, `errRawOwnership`, `context.Canceled`) as `rpc.ReasonLocalClose` (BMP reason 2 with Event 18) in `sessionCloseFor`, keep remote transport drops (including those meeting a held write path) as `rpc.ReasonTCPFailure` (BMP reason 4, no Data), and verify version-error NOTIFICATION (Event 24) and `read body` error exit (Event 18) in unit tests (R-2).
3. Gate `handleSenderUpdate` and `handleSenderPrePolicyOut` on `peerUps` (leaving `handleSenderMirror` ungated so pre-Established OPEN mirroring continues), closing `message-for-a-peer-never-announced.md` (R-3).
4. Add and prove the `bmp-peerdown-reason-pmacct` interop scenario (reasons 1, 3, and 4 decoded by `pmacct`, with red-then-green discrimination) and the `bmp-sender-peer-down-without-notification-grant.ci` functional test (R-4).

**Key insights:**
- `4ef90497c6` and `b3dc0806e5` already carry `CloseFSMEvent` and `CloseNotification` (direction, code, subcode) on `sessionClose` -> `PeerInfo`, and `FSMEvent` onto `rpc.StructuredEvent`. R-1 simply extends that exact same pipeline with the immutable NOTIFICATION body bytes (`CloseNotificationBody`) and direction (`CloseNotificationDirection`) on `StructuredEvent` and deletes `BMPPlugin.notifyCache`.
- Storing the closing NOTIFICATION body on `Session` (`closingNotifBody atomic.Pointer[[]byte]`, immutable clone) rather than on `Peer` guarantees by construction that a NOTIFICATION PDU never outlives its `Session`, matching the guarantee `TestPeerDownDropsTheNotificationWithTheSession` pinned for `notifyCache`.
- `ErrWritePathHeld` describes a socket-close obstacle (another writer held `writeMu`), not who closed the session: a teardown or hold expiry leaves on its own non-18 stop event (`ReasonLocalClose`), a local Event 18 close (`ErrWriteBudgetExpired`, `errRawOwnership`, `context.Canceled`, `ErrCongestionTeardown`) already sets a local `closeReason` (`ReasonLocalClose`), and a peer TCP drop meeting a held write path really was closed by the remote peer (`ReasonTCPFailure` -> BMP reason 4). So `sessionCloseFor` keeps receiving `leave.cause` (not `leaveCause`), and `ErrWritePathHeld` stays an operator diagnostic (`doctor-bgp-write-path-held`) and `sessionDroppedOwed` suppressor.
- `TestSessionCloseForCoversEveryCause` (`peer_close_test.go:153`) explicitly asserts that an unrelated error (`ErrHoldTimerExpired`) on Event 18 still yields `ReasonTCPFailure`; therefore `sessionCloseFor` uses an explicit predicate `isLocalEvent18Cause(cause)` matching only the four intentional Event 18 local causes (`ErrCongestionTeardown`, `ErrWriteBudgetExpired`, `errRawOwnership`, `context.Canceled`), keeping all existing tests green without weakening.
- Several existing unit tests in `internal/component/bgp/plugins/bmp/` call `handleStructuredEvent`/`handleSenderUpdate`/`handleSenderPrePolicyOut` with UPDATE events without calling `recordPeerUpFor` first; gating Route Monitoring on `peerUps` (R-3) requires seeding `peerUps` in those unit fixtures (matching production, where Peer Up precedes UPDATEs). `handleSenderMirror` (Route Mirroring) stays ungated because Section 4.7 mirrors OPENs before Established.

**Behavior to preserve:**
- `peerDownFor` continues to emit reason 5 with no Data for `rpc.ReasonPeerRemoved`, reason 4 with no Data for `rpc.ReasonTCPFailure`, reason 2 with 2-octet `FSMEvent` Data for `rpc.ReasonLocalClose` / `rpc.ReasonAdjRIBInInvalid`, and reason 1 / 3 carrying the complete 19-byte-header + body BGP NOTIFICATION PDU when a NOTIFICATION closed the session.
- A peer never reported up (`peerUps[addr] == nil`) still gets no Peer Down (RFC 7854 Section 3.3, `TestPeerDownIsNotSentForAPeerNeverReportedUp`).
- Loc-RIB Peer Down reason 6 (`bmp_locrib.go`, `bmp-locrib-pmacct`) is untouched.
- Route Mirroring (`handleSenderMirror`) continues to mirror all BGP message types including OPENs and NOTIFICATIONs before or during Established regardless of `peerUps`.
- Graceful Restart retention (`rpc.ReasonForbidsRetention`) is unchanged: both `ReasonTCPFailure` and `ReasonLocalClose` retain routes; `ReasonNotification` and `ReasonAdjRIBInInvalid` forbid retention.
- ExaBGP bridge output (`exabgpDownReason`) is unchanged: both `ReasonTCPFailure` and `ReasonLocalClose` map to `"closing connection"`, and a NOTIFICATION with empty Data writes byte-identical JSON/text on Ze state events.
- `TestSessionCloseForCoversEveryCause` existing rows remain green unchanged.

**Behavior to change:**
- R-1: `Session` captures the delivered/received closing NOTIFICATION body bytes; `sessionClose` -> `PeerInfo` -> `rpc.StructuredEvent` carries `CloseNotificationDirection` and `CloseNotificationBody` (and JSON/text down state events include optional `data` hex when non-empty); `BMPPlugin.notifyCache`, `notifyPDU`, and `cacheNotificationPDU` are deleted; `peerDownFor` reads the closing NOTIFICATION from the down `StructuredEvent` alone (logging a WARN if `ReasonNotification` ever arrives with missing direction/body).
- R-2: `sessionCloseFor` treats Event 18 closes whose recorded cause matches `isLocalEvent18Cause` (`ErrCongestionTeardown`, `ErrWriteBudgetExpired`, `errRawOwnership`, `context.Canceled`) as `rpc.ReasonLocalClose` with Event 18 (BMP reason 2 with `00 12`), while remote drops and held-write-path remote drops remain `rpc.ReasonTCPFailure` (BMP reason 4, no Data).
- R-3: `handleSenderUpdate` and `handleSenderPrePolicyOut` return early without sending Route Monitoring (or populating dedup state) when `bp.peerUps[se.PeerAddress] == nil`.
- R-4: Add `test/interop/scenarios/bmp-peerdown-reason-pmacct/` + checker proving `pmacct` decodes `"reason_type": 1`, `"reason_type": 3`, and `"reason_type": 4` (with `"reason_type": 2` absent), and add `test/plugin/bmp-sender-peer-down-without-notification-grant.ci`.

## Data Flow (MANDATORY - see `ai/rules/architecture.md`)

### Entry Point
- R-1 / R-2: a BGP `Session` leaving Established (sent or received NOTIFICATION, local Event 18 close such as write-budget expiry / congestion / raw-ownership / context cancel, remote TCP drop, or `read body` exit).
- R-3: a received or sent BGP UPDATE delivered to `BMPPlugin.handleStructuredEvent` (`EventKindUpdate` or `EventKindUpdatePrePolicyOut`).
- R-4: FRR + Ze + `pmacct` `pmbmpd` interop scenario `bmp-peerdown-reason-pmacct`, and functional test `bmp-sender-peer-down-without-notification-grant.ci`.

### Transformation Path
1. **Closing NOTIFICATION capture (R-1):**
   - Sent NOTIFICATION: `Session.sendNotificationWithin` / `tryNotificationWithin` (`session_write.go`) builds the NOTIFICATION (`code`, `subcode`, `data`); when `notificationWritten` observes `delivered == true`, it stores an immutable copy of the body (`2 + len(data)` octets: `code`, `subcode`, `data...`) in `s.closingNotifBody` (first-writer-wins atomic pointer on `Session`) before firing `s.onNotifSent`. When `delivered == false`, `s.closingNotifBody` stays nil (matching `notificationExchanged == false` in `4ef90497c6`).
   - Received NOTIFICATION: `Session.handleNotification` (`session_handlers.go`) stores `bytes.Clone(body)` in `s.closingNotifBody` before `s.onNotifRecv` and `s.fsmMessageEvent`, so the slice is independent of the pooled read buffer.
2. **Close derivation (R-2):**
   - `Peer.leaveSession` (`peer_session_end.go`) captures `leave.event`, `leave.notified`, `leave.cause = closeCause(session)`, `leave.notification = p.closingNotification()`, and `leave.notificationBody = session.closingNotificationBody()`.
   - `Peer.sessionDown` runs `closed := leave.close(publication.failed.Load())` -> `sessionCloseFor`.
   - `sessionCloseFor` (`peer_close.go`) checks in order: `notified` -> `ReasonNotification`; `publicationFailed` -> `ReasonAdjRIBInInvalid`; `event != EventTCPConnectionFails` -> `ReasonLocalClose`; `isLocalEvent18Cause(cause)` (`ErrCongestionTeardown`, `ErrWriteBudgetExpired`, `errRawOwnership`, `context.Canceled`) -> `ReasonLocalClose`; otherwise -> `ReasonTCPFailure`. Every return carries `event.Number()` (or `0` when unregistered).
3. **Propagation to plugins (R-1):**
   - `apiStateObserver.OnPeerClosed` (`reactor_api.go`) sets `PeerInfo.CloseFSMEvent`, `PeerInfo.CloseNotification`, and `PeerInfo.CloseNotificationBody`.
   - `getStructuredStateEvent` (`server/events.go`) copies `se.Reason`, `se.FSMEvent`, `se.CloseNotificationDirection` (mapped from `PeerInfo.CloseNotification.Direction`), and `se.CloseNotificationBody` onto `rpc.StructuredEvent`. `PutStructuredEvent` (`pkg/plugin/rpc/bridge.go`) resets `CloseNotificationDirection = DirectionUnspecified` and `CloseNotificationBody = nil`.
   - `format.appendCloseNotificationJSON` and `appendCloseNotificationText` (`format/session_events.go`) keep `"notification":{"direction":...,"code":...,"subcode":...}` / `notification <dir> <code> <subcode>` unchanged when `len(body) <= 2`, and append `,"data":"<hex>"` / ` data <hex>` when `len(body) > 2`.
4. **BMP Peer Down selection (R-1, R-2):**
   - `BMPPlugin.handleStructuredEvent` no longer caches NOTIFICATIONs (`notifyCache`, `notifyPDU`, `cacheNotificationPDU` deleted); the `EventKindNotification` mirror arm (`handleSenderMirror`) stays intact.
   - `clearPeerState` reads `bp.peerUps[se.PeerAddress]` (`cause.reported`), drops peer state, and calls `peerDownFor(se.Reason, se.FSMEvent, se.CloseNotificationDirection, se.CloseNotificationBody)`:
     - `ReasonPeerRemoved` -> reason 5 (`PeerDownDeconfigured`), no Data.
     - `len(body) >= 2` and `dir == DirectionSent` -> reason 1 (`PeerDownLocalNotify`), Data = `bgpPDU(TypeNOTIFICATION, body)`.
     - `len(body) >= 2` and `dir == DirectionReceived` -> reason 3 (`PeerDownRemoteNotify`), Data = `bgpPDU(TypeNOTIFICATION, body)`.
     - `ReasonTCPFailure` -> reason 4 (`PeerDownRemoteNoData`), no Data.
     - Otherwise -> if `reason == ReasonNotification`, log WARN `bmp: peer down reason notification without closing PDU` naming the peer; emit reason 2 (`PeerDownLocalNoNotify`), Data = `fsmEventData(fsmEvent)`.
5. **BMP Route Monitoring Peer Up gate (R-3):**
   - `handleSenderUpdate` and `handleSenderPrePolicyOut` check `bp.peerReportedUp(se.PeerAddress)` (`bp.peerUps[se.PeerAddress] != nil` under `bp.mu.RLock()`). If false, return early before updating `dedupState`, `dedupCount`, or calling `writeRouteMonitoring`. `handleSenderMirror` is NOT gated on `peerUps`.

|-------|-------------------|-------------------|-----------------------------|
| AC-1 (R-1) | Established peer closes via delivered local NOTIFICATION (e.g., Cease 6/2 with shutdown data) or received remote NOTIFICATION (including Unsupported Version Number 2/1 Event 24) on a bus binding granting `state` and `open` WITHOUT `notification` | `rpc.StructuredEvent` carries `ReasonNotification`, `CloseNotificationDirection` (`DirectionSent` / `DirectionReceived`), and exact `CloseNotificationBody`; JSON/text down state events include `notification` with `direction`, `code`, `subcode` (and `data` hex when non-empty); BMP emits Peer Down reason 1 (sent) or reason 3 (received) carrying the full 19-byte-header + body BGP NOTIFICATION PDU | None: a delivered or received closing NOTIFICATION must never degrade to reason 2 on a binding lacking `notification` |
| AC-2 (R-1) | `BMPPlugin` source and runtime state after R-1 | `notifyCache`, `notifyPDU`, and `cacheNotificationPDU` are removed from `bmp.go` and `bmp_events.go`; an isolated `EventKindNotification` event does not alter Peer Down reason selection (while Route Mirroring still mirrors it when `route-mirroring true`); a down event with a PDU followed on the next session by a down event with none emits reason 2 carrying no stale PDU; `PutStructuredEvent` zeroes both new fields | If a synthetic or malformed `ReasonNotification` down event ever arrives without direction/body, BMP logs WARN naming the peer and emits reason 2 (`fsmEventData`) rather than panicking or writing a truncated reason 1/3 PDU |
| AC-3 (R-2, OD-3) | Established peer closes on Event 18 (`TcpConnectionFails`) with no NOTIFICATION because of a local cause: `ErrWriteBudgetExpired` (write blocked past budget), `ErrCongestionTeardown`, `errRawOwnership` (`finishRawWrite`), or `context.Canceled` (`StopForRestart` / `Peer.Stop`) | `sessionCloseFor` returns `rpc.ReasonLocalClose` with RFC 4271 Event 18 (`18`); BMP emits Peer Down reason 2 with Data `00 12`, never reason 4; Graceful Restart retention (`rpc.ReasonForbidsRetention`) stays `false` and ExaBGP bridge still writes `"closing connection"` | None: a close Ze initiated with no NOTIFICATION must never report `tcp-failure` or BMP reason 4 |
| AC-4 (R-2) | Established peer closes on Event 18 due to remote TCP drop (EOF, reset, socket write error, or `read body` exit) with no local close cause — both normally and when a close meets a held write path (`ErrWritePathHeld`) — vs a teardown or hold expiry meeting a held write path | Remote TCP drop (including `read body` exit and remote drop meeting `ErrWritePathHeld`) returns `rpc.ReasonTCPFailure` and BMP Peer Down reason 4 with empty Data; teardown or hold expiry meeting `ErrWritePathHeld` returns `rpc.ReasonLocalClose` with the closer's stop event number (`2`, `8`, `10`, `23`, `31`) and BMP Peer Down reason 2 with that two-octet event code | `ErrWritePathHeld` remains reported to the operator via `doctor-bgp-write-path-held` and suppresses duplicate `session-dropped` (`sessionDroppedOwed`); it never turns a remote transport loss into `ReasonLocalClose` |
| AC-5 (R-3) | `EventKindUpdate` (received or sent) or `EventKindUpdatePrePolicyOut` arrives at `BMPPlugin` for a peer whose Peer Up was never recorded (`peerUps[addr] == nil`, e.g., binding without `open`), compared with a peer in `peerUps` | Zero Route Monitoring messages are emitted and no `dedupState`/`dedupCount` entry is created for the unannounced peer; Route Monitoring continues normally for peers present in `peerUps`, and Route Mirroring (`handleSenderMirror`) continues mirroring OPEN/UPDATE/NOTIFICATION/KEEPALIVE/REFRESH regardless of `peerUps` | Route Mirroring (RFC 7854 Section 4.7) intentionally mirrors pre-Established OPENs and stays ungated by `peerUps` |
| AC-6 (R-4) | Interop scenario `bmp-peerdown-reason-pmacct` running FRR + Ze + `pmacct` `pmbmpd` through three sequential session teardowns (Ze operator teardown, FRR `neighbor shutdown`, FRR `bgpd` kill) | `pmacct` decodes and logs `"reason_type": 1`, `"reason_type": 3`, and `"reason_type": 4`, with `"reason_type": 2` absent; reverting `peerDownFor`'s `ReasonTCPFailure` arm turns the scenario red (`"reason_type": 2` logged instead of `4`) and restoring it turns it green | None: all three reasons must be independently decoded by `pmacct` |
| AC-7 | RFC-tagged BMP tests updated for R-1/R-3 (`TestHandleSenderStatePeerDown`, `TestRFC7854PeerDownCarriesTheDataItsReasonRequires`, and any RFC-tagged UPDATE test gaining `recordPeerUpFor` setup) | Every edited RFC-tagged test carries independent `ze-test-judge` approval (`./le rfc approve`), fresh `./le rfc record` discrimination records, and `./le rfc check` passes with `RFC7854-x-10` and `RFC7854-4.9-1` remaining `enforced` | None: no stale discrimination record or unapproved RFC-tagged test edit may survive |

## Design presentation

### What changes

This spec finishes the four remaining BMP RFC 7854 defects on top of the landed close-reason architecture (`4ef90497c6`, `b3dc0806e5`):
1. The closing NOTIFICATION body bytes and direction now travel from `Session` through `PeerInfo` onto `rpc.StructuredEvent` (and as optional `data` hex on JSON/text down state events), allowing `BMPPlugin` to delete its separate `notifyCache` and emit accurate Peer Down reason 1 / reason 3 PDUs even when a peer binding grants `state` without `notification` (R-1).
2. `sessionCloseFor` classifies all Event 18 local closes Ze initiates without a NOTIFICATION (`ErrCongestionTeardown`, `ErrWriteBudgetExpired` per OD-3, `errRawOwnership`, `context.Canceled`) as `rpc.ReasonLocalClose` (BMP Peer Down reason 2 carrying `00 12`) while keeping remote transport drops — including remote drops that meet a held write path — as `rpc.ReasonTCPFailure` (BMP Peer Down reason 4, no Data), leaving Graceful Restart retention and ExaBGP bridge output unchanged (R-2).
3. `handleSenderUpdate` and `handleSenderPrePolicyOut` gate Route Monitoring on `bp.peerUps[se.PeerAddress]` (matching `cacheAdjUpdate` and Peer Down's `reported` guard), so collectors never receive Route Monitoring for a peer whose Peer Up was never sent, while Route Mirroring stays ungated (R-3).
4. A new `pmacct` interop scenario `bmp-peerdown-reason-pmacct` proves reasons 1, 3, and 4 end to end against FRR and `pmbmpd`, paired with functional test `bmp-sender-peer-down-without-notification-grant.ci` (R-4).

### Before and after

1. **BMP bound with `receive { allow [ state open update ]; }` (no `notification` grant) when Ze tears down a peer with Cease 6/2:**
   - Before: `notifyCache` is empty, so `peerDownFor` writes Peer Down reason 2 ("No notification message was sent.") carrying `00 02` instead of reason 1 carrying the Cease PDU.
   - After: `StructuredEvent` carries `CloseNotificationDirection = DirectionSent` and `CloseNotificationBody = [6, 2, ...]`, `notifyCache` is gone, and `peerDownFor` writes Peer Down reason 1 carrying the exact BGP NOTIFICATION PDU.
2. **Slow peer stops reading until Ze's write budget expires (`ErrWriteBudgetExpired`):**
   - Before: `retireWrite` records `ErrWriteBudgetExpired` and leaves on Event 18; `sessionCloseFor` returns `rpc.ReasonTCPFailure`; BMP writes Peer Down reason 4 ("The remote system closed the session without a notification message.").
   - After: `sessionCloseFor` returns `rpc.ReasonLocalClose` with Event 18; BMP writes Peer Down reason 2 with Data `00 12`; Graceful Restart still retains routes and ExaBGP bridge still writes `"closing connection"`.
3. **BMP bound without `open` (so `recordPeerUp` recorded nothing and no Peer Up was sent) while the peer exchanges UPDATEs:**
   - Before: `handleSenderUpdate` streams Route Monitoring for a peer the collector has never seen a Peer Up for.
   - After: `handleSenderUpdate` and `handleSenderPrePolicyOut` check `peerUps`, suppress Route Monitoring for unannounced peers, and continue streaming normally for every peer in `peerUps`.
4. **Independent collector proof of Peer Down reasons:**
   - Before: Only `bmp-locrib-pmacct` (reason 6) existed in `test/interop/scenarios/`.
   - After: `bmp-peerdown-reason-pmacct` verifies `pmacct` `pmbmpd` decodes `"reason_type": 1` (Ze teardown), `"reason_type": 3` (FRR shutdown), and `"reason_type": 4` (FRR `bgpd` kill), with `"reason_type": 2` absent.

### Alternatives set aside

| Alternative | Why set aside |
|-------------|---------------|
| Keep `BMPPlugin.notifyCache` as a fallback beside `StructuredEvent.CloseNotificationBody` | Violates `ai/rules/no-layering.md` (two sources of truth for the same closing NOTIFICATION PDU) and keeps stale cache risk alive |
| Refuse at commit any `bgp-bmp` binding that lacks `notification` | Requires a BMP-specific validator in config/bus and forces operators who do not want Route Mirroring or separate `notification` events to enable them; carrying the closing PDU on the down event fixes every `state` consumer cleanly |
| Treat `ErrWritePathHeld` itself as `rpc.ReasonLocalClose` inside `sessionCloseFor` | `ErrWritePathHeld` records that `writeMu` was busy when a close arrived, not who initiated the close: when the peer drops TCP while Ze's writer is busy, the peer closed the session and `ReasonTCPFailure` (BMP reason 4) is the true RFC 7854 Section 4.9 answer; local closes already carry either a non-18 stop event or a local `closeReason` |
| Add a new `rpc.ReasonWriteBudget` close reason | Unnecessary public API expansion: `rpc.ReasonLocalClose` already exists, carries the exact semantics BMP (reason 2), GR (retain), and ExaBGP (`closing connection`) need, and operators already see the specific cause via `doctor-bgp-peer-not-reading` and `Plugin.CloseCauseWriteBudget` |
| Gate `handleSenderMirror` (Route Mirroring) on `peerUps` too | RFC 7854 Section 4.7 Route Mirroring mirrors verbatim BGP messages including pre-Established OPENs, which arrive before `recordPeerUp` runs |

## Design Insights
- Separating the sFlow D2 work into `plan/release/fixes/spec-sflow-export-rfc-defects.md` keeps each spec scoped to one subsystem family while keeping the existing BMP spec filename intact for all incoming citations.

| Decision | Alternatives Considered | Rationale |
