## Task

Validation-triggered single-path replay (`ribevents.RelayReplayPath` calling
`adj_rib_in.replayPathCommand`, followed by `RelayStoredRoute`) reads one named
source path from `bgp-adj-rib-in` and separately relays its answer to a
destination peer. Even with bound destination replay (`RelayStoredRouteBound`)
and cold source catch-up (`coldBoundRelaySource`) landed on HEAD, the two-RPC
sequence remains uncoordinated across the query-to-write window:

1. **Same-source replacement/withdrawal race:** a newer live UPDATE (announcement,
   unheld withdrawal, or End-of-RIB retirement) from the same source can arrive
   while `replay-path` is in flight or delayed. An absent-path withdrawal carries
   `MsgID: 0` and `SourceReceipt: 0`, which `retireOriginalStoredRoute` refuses,
   while an ordinary forwarded withdrawal in `adjOutWrite.allow` ignores `MsgID`.
   A delayed old announcement or withdrawal is not fenced by a per-query ticket
   invalidated at the receive publication frontier.
2. **Intervening destination takeover / selected winner / absence ABA:** a
   foreign peer takeover, local origination, validation withdrawal, `adjOutSelected`
   winner, or full `absent → announce → withdraw → absent` cycle can occur on the
   destination key with no new source UPDATE while the query response is held.
   Inspecting only the final `adjOut.routes[key]` slot cannot detect an absence
   ABA cycle.
3. **RS live source-worker blocking:** `bgp-rs` (`server_validation.go`,
   `validationChanged` and `replayValidation`) still executes single-path replay
   synchronously on its live per-source forwarding worker (`rs.workers`),
   stalling live UPDATE forwarding for that source whenever a validation replay
   waits on the receive store or destination FIFO, whereas `bgp-rr`
   (`rr/validation.go`) already uses a dedicated coalescing joined validation
   worker.
4. **Receive-store terminal/denied truthfulness:** `adj_rib_in.replayPathCommand`
   does not check `r.terminal != nil` (unlike `routeEligible` and
   `eligibilityProgress`), and strips `stored.MsgID` to zero on retained
   `ImportFiltered` or `sourcePolicyDeniedLocked` withdrawals, making retained
   denials indistinguishable from genuinely absent paths.

Goal: coordinate single-path replay end-to-end inside one authenticated,
cancellable engine operation (`ze-plugin-engine:replay-path`) served identically
over DirectBridge and forked RPC, backed by short-lived per-query
source/destination tickets (bounded to `0..1` active cold query per calling
process), frontier invalidation on live inbound UPDATEs and EOR, sticky
destination-key invalidation through final `writeMu` + `adjOut.mu` admission,
exact-identity ticket cleanup, truthful explicit outcomes (`applied`,
`superseded`, `refused`, `canceled`), and a dedicated coalescing joined
validation worker in `bgp-rs`.

**Key insights:**
- Bound destination flush (`RelayStoredRouteBound`, `boundForwardStage`), cold source catch-up (`coldBoundRelaySource`), and `Process.DrainEventsApplied` already exist on HEAD and are extended rather than rebuilt.
- Putting the ticket lifecycle inside one engine-side `ze-plugin-engine:replay-path` operation eliminates cross-RPC ticket leaks on plugin crash, guarantees DirectBridge and forked RPC parity, and lets the engine sample `Peer.receiveCut()` and run `drainReceiveStore` directly without exposing reactor internals to plugins.
- Sticky invalidation on `adjRIBOut` per destination key is strictly necessary to defeat absence ABA (`absent → announce → withdraw → absent`), because final slot state alone looks identical before and after the cycle.

## Current Behavior (MANDATORY)

- [ ] `internal/component/bgp/plugins/adj_rib_in/rib_replay_path.go` (`replayPathCommand`) - reads one `(source, owner, connectionID, family, prefix, pathID)` path from `pending` or `ribIn`; does not fail closed when `r.terminal != nil`; zeroes `MsgID` on `ImportFiltered` / `sourcePolicyDeniedLocked` withdrawals as well as genuinely absent paths.

- [ ] `internal/component/plugin/server/dispatch_registry.go` (`engineOps`) & `internal/component/plugin/server/dispatch_cached_bound.go` (`relayStoredRouteRequest`, `cachedWriteOwner`) & `internal/core/ipc/yang/ze-plugin-engine.yang` - single registry wiring JSON, Direct, and typed DirectBridge engine ops with `BusMessage` authorization and `cancellationScope`.

**Behavior to preserve:**
- Normal live forwarding FIFO order, zero-copy wire forwarding, and native RS pending gates (`fwdPool.dispatchOverflow` / `tryDispatchBound`).
- Unrelated destination traffic and cold recovery (`recoveryWorker`) progress while any single-path replay query is paused.
- Existing `request bgp adj-rib-in replay-path` 7-argument CLI grammar and `ReplayPage` JSON structure, existing `ze-plugin-engine:relay-stored-route` wire contract for peer-up and FlowSpec replay, and existing `bgp-rr` coalescing validation settlement semantics.
- Lock ordering (`aigp.dispatch` before `validationForwardMu`; `writeMu` before `adjOut.mu`) and zero locks held across IPC, event drain, or export execution.
- Lossless engine-to-plugin event delivery (`process-protocol.md` decision of 2026-11-25) and per-op `BusMessage` authorization (`process-protocol.md` decision of 2026-11-23).

**Behavior to change:**
- Add one coordinated, cancellable engine RPC (`ze-plugin-engine:replay-path`, DirectBridge + forked RPC) that registers a short-lived source/destination ticket (bounded to `0..1` active cold query per authenticated calling process) before sampling `receiveCut()` and draining the captured receive store, invalidates matching tickets at the inbound UPDATE/EOR frontier and stickily on any intervening same-key destination `adjRIBOut` decision, admits prepared output through ordinary eligibility/export/ownership machinery without blocking `fwdPool` workers, unregisters by exact ticket identity after releasing locks, and returns explicit `applied` / `superseded` / `refused` / `canceled` outcomes.
- Move `bgp-rs` unicast single-path validation replay off its live per-source forwarding workers onto a dedicated coalescing joined validation worker (mirroring `bgp-rr`), joined by `source_policy.go` (`settleSource`), `retained_settlement.go` (`settleRetainedEvents`), and shutdown, while keeping FlowSpec `parkValidation` (`rs/server_validation.go:90-175`) on `rs.workers` so FlowSpec rules remain ordered behind per-source `batch.processed` unicast UPDATEs; switch both `bgp-rs` and `bgp-rr` unicast single-path validation replay to `Plugin.ReplayPath`.
- Make `adj_rib_in.replayPathCommand` fail closed when `r.terminal != nil` and preserve `stored.MsgID` on retained `ImportFiltered` / `sourcePolicyDeniedLocked` withdrawals while leaving `MsgID: 0` strictly for genuinely absent paths.

## Data Flow (MANDATORY - see `ai/rules/architecture.md`)

### Entry Point
- `bgp-rib/validation-change` event delivered to `bgp-rs` (`rs.validationChanged`) or `bgp-rr` (`rr.validationChanged`).
- Coalesced `ribevents.ValidationRoute` keys are picked up by the plugin's dedicated joined validation worker (`rs/validation_worker.go` or `rr/validation.go`), which calls `sdk.Plugin.ReplayPath(ctx, rpc.ReplayPathInput)` over DirectBridge (internal) or `#<id> ze-plugin-engine:replay-path <json>` (forked RPC).

### Transformation Path
1. **Authenticate and admit (`dispatch_replay_path.go`, `engineOps`):** validate `ReplayPathInput` (non-zero `DestinationOwner`, `DestinationSession`, `SourceOwner`, `SourceConnectionID`, valid `Destination`/`Source` IPs, simple prefix `Family`/`Prefix`, positive finite `DeadlineMS`), check `proc.RequirePeerDeclarations()`, check `checkEngineOpBusSend(s, proc, busMsgBGPUpdate)`, capture `plugin.SelectedOwner` via `cachedWriteOwner`, and hand off to `reactor.ReplayPath`.
2. **Register short-lived ticket before cut (`replay_path_ticket.go`):** enforce the `0..1` active cold single-path query bound per authenticated calling process incarnation (returning explicit `refused` busy outcome if already active); resolve the exact source peer/session `(SourceOwner, SourceConnectionID)` and exact destination peer/session `(DestinationOwner, DestinationSession)` (returning `refused` if retired or mismatched); compute the destination `adjOutKey` (`fwdPathKey` for family + prefix + destination ADD-PATH mode); register the ticket on the reactor's caller map, the source peer's ticket list under `source.replayTicketMu`, and the destination `adjRIBOut.replayTickets[key]` under `dest.adjOut.mu`; sample `cut := source.receiveCut()` and capture the exact receive-store `*process.Process` registered for `request bgp adj-rib-in replay-path`; release all locks immediately.
3. **Inbound frontier invalidation (`reactor_notify.go`, `peer.go`):** every original received UPDATE on a peer advances `peer.acceptedReceive(messageID)` BEFORE acquiring `peer.replayTicketMu` to invalidate matching active source tickets (before import policy, projection, selection, or forwarding). This covers announcements, unheld withdrawals, EOR retirement (`IsEOR` for the ticket's family), and session generation change / peer teardown.
4. **Lock-free cut wait, store drain, and query (`replay_path_ticket.go`, `rib_replay_path.go`):** holding NO reactor, session, or `adjOut` locks, wait on `cut.wait(ctx)`, call `drainReceiveStore(ctx, capturedStore)` (`capturedStore.Process.DrainEventsApplied(ctx)`), verify the captured store process is unchanged and running (refusing if reconnected or stopped), and dispatch `request bgp adj-rib-in replay-path` to that exact captured store process. `replayPathCommand` fails closed on `r.terminal != nil`, returns retained `StoredRoute` with its original `MsgID` (including retained `ImportFiltered` / `sourcePolicyDeniedLocked` withdrawals), or an absent-path withdrawal (`Withdraw: true`, `MsgID: 0`).
5. **Prepare and verify source ticket before destination FIFO enqueue (`replay_path_ticket.go`, `relay_bound.go`):** prepare the answered `StoredRoute` through the ordinary eligibility/export/ownership machinery (`forwardUpdateCore` / `boundForwardStage`, preserving `aigp.dispatch` before `validationForwardMu` and holding no locks across export IPC). Under `source.replayTicketMu`, verify `!ticket.sourceInvalidated` and that source/caller/destination remain current; if invalidated, release staged items and return `superseded`. Enqueue the bound target write onto the destination's existing FIFO (`fwdPool.dispatchOverflow` / `tryDispatchBound`) with NO blocking placeholder on the forward worker so unrelated traffic and cold recovery progress freely.
6. **Final write admission under sticky destination ticket (`session_ownership.go`, `adj_rib_out.go`, `relay_bound.go`, `relay_retire_original.go`):** any intervening decision touching `adjOut` for that destination key (live forwarded announcement/withdrawal, foreign/local takeover, validation withdrawal, `adjOutSelected` write/retirement, `recoveryAdmission` write/withdrawal, or `adjOut.clearRoutes()` on session reset) stickily sets `destInvalidated = true` on every active destination ticket for that key — defeating announce/withdraw/absence ABA. When the bound target write reaches final admission under `writeMu` then `adjOut.mu`, it checks `ticket.sourceInvalidated`, `ticket.destInvalidated`, and `stage.current`: if invalidated, it writes nothing and reports `superseded`; if valid and absent-path withdrawal (`Withdraw: true`, `MsgID: 0`), it retires only an existing slot owned by exact `(SourceOwner, SourceConnectionID, PathID)` (sparing foreign, local, and `adjOutSelected` slots); if valid and announcement or retained-denied withdrawal, it writes through `writeSelectedItem` and flushes.
7. **Exact-identity cleanup and explicit completion receipt (`replay_path_ticket.go`, `dispatch_replay_path.go`):** on every exit path (defer after all locks are released), unregister the ticket from the caller map, source peer list, and destination `adjOut.replayTickets` strictly by exact ticket identity (`existing == ticket`) so stale cleanup never removes a successor ticket. Return `ReplayPathOutput{Completed: true, DeadlineMS: input.DeadlineMS, Outcome: applied|superseded|refused|canceled, Reason: ...}`.

## Acceptance Criteria

| AC ID | Input / Condition | Expected Behavior | Permitted Survivors and Why |
|-------|-------------------|-------------------|-----------------------------|
| AC-1 | Delayed old announcement or missing-path answer from `replayPathCommand` is released after a newer same-source replacement UPDATE, unheld withdrawal, or EOR retirement crossed `acceptedReceive` | The reactor invalidates the active source ticket at the inbound frontier, rejects the delayed replay with explicit `superseded` outcome, and preserves the destination's newer live route or withdrawn state intact | Only the newer live UPDATE's state (or post-EOR withdrawn state) survives on the destination peer, because it is causally later than the replay cut |
| AC-2 | Foreign peer announcement or local origination takes over the destination key while a single-path replay query/response is paused | Sticky destination-ticket invalidation fires on the takeover write under `writeMu` + `adjOut.mu`; when the delayed replay reaches admission it emits nothing, returns explicit `superseded`, and leaves the foreign or local winner's bytes and `adjOut` ownership untouched | The foreign or local winner survives intact with its original `adjOut` ownership and revision, because it won after the replay ticket was registered |
| AC-3 | Validation withdrawal or another `adjOutSelected` winner updates the destination key with no new source UPDATE while the single-path replay response is held | Sticky destination-ticket invalidation fires on the intervening decision; the delayed replay writes nothing, returns explicit `superseded`, and leaves the validation withdrawal or selected winner in effect | The validation withdrawal or newer `adjOutSelected` winner survives untouched, because the delayed query observed a pre-decision snapshot |
| AC-4 | Destination key undergoes a full absence ABA cycle (`absent → announce → withdraw → absent`) while a single-path replay query is paused | Sticky invalidation latched during the intervening announce/withdraw cycle rejects the delayed old announcement at final admission with explicit `superseded`, leaving the destination key absent | None: the key remains absent on the destination peer because the intervening cycle already decided its final state |
| AC-5 | Single-path replay query is paused at the receive store (both in `bgp-rs` coalescing validation worker and in `reactor.ReplayPath`) | Unrelated destination traffic, live source UPDATE forwarding on `bgp-rs`, and destination cold recovery (`recoveryWorker`) all complete promptly without waiting on the paused query, because no forward-worker placeholder or live-worker block is held | The paused query itself remains bounded by its own finite deadline while all unrelated traffic and recovery proceed normally |
| AC-6 | Caller cancels context / hits deadline, source or destination peer retires/reconnects, receive store disconnects/reconnects or is `r.terminal != nil`, or same calling process submits a 2nd concurrent cold query | The engine returns explicit `canceled` or `refused` outcome (busy refusal for a 2nd concurrent query), performs zero late writes to `adjOut` or the wire, and unregisters only the exact ticket identity so zero stale tickets remain and any successor ticket for the same key is undisturbed | A valid earlier active ticket survives a rejected 2nd concurrent busy request from the same process, and a newly registered successor ticket survives stale cleanup of an older ticket |
| AC-7 | The same single-path replay ordering, drain, delayed answer, cancellation, and busy-refusal scenarios run over both DirectBridge (internal plugin) and forked subprocess TLS RPC | Both transports execute the single `replayPathRequest` evaluator and produce identical `ReplayPathOutput` outcomes (`applied`, `superseded`, `refused`, `canceled`), wire output, and `adjOut` state | None: transport-specific behavioral divergence is forbidden |

## Design presentation

### What changes

Single-path validation replay in `bgp-rs` and `bgp-rr` moves from two uncoordinated calls (`request bgp adj-rib-in replay-path` followed by `relay-stored-route`) to one coordinated, cancellable engine RPC (`ze-plugin-engine:replay-path`) served identically over DirectBridge and forked TLS RPC. Before reading the receive store, the reactor registers a short-lived source/destination ticket (at most one active cold query per calling process), invalidates matching tickets at the inbound UPDATE/EOR publication frontier and stickily on any intervening same-key destination `adjRIBOut` write or decision (including `absent → announce → withdraw → absent` ABA cycles), prepares output through the ordinary export/ownership pipeline without blocking forward workers, unregisters only by exact ticket identity, and returns explicit `applied`, `superseded`, `refused`, or `canceled` outcomes. `bgp-rs` moves validation replay off its live per-source forwarding workers onto a dedicated coalescing joined validation worker (matching `bgp-rr`), and `bgp-adj-rib-in` fails closed on a terminal store while preserving original `MsgID` on retained policy-denied withdrawals.

### Before and after

1. **Delayed single-path replay after newer live UPDATE or withdrawal:**
   - Before: `bgp-rs` or `bgp-rr` calls `replay-path` then separately calls `relay-stored-route`; a delayed response carrying an older announcement or a missing-path `MsgID: 0` withdrawal can arrive after a newer live replacement, foreign takeover, or absence ABA cycle, causing stale overwrite, refusal of missing-path retirement, or route resurrection.
   - After: `bgp-rs` and `bgp-rr` call `ze-plugin-engine:replay-path`; any newer same-source UPDATE/EOR invalidates the source ticket at `acceptedReceive` and any intervening destination decision or absence ABA cycle stickily invalidates the destination ticket under `writeMu` + `adjOut.mu`, returning `{"completed":true,"deadline-ms":...,"outcome":"superseded"}` with zero wire writes.
2. **RS validation replay under store or destination pause:**
   - Before: `rs.validationChanged` dispatches all validation work onto the live per-source worker (`rs.workers`), stalling live UPDATE forwarding for that source peer whenever `replay-path` or `relay-stored-route` waits.
   - After: `rs.validationChanged` coalesces unicast validation keys into `rs/validation_worker.go` off both the SDK callback loop and `rs.workers` (while FlowSpec `parkValidation` in `rs/server_validation.go:90-175` stays on `rs.workers` to preserve per-source `batch.processed` ordering); live UPDATE forwarding, unrelated destination traffic, and `recoveryWorker` progress without blocking, while both `rs.settleSource` and `rs.settleRetainedEvents` join the validation worker cleanly during source-policy phases and retained cleanup.
3. **Receive-store terminal failure and retained-denied `replay-path` answers:**
   - Before: `adj_rib_in.replayPathCommand` ignores `r.terminal != nil` and returns `MsgID: 0` for both retained `ImportFiltered`/`sourcePolicyDeniedLocked` paths and genuinely absent paths.
   - After: `replayPathCommand` fails closed with `statusError` when `r.terminal != nil` (resulting in explicit `refused` from `ze-plugin-engine:replay-path`) and preserves `stored.MsgID` on retained denied withdrawals so only genuinely absent paths carry `MsgID: 0`.

### Alternatives set aside

| Alternative | Why set aside |
|-------------|---------------|
| Client-managed ticket IDs spanning two separate RPCs (`replay-path` then `relay-stored-route`) | Leaks active tickets if a forked plugin crashes or disconnects between calls, exposes engine-internal `receiveCut()`/`DrainEventsApplied` choreography across the protocol boundary, and complicates `0..1` per-process enforcement |
| Relying on `adjOut.routes[key]` slot comparison alone at final write admission | Cannot detect absence ABA (`absent → announce → withdraw → absent`), where the slot is empty both before and after the intervening cycle |
| Holding a placeholder item on `fwdPool` destination workers during the receive-store query | Violates AC-5 by head-of-line blocking unrelated destination traffic and `recoveryWorker` cold recovery whenever a single-path query pauses |
| Keeping `bgp-rs` validation replay on live per-source workers (`rs.workers`) | Stalls live UPDATE forwarding for the source peer during cold store drain/query and risks SDK callback backpressure under forked RPC |
| Allowing unticketed `MsgID == 0` withdrawals in `retireOriginalStoredRoute` | Weakens the existing `update-building.md` invariant ("Message zero is not withdrawal authority") for ordinary callers; gating absent-path retirement strictly on a valid active `replayPathTicket` preserves the existing invariant while solving missing-path replay |

## Design Insights
- Bound destination flush (`RelayStoredRouteBound` / `boundForwardStage`), `receivePublicationCut`, and `Process.DrainEventsApplied` are already present on HEAD; coordinating single-path replay inside one `ze-plugin-engine:replay-path` operation reuses all three without duplicating transport or ownership machinery.
- Checking `r.terminal != nil` in `adj_rib_in/rib_replay_path.go` closes a latent fail-open gap where a fenced receive store could answer `statusDone` with a stale or absent withdrawal instead of failing closed.

## Key Design Decisions
| Decision | Alternatives Considered | Rationale |
|----------|------------------------|-----------|
| Single coordinated `ze-plugin-engine:replay-path` RPC executing steps 1–6 in the engine | Two-step client RPCs (`replay-path` + `relay-stored-route`) with client-held ticket IDs | Keeps ticket lifecycle inside engine memory (no crash leaks), enforces DirectBridge/forked RPC parity in one `engineOps` evaluator, and accesses `receiveCut()` + `drainReceiveStore` directly |
| Sticky per-key destination invalidation on `adjRIBOut` | Comparing final `adjOut.routes[key]` slot state at write admission | Final slot comparison misses `absent → announce → withdraw → absent` ABA cycles; sticky invalidation on any intervening same-key decision defeats ABA with O(1) cost when active tickets exist |
| Atomic active-ticket fast-path check on `Peer` and `adjRIBOut` | Unconditional mutex acquisition on every inbound UPDATE and outbound write | Keeps the common hot forwarding path zero-alloc and lock-free when no cold single-path replay is active |
| Dedicated coalescing joined validation worker in `bgp-rs` mirroring `bgp-rr` | Keeping `replayValidation` on live per-source forwarding workers (`rs.workers`) | Prevents cold store/destination waits from stalling live source UPDATE forwarding and keeps SDK callbacks non-blocking |
| Ticket-gated absent-path (`MsgID: 0`) retirement for exact `(SourceOwner, SourceConnectionID, PathID)` | Allowing unticketed `MsgID == 0` in `retireOriginalStoredRoute` | Preserves the `update-building.md` invariant for unticketed callers while safely retiring unchanged slots when an active uninvalidated ticket proves no intervening source or destination change occurred |

## Known Limitations
- Scoped to simple prefix families served by `adj_rib_in.replayPathCommand` (`ipv4/unicast`, `ipv4/multicast`, `ipv6/unicast`, `ipv6/multicast`). Non-simple-prefix families (VPN/labeled `ValidationChange` consumer support) remain tracked in the existing open row of `plan/journal/parser-refuses-a-form-its-producer-emits.md` (2026-10-29).
- FlowSpec validation replay continues to read from mandatory `bgp-rib` (`LookupFlowSpecPath`) and relay via `RelayStoredRouteBound`.
