| Field | Value |

| Release reason | Incorrect shipped behavior in routing: `fib-kernel` (and `fib-vpp`) had two competing IP-table writers (`sysrib` and `mpls-fib` table-0 pushes) so a label push could clobber a better route or delete it on withdraw, and a new `fib-kernel` refused and never swept or flushed the `AF_MPLS` label entries its own previous run left (`plan/README.md`, `release/fixes/`: routing and lifecycle defects). ## Task

Today two separate owners program table-0 IP routes into the FIB writers (`fib-kernel` and `fib-vpp`): the system RIB (`(system-rib, best-change)`) and label-distribution sources pushing table-0 FEC routes through `(mpls-fib, entry)` (OSPF SR, RSVP-TE ingress LSPs, and LDP). Because table-0 pushes bypassed `locrib`/`sysrib`, neither writer could decide which route was better, producing six defects (all verified in source):

| ID | Symptom | Root cause at the producer |
|----|---------|----------------------------|
| D-1 | A label source's table-0 push replaces a live labeled system-RIB route (BGP labeled-unicast) of the same prefix, while the system-RIB record still lists that route as installed | `addMPLSPushLocked` (`mplscontext.go`) shares `f.mplsInstalled` with `recordInstalledLocked` (`fibkernel.go`), and `fib-vpp`'s `addLabelPushLocked` (`fib/vpp/mplsentry.go`) writes directly to the IP table without `sysrib` arbitration |
| D-2 | Withdrawing a push that was never installed deletes the system RIB's route for the FEC | `delMPLSEntryLocked` (`mplsentry.go`) calls `delRichRoute(FEC, 0)` unconditionally; `ldpFIB.Remove` withdraws any wanted FEC even after a refused add |
| D-3 | A push relabel deletes the system RIB's route of the same prefix at another metric, and a system-RIB replace, withdraw or stale sweep removes or overwrites the push | Two writers program protocol-250 routes into table 0; `replaceOwnedRoute` (`backend_linux.go`) deletes every other protocol-250 route of the prefix in the table, and `delRichRoute` names no priority |
| D-4 | A new `fib-kernel` refuses the `AF_MPLS` swap and pop entries its own previous run left, and never removes the ones no source wants any more | `addMPLSEntryLocked` asks for a replace only for an in-label in `f.mplsSwaps`, which a new process holds empty, so `addMPLSSwap` calls `RouteAdd` and gets `EEXIST`; `listZeRoutes` skips non-IP routes, so `startupSweep` never records an `AF_MPLS` entry and `sweepStale` never removes one |
| D-5 | A new `fib-kernel` refuses the table-0 push its own previous run left until the IP sweep removes it, and nothing applies it again afterwards | `startupSweep` records the leftover push as a protocol-250 route, but `addMPLSPushLocked` consults only `f.mplsInstalled` |
| D-6 | With `flush-on-stop` true, a stopping `fib-kernel` leaves label-source pushes and `AF_MPLS` entries in the kernel | `flushRoutes` walks `f.installed`, `f.retained`, `f.staleTables` and `f.supersededTables`; table-0 pushes lived only in `f.mplsInstalled` and swaps/pops only in `f.mplsSwaps` |

### Owner architectural decision (2026-11-28)

When the sixth design judge approved the previous multi-owner table-0 design, Thomas questioned why a route was ever replaced without checking whether the new route is better, and asked why table-0 pushes bypassed `sysrib`. On 2026-11-28 he directed the architectural fix:

1. **Single IP-table arbiter (`locrib` / `sysrib`).** Table-0 MPLS ingress pushes move into `locrib` / `sysrib` in the hybrid router model:
   - **OSPF Segment Routing** attaches outgoing Prefix-SID labels directly onto OSPF's own `locrib.Path` during SPF install (matching BGP labeled-unicast), stopping `OpPush` on `mpls-fib`.
   - **RSVP-TE** registers protocol `rsvp-te` with administrative distance declared under `rib { distance { rsvp-te } }` (default `100`: beats `ospf` 110, `isis` 115 and `ibgp` 200; loses to `connected` 0, `static` 10 and `ebgp` 20 unless overridden), and inserts table-0 ingress LSPs (including ingress FRR local-repair stacks and `PathMTU`) into `locrib` (using `routeinstall.Sink` when forked). Private-table facility-backup bypasses (`TableID != 0`) stay on `mpls-fib`.
   - **LDP** publishes remote FEC-to-label bindings through a typed core bus event `(mpls-fib, label-binding)` (with `(mpls-fib, binding-replay-request)` for late/restarted `sysrib`, working internal and forked). `sysrib` decorates eligible winning paths with the peer's label when the resolved next hop matches the advertising LDP peer (RFC 5036 §3.5.7): only protocols that declare LDP-decoration eligibility through `redistevents.RegisterLDPDecoratable` (`ospf`, `isis`, and `static` in their own `init()`, mirroring `RegisterOSInstalled` so `sysrib` names no plugin protocol literal) and only unlabeled ordinary unicast paths without `SRv6SID` — never `connected`, `bgp`, `rsvp-te`, already-labeled paths (BGP-LU, OSPF SR, RSVP-TE), SRv6 routes, or non-unicast routes.
2. **`mpls-fib` scope narrowed.** `(mpls-fib, entry)` carries only `AF_MPLS` transit `OpSwap` and `OpPop` entries (in-label keyed) and RSVP-TE private-table bypass pushes (`OpPush` with `TableID != 0`). `mplsfib.ValidateEntry` refuses `OpPush` with `TableID == 0`. Table-0 ingress pushes follow the asynchronous `locrib` / `sysrib` model (FIB programming failures report `fib-sync-failure` on `fib-kernel`, same as BGP-LU/OSPF/static); synchronous `mplsfib.Apply` and producer doctor checks (`ldp-label-entries`, `rsvp-te-label-entries`, `ospf-sr-label-entries`) remain for `AF_MPLS` swap/pop and RSVP-TE private-table bypasses (preserving `fib-dummy` refusal behavior on LDP egress pops and transit labels).
3. **`fib-kernel` `AF_MPLS` ownership across restart and stop (D-4, D-6).** Because `sysrib` is now the sole IP route owner for both `fib-kernel` and `fib-vpp`, defects D-1, D-2, D-3 and D-5 vanish by construction (and the previous C-2 departure from `core-design.md` disappears completely). Only `AF_MPLS` swap/pop restart reclaim, sweep and stop flush remain for `fib-kernel`:
   - Save `in-label -> source` in the plugin state store (`meta/fib-kernel/label-owner/in-label/{bucket}`, saved before kernel add and removed after kernel delete, batched once per bucket per batch).
   - At `startupSweep`, list protocol-250 `AF_MPLS` in-labels, attach each saved source from the store, reconcile unlisted saved entries out of the store, let only the saved source reclaim its own in-label by replace (`mpls-kernel.md`), sweep unreclaimed attributed in-labels after `SelectionComplete` or `sweep-delay` (leaving unattributed in-labels alone and reporting them under `doctor-fib-sweep-incomplete` with the `ip -f mpls route` fix), and call `emitLabelReplayRequest` once outside `f.mu` if any in-label was refused over a leftover.
   - In `flushRoutes` when `flush-on-stop` is true, remove `f.mplsSwaps` and every attributed stale in-label (forgetting them in the store after delete, leaving unattributed in-labels and counting them in `doctor-fib-flush-incomplete`).

**Behavior to preserve:**
- `sysrib` works identically internal and external (forked), and OSPF, RSVP-TE, and LDP each work internal and forked.
- Administrative distance ranking in `locrib` continues to pick one winning IP route per prefix (`connected 0 < static 10 < ebgp 20 < rsvp-te 100 < ospf 110 < isis 115 < ibgp 200`); a route is replaced only when a better route wins or the winning route's own attributes (including `Labels` or `PathMTU`) change.
- `AF_MPLS` swap and pop entries keep per-source ownership, synchronous `mplsfib.Apply` acknowledgement, and producer doctor checks (`ldp-label-entries`, `rsvp-te-label-entries`, `ospf-sr-label-entries`, `bgp-epe-label-entries`), including refusal by `fib-dummy`.
- RSVP-TE facility-backup bypass pushes (`TableID != 0`) keep their private mark-selected table lifecycle and synchronous acknowledgement on `mpls-fib` (and stay refused on `fib-vpp`).
- `fib-kernel` preserves `startupSweep`, `sweepStale`, `waitAndSweepStale`, `staleTables`, and `retained` shapes so `rfc4724_restarting_fib_test.go` is untouched.
- `flush-on-stop` false retains all kernel IP routes and `AF_MPLS` entries across stop.

**Behavior to change:**
- D-1, D-2, D-3, D-5: eliminated by removing table-0 `OpPush` from `mpls-fib` and routing OSPF SR, RSVP-TE ingress LSPs, and LDP label bindings through `locrib` / `sysrib`.
- D-4, D-6: add persistent `in-label -> source` store, `AF_MPLS` startup listing, saved-source reclaim, stale in-label sweep, post-sweep `emitLabelReplayRequest`, and `AF_MPLS` stop flush in `fib-kernel`.

## Data Flow

### Entry Point
- **OSPF SR:** LSDB change triggers SPF (`spf.Computer.run`); primary Prefix-SID labels are attached to `RouteEntry` before `Installer.Apply` inserts `locrib.Path` (in-process or via `routeinstall.Sink`). Post-SPF `srInstaller` emits only transit `OpSwap`/`OpPop` and Adj-SID pops on `(mpls-fib, entry)`.
- **RSVP-TE:** RESV / ingress FRR local-repair / teardown calls `busFIB.programPush` or `removePush`; `TableID == 0` inserts or removes a `locrib.Path` (protocol `rsvp-te`, carrying `Labels` and `PathMTU`, in-process or via `routeinstall.Sink`). `TableID != 0` (facility bypass) and transit `OpSwap`/`OpPop` stay on `mplsfib.Apply`.
- **LDP:** Remote label mapping, label withdraw, and peer-down emit `(mpls-fib, label-binding)` batches; `(mpls-fib, binding-replay-request)` triggers LDP to re-emit all active remote non-Implicit-NULL bindings. Local egress `OpPop` stays on `mplsfib.Apply`.
- **System RIB (`sysrib`):** Receives selected winners from Loc-RIB (local authority or external `route-view` stream) and `(mpls-fib, label-binding)` events via `routeViewClient.HandleEvent`, decorates eligible winners in `fibChange`, and publishes `(system-rib, best-change)` to `fib-kernel` / `fib-vpp` / `fib-dummy`.
- **`fib-kernel` `AF_MPLS` lifecycle:** `startupSweep` lists protocol-250 `AF_MPLS` in-labels and reconciles the saved `in-label -> source` store; `handleMPLSEntry` programs `OpSwap`/`OpPop` and nonzero-table `OpPush` and persists `in-label -> source`; `sweepStale` sweeps unreclaimed attributed in-labels and `waitAndSweepStale` calls `emitLabelReplayRequest` outside `f.mu` if a leftover refused a label; `flushRoutes` flushes `mplsSwaps` and attributed stale in-labels when `flush-on-stop` is true.

### Transformation Path

1. **Carry `PathMTU` through `locrib` and `sysrib`.**
   - `locrib.Path` adds `PathMTU uint32` (carry-through forwarding metadata: excluded from `key()`, compared in `Equal`, copied in `RouteInstallEntry`, `parseRouteInstall`, `RouteViewPath`, `projectionPath`, `prepareRouteViewSelectedMetadata`, `protocolRoute`, `installedPath`, and `BestChangeEntry`).
   - `sysrib`'s `recomputeForwarding` no-op check compares `prev.pathMTU == winner.pathMTU` alongside `installedPath.matches` (so a `PathMTU`-only change on an RSVP-TE ingress LSP is never dropped as a no-op), and `routeViewOutputEntryBytes` (`route_view_output_size.go`) accounts for the `path-mtu` JSON field when nonzero so frame-budget sizing stays exact.
   - `fib-kernel`'s `changeToRichRoute` copies `PathMTU: c.PathMTU` into `RichRoute.PathMTU` (which `buildRichRoute` already writes as `RTAX_MTU`) and `hasRichFields` returns true when `c.PathMTU != 0`.
   - `fib-vpp`'s `processEvent` calls `warnPathMTULocked` once per writer when `BestChangeEntry.PathMTU > 0`, raising `doctor-fib-vpp-mpls-path-mtu` as `mplsentry.go` already does for transit labels.

2. **OSPF SR primary push via `locrib.Path`.**
   - `spf.RouteEntry` gains `Labels [][]uint32` aligned with `NextHops` (mirroring `Backups []Backup`). `DiffRoutes` compares `Labels` so a Prefix-SID or SRGB change without a topology change still updates the installed route.
   - `spf.Computer` gains a primary Prefix-SID labeler hook (parallel to `SetSRResolver`). Right after `selectBestRoutes` (and before `c.installer.Apply(selected)`), it resolves each next hop's outgoing SR action (`srInstaller.forwarding`): `ActionKeep` yields `[outLabel]`, `ActionExplicitNull` yields `[explicitNull]`, `ActionPHP` yields `nil` (plain IP, RFC 3032 §2.1).
   - `Installer.insert` copies each next hop's label slice onto `locrib.Path.Labels`. Because every LSDB change (including Opaque RI-LSA and Extended Prefix LSA) triggers SPF (`spf_wiring.go`), OSPF routes and their SR labels stay atomic in one `Installer.Apply` pass, in-process and forked alike.
   - `srInstaller.installRoutes` stops calling `programPush` / `removePush` on `mpls-fib` and programs only transit `OpSwap` / `OpPop` (for `myLabel` when `myOK`) and Adj-SID pops.

3. **RSVP-TE table-0 ingress LSPs via `locrib.Path` and `rib { distance { rsvp-te } }`.**
   - `rsvpte` registers protocol `"rsvp-te"` via `redistevents.RegisterProtocol("rsvp-te")` in `init()`.
   - `ze-rib-conf.yang` adds `leaf rsvp-te` under `rib/distance` (`uint8`, range `1..255`, default `100`); `internal/core/rib/distance/distance.go` adds `"rsvp-te": 100` to `bootstrap` (verified by `distance_bootstrap_test.go`). `parseAdminDistanceConfig` discovers it from YANG automatically.
   - `rsvpte` acquires `locrib.Default()` in-process or `routeinstall.New(ctx, p)` when forked (matching `ospf/spf_wiring.go`).
   - When `installReservation` or ingress FRR local repair (`frr.go`) programs a push with `TableID == 0`, it inserts `locrib.Path{Source: rsvpteProtocolID, Instance: uint32(key.TunnelID), NextHop: nextHop, Labels: imposedLabels(...), PathMTU: pathMTU}` (empty `Labels` on Implicit NULL installs a plain IP route, RFC 3032 §2.1; `Flush()` after each batch when forked). Keying `Instance` by `TunnelID` means a make-before-break replacement generation (`LSPID` bump for the same tunnel) replaces the tunnel's `locrib.Path` cleanly in place with no orphaned ECMP sibling, while two distinct tunnels to the same destination hold distinct instances. In `teardownLSP` (`reroute.go`), the replacement check matches both `other.Key.TunnelEndpoint == key.TunnelEndpoint` and `other.Key.TunnelID == key.TunnelID`, so retiring an old generation skips `Remove` while tearing down an unreplaced tunnel (or stopping the plugin) removes `(rsvpteProtocolID, uint32(key.TunnelID))` from `locrib` / `routeinstall.Sink`.
   - Facility-backup bypass pushes (`TableID != 0`) and transit `OpSwap` / `OpPop` remain on `mplsfib.Apply` with synchronous acknowledgement and `rsvp-te-label-entries`.

4. **LDP FEC-to-label bindings and `sysrib` decoration (RFC 5036 §3.5.7).**
   - `internal/core/redistevents/registry.go` adds `RegisterLDPDecoratable(id ProtocolID)` and `LDPDecoratable(id ProtocolID) (decoratable, known bool)` (mirroring `RegisterOSInstalled` / `OSInstalled`, fail-closed `(false, false)` for unknown IDs). `ospf` (`ospf/spf/install.go`), `isis` (`isis/spf/install.go`), and `static` (`static/events/events.go`) each call `redistevents.RegisterLDPDecoratable(...)` in their own `init()`. `sysrib` never hardcodes a plugin protocol name.
   - `internal/core/mplsfib/events.go` defines JSON-serializable `LabelBinding` (`Action`: `"add"`, `"withdraw"`, `"withdraw-peer"`; `FEC`; `PeerID`; `NextHops []netip.Addr`; `Label uint32`), `LabelBindingBatch`, `(mpls-fib, label-binding)`, and `(mpls-fib, binding-replay-request)`.
   - When LDP receives a remote Label Mapping, Label Withdraw, or peer-down (`reconcilePeerDown`), instead of calling `OpPush` on `mpls-fib`, LDP emits `(mpls-fib, label-binding)`:
     - On a non-Implicit-NULL mapping: `Action: "add"` with `FEC`, `PeerID`, `NextHops` (the peer's directly connected next hop from `pickNextHop` plus the peer's advertised addresses and `PeerAddr`), and `Label`.
     - On an Implicit NULL (label 3) mapping or a Label Withdraw: `Action: "withdraw"` for `(FEC, PeerID)` (RFC 5036 §3.5.7 / RFC 3032 §2.1: plain IP forwarding, never label 3).
     - On peer-down or LDP shutdown: `Action: "withdraw-peer"` for `PeerID` so `sysrib` drops every binding from that peer in one step.
   - LDP subscribes to `(mpls-fib, binding-replay-request)` and answers by emitting a `(mpls-fib, label-binding)` batch containing every active remote non-Implicit-NULL binding in `lib`.
   - `sysrib` declares `mpls-fib:label-binding` in `sysRIBReceives()` and `mpls-fib:binding-replay-request` in `sysRIBSends()`. `routeViewClient.HandleEvent` accepts `(mpls-fib, label-binding)` envelopes, enqueues the batch losslessly, and wakes the worker; after initial sync (and after `reopenOnce`, which clears `s.ldpBindings`), the worker emits `(mpls-fib, binding-replay-request)`.
   - In `sysrib`: `s.ldpBindings` maps `prefix -> peerID -> {nextHops, label}` under `s.mu`. `forwardingPath` (`ecmp.go`) carries `protocol string` (populated by `routePath`, `memberPath`, and `siblingPath` from `siblingProtocol`), so cross-protocol ECMP siblings retain their own protocol identity. When `fibChange` builds a `BestChangeEntry` for an ordinary unicast winner (`best.routeType == 0`):
     - Decoration is evaluated **per path** (both the primary resolved path and each resolved ECMP member independently): a path is decorated **only** when `protocolLDPDecoratable(path.protocol)` is true (via `redistevents.ProtocolIDOf` + `redistevents.LDPDecoratable`), `len(path.Labels) == 0`, and `!path.srv6SID.IsValid()`. Connected, BGP (plain or labeled-unicast), RSVP-TE, already-labeled OSPF SR, SRv6, and non-unicast paths are never decorated, even when mixed into a cross-protocol ECMP group.
     - For each eligible path, if `s.ldpBindings[key.prefix]` holds a binding whose `nextHops` contains `path.NextHop` (tie-broken by lowest `peerID`), `fibChange` attaches `[]uint32{label}` to that path/member.
     - When `applyLabelBindings` mutates `s.ldpBindings`, it collects every affected `prefixKey` present in `s.best`, runs `s.fibStateChange(key, route)` for each (reusing the exact `fibEntry` + `fibInstall` comparison that already compares primary and ECMP `Labels`), and publishes the resulting `BestChangeBatch` via `worker.publish`.
   - Because decoration happens in `sysrib`'s forwarding projection, `locrib` selection, `show rib`, redistribution, and `rib { fib-withhold }` stay clean: a better protocol (`static`, `eBGP`, `BGP-LU`, `rsvp-te`) is never replaced by LDP, an LDP binding for an unknown FEC or non-next-hop peer installs nothing, and when a binding appears or disappears the existing eligible route updates in place with or without the label.

5. **Remove table-0 `OpPush` from `mpls-fib` and both FIB writers.**
   - `mplsfib.ValidateEntry` (`validateEntryKey`) refuses `OpPush` when `TableID == 0` with a clear error naming `sysrib`.
   - `fib-kernel`: `addMPLSPushLocked` (`mplscontext.go`) and `delMPLSEntryLocked` (`mplsentry.go`) handle `OpPush` only for `TableID != 0` (private contexts); `f.mplsInstalled` belongs solely to `recordInstalledLocked` / `processEvent` for the gauge.
   - `fib-vpp`: `mplsentry.go` deletes `addLabelPushLocked`, `delLabelPushLocked`, and `f.labelPushes` (`ValidateEntry` already refuses table-0 `OpPush`, and `mplsentry.go` keeps refusing nonzero-table `OpPush` on VPP).

6. **`fib-kernel` saved `AF_MPLS` source ownership, restart reclaim, sweep, and stop flush (D-4, D-6).**
   - **Store layout:** Key pattern `meta/fib-kernel/label-owner/in-label/{bucket}`, registered with `zefs.MustRegister` and granted to `fib-kernel` via `statestore.RegisterPluginKeys` in `register.go`. `bucket` is `inLabel / 256` (at most 4096 buckets for 20-bit labels, so one `ListKeys` call lists every bucket). Each bucket stores the `(in-label, source)` pairs currently held in `f.mplsSwaps` or attributed in the stale in-label record.
   - **Write ordering & batching (under `f.mu`, before ack):** Each batch (`handleMPLSEntry`, `sweepStale`, `flushRoutes`) runs in three passes, writing each touched bucket at most once per pass:
     1. Pass 1 writes each bucket for in-labels about to be added (so a crash between save and kernel add leaves at worst an unlisted saved entry that the next open drops).
     2. Pass 2 performs the kernel `AF_MPLS` writes (`addMPLSSwap`, `delMPLSSwap`).
     3. Pass 3 writes once each bucket whose recorded ownership changed after pass 2 (removing refused adds and successful deletes).
     The first store failure or timeout (5 seconds, SDK bound) ends store calls for that batch, marks remaining touched buckets dirty, raises warning `fib-label-owner-unsaved`, and lets kernel writes and ack proceed; dirty buckets are flushed on the next store-calling batch and at stop (whatever `flush-on-stop` says).
   - **Open (`startupSweep`):** Lists protocol-250 IP routes as today (preserving `staleTables` and `retained` shapes for `rfc4724_restarting_fib_test.go`), then lists protocol-250 `AF_MPLS` in-labels via a new listing interface beside `mplsBackend` (`mplsstale.go`, implemented by `netlinkBackend` in `mplsentry_linux.go` over the AF_MPLS dump `mplsSwapOwned` already reads; `mplsBackend` keeps its two methods). Reads the saved buckets, attaches each saved source to matching listed in-labels, drops saved in-labels not present in the kernel listing (reconcile; skipped if the kernel listing failed), and reports any failed listing, unreadable bucket, or unattributed leftover in-label under `doctor-fib-sweep-incomplete` with the `ip -f mpls route` fix. Nothing at open writes to the kernel. `OnStarted` starts `waitAndSweepStale` whenever either IP `stale` or the stale in-label record is non-empty.
   - **Reclaim (`addMPLSEntryLocked` / `delMPLSEntryLocked` / `delMPLSSourceLocked`):**
     - In-label in `f.mplsSwaps`: as today.
     - In-label in stale record with matching saved source: replace via `addMPLSSwap(..., replace=true)` (`mplsSwapOwned` rechecks kernel), move to `f.mplsSwaps`.
     - In-label in stale record with another saved source: refuse with `EEXIST` and note a post-sweep label replay is owed.
     - In-label in stale record with no saved source: refuse with `EEXIST` naming the `doctor-fib-sweep-incomplete` report, no kernel write.
     - Removal and `ActionRemoveLabelSource` treat a stale in-label saved for that source as that source's own (`delMPLSSwap` + forget in store).
   - **Sweep (`sweepStale` & `waitAndSweepStale`):** Under `f.mu`, after sweeping IP routes, `sweepStale` deletes every remaining stale in-label that has a saved source through `delMPLSSwap` and forgets it in the store in pass 3; unattributed in-labels stay untouched (already reported at open). Refused deletes raise `doctor-fib-sweep-incomplete` with the AF_MPLS fix. After `sweepStale` releases `f.mu`, if any in-label was refused over a leftover, `waitAndSweepStale` calls `emitLabelReplayRequest` once outside `f.mu` (reusing `spec-fib-dummy`'s token and emit).
   - **Stop flush (`flushRoutes`):** When `flush-on-stop` is true, beside today's IP routes, deletes every in-label in `f.mplsSwaps` and every attributed stale in-label via `delMPLSSwap`, forgets removed entries in the store in pass 3, keeps unattributed stale in-labels and counts them plus any failed deletes in `doctor-fib-flush-incomplete`. When `flush-on-stop` is false, removes nothing and flushes any dirty store buckets once.

## Acceptance Criteria

| AC ID | Input / Condition | Expected Behavior |
|-------|-------------------|-------------------|
| AC-1 | BGP labeled-unicast (or `static` at distance 10) wins a prefix in `locrib`, and LDP advertises a label binding for that FEC (or RSVP-TE signals an ingress LSP at default distance 100) | The better route stays installed in the kernel and VPP unchanged; LDP does not decorate a `bgp` or already-labeled route, and `rsvp-te` (100) loses to `static` (10) and `ebgp` (20) (D-1) |
| AC-2 | OSPF (`110`) wins a prefix via next hop `N`, and LDP advertises label `16` for that FEC from peer `N`; then LDP relabels to `17`, then withdraws the binding (or receives Implicit NULL 3) | `sysrib` updates the single route in place: plain OSPF -> OSPF with label `16` -> OSPF with label `17` -> plain OSPF. No second route is ever installed, and withdrawing the LDP binding never deletes the OSPF route (D-2, D-3) |
| AC-3 | LDP advertises a label for a FEC from peer `P`, while OSPF's winning next hop is `Q != P` (or no route exists for the FEC, or the winner is `connected` or `bgp`) | `sysrib` does not decorate the route and installs nothing for an absent FEC (RFC 5036 §3.5.7) |
| AC-4 | `static` (unlabeled, distance 10) wins a prefix via next hop `N` and LDP advertises label `16` from peer `N`; then OSPF (`110`) also has a route | `static` wins in `locrib` and `sysrib` decorates the unlabeled `static` route with label `16` because `static` is eligible and its next hop matches `N` |
| AC-5 | OSPF ECMP route has two next hops (`N1`, `N2`); LDP peer `N1` advertises label `16` and peer `N2` advertises label `26` (or only `N1` advertises a label) | `sysrib` decorates each ECMP member independently (`N1` with `16`, `N2` with `26` or unlabeled) |
| AC-6 | OSPF SR computes a Prefix-SID for a prefix (with `ActionKeep`, `ActionExplicitNull`, or `ActionPHP`) | OSPF attaches the outgoing label directly onto its own `locrib.Path` (none for `ActionPHP`, RFC 3032 §2.1), emits no `OpPush` on `mpls-fib`, keeps transit `OpSwap`/`OpPop` and Adj-SID pops on `mpls-fib`, and obeys `rib { distance { ospf } }` and `rib { fib-withhold [ ospf ] }` (in-process and forked) |
| AC-7 | RSVP-TE signals a table-0 ingress LSP with `PathMTU = 1400` and label `200` for a prefix also learned via OSPF (`110`) | RSVP-TE inserts `locrib.Path` (protocol `rsvp-te`, default distance `100`, `Labels: [200]`, `PathMTU: 1400`); RSVP-TE beats OSPF, `fib-kernel` installs the route with label `200` and `RTAX_MTU = 1400`, and `fib-vpp` installs the labeled route and raises `doctor-fib-vpp-mpls-path-mtu` once. Raising `rib { distance { rsvp-te 120 } }` re-ranks in favor of OSPF; tearing down the LSP falls back to OSPF immediately |
| AC-8 | RSVP-TE signals an ingress LSP with Implicit NULL (label 3), or performs ingress FRR local repair, or signals a facility-backup bypass (`TableID != 0`) | Implicit NULL installs a plain IP `locrib.Path` with no label 3 (RFC 3032 §2.1); ingress FRR updates the same `locrib.Path` with the bypass+inner label stack and `PathMTU`; `TableID != 0` bypasses stay on `mpls-fib` with synchronous `mplsfib.Apply` and private packet-mark tables |
| AC-9 | `sysrib` starts or restarts (internal or forked) after LDP already holds active remote bindings | `sysrib` emits `(mpls-fib, binding-replay-request)`, LDP re-emits active remote non-Implicit-NULL bindings, and `sysrib` decorates matching routes identically in internal and forked modes |
| AC-10 | Any caller submits `OpPush` with `TableID == 0` on `(mpls-fib, entry)` | `mplsfib.ValidateEntry` refuses it with an error stating table-0 pushes flow through `sysrib`; neither `fib-kernel` nor `fib-vpp` programs it |
| AC-11 | `fib-dummy` runs with LDP | LDP's local egress `OpPop` on `mpls-fib` is still refused by `fib-dummy` and reported by `ldp-label-entries` under `doctor-fib-mpls-no-writer` (preserving `test/plugin/fib-dummy-labels-refused.ci`) |
| AC-12 | `fib-kernel` opens on a kernel holding protocol-250 `AF_MPLS` entries a previous run left, and the store names the source of each; that source applies a swap or pop for one of them | The entry is replaced (`addMPLSSwap(..., replace=true)`) and acknowledged; the in-label belongs to that source and the sweep leaves it (D-4) |
| AC-13 | Same open; another source applies a swap or pop for an in-label whose saved source differs (in either arrival order) | The other source's add is refused with `EEXIST` without touching the kernel; the saved source's add replaces it; a post-sweep replay is noted if refused over a leftover |
| AC-14 | Same open; BGP's `SelectionComplete` arrives or `sweep-delay` passes with a leftover attributed in-label its saved source did not apply again | `sweepStale` deletes the in-label via `delMPLSSwap` and forgets it in the store; an in-label taken over by another kernel protocol is left alone (`mplsSwapOwned`); a failed delete raises `doctor-fib-sweep-incomplete` with the `ip -f mpls route` fix; `waitAndSweepStale` calls `emitLabelReplayRequest` once outside `f.mu` if a replay was owed (D-4) |
| AC-15 | `fib-kernel` opens on a kernel holding a protocol-250 `AF_MPLS` in-label the store names no source for | An add is refused with `EEXIST` without a kernel write; the sweep and stop flush leave it alone; `doctor-fib-sweep-incomplete` reports the label and `ip -f mpls route del <label>` fix at open, and `doctor-fib-flush-incomplete` counts it on stop flush (R-6) |
| AC-16 | `fib-kernel` restarts with `flush-on-stop false` over a previous run's labeled IP route (LDP-decorated OSPF, OSPF SR, RSVP-TE, or BGP-LU) | `startupSweep` retains the protocol-250 IP route as a `sysrib` leftover, `sysrib` replay replaces it cleanly in place (no `EEXIST` refusal), and a BGP-LU route retained during BGP GR deferral forwards untouched until `SelectionComplete` (D-5, RFC 4724 §4.1) |
| AC-17 | `fib-kernel` saves `in-label -> source` across a 1,000-entry batch over 40 buckets, and across a store failure/timeout | In-labels are saved before kernel add and removed after kernel delete, at most one write per bucket per pass; on first store failure/timeout, no further store call runs in that batch, kernel writes and ack succeed, remaining buckets are marked dirty, `fib-label-owner-unsaved` is raised, and the next batch (or stop) writes dirty buckets and clears the warning (R-5) |
| AC-18 | `fib-kernel` opens with saved in-labels the kernel listing does not hold (e.g. crash between save and kernel add) | Unlisted saved in-labels are dropped from the store at open (each changed bucket written once) with zero kernel writes; if the kernel listing itself failed, nothing is dropped from the store |
| AC-19 | `fib-kernel` stops with `flush-on-stop true` while `mplsSwaps` and attributed stale in-labels exist | Every `mplsSwaps` entry and attributed stale in-label is deleted via `delMPLSSwap` and removed from the store; failed deletes and unattributed in-labels are reported under `doctor-fib-flush-incomplete` (D-6) |
| AC-20 | `fib-kernel` stops with `flush-on-stop false` | No IP route and no `AF_MPLS` entry is removed; dirty store buckets are flushed once |

## Design presentation

### What changes
- **One IP-table arbiter for every data plane (`fib-kernel` and `fib-vpp`):** table-0 MPLS ingress pushes move off `(mpls-fib, entry)` and into `locrib` / `sysrib`, so a route in table 0 is replaced only when a better route wins or the winning route's own attributes change:
  - **OSPF SR** attaches outgoing Prefix-SID labels directly to OSPF's own `locrib.Path`.
  - **RSVP-TE** registers protocol `rsvp-te` with `rib { distance { rsvp-te } }` (default `100`, beating OSPF `110`, IS-IS `115`, and iBGP `200`, while losing to `connected` `0`, `static` `10`, and `ebgp` `20`), carrying `PathMTU` on `locrib.Path` → `BestChangeEntry`.
  - **LDP** publishes remote FEC-to-label bindings via `(mpls-fib, label-binding)` (with replay for late/restarted `sysrib`, internal and forked); `sysrib` decorates unlabeled `ospf`, `isis`, and `static` winners whose resolved next hop matches the advertising LDP peer (RFC 5036 §3.5.7).
- **`mpls-fib` narrowed:** carries only `AF_MPLS` transit `OpSwap` / `OpPop` entries and RSVP-TE private-table facility bypasses (`TableID != 0`); `ValidateEntry` refuses table-0 `OpPush`.
- **`fib-kernel` `AF_MPLS` restart and stop lifecycle (D-4, D-6):** `in-label -> source` is saved in bucketed keys under `meta/fib-kernel/label-owner/in-label/{bucket}` before kernel add and removed after delete; `startupSweep` lists protocol-250 `AF_MPLS` in-labels and reconciles the store; only the saved source reclaims its own in-label; unreclaimed attributed in-labels are swept after `SelectionComplete` or `sweep-delay` (unattributed ones are kept and reported under `doctor-fib-sweep-incomplete`); `waitAndSweepStale` reuses `emitLabelReplayRequest` once if a leftover refused a label; `flushRoutes` removes `mplsSwaps` and attributed stale in-labels when `flush-on-stop` is true.

### Before and after
- **Before (D-1, D-2, D-3, D-5):** Two independent writers (`sysrib` and `mpls-fib`) wrote protocol-250 routes into Linux table 0 (and VPP's IP table). An LDP push could overwrite a BGP labeled-unicast route; withdrawing a refused push could delete a static/IGP route; relabeling a push could wipe out an OSPF route at metric 20; restarting `fib-kernel` refused its own leftover table-0 pushes with `EEXIST`.
- **After:** Only `sysrib` writes table-0 IP routes. BGP-LU (distance 20) or `static` (distance 10) beats RSVP-TE (distance 100) and OSPF (distance 110); LDP decorates only unlabeled `ospf`/`isis`/`static` winners whose next hop matches the peer; OSPF SR labels OSPF's own path. Relabeling or withdrawing LDP/OSPF-SR/RSVP-TE updates or falls back cleanly in `sysrib`, and restarting `fib-kernel` reclaims table-0 routes through `sysrib`'s normal replay with zero split-brain and zero departure from `core-design.md`.
- **Before (D-4, D-6):** Restarting `fib-kernel` with `flush-on-stop false` refused every leftover `AF_MPLS` swap/pop with `EEXIST` and never swept dropped labels; stopping with `flush-on-stop true` left `AF_MPLS` entries in the kernel.
- **After:** Saved-source `AF_MPLS` entries are reclaimed in place by their own source, unreclaimed attributed entries are swept after `SelectionComplete`/`sweep-delay`, unattributed entries are kept and reported with their `ip -f mpls route del` command, and `flush-on-stop true` removes every owned and attributed stale `AF_MPLS` entry.

### Alternatives set aside
- **Keep table-0 pushes on `mpls-fib` with dual-owner tracking and slot-priority isolation in `fib-kernel`** (previous revisions 1–6 of this spec): required a second IP owner map, a persistent push state store, guarded IPv4 priority-0 lookup-and-delete, a monitor push branch, and a departure (`C-2`) from `core-design.md`, while still leaving `fib-vpp` with two IP writers and still never deciding "which route is better". Replaced by Thomas's 2026-11-28 decision.
- **Put LDP into `locrib` as a competing IP route protocol:** violates RFC 5036 §3.5.7 (LDP should not originate an IP route without a matching IGP/static next hop or replace `show rib` protocol ownership). Set aside in favor of `sysrib` decoration on matching next hops.
- **Put RSVP-TE into `sysrib` as label decoration only:** RSVP-TE tunnels steer onto explicit non-SPF paths with their own next hops and `PathMTU`, so they are genuine competing routes in `locrib`.
- **Keep synchronous FIB refusal for table-0 ingress pushes:** would bolt a synchronous FIB round-trip onto `locrib`; ingress headends advertise no incoming label upstream, so following the async `locrib`/`sysrib` model (while keeping synchronous `mplsfib.Apply` for transit swap/pop and private bypasses) matches BGP-LU, OSPF, and static.

   - **After:** Table-0 pushes flow through `locrib` / `sysrib` (including forked OSPF via `routeinstall.Sink`, with FIB programming failures reported under `fib-sync-failure`), so `ldp-label-entries`, `ospf-sr-label-entries`, and `rsvp-te-label-entries` report only `mpls-fib` swap/pop/private-bypass refusals. ## Known limits

- An `AF_MPLS` in-label with no saved source (only possible after a lost, unreadable, or unwritable state store) stays in the kernel until the operator runs the `ip -f mpls route del <label>` command reported under `doctor-fib-sweep-incomplete` (R-6).
- `fib-vpp` has no per-route IP MTU, so an RSVP-TE ingress LSP's `PathMTU` on VPP raises `doctor-fib-vpp-mpls-path-mtu` once per writer and relies on interface MTU, matching transit labels today.
- RSVP-TE facility-backup bypasses (`TableID != 0`) remain kernel-only via `mpls-fib` and remain refused on `fib-vpp`.
