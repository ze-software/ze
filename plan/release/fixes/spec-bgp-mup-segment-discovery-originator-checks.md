## Task

Split out of `spec-bgp-unowned-rfc-rows` on 2026-11-14 (owner: "split bgp-unowned-rfc-rows"). This spec owns every MUP Segment Discovery Prefix-SID and locator-originator validation row. Row numbers are kept from `spec-bgp-unowned-rfc-rows` so quotes and comparisons stay traceable.

Enforce the `draft-ietf-bess-mup-safi` §3.3.3 (Interwork Segment Discovery, ISD) and §3.3.6 (Direct Segment Discovery, DSD) receive checks through the existing per-family `nlritype.UpdateCheck` seam (`internal/component/bgp/plugins/nlri/mup/rfc7606.go`):

- Withdraw any received DSD or ISD route that arrives without a Prefix-SID attribute (including after the RFC 8669 §4 EBGP Prefix-SID discard) while skipping only that NLRI and continuing UPDATE processing.
- Publish the IS-IS two-level SRv6 locator-originator snapshot over the EventBus via `sdk.Plugin.EmitEvent` (`locator-origin:snapshot`, with `locator-origin:snapshot-request` replay) into a read-locked in-daemon index in `internal/core/locatororigin`, clearing entries on IS-IS stop or abrupt process disconnect via `pluginserver.RegisterProcessGenerationCleanup`. This keeps zero RPC on the BGP receive hot path, never imports IS-IS from BGP (owner decision, 2026-10-11: "Yes, IS-IS resolver"), and behaves identically whether IS-IS runs internal or forked/external.
- When the locator originator is known, treat-as-withdraw a DSD route whose MP_REACH next hop is not in the originator's advertised address set, and treat-as-withdraw an ISD route whose Address field is not held by that originator (ignoring the MP_REACH next hop on ISD per §3.3.3), logging a rate-limited Warn and raising `doctor-bgp-mup-locator-mismatch` on the daemon report bus.
- When the locator originator cannot be resolved, keep the route, log a rate-limited Warn naming the peer, route, SID, reason, and fix under `doctor-bgp-mup-locator-unresolved`, and raise the same warning on the daemon report bus via `report.RaiseWarningFix` (owner decision, 2026-10-11: "Keep it, log a warning"); only a proven mismatch withdraws.
- Complete the two owed proofs for landed row 2 (`DRAFT-IETF-BESS-MUP-SAFI-3.3.6-5`): the EBGP-discard `.ci` test and the GoBGP v4.11.0 interop scenario `bgp-mup-dsd-gobgp`.

### How FRR and BIRD handle it

Neither implements the MUP SAFI: no MUP code in FRR `bgpd/` nor in BIRD `proto/bgp/`. GoBGP implements MUP from v3.6.0, and Ze's interop image pins GoBGP v4.11.0 (`test/interop/Dockerfile.gobgp`, A-4).

  → Constraint: "The Prefix Attribute Flags sub-TLV MUST be included in the Locator TLV when it is leaked upwards in the hierarchy or originated as a result of the redistribution from another protocol or another IS-IS instance." (RFC 9352 §7.1). Only flags present with R and X clear prove an originator; an IPv6 Source Router ID equal to the next hop is a known match (Design resolutions, B1)
- [ ] `rfc/full/rfc9352.txt` §6 (lines 324-372), `rfc/full/rfc7794.txt` §2.1 X-Flag in TLVs 236 and 237 (lines 218-221), `rfc/full/rfc5308.txt` §2 external bit (lines 107-108)
  → Constraint: "If at least one of them sets the A-flag in its advertisement, the prefix/SRv6 Locator SHOULD be considered as anycast." and "In case of any inconsistency between the Prefix Attribute Flags advertised in the Locator TLV and in the Prefix Reachability TLV, the ones advertised in the Prefix Reachability TLV MUST be preferred." (RFC 9352 §6). Any covering advertisement with A-flag (bit 4) set is the anycast not-known; a same-system TLV 236 entry for the prefix decides X by its fixed-header external bit whether or not it carries a Prefix Attribute Flags sub-TLV, while the sub-TLV's own X-Flag is ignored in TLV 236 per RFC 7794 §2.1; that sub-TLV, when present, decides R and A (Design resolutions, B1, round-4 I1, round-5 I1)

## Data Flow (MANDATORY - see `ai/rules/architecture.md`)

### Entry Point
- Receive: BGP UPDATE wire bytes on an established peer session carrying MUP NLRIs (`ipv4/mup` AFI 1 / SAFI 85 or `ipv6/mup` AFI 2 / SAFI 85) inside `MP_REACH_NLRI`.
- IGP locator publication: IS-IS LSDB startup, config reconcile, LSP mutation (`lsdb_wiring.go`), and `locator-origin:snapshot-request` replay arriving on `p.OnEvent`.

### Transformation Path
1. **IGP locator-originator publication (off the BGP hot path, identical internal and forked/external):**
   - On `OnStarted`, every LSDB mutation (`emitLSPChange` / `publishLSPChange`), config reconcile, and `locator-origin:snapshot-request` on `p.OnEvent`, `internal/plugins/isis/locator_origin.go` builds a compact, self-contained `locatororigin.Snapshot` (`Source: "isis"`, monotonic `Generation`, `Active: cfg.Present()`, and one resolved `LocatorEntry` per SRv6 locator prefix across Level 1 and Level 2) and emits compact JSON via `p.EmitEvent(ctx, locatororigin.Namespace, locatororigin.EventSnapshot, "", "", string(payload))`.
   - `pluginserver.deliverEvent` (`internal/component/plugin/server/dispatch.go`) validates the declared send, decodes the JSON string into `*locatororigin.Snapshot` via `events.Register[*Snapshot]`, and invokes the BGP reactor's typed EventBus subscriber (`internal/component/bgp/reactor/register_locator_origin.go`), which calls `locatororigin.ApplySnapshot` to update the read-locked in-daemon index (`internal/core/locatororigin`).
   - Before peers open (`Reactor.StartPeers`), the reactor emits `locatororigin.SnapshotRequest` so any already-running internal or forked IS-IS process replays its current snapshot.
   - On graceful IS-IS shutdown, IS-IS emits `{Source: "isis", Generation: next, Active: false}`. On abrupt process stop or disconnect, `pluginserver.RegisterProcessGenerationCleanup` invokes `locatororigin.ClearSource(proc.Name())` after admitted requests drain and before any replacement connects.
2. **BGP receive framing and RFC 7606 classification:** `internal/component/bgp/message/` and `session_validation_receive.go`.
3. **RFC 8669 §4 EBGP Prefix-SID discard:** marks `AttrPrefixSID` in `result.DiscardEntries` when the session is EBGP and `accept-srv6-prefix-sid` is false; `typedNLRIUpdateAttrs` marks discarded attribute codes absent on `nlritype.UpdateAttrs`.
4. **Typed-NLRI pass (`session_validation_nlritype.go`, `applyTypedNLRIDiscard` -> `typedNLRIEdit` -> `nlritype.RetainUpdate`):**
   - Per carved NLRI, the family recognizer (`mup.recognizerFor`) decides type recognition and body syntax.
   - For each announced NLRI the recognizer keeps, the registered MUP `nlritype.UpdateCheck` runs:
     - For DSD (`MUPDSD`) and ISD (`MUPISD`) routes: if `!attrs.Has(attribute.AttrPrefixSID)`, return `nlritype.Withdraw` (rows 2 and 14).
     - Otherwise extract the first SRv6 SID from the raw Prefix-SID attribute value via the zero-copy helper in `internal/core/bgp/attribute/prefixsid_wire.go`, and query `locatororigin.Resolve(sid)` (read-locked in-daemon lookup, zero RPC).
     - If the originator is not known (any named reason below), keep the route (`nlritype.Keep`), emit a rate-limited Warn under `doctor-bgp-mup-locator-unresolved` naming peer, route, SID, reason, and fix, and raise on the daemon report bus via `report.RaiseWarningFix` with `report.FitMessage` and a bounded subject (peer + reason class) (owner decision: "Keep it, log a warning"; `docs/architecture/doctor-and-health-checks.md` lines 1502-1504).
     - If the originator is known, compare the DSD MP_REACH next hop (row 1) or the ISD Address field (rows 13 and 15; ignoring the MP_REACH next hop per §3.3.3) against the originating system's advertised IPv6 and IPv4 address/prefix set (TLV 140, TLV 232, local TLV 236, TLV 132, TLV 134, local TLV 135, plus any matching IPv6 Source Router ID sub-TLV on a covering locator). A proven mismatch logs a rate-limited Warn and raises `doctor-bgp-mup-locator-mismatch` via `report.RaiseErrorFixOnce` naming peer, route, next hop/address, and originator system ID, and returns `nlritype.Withdraw`.
5. **Withdrawal placement and dispatch:** `applyTypedNLRIDiscard` strips rejected NLRIs from `MP_REACH_NLRI` (`rewriteMPNLRISections`) and places their withdrawals through the landed `typedNLRIPlaceWithdrawals` / `typedNLRIWithdrawBodies` (`message.AppendMPUnreachNLRI` / `message.BuildMPUnreachBody`) and `session_read.go` `validation.typedWithdrawBodies` loop. Kept NLRIs proceed to the RIB and relays; rejected NLRIs are withdrawn without resetting the session.

## Design presentation

### What changes

Ze completes receive-side `draft-ietf-bess-mup-safi` Segment Discovery validation for both Direct Segment Discovery (§3.3.6) and Interwork Segment Discovery (§3.3.3) routes by extending the single MUP `nlritype.UpdateCheck` that already landed for row 2, with full internal/forked plugin parity:

1. An ISD route arriving without a Prefix-SID attribute (including after RFC 8669 §4 EBGP Prefix-SID discard) is treated as withdrawn via `MP_UNREACH_NLRI` while sibling NLRIs in the UPDATE continue processing — matching the landed DSD behavior.
2. IS-IS (`internal/plugins/isis`) maintains a two-level (Level 1 + Level 2) SRv6 locator-to-originator snapshot (reusing/mirroring the TLV 27 decoder and RFC 9352 §6 / RFC 7794 flag-precedence rules already in `bgpls_export.go`) and publishes it over the EventBus via `sdk.Plugin.EmitEvent` (`locator-origin:snapshot`), answering `locator-origin:snapshot-request` via `p.OnEvent` and declaring both messages in `registry.Registration` and Stage 1 `sdk.Registration`. Internal (`DirectBridge`) and forked/external (TLS RPC) IS-IS run the exact same code path.
3. The BGP reactor subscribes to `locator-origin:snapshot` on the daemon `EventBus`, updating a read-locked in-daemon index in `internal/core/locatororigin`, requests an initial replay before peers open, and registers a `pluginserver.RegisterProcessGenerationCleanup` hook so an abrupt IS-IS stop or disconnect clears stale entries before any replacement starts.
4. When a DSD or ISD route carries a Prefix-SID attribute, Ze extracts its first SRv6 Service SID with zero-copy framing in `internal/core/bgp/attribute/prefixsid_wire.go` and calls `locatororigin.Resolve(sid)` (read-locked in-daemon lookup, zero RPC on the BGP receive hot path).
5. Against a known originator, a DSD next-hop mismatch or an ISD Address mismatch (ignoring the MP_REACH next hop on ISD per §3.3.3) is treated as withdrawn with a rate-limited Warn and `doctor-bgp-mup-locator-mismatch` report-bus error naming peer, route, address/next hop, and originator system ID. Against an unknown originator (including IS-IS unconfigured/stopped, anycast/A-flag, leaked/redistributed without matching Source Router ID, missing Prefix Attribute Flags sub-TLV, non-4/16/32 next-hop length, or undecoded TLV 237), the route is kept, logs a rate-limited Warn under `doctor-bgp-mup-locator-unresolved`, and raises on the daemon report bus via `report.RaiseWarningFix` so `ze doctor` (`recent-events`) and `ze show warnings` surface it.
6. Row 2's two owed proofs (`test/plugin/mup-dsd-ebgp-prefix-sid-discarded-withdraw.ci` and GoBGP v4.11.0 interop scenario `bgp-mup-dsd-gobgp`) land alongside five new `.ci` tests (including forked IS-IS parity) and full RFC discrimination records.

### Before and after

1. **Received ISD route without Prefix-SID (or after EBGP discard):**
   - Before: stored in Adj-RIB-In and relayed unchanged (`CheckDSDPrefixSID` checks `MUPDSD` only).
   - After: stripped from `MP_REACH_NLRI` and emitted as an `MP_UNREACH_NLRI` withdrawal while sibling NLRIs in the same UPDATE are processed normally.
2. **Received DSD route whose next hop or ISD route whose Address field disagrees with the known IS-IS locator originator (whether IS-IS runs internal or forked/external):**
   - Before: stored and relayed without consulting IS-IS.
   - After: treated as withdrawn via `MP_UNREACH_NLRI` (removing any earlier generation from Adj-RIB-In), sibling NLRIs continue processing, and Ze logs a Warn and raises `doctor-bgp-mup-locator-mismatch` naming peer, route, next hop/address, and originator system ID — identically whether IS-IS runs internal or forked/external (while conforming ISD routes are kept even if MP_REACH next hop differs per §3.3.3).
3. **Received DSD or ISD route when no IS-IS locator originator can be resolved (no IS-IS, stopped IS-IS, anycast, leaked without Source Router ID, missing flags):**
   - Before: silently stored with no diagnostic signal.
   - After: kept (never falsely withdrawn) with a rate-limited Warn and a report-bus warning (`report.RaiseWarningFix`) under `doctor-bgp-mup-locator-unresolved` naming peer, route, SID, exact reason, and fix, visible in `ze doctor` and `ze show warnings`.
4. **Landed row 2 (`DRAFT-IETF-BESS-MUP-SAFI-3.3.6-5`) verification:**
   - Before: proven by unit tests and one accepting-peer `.ci` test only, with no EBGP-discard daemon test and no GoBGP DSD interop scenario.
   - After: proven end-to-end by `test/plugin/mup-dsd-ebgp-prefix-sid-discarded-withdraw.ci` and GoBGP v4.11.0 interop scenario `bgp-mup-dsd-gobgp` with a recorded red on revert.

### Alternatives set aside

| Alternative | Why set aside |
|-------------|---------------|
| Internal-only `locatororigin.Register` callback guarded by `p.IsInternal()` + `warnIfExternal` + `dangerousCalls` | Contradicts `ai/doors/system.md` ("Code that only works internal is broken") and `docs/architecture/plugin/plugin-system.md` ("One plugin, two ways to reach the bus") whenever IS-IS runs forked/external; EventBus snapshot publication into a read-locked in-daemon index achieves the same zero-RPC BGP hot path with full internal/forked parity |
| Query IS-IS over a DirectBridge or plugin RPC per received DSD or ISD NLRI | Puts a synchronous RPC on the BGP receive hot path (forbidden by Security checklist) and adds latency/failure coupling to every received MUP UPDATE |
| Widen `nlritype.Recognizer` to accept path attributes, or add a central MUP switch in the BGP reactor | Changes the per-NLRI recognizer contract for every family, or hardcodes MUP in the engine (`ai/rules/principles.md`); `nlritype.UpdateCheck` already exists for this exact purpose |
| Look up the locator originator via `sysrib` or import `internal/plugins/isis` from BGP | `sysrib`'s `protocolRoute` holds no originating router identity, and importing IS-IS from BGP violates component boundaries and `ze_isis` compile-out. Owner decided: "Yes, IS-IS resolver" |
| Withdraw DSD/ISD routes whenever the locator originator cannot be resolved | Drops all MUP Segment Discovery routes in deployments without IS-IS. Owner decided: "Keep it, log a warning" |
| Add a new `message.SynthesizeWithdrawNLRI` helper beside `SynthesizeWithdrawFamilies` | Already superseded in HEAD by `message.AppendMPUnreachNLRI`, `message.BuildMPUnreachBody`, `Session.typedNLRIPlaceWithdrawals`, and `session_read.go`'s `validation.typedWithdrawBodies` loop |
| Match only IS-IS TLV 140 (TE Router ID) or only one IS-IS level | A PE's BGP next hop is often a loopback in TLV 232 or `/128` TLV 236 rather than TLV 140, and a single-level read mistakes an L1/L2 leaker for the originator, falsely withdrawing valid routes |
