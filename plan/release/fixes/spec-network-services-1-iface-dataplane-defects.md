## Data Flow (MANDATORY)

### Entry Point
1. Config commit/reload for `interface {}` and `traffic-control {}`.
2. Kernel netlink multicast events (`RTM_NEWLINK`, `RTM_DELLINK`, `RTM_NEWADDR`, `RTM_DELADDR`, `RTM_NEWNEIGH`, `RTM_NEWROUTE`, `RTM_DELROUTE`).
3. DHCPv4 (`DHCPOFFER`/`DHCPACK`) and DHCPv6 (`Renew`/`Rebind`/`Decline`) network replies.
4. Operator commands `show interface <name> counters`, `monitor system netlink`, and `ze doctor` (`iface-ra-forwarding`).

### Transformation Path
1. **Route add ownership (AC-1):** `netlinkBackend.AddRoute` attempts `netlink.RouteAdd(route)` first; on `EEXIST`, it checks `routeUnderAnotherProtocol`—if the existing route belongs to `proto`, it runs `netlink.RouteReplace(route)`, and if another protocol holds that key it returns an error naming the conflicting protocol without overwriting it.
2. **Lossless resolver link-event fan-out (AC-2):** Replace the fixed 8-slot drop-oldest channel in `resolver.subscribe` with a per-subscriber coalescing ring/queue drained by a non-blocking notification trigger (or bounded lossless queue sized for bursts with coalescing only on identical consecutive state) so a 100-event burst delivers every transition without loss while keeping `onLinkEvent` strictly non-blocking on the monitor loop.
3. **Identity-default mappings (AC-3):** `RegisterOwnedAddresses` / `desiredState` and `RegisterOwnedMacvlan` / `reconcileOwnedDevices` resolve logical interface names through `iface.ResolveDevice` (failing closed when a selector has no binding rather than falling back to the logical name); `traffic/netlink` `resolveOSName` returns `(string, error)` using `iface.ResolveDevice` on `Apply` and `ListQdiscs` while keeping the documented no-op fallback on `restoreOriginalLocked`; `checkRAForwarding` resolves `mac/match` entries through `iface.SelectedNetDevice` so both `ze doctor` and `ze show doctor` read the real kernel device's IPv6 forwarding sysctl.
4. **MPLS egress pop via `lo` (AC-4):** Run `TestMPLSIntegration_EgressPopNoNextHop` in Ze's QEMU guest, trace whether guest `rp_filter`, `net.mpls.conf.lo.input`, or `0002-mpls-ip-mtu.patch` drops the re-injected packet, fix the root cause (or refuse an unsupported pop form with an operator-actionable reason), and prove green in Ze's guest.
5. **DHCPv6 mid-exchange flap (AC-5):** Create a per-exchange child context in `extend` and `decline` that cancels when a `LinkDown`/`LinkUp` event arrives on `w.links`, aborting `runExchange` promptly so `maintain` immediately runs `noteMove` and `expireDue` without reinstalling deleted addresses.
6. **Link-only reads (AC-6):** `showInterfaceCounters` calls `iface.GetLink(name)` (which returns link stats with no address dump); `Backend` gains `ListLinks() ([]InterfaceInfo, error)` (implemented in `ifacenetlink`, `ifacevpp`, and test fakes without dumping addresses), and `resolver.matchByMACFrom` uses `ListLinks` instead of `ListInterfaces`.
7. **VPP address lifetimes (AC-7):** Populate `AddrInfo.ValidLifetime` (and preserve leased/learned addresses via `RegisterLeasedAddresses`) in the VPP interface backend so `reconcileOnReadyWithJournal` spares learned addresses on VPP as it already does on kernel.
8. **Netlink monitor survival and state-change dedup (AC-8, AC-9):** `(*monitor).start` attaches an `ErrorCallback` to all three subscriptions; on receive error (`ENOBUFS`) or channel close, `(*monitor).run` increments a restart counter, logs a WARN, closes the old subscription's `done` channel, resubscribes with bounded backoff, and performs a full link/addr dump resync without exiting `run`. `handleLinkUpdate` tracks last emitted `(operUp, name, mac)` per link index: `EventUp`/`EventDown` emit only on operational state transitions, while rename/MAC changes still invalidate the resolver cache via a dedicated metadata/link-change invalidation path without firing spurious `EventUp`/`EventDown`.
9. **Absent mirror destination retry (AC-10):** When `applyMirror` receives `ErrInterfaceNotFound` / `LinkNotFoundError` for the mirror destination, it records the mirror as pending (not a commit-aborting error), logs a WARN and raises a warning via `issuequeue` under registered `doctor-iface-mirror-destination-absent`, and retries automatically when the destination appears on `interface/created` or `interface/up`, clearing the issue once installed.
10. **DHCPv6-PD config proof (AC-11):** Add a test starting from parsed YANG config (`pd { length N; }`) through the real DHCP client factory asserting `pdRequested`, `pdLength`, and the derived `iaidPD` reach the Solicit/Request wire messages.
11. **DHCPv4 route removal metric (AC-12):** Expose the effective route metric from `routeMetricState` (`internal/component/iface/register.go`) so `DHCPClient.removeV4Route` removes the default route at `effectiveMetric` (`metric + 1024` while carrier is down), leaving zero `rtproto.Iface` default routes behind.
12. **VPP tunnel idempotency (AC-13):** Check `b.names.lookupIndex(spec.Name)` at the start of `createGRETunnel`, `createIPIPTunnel`, and `createVxlanTunnel` (returning nil when already present); ensure delete calls `b.names.Remove(name)` so no stale reverse entry remains in `nameMap`.
13. **Netlink monitor late-event naming (AC-14):** In `internal/component/iface/cmd/monitor_netlink_linux.go`, maintain a per-stream link-index table seeded from `netlink.LinkList()` at stream start and updated solely by link events (with a short tombstone on `RTM_DELLINK`); route and address events resolve names exclusively from that table and omit `interface` (keeping `interface-index`) when a deleted link's index is tombstoned or unknown, never calling `netlink.LinkByIndex` after the fact.
14. **DHCPv4 client option overload (AC-15):** Wrap the client reply decode in `internal/plugins/iface/dhcp/dhcp_v4_exchange_linux.go` with an RFC 2131 §4.1 overload merger (`decodeV4ReplyWithOverload`) on raw wire bytes (or custom `PacketConn` wrapper over `nclient4`'s receive path before `dhcpv4.FromBytes`): parse options field first, read option 52 from options field only (values 1=`file`, 2=`sname`, 3=both), then parse `file` (128 octets) and/or `sname` (64 octets) within strict field bounds and merge any missing/continued options into `DHCPv4.Options` (options field precedence first, then `file`, then `sname`; option 52 inside `file`/`sname` ignored).

## Acceptance Criteria

| AC ID | Input / Condition | Expected Behavior | Permitted Survivors and Why |
|-------|-------------------|-------------------|-----------------------------|

## Design presentation

### What changes
- Netlink route adds check `rtm_protocol` ownership before replacing; netlink monitor survives `ENOBUFS` with resubscribe + dump-resync and emits `EventUp`/`EventDown` only on state transitions; `monitor system netlink` uses a tombstoned per-stream index map instead of post-hoc `LinkByIndex`.
- `resolver` delivers 100-event bursts without drop and resolves MAC selectors via `Backend.ListLinks`; `showInterfaceCounters` uses `iface.GetLink`; owned registries, `traffic/netlink`, and `checkRAForwarding` resolve logical names to kernel devices; absent mirror destinations defer and retry on link appearance.
- DHCPv6 aborts active Renew/Rebind/Decline exchanges on link flap and tests PD from config; DHCPv4 removes default routes at `effectiveMetric` and decodes RFC 2131 §4.1 option 52 overloaded `file`/`sname` options (`RFC2131-4.1-7`, `RFC2131-4.1-15`).
- VPP GRE/IPIP/VXLAN creates check `nameMap.lookupIndex` and clean reverse entries on delete; VPP reports address lifetimes for reconcile; `TestMPLSIntegration_EgressPopNoNextHop` is proven in Ze's QEMU guest.

### Before and after
- **Before:** Interface route adds can clobber static routes; one netlink `ENOBUFS` kills interface monitoring; every `RTM_NEWLINK` emits spurious up/down events; an absent mirror destination aborts the whole interface commit; DHCPv4 teardown leaves deprioritized routes in the kernel and drops option 52 overloaded options; VPP recreates GRE/IPIP/VXLAN tunnels on every apply; `show interface counters` and MAC lookup fail on unrelated address-dump errors; `checkRAForwarding` goes silent on `mac/match` devices.
- **After:** Every one of those 15 forwarding/interface defects is fixed at its producer with unit, QEMU integration (`userns.Enter`), and RFC 2131 interop proofs.

### Alternatives set aside
- **Doing full Loc-RIB route arbitration for AC-1 here:** set aside because `plan/release/fixes/spec-iface-route-arbitration.md` owns Loc-RIB integration; AC-1 adds only the local protocol-ownership check on `netlinkBackend.AddRoute`.
- **Patching vendored `insomniacslk/dhcp` for AC-15:** set aside per repository dependency hygiene; Ze decodes option 52 overload on the raw reply bytes in `internal/plugins/iface/dhcp/dhcp_v4_exchange_linux.go` before handing off to lease installation.
- **Ignoring absent mirror destinations silently:** set aside because silent drops hide misconfigurations; AC-10 logs a WARN, raises `doctor-iface-mirror-destination-absent` via `issuequeue`, and clears it when the destination appears and installs.

### Documents departed from
- `docs/architecture/iface/logical-name-resolution.md` ("Where the resolver lives, and what it returns"): currently notes that `mac/match` scans the full interface listing including addresses; AC-6 introduces `Backend.ListLinks` so `mac/match` uses link-only reads, and updates this section in the same commit.
- All other documentation updates (`docs/features/interfaces.md`, `docs/architecture/iface/netlink-monitor.md`, `rfc/short/rfc2131.md`) extend existing pages in the same commit without departing from prior decisions.
