## Task

Three live defects remain at HEAD on the BGP peer/dynamic-group add, listener, and pre-start rebuild path (a fourth item from the 2026-11-12 skeleton, `startListenerForAddressPort` returning a bare wrapped listen error with no fix or doctor code, already landed in commit `113f630a83` via `listen_refusal.go` and `internal/core/network/listen_error.go` and is retired into `## Existing Mechanisms`, with its stale open journal row closed by this spec):

| Part | Producer | What the operator meets today | Intended observable fix |
|------|----------|-------------------------------|-------------------------|
| 1. Passive dynamic group installed in the start window gets no listener | `installDynamicGroupsLocked` (`internal/component/bgp/reactor/reactor_dynamic.go`) | After `startMultiListeners` sets `listenersStarted` and releases `r.mu` during `StartWithContext` (before `r.running` is set at the end of standalone plugin waits / announce delay, or in the borrow-mode gap before `r.running = true`), `installDynamicGroupsLocked` returns early on `!r.running \|\| r.stopping`. Nothing else opens a socket for the group, so no dynamic member can connect | Gate `installDynamicGroupsLocked` on `!r.listenersStarted \|\| r.stopping`, matching `addPeerLocked`. A passive dynamic group installed after `startMultiListeners` opens its listener immediately; any member accepted before `peersStarted` is created inert and held in its inbound slot until the barrier lifts, then sends OPEN |
| 2. Refused `AddPeer` leaves partial state behind | `addPeerLocked` (`internal/component/bgp/reactor/reactor_peers.go`) | `addPeerLocked` writes `r.peers[key]`, increments `peerGeneration`, calls `fwdWeights.AddPeer`, `fwdPool.registerOutgoingPool`, updates `peersConfigured`, increments `peersAddedTotal`, calls `setPrefixConfigMetrics`, `raisePrefixStale`, and logs a stale-prefix warning BEFORE opening or MD5-restarting the passive listener. On listen failure, rollback deletes only `r.peers[key]`, leaving pool demand, outgoing pool registration, gauges, irreversible counter increment, prefix metrics, and stale alarm for a peer that does not exist — and in the MD5 restart branch leaves the previously running shared listener stopped | Validate and insert `r.peers[key] = peer` (so `md5PeersForListener`, `listenTTLForListener`, and `listenOwner` see the peer), run the listener open/MD5-restart step FIRST, and on failure delete `r.peers[key]` (and restore any stopped MD5 listener for surviving claimants using its original stored `lkey` host address so its map key spelling stays unchanged). Only after the listener succeeds publish `peerGeneration`, `fwdWeights`, `fwdPool`, `rmetrics`, `setPrefixConfigMetrics`, `raisePrefixStale`, and the stale warning log |
| 3. Pre-start peer replacement closes concurrent inbound TCP connections | `reconcilePeersJournaled` (`internal/component/bgp/reactor/reactor_api.go`), `peer_inbound_held.go`, `peer_connection.go`, `reactor_connection.go` | Before `StartPeers` (`!r.peersStarted`), `RebuildRunningPeers` (called from `OnPostStartup` after Stage 1 plugin declarations) or a reload replaces a restarted peer by deleting it in the remove loop, unlocking `r.mu` for `completeRemovals`, and re-adding it in the add loop (~2 ms gap). A neighbor connecting in that gap — or whose accept resolved the outgoing peer just before `r.mu` was taken and reaches `setInboundConnection` after `stopping` is set — is closed with EOF and waits for its ConnectRetry timer | Replace an unstarted restarted peer (`!r.peersStarted` and `restarted[key]`) atomically in one `r.mu.Lock()` hold (`replaceUnstartedPeer`), transferring its held inbound socket to the replacement (or rejecting with Cease 6/5 if the replacement is active-only) and recording `oldPeer.replacedBy = newPeer` under `oldPeer.mu` before setting `stopping`. `acceptOrReject` and `setInboundConnection` follow `replacedBy` so neither the map gap nor the lookup-to-store race can close the neighbor's connection |

### RFC Summaries (Scope: protocol)
- [ ] `rfc/short/rfc4271.md` - passive TCP establishment and ManualStop / session establishment rules
  → Constraint: RFC 4271 Section 8.2.2 ManualStop forbids opening sessions during a stop (`!r.stopping`); passive TCP establishment accepts inbound TCP connections and sends OPEN once the peer starts in Active state.
- [ ] `rfc/short/rfc4486.md` - BGP Cease NOTIFICATION subcodes
  → Constraint: RFC 4486 Section 4 SHOULD send Cease / Connection Rejected (6/5) when disallowing an accepted inbound transport connection (e.g., when a held connection cannot be adopted because the peer left the configuration or was replaced by an active-only peer) and Cease / Other Configuration Change (6/6) for a restarted peer.

**Key insights:**
- `createDynamicPeer` (`reactor_dynamic.go:139-143`) ALREADY holds a dynamic member accepted before `peersStarted`: it does not call `peer.StartWithContext(r.ctx)` while `!r.peersStarted`, `acceptOrReject` buffers its socket in `peer.inbound`, `openPeerStartBarrierLocked` starts every peer in `r.peers` (including held dynamic members), `peerSlice` excludes `IsDynamic` from `updateDelay`, and `abortStartup` discards every held inbound connection across `r.peers`. The sole remaining defect for Part 1 is the `!r.running` gate in `installDynamicGroupsLocked`.
- `peersAddedTotal` is a monotonic `metrics.Counter` with no decrement operation, so a rollback after calling `Inc()` can never restore it. Moving the listener step BEFORE the six state publications in `addPeerLocked` (keeping only `r.peers[key] = peer` ahead of it so `md5PeersForListener`, `listenTTLForListener`, and `listenOwner` observe the new peer) is the only way a refused add leaves zero state behind.
- Closing ONLY the map-absence gap in `reconcilePeersJournaled` still leaves a lookup-to-store race where an accept goroutine resolved `oldPeer` under `r.mu.RLock()`, released `r.mu`, and reaches `oldPeer.setInboundConnection(conn)` after `oldPeer.stopping` is set. Recording `oldPeer.replacedBy = newPeer` under `oldPeer.mu` alongside `takeUnstartedInbound` and following it in `acceptOrReject` / `setInboundConnection` makes pre-start replacement linearizable with zero drop window.
- Part 3 from the skeleton (`startListenerForAddressPort` returning a plain wrapped error) ALREADY landed in commit `113f630a83` (`listen_refusal.go`, `internal/core/network/listen_error.go`, `internal/component/doctor/checks_listener.go`, `test/plugin/bgp-listen-privileged-port-refused.ci`).

**Behavior to preserve:**
- An active-only peer or active-only dynamic group gets no listener.
- Adding a peer or dynamic group before `StartWithContext` (`!r.listenersStarted`), or after a stop or aborted start (`stopAllListeners` clears `listenersStarted = false`), opens no listener.
- A stop that has begun (`r.stopping == true`) opens no listener and starts no peer.
- No configured peer or dynamic-group member starts or reaches Established before the plugin startup barrier lifts (`r.peersStarted == true`).
- `AddPeer` listener bind refusals continue to name the new peer as owner via `listenOwner` and return `network.ListenError`'s `*opererr.Error` (with `CAP_NET_BIND_SERVICE` / `ss -ltnp` / `ip -brief address show` / `ze doctor`).
- Stored listener map keys retain their original bound spelling across alias lookups and MD5-restart rollback restoration; physical duplicate and self-address validation runs at the binder boundary before peers are installed or listeners open.
- A peer removed from configuration before `StartPeers` still rejects its held inbound connection with RFC 4486 Cease / Connection Rejected (6/5), and a daemon stop or aborted start still closes held inbound connections silently.
- Reloading an already-started peer (`r.peersStarted == true`) that requires restart keeps its existing remove-with-Cease-then-add sequence so the old session sends Cease (6/6) and releases its router-ID claim and captures before the replacement dials or accepts.

**Behavior to change:**
- `installDynamicGroupsLocked` opens listeners whenever `r.listenersStarted && !r.stopping` (matching `addPeerLocked`), rather than waiting for `r.running`.
- `addPeerLocked` keeps its exact-key duplicate check separate from shared `validatePeerSettingsLocked` and runs `ensurePeerListenerLocked` before writing `peerGeneration`, `fwdWeights`, `fwdPool`, `rmetrics`, `setPrefixConfigMetrics`, `raisePrefixStale`, and the stale warning log; on listener failure it deletes `r.peers[key]`, restores any stopped MD5 listener using the original `lkey`'s host address (preserving its stored key spelling), and returns the refusal with zero leaked reactor state.
- `validatePeerTransportsLocked` accepts an excluded `replaceKey` (`netip.AddrPort`, zero for startup and add, `key` for pre-start replacement) so `replaceUnstartedPeer` runs physical duplicate/self-address validation strictly before mutating `r.peers[key]` or opening a listener without colliding `newSettings` against `oldPeer`.
- `reconcilePeersJournaled` replaces unstarted restarted peers (`!r.peersStarted && restarted[key]`) atomically under one `r.mu.Lock()` hold, transfers any held inbound socket to a passive replacement (or rejects it with Cease 6/5 if the replacement is active-only), and sets `oldPeer.replacedBy = newPeer` under `oldPeer.mu` so concurrent accepts follow the replacement instead of closing.

## Data Flow (MANDATORY - see `ai/rules/architecture.md`)

### Entry Point
- **Part 1 (dynamic group in start window):** `Reactor.SetDynamicGroups`, `Reactor.ReconcilePeersWithJournal`, `reactorAPIAdapter.ApplyConfigDiff`, `reactorAPIAdapter.Reload`, or `ApplyConfigOperation(ReconcilePeers)` entering `installDynamicGroupsLocked` while `r.listenersStarted && !r.running && !r.stopping`.
- **Part 2 (refused passive peer add):** `Reactor.AddPeer` (from config reload, `ApplyConfigOperation`, or `AddDynamicPeer`) entering `addPeerLocked` while `r.listenersStarted && !r.stopping` for a passive peer whose `startListenerForAddressPort` returns a bind error.
- **Part 3 (pre-start peer rebuild):** `Reactor.RebuildRunningPeers` (invoked by `bgp/plugin` `OnPostStartup` before `StartPeers`) or any reload calling `reconcilePeersJournaled` while `!r.peersStarted`, concurrent with inbound TCP connections arriving on `Listener` -> `handleListenerConnection`.

### Transformation Path
1. **Part 1:** Caller acquires `r.mu.Lock()` -> `installDynamicGroupsLocked` installs `r.dynamicGroups` and recounts `ActivePeers` -> checks `if !r.listenersStarted || r.stopping { return }` -> for each passive group with valid `LocalAddress`, calls `startListenerForAddressPort(s.LocalAddress, r.peerListenPort(s))` (logging refusal via `logListenRefusal` on bind error). When a dynamic member connects before `peersStarted`, `handleListenerConnection` -> `peerForConnection` -> `tryCreateDynamicPeerAt` -> `createDynamicPeer` inserts the peer without starting it; `acceptOrReject` stores the TCP socket in `peer.inbound`; `openPeerStartBarrierLocked` starts the peer and `runOnce` consumes `peer.inbound` and sends OPEN.
2. **Part 2:** `addPeerLocked` normalizes `settings.Address`, performs its exact-key duplicate check against `r.peers[key]` (returning `ErrPeerExists`), and calls shared `validatePeerSettingsLocked(settings, netip.AddrPort{})` (normalizing `LocalAddress`, checking self-address, link-local zone, address-family match, and calling `validatePeerTransportsLocked(settings, netip.AddrPort{})` when `r.listenersStarted`) -> constructs `peer` via `NewPeer(settings)` -> inserts `r.peers[key] = peer` -> calls `ensurePeerListenerLocked(key, settings, nil)`:
   - If `!r.listenersStarted || r.stopping || !settings.LocalAddress.IsValid() || !settings.Connection.IsPassive()`: returns `nil`.
   - If no listener exists for `(LocalAddress, listenPort)`: calls `startListenerForAddressPort`; on error rolls back `r.peers[key]` (deleting `key` when `oldPeer == nil`, or restoring `r.peers[key] = oldPeer` on replacement) and returns `err`.
   - If a listener exists under original key `lkey` and `settings.MD5Key != ""`: parses the original host address `restoreAddr` from `lkey` via `netip.ParseAddrPort(lkey)` (falling back to `settings.LocalAddress` only if `lkey` fails to parse), stops and removes the existing listener at `lkey`, and calls `startListenerForAddressPort(settings.LocalAddress, listenPort)`; on error first rolls back `r.peers[key]` (deleting `key` when `oldPeer == nil`, or restoring `r.peers[key] = oldPeer` on replacement), then restores the prior listener by calling `startListenerForAddressPort(restoreAddr, listenPort)` so the restored entry retains its original stored key spelling `lkey` for surviving claimants (calling `logListenRefusal` if restore also fails), and returns `err`.
   - Only after `ensurePeerListenerLocked` returns `nil`: calls `publishPeerStateLocked(key, peer, settings)` (`peerGeneration.Add(1)`, `fwdWeights.AddPeer`, `fwdPool.registerOutgoingPool`, `rmetrics.peersConfigured`, `rmetrics.peersAddedTotal`, `setPrefixConfigMetrics`, `raisePrefixStale`, stale-prefix `Warn`), starts `peer` if `r.running && !r.stopping && r.peersStarted`, and republishes the delivery graph if `r.deliveryPublished`.
3. **Part 3:** In `reconcilePeersJournaled`, each key with `restarted[key] == true` when `!r.peersStarted` is placed in `toReplace` (instead of separate `toRemove` + `toAdd` loops). For each replacement, a single `j.Record` step executes `replaceUnstartedPeer(key, newSettings)`:
   - Acquires `r.mu.Lock()`. Checks `!r.peersStarted`, `oldPeer` still present at `key`, and `!oldPeer.hasStarted()` (`oldPeer.cancel == nil`). If the barrier already opened concurrently, releases `r.mu` and falls back to the ordinary remove-then-add sequence.
   - Normalizes `newSettings.Address` and validates `newSettings` via `validatePeerSettingsLocked(newSettings, key)` (omitting `addPeerLocked`'s exact-key duplicate check and passing `replaceKey = key` to `validatePeerTransportsLocked` so `oldPeer` at `r.peers[key]` is excluded while every other peer and self-address alias is checked strictly before mutating `r.peers[key]` or opening any listener). Builds `newPeer`, stores `r.peers[key] = newPeer`, and runs `ensurePeerListenerLocked(key, newSettings, oldPeer)`. On error `ensurePeerListenerLocked` restores `r.peers[key] = oldPeer` (plus rebinding any stopped MD5 listener using its original `lkey` host address), and `replaceUnstartedPeer` releases `r.mu` and returns the error with `oldPeer` untouched.
   - Calls `held, ok := oldPeer.takeUnstartedInboundForReplacement(newPeer)` (locks `oldPeer.mu`, confirms `oldPeer.cancel == nil`, sets `oldPeer.replacedBy = newPeer`, sets `oldPeer.stopping.Store(true)`, takes and clears `oldPeer.inbound`).
   - If `held != nil`: if `newSettings.Connection.IsPassive()`, calls `newPeer.adoptHeldInbound(held)`; otherwise retains `held` to call `rejectHeldInbound(held, r.clock)` after unlocking `r.mu`.
   - Performs `oldPeer` locked teardown (`releaseRouterIDClaim`, `clearPrefixStale`, `health.stop`), deletes `r.peers[key]`, calls `removal := r.removalLocked(oldPeer, peerStop{peer: oldPeer, subcode: message.NotifyCeaseOtherConfigChange})`, immediately stores `r.peers[key] = newPeer` (still under the same `r.mu.Lock()`), and calls `publishPeerStateLocked(key, newPeer, newSettings)`.
   - Releases `r.mu.Unlock()`, rejects any unadoptable `held` socket, and runs `r.completeRemovals(removal)`.
   - Concurrently, any accept goroutine in `acceptOrReject` calls `peer = peer.followReplacement()` at entry, and if `peer.setInboundConnection(conn)` observes `p.replacedBy != nil` under `p.mu` (before the `stopping` close check), it returns that replacement `*Peer` without closing `conn` and `acceptOrReject` retries on the replacement.

### Risks
| ID | Risk | Early signal | Mitigation / fallback |
|----|------|--------------|----------------------|
| R-1 | MD5 listener restart in `addPeerLocked` or `replaceUnstartedPeer` fails after stopping a pre-existing listener stored under original key `lkey` (including when the failed peer's `LocalAddress` is an alias spelling such as `fe80::1%2` for `[fe80::1%eth0]:179`), stranding surviving passive peers or rewriting the stored listener key spelling | Surviving peer tests fail to connect after an MD5 add refusal, or `r.listeners` no longer holds the original `lkey` spelling | Before stopping `existing`, parse the original host address `restoreAddr` from `lkey` (`netip.ParseAddrPort(lkey)`, falling back to `settings.LocalAddress` only on parse error). On MD5 restart failure, first delete `r.peers[key]` (or restore `r.peers[key] = oldPeer` on replacement), then immediately call `startListenerForAddressPort(restoreAddr, listenPort)` to restore the pre-existing listener under its exact original `lkey` spelling (without the failed peer's MD5 key); if restore also fails, log with `logListenRefusal` and return the original refusal |
| R-2 | A second pre-start rebuild replaces `newPeer` again before a slow accept goroutine resumes from `oldPeer`, creating a multi-hop `replacedBy` chain | Accept goroutine lands on a stale intermediate peer and closes | `followReplacement()` and `acceptOrReject`'s retry loop iterate until `replacedBy == nil` (strictly acyclic because every replacement allocates a fresh `*Peer`), so arbitrary chains resolve to the live peer |
| R-3 | `StartPeers` lifts `r.peersStarted` concurrently between `reconcilePeersJournaled`'s snapshot and the `replaceUnstartedPeer` journal step | Peer with a live session enters unstarted replacement path | `replaceUnstartedPeer` re-checks `!r.peersStarted` under `r.mu.Lock()` AND `oldPeer.cancel == nil` under `oldPeer.mu.Lock()`; if either fails, it falls back cleanly to the normal remove-with-Cease-then-add path |
| R-4 | A pre-start replacement changes a peer from passive to active-only while an inbound connection is already held | Active-only peer unexpectedly adopts an inbound socket | `replaceUnstartedPeer` adopts `held` only when `newSettings.Connection.IsPassive()`; otherwise it rejects `held` with `rejectHeldInbound` (RFC 4486 Cease 6/5) after releasing `r.mu`, and `acceptOrReject` closes any redirected concurrent arrival on `!IsPassive()` |
| R-5 | A later peer in the same `reconcilePeersJournaled` batch fails after an atomic pre-start replacement succeeded, requiring journal rollback | Rollback drops the peer or drops its held inbound connection | The `replaceUnstartedPeer` journal undo restores `oldSettings` via the same atomic `replaceUnstartedPeer` while `!r.peersStarted` (preserving held inbound across rollback too), or via remove+`AddPeer` if `peersStarted` has lifted |

## Design presentation

### What changes
Fixes three remaining defects on the BGP peer and dynamic-group listener/startup path (while retiring the already-landed `113f630a83` listen-refusal error item): passive dynamic groups installed during the start window open their listeners on `Reactor.listenersStarted` just like configured peers; a refused `AddPeer` opens or MD5-restarts its listener before mutating pool demand, outgoing pool, metrics, or prefix-stale warnings (and restores any stopped shared MD5 listener on failure), leaving zero partial state behind; and pre-start peer rebuilds replace unstarted restarted peers atomically under `Reactor.mu` with `Peer.replacedBy` forwarding so inbound neighbor TCP connections arriving during the rebuild are held and answered with OPEN rather than closed with EOF.

### Before and after
1. **Passive dynamic group installed during standalone start window:**
   - **Before:** `installDynamicGroupsLocked` checks `!r.running || r.stopping` and returns without binding; a member connecting to the group's address receives `ECONNREFUSED` permanently because `startMultiListeners` already ran.
   - **After:** `installDynamicGroupsLocked` checks `!r.listenersStarted || r.stopping` and opens the group's listener immediately; a member connecting before `peersStarted` is accepted, built inert in `r.peers` with its TCP socket held in `peer.inbound`, and receives BGP OPEN once the startup barrier lifts.
2. **Refused `AddPeer` when listener bind fails:**
   - **Before:** `addPeerLocked` increments `peerGeneration` and `ze_peers_added_total`, adds demand to `fwdWeights`, registers an outgoing `fwdPool`, sets `ze_peers_configured` and `ze_bgp_prefix_*` gauges, raises `prefix-stale` on the report bus, and only then attempts to bind; on bind error it deletes only `r.peers[key]`, leaking all six writes (and stranding surviving peers if an MD5 listener restart failed).
   - **After:** `addPeerLocked` opens or MD5-restarts the listener before any of those six writes; on failure it deletes `r.peers[key]` (and restores a stopped MD5 listener for surviving claimants) and returns the `listenRefusal` `*opererr.Error` with counters, gauges, weights, pools, and report bus completely unchanged.
3. **Neighbor connecting during pre-start peer rebuild (`RebuildRunningPeers`):**
   - **Before:** `reconcilePeersJournaled` deletes the old peer, unlocks `r.mu` for `completeRemovals`, and re-adds the replacement in a later loop (~2 ms gap), closing any inbound connection that arrives in the gap or hits the old peer's `stopping` flag with EOF.
   - **After:** `reconcilePeersJournaled` replaces the unstarted peer atomically under one `r.mu.Lock()` hold and sets `oldPeer.replacedBy = newPeer` under `oldPeer.mu`; every inbound connection arriving before, during, or concurrently with the replacement reaches the replacement's inbound slot and receives BGP OPEN once `StartPeers` lifts the barrier.

### Alternatives set aside
| Alternative | Why set aside |
|-------------|---------------|
| Mutate `PeerSettings` in place on the same `*Peer` during pre-start rebuild (as `planDynamicGroupsLocked` does for dynamic peers) | Does not re-initialize constructor-derived fields (`localAddrString`, `health`, `fwdWeights`, listeners for changed `LocalAddress`/`LocalPort`/`MD5Key`) and breaks the existing peer-replacement contract tested by `TestHeldInboundMovesToTheReplacedPeer` (`require.NotSame(t, before, after)`). |
| Keep a reactor-level `replacingInbound` buffer map keyed by `AddrPort` during the remove-to-add gap | Still leaves the lookup-to-store race on `oldPeer.setInboundConnection` unless `oldPeer` also redirects, adds a second buffer lifetime to drain on failure/abort/stop, and is strictly more complex than atomic single-lock replacement + `replacedBy` forwarding. |
| Undo all six writes inside `addPeerLocked`'s error branch instead of reordering the listener step first | `ze_peers_added_total` is a monotonic Prometheus counter with no `Dec()` method, `peerGeneration` cannot move backwards safely, and `raisePrefixStale` + `Warn` log cannot be un-logged. Opening the listener before publishing those writes is the only way a refusal leaves zero trace. |
| Reject dynamic-group connections arriving before `peersStarted` instead of holding them | `createDynamicPeer` + `acceptOrReject` + `openPeerStartBarrierLocked` already hold pre-barrier dynamic members safely without reaching Established; rejecting them would force neighbors into ConnectRetry backoff unnecessarily. |

## Design Insights

- `addPeerLocked` wrote six pieces of state before the one step that can fail (`startListenerForAddressPort`), including a monotonic Prometheus counter (`peersAddedTotal`) that cannot be decremented on rollback. Because `startListenerForAddressPort` reads only `r.peers` (`md5PeersForListener`, `listenTTLForListener`, `listenOwner`), keeping `r.peers[key] = peer` ahead of the listener step and moving all six state publications after it makes refusal completely side-effect-free.
- Eliminating the map-absence gap in `reconcilePeersJournaled` via atomic single-lock replacement is necessary but not sufficient: an accept goroutine can hold a pointer to `oldPeer` across `r.mu.RUnlock()` and reach `oldPeer.setInboundConnection(conn)` after `oldPeer.stopping` is set. Pairing atomic replacement with `oldPeer.replacedBy = newPeer` under `oldPeer.mu` closes both races completely.
- Commit `113f630a83` already landed the complete operator error + `doctor-bgp-listen` fix for `startListenerForAddressPort` (`listen_refusal.go` + `network.ListenError` + `doctor/checks_listener.go`), leaving only its stale open journal row in `plan/journal/error-names-no-fix-command.md` to close.

## Key Design Decisions
| Decision | Alternatives Considered | Rationale |
|----------|------------------------|-----------|
| Gate `installDynamicGroupsLocked` on `r.listenersStarted && !r.stopping` | Separate flag for groups; wait until `r.running` | Matches `addPeerLocked` (`0de757b33c`) and reuses the single lifecycle flag `startMultiListeners` sets and `stopAllListeners` clears; `createDynamicPeer` already holds pre-barrier members safely |
| Reorder `addPeerLocked` so listener open/MD5-restart runs before the six state publications | Undo each write on failure | `peersAddedTotal` cannot be decremented and `Warn` logs cannot be retracted; listener setup needs only `r.peers[key] = peer` |
| Replace unstarted restarted peers atomically under `r.mu.Lock()` with `Peer.replacedBy` forwarding | In-place `*dst = *src` mutation; reactor-level `replacingInbound` buffer map | Preserves fresh `*Peer` construction semantics (`TestHeldInboundMovesToTheReplacedPeer`), closes both the map gap and the concurrent lookup-to-store race with one pointer field and zero extra cleanup state |
| Retire Part 3 into Existing Mechanisms instead of re-implementing | Add redundant wrapper in `reactor.go` | Commit `113f630a83` already implemented `listenRefusal` (`network.ListenError`), `logListenRefusal` (`doctor-bgp-listen`), `doctor/checks_listener.go`, and `test/plugin/bgp-listen-privileged-port-refused.ci` |

## Known Limitations
- Post-start peer restarts (`r.peersStarted == true`) still remove the old peer with RFC 4486 Cease / Other Configuration Change (6/6) and then add the replacement, which is deliberate because an established session must be torn down and its router-ID claim and captures released before the replacement connects.
- A dynamic group removed on reload continues to leave its listening socket open (shared-socket cleanup remains on the peer-removal and interface-removal paths, as documented in `installDynamicGroupsLocked`).
