## Owner decisions (2026-11-24)

| ID | Decision |
|----|----------|
| D-1 (YANG defaults for external plugins) | Option 3 (presented as Option 1 in interview): Ze delivers **both** the operator-configured values and a separate defaults map in Stage 2 / transaction config payloads (documented in `docs/plugin-development/protocol.md`, with an SDK merge helper), so external plugins receive defaults automatically while still distinguishing explicit settings from omitted leaves. |

## Task

**Problem.** A YANG `default` is applied today only by the four consumers that
remember to call `config.ApplyDefaults` on their own subtree (`iface` tunnels,
`iface` PPPoE client timing, `sysrib` admin distances, and `bgp/config` peer
resolution). Every other consumer either restates the default in Go or runs
with the zero value. Two recorded defects follow directly:

1. `internal/component/iface/yang/ze-iface-conf.yang` declares `default 0;` on
   `leaf accept-ra`, nothing applies it to unit `ipv6`, and the device runs the
   Linux kernel default (`accept_ra = 1`) instead — contradicting both the
   declared schema and (if `default 0` were applied) RFC 4862 Section 5.5.
2. `goyang` parses `uses ... { refine ip { default ...; } refine port { default ...; } }`
   into `Uses.Refine` without applying it onto resolved `Entry` nodes, so
   `LeafNode.Default` is empty for every `uses zt:listener` service. A
   hand-maintained Go table (`RegisterBuiltinListenerDefaults` in
   `listener_defaults.go`) duplicates those ports and is called only by
   `ze doctor` (`CollectListenersWithDefaults`), while `ze config validate`,
   commit (`ValidateContent`), `BuildGraph`, and reload call `CollectListeners`
   (no defaults) or skip the check entirely. Two services colliding on a default
   port pass validation and fail at bind.

**Goal.** Compute YANG schema defaults once on the config delivery path,
delivering both operator-configured values (`ConfigSection.Data`) and a
separate schema defaults map (`ConfigSection.Defaults`) per Owner Decision D-1
with a public `pkg/plugin/sdk` merge helper; delete the four per-consumer
`ApplyDefaults` call sites and fail closed on schema load errors; propagate
YANG `refine` defaults into `LeafNode.Default`, unify listener collection into
one `CollectListeners` backed by schema defaults and per-service empty-list
registrations, delete `RegisterBuiltinListenerDefaults` and
`CollectListenersWithDefaults`, refuse listener conflicts strictly on
`ze config validate`, commit, and reload while `LoadConfigForStart` isolates
conflicts per endpoint across every `ze:listener` service (derived from
`DiscoverListenerServices` so healthy sibling endpoints keep serving and whole
service-container exclusion runs only when an empty-list default is the sole
endpoint or removing the sole explicit entry would synthesize an unconfigured
default); and remove the contradictory `default 0;` from `leaf accept-ra` so
the schema matches RFC 4862 Section 5.5 and runtime behavior.

### RFC Summaries
- [ ] `rfc/short/rfc4862.md`, row `RFC4862-5.5-2`
  → Constraint: RFC 4862 Section 5.5: "However, the processing described below MUST be enabled by default." Removing `default 0;` from `leaf accept-ra` aligns the YANG declaration with Linux runtime behavior and the RFC requirement

**Key insights:**
- `goyang` parses `Uses.Refine` (`[]*yang.Refine`, each carrying `Name` and `Default *Value`) into the AST (`yang.go`) but `goyang/pkg/yang/entry.go` never applies `Refine` onto resolved `Entry` nodes; propagating `Uses.Refine` defaults in `yang_schema.go` removes the need for `RegisterBuiltinListenerDefaults`.
- External plugin YANG modules are already joined and published at `ze start` (`config.PublishExternalModules`) and offline validation (`config.SchemaWithDeclaredPlugins`), so Ze already holds the schema for external plugin roots at Stage 2 and transaction delivery.
- Keeping `ConfigSection.Data` strictly operator-configured and carrying schema defaults in `ConfigSection.Defaults` satisfies D-1, preserves BGP/plugin inheritance-by-absence and reload deletion (`data: "{}"`), and ensures `ConfigDiff` produces zero spurious diffs from defaults.

- [ ] `internal/le/config/ports/portdefaults.go` (`./le config ports check`) - parses `listener_defaults.go` with regexes to compare hardcoded ports against `refine port` in YANG modules (missing `mcp` because `listener_defaults.go` uses a constant name instead of a string literal).

**Behavior to preserve:**
- Every valid config without listener conflicts or contradictory `accept-ra` defaults loads with the same effective behavior.
- `ConfigSection.Data` carries strictly operator-configured values (JSON strings, list order keys, `"{}"` on root removal) so reload diffs and inheritance-by-absence (BGP global -> group -> peer) remain unchanged.
- `ze start` never exits over a service listener conflict (`docs/architecture/core-design.md`, Design decisions, 2026-11-26); only the conflicting endpoint (or sole empty-list-default service block) stays down and is reported in the log and `ze doctor` under `doctor-service-not-started`, while healthy sibling endpoints of the same service and all other services start.
- External plugins that ignore the new `ConfigSection.Defaults` field continue working identically on `ConfigSection.Data`.

**Behavior to change:**
- `rpc.ConfigSection` carries an additive `defaults` (`json:"defaults,omitempty"`) field populated once on the delivery path from the published YANG schema, and `pkg/plugin/sdk` provides the merge helper (D-1).
- The four per-consumer `config.ApplyDefaults` call sites are removed; schema load/lookup failures fail closed everywhere (including BGP peer defaults).
- YANG `refine` defaults propagate into `LeafNode.Default`; `RegisterBuiltinListenerDefaults` and `CollectListenersWithDefaults` are deleted; one `CollectListeners` with schema defaults and per-service empty-list registrations serves `ze config validate`, commit, reload, `BuildGraph`, and `ze doctor`.
- `leaf accept-ra` in `ze-iface-conf.yang` declares no `default 0;`.

## Data Flow (MANDATORY - see `ai/rules/architecture.md`)

### Entry Point
- Config file, CLI/web editor commit, API commit, SIGHUP reload, or `ze config validate`: parsed into `*config.Tree` against the published `*config.Schema` (compiled-in plus joined external plugin YANG modules).

### Transformation Path
1. Schema build (`internal/component/config/yang_schema.go`): convert resolved goyang modules into `*config.Schema`, propagating `Uses.Refine` `default` statements onto refined `LeafNode.Default` with `validateLeafDefaults` and `CanonicalModuleDefault`.
2. Parse and validate (`cmd_validate.go`, `loader.go`, `service_blocks.go`):
   - Listener conflict check runs the single `config.CollectListeners(tree, schema)` (which reads explicit entries plus schema-derived `refine` defaults and per-service empty-list registrations, attaching `ContainerPath`, `ListName`, `EntryKey`, and empty-list-synthesis provenance from `DiscoverListenerServices(schema)` onto each `ListenerEndpoint`) and `FindListenerConflict` / `ValidateListenerConflicts`.
   - `ze config validate`, commit (`ValidateContent`), and SIGHUP reload (`LoadConfig`) refuse any conflict with `config-listener-conflict`.
   - Daemon startup (`LoadConfigForStart`) runs `excludeListenerConflicts(tree, schema)` after `excludeInvalidServiceBlocks(tree)` so every `ze:listener` service (including `environment/ssh`, `environment/api-server/rest`, `telemetry/prometheus`, `service/dns-resolver`, `interface/wireguard`, `environment/bmp`, and external plugins) is covered without exiting `ze start`: when a conflicting endpoint is an explicit list entry with healthy sibling entries remaining (or belongs to a service with no empty-list default), only `<ContainerPath>/<ListName>[<EntryKey>]` is removed so healthy sibling endpoints still serve; only when an empty-list default is the sole endpoint (or removing the sole explicit entry would leave an empty list that synthesizes an unconfigured default) is the service container `<ContainerPath>` removed. Each exclusion is appended to `LoadConfigResult.ExcludedBlocks` (reported under `doctor-service-not-started` in log and `ze doctor`, with `saveToStore = false` in `applyEvolutions`).
3. Plugin config delivery (`BuildPluginConfigSections`, `buildPluginConfigSectionsTransition`, `reloadConfigSections`):
   - Lower `*Tree` with `ToPluginMap()` for `ConfigSection.Data` (operator-configured values unchanged, `"{}"` on root removal).
   - Compute the root's schema defaults map from `config.YANGSchema()` once (non-mutating, respecting presence containers, list entries, and `yang.CaseInEffect`), failing closed if the schema fails to load.
   - Marshal the defaults map into `ConfigSection.Defaults` (`omitempty` when empty or when an external root declares no YANG schema).
   - Deliver `[]rpc.ConfigSection` over Stage 2 (`ze-plugin-callback:configure`), transaction verify (`ze-plugin-callback:config-verify`), and in-process `VerifyPluginConfig`.
4. Consumer read:
   - Compiled-in and external Go plugins call `sdk.MergeSectionDefaults` (or `sdk.MergeConfigMaps`) to obtain defaults merged under operator values, or inspect `Data` and `Defaults` separately when explicit-vs-omitted matters (for example, `accept-ra` or inheritance).
   - Non-Go external plugins read the JSON `data` and `defaults` fields directly per `docs/plugin-development/protocol.md`.
   - In-process BGP peer resolution (`peerSettingsFromTree`) runs `ResolveBGPTree` (global -> group -> peer inheritance-by-absence) and then applies peer schema defaults via the shared fail-closed `config` helper.
5. `ze doctor` (`checks_listener.go` `collectSchemaListeners`): calls the same `config.CollectListeners(tree, schema)` with no `sync.Once` registration.

## Design presentation

### What changes

YANG defaults are computed once on the config delivery path and delivered to both compiled-in and external plugins as an additive `defaults` map beside operator-configured `data` on `rpc.ConfigSection` (Owner Decision D-1), with a public `pkg/plugin/sdk` merge helper (`MergeSectionDefaults`, `MergeConfigMaps`) so every plugin receives YANG defaults automatically while still distinguishing explicit operator settings from omitted leaves. The four per-consumer `config.ApplyDefaults` calls (`iface` tunnels, `iface` PPPoE client timing, `sysrib` admin distances, and `bgp/config` peers) are removed, and schema load failures fail closed everywhere instead of returning silent zero defaults. On the listener side, `yang_schema.go` propagates `Uses.Refine` `default` statements onto `LeafNode.Default`, `RegisterBuiltinListenerDefaults` and `CollectListenersWithDefaults` are deleted, each service registers its own empty-list and transport facts from its own package, and one `CollectListeners` feeds `ze config validate`, commit, SIGHUP reload, `BuildGraph`, and `ze doctor` — refusing default-port conflicts whole on validate, commit, and reload while `LoadConfigForStart` isolates conflicts per endpoint across every `ze:listener` service (via `DiscoverListenerServices` provenance, removing only the conflicting `<container>/<listName>[<key>]` entry when healthy siblings remain or no empty-list default exists, and falling back to `<container>` only when an empty-list default is the sole endpoint or removing the sole explicit entry would synthesize an unconfigured default) per the 2026-11-26 "Ze always starts" decision. Finally, `leaf accept-ra` in `ze-iface-conf.yang` drops its contradictory `default 0;` so omitted `accept-ra` leaves Linux kernel RA processing enabled per RFC 4862 Section 5.5.

### Before and after

1. **Default-port listener conflict at `ze config validate` and reload**
   - Before: Enabling `environment { web { enabled true; } looking-glass { enabled true; server main { ip 0.0.0.0; port 3443; } } }` passes `ze config validate` (exit 0) because `CollectListeners` never sees `web`'s `refine port { default 3443; }`, then fails at bind time.
   - After: `ze config validate` exits 1 with `config-listener-conflict: listener conflict: web (tcp 0.0.0.0:3443) and looking-glass main (tcp 0.0.0.0:3443) bind to the same endpoint`. Commit and SIGHUP reload refuse whole with the same conflict; `ze start` (`LoadConfigForStart`) excludes only the conflicting endpoint (`<container>/<listName>[<key>]` when healthy sibling entries remain or no empty-list default exists, or `<container>` only when an empty-list default is the sole endpoint or removing the sole explicit entry would synthesize an unconfigured default), logs `doctor-service-not-started` (keeping `saveToStore = false`), and starts networking, healthy sibling endpoints, and all other services across every `ze:listener` service.

2. **Plugin config delivery (compiled-in and external, D-1)**
   - Before: Stage 2 `ze-plugin-callback:configure` and reload `ze-plugin-callback:config-verify` send only `{"sections":[{"root":"<root>","data":"{...}"}]}` with no YANG defaults; every consumer either calls `internal/component/config.ApplyDefaults` itself, hardcodes the default in Go, or runs with Go's zero value.
   - After: Stage 2 and `config-verify` send `{"sections":[{"root":"<root>","data":"{...}","defaults":"{...}"}]}` where `data` holds strictly operator-configured JSON strings (`"{}"` on removal) and `defaults` holds the schema-derived defaults map for that root. Go plugins (compiled-in and external) call `sdk.MergeSectionDefaults` to merge defaults under explicit values while still able to inspect `Data` and `Defaults` separately.

3. **Interface `ipv6 accept-ra` when omitted**
   - Before: `ze-iface-conf.yang` declares `default 0;` on `leaf accept-ra`, so `show` and docs report `0`, while `applySysctl` writes no `accept_ra` sysctl when omitted and Linux runs `accept_ra = 1`.
   - After: `ze-iface-conf.yang` declares no `default` on `leaf accept-ra`; omitting it writes no `accept_ra` sysctl (leaving Linux's RFC 4862 Section 5.5 default in force), and explicitly setting `accept-ra 0`, `1`, or `2` writes that value to `net.ipv6.conf.<iface>.accept_ra`.

4. **Schema load failure during BGP peer default application**
   - Before: `applyPeerSchemaDefaults` silently returns with no defaults and no error if `YANGSchema()` or `schema.Lookup("bgp/peer")` fails.
   - After: Peer default application returns the schema error and refuses the build instead of running with zeroed defaults.

### Alternatives set aside

| Alternative | Why set aside |
|-------------|---------------|
| Merge YANG defaults directly into `ConfigSection.Data` for all plugins (D-1 Option 1) | Erases the distinction between an omitted leaf and an explicit setting equal to the default, breaking inheritance-by-absence and changing `data` bytes for third-party plugins; Thomas selected Option 3 (separate `defaults` map + SDK merge helper) on 2026-11-24 |
| Deliver no defaults to external plugins (D-1 Option 2) | Splits compiled-in and external plugin behavior and forces external plugin authors to restate every YANG default in code; Thomas selected Option 3 on 2026-11-24 |
| Keep `RegisterBuiltinListenerDefaults` and `./le config ports check` beside YANG `refine` | Maintains a second hand-edited port table that drifts from YANG `refine` (and already missed `mcp` due to a constant literal) and runs only for `ze doctor` |
| Apply `default 0` to `accept-ra` on Linux interfaces | Violates RFC 4862 Section 5.5 ("However, the processing described below MUST be enabled by default") |
| Refuse `ze start` on a listener conflict via `CreateReactorFromTree` | Contradicts Thomas's 2026-11-26 ruling ("Ze always starts"): a service configuration must not prevent networking from starting |

## Key Design Decisions

| Decision | Alternatives Considered | Rationale |
|----------|------------------------|-----------|
| Deliver `ConfigSection.Data` (operator-configured) plus separate `ConfigSection.Defaults` (schema defaults) with an SDK merge helper (Owner Decision D-1) | (1) Merge defaults into `Data` for all plugins; (2) deliver no defaults to external plugins | Both compiled-in and external plugins receive schema defaults from one delivery-path computation without breaking inheritance-by-absence, deletion detection (`data: "{}"`), reload diffs, or third-party wire compatibility |
| Propagate `Uses.Refine` defaults into `LeafNode.Default` and unify on one `CollectListeners` | Keep `RegisterBuiltinListenerDefaults` and `./le config ports check` | The Go port table existed only because `goyang` drops `refine` on `Entry` nodes; propagating `refine` removes the second copy and lets validate, commit, reload, graph, and doctor share one collector |
| Refuse listener conflicts whole on validate, commit, and reload; isolate conflicts per endpoint via `DiscoverListenerServices` provenance at `ze start` | Refuse at `ze start` via `CreateReactorFromTree`, or exclude whole service blocks only via `RegisterServiceBlock` | Obeys both halves of the 2026-11-26 owner decision ("Ze always starts"): every `ze:listener` service is coverable at `LoadConfigForStart` without exiting, healthy sibling `server` endpoints keep serving when one entry conflicts, whole-container exclusion runs only when an empty-list default is the sole endpoint (or removing the sole explicit entry would synthesize an unconfigured default), and every exclusion is reported in `ExcludedBlocks` under `doctor-service-not-started` and `ze doctor` |
| Remove `default 0;` from `leaf accept-ra` | Apply `default 0` to `net.ipv6.conf.<iface>.accept_ra` | RFC 4862 Section 5.5 requires RA processing to be enabled by default; leaving the leaf with no default matches Linux runtime behavior and the RFC |
