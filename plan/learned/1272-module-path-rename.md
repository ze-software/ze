# 1272 -- Renaming the module path (codeberg.org -> github.com)

## Context

Codeberg's 2026-07-23 policy change made the project's hosting there untenable,
so the Go module path moved from `codeberg.org/thomas-mangin/ze` to
`github.com/ze-software/ze`. The path appears 9162 times in 3715 tracked files,
which makes it look like a `sed` job. It is not: several of the places the module
path lives are invisible to a text substitution, and one of them corrupts a file
silently while leaving it compiling. The work was to build the rename as a tool
(`scripts/dev/rename_module_path.py`) rather than a one-off command, so the next
rename is a dry run and an `--apply` instead of a forensic exercise.

## Decisions

- **A tool with a dry run, not a shell one-liner.** Chosen over
  `git grep -l | xargs sed` because the interesting part of the rename is the set
  of places `sed` cannot reach, and a one-liner has nowhere to put that
  knowledge. Dry-run by default, `--apply` to execute, matching
  `migrate_module.py` and `yang_move.py`.
- **Refuse `*.pb.go`, regenerate them instead.** The embedded `rawDesc` is a
  serialized `FileDescriptorProto`, where `go_package` is a length-prefixed
  field. The old value needed 44 bytes (`Z,`), the new one 40 (`Z(`). A textual
  substitution leaves the prefix claiming 44 bytes of a 40-byte string: the file
  still compiles, and the descriptor decodes to garbage at package init. The tool
  refuses those files, rewrites the `.proto` (the canonical input), and points at
  the new `make ze-proto-gen`, which builds `protoc-gen-go` and
  `protoc-gen-go-grpc` from `vendor/` so the generator versions stay pinned by
  `go.mod`.
- **Rewrite the path spelled as quoted segments too.** Six appliance tests name
  gokrazy's builddir as
  `filepath.Join(.., "codeberg.org", "thomas-mangin", "ze")`. A literal-only
  rename leaves them compiling, passing review, and failing at run time against a
  directory that moved. The segment rewrite applies only when the old and new
  paths have the same depth; a depth change is skipped rather than guessed at.
- **Move directories whose NAME is the module path.**
  `gokrazy/ze/builddir/<module>/` mirrors the path on disk. Both paths happen to
  be three segments, so the builddir's `replace ../../../../../../` still
  resolves; a depth change would have needed that rewritten as well.
- **Re-stamp the RFC audit fingerprints mechanically, and prove it.** Rejected a
  full `/ze-rfc-audit rfc7606` re-run and rejected editing the fingerprints by
  hand. See Gotchas.
- **Report rather than guess at things that merely look like the module path.**
  `.claude/settings.local.json` holds this machine's absolute checkout path,
  which the rename does not move; `rfc/audit/*.json` holds the written history of
  past renames. Both are skipped, and every skipped occurrence is counted and
  printed, so an exclusion that stops being correct is visible.
- **Hosting URLs are a separate decision from the module path.** The tool reports
  leftover references to the old HOST instead of rewriting them, because the two
  forges spell paths differently: Codeberg's `/src/branch/<b>/<path>` is GitHub's
  `/blob/<b>/<path>`. A blind rewrite produces plausible dead links.

## Consequences

- A future rename is `python3 scripts/dev/rename_module_path.py --to <module>`,
  then `--apply`, then `make ze-proto-gen`. The tool is idempotent: a second run
  reports zero occurrences and zero moves.
- `make ze-proto-gen` exists for the first time. The `.pb.go` files were
  previously regenerated by hand; the target pins the plugins to `vendor/` so
  only the `protoc vN` header comment tracks the locally installed protoc.
- `Makefile` now carries `ZE_MODULE`, so a target needing the module path has one
  place to read it.
- The `rfc/audit/*.json` files grew a `reaudit_history` array. `load_audit` reads
  only `requirements`, so extra top-level keys are inert.

## Gotchas

- **The protobuf descriptor fails silently.** It compiles. It only shows up when
  something forces `zepb`'s package init, and nothing under `api/` has tests. The
  proof the regeneration was right is
  `go test ./internal/component/api/grpc/...`, which imports the package and
  therefore parses the descriptor.
- **`goimports` must be `-format-only`.** Plain `goimports -w` also adds and
  removes imports, resolved for ONE build context, so it strips imports that only
  a build-tagged file uses. The module-local group must still be re-sorted
  (`-local <new>`): `go build` tolerates a mis-sorted group, golangci-lint does
  not.
- **The RFC audit gate fires on a rename, and re-auditing is the wrong answer.**
  `tagged_unit_shas` fingerprints the WHOLE enclosing test file, so one rewritten
  import line stales every verdict tagged in that file: 16 RFC 7606 verdicts
  here. Re-running the semantic audit to conclude "nothing changed" gains no
  information and risks a rushed pass stamping `enforced` without reading, which
  is exactly the stale assurance the fingerprint exists to prevent. The project
  had already resolved this once by hand (`reaudit_note`, 2026-07-22) with a
  written argument that a later revision of that same note admits was partly
  wrong about its own scope. So the re-stamp is now mechanical:
  `reseal_rfc_audits` re-seals a verdict ONLY after proving, per file, that the
  file's normalised content at HEAD with the old path replaced by the new one is
  identical to its content now, and that the requirement text is unchanged.
  Anything else is refused and left stale. It imports `rfc_requirements`' own
  `_normalize`/`test_sha` rather than reimplementing them, because a second copy
  of the fingerprint rule that drifted would re-seal against a hash the gate does
  not compute.
- **The proof only works before the commit.** It compares the working tree
  against HEAD, so the re-stamp must run while the rename is still uncommitted.
- **`git ls-files` reports the pre-move path until the rename is committed**, so
  a second dry run would otherwise keep listing a directory move that already
  happened. The plan filters moves whose source no longer exists on disk.
- **Do not put the module paths in a file the tool rewrites.** The first version
  of the re-stamp note named both paths while `rfc/audit/` was still in scope, so
  the NEXT rename would have quietly rewritten the record of this one into a
  false account. `rfc/audit/` is now skipped outright.
- **Test fixtures must not use the real module paths.** The tool rewrites every
  tracked file, so `rename_module_path_test.py` uses
  `oldforge.example/owner/proj`; real paths would have rewritten the fixtures out
  from under the test.
- **`gokrazy/modcache/` looks skippable and is not.** It is a cache of
  third-party modules, but the shim `go.mod` at its root declares a module inside
  our own namespace.
