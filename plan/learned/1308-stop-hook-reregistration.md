# 1308 -- Stop hook re-registration

## Context

`.claude/hooks/block-premature-stop.sh` left the `Stop` event on 2026-06-29, in
commit `41e5fa44f`. `plan/learned/1306-delegation-reminder-position.md` recorded
the owner decision of 2026-07-30: leave it unregistered, and correct the ten
surfaces that called it live (`1306:22`, which corrects eight and holds two
back). On 2026-07-31 Thomas reversed that decision. The
trigger was a session that worked inline instead of delegating, which is the one
failure the hook's delegation nudge exists to report. Nothing else reports it.

## Decisions

- **Register the hook FIRST in the `Stop` array**, ahead of `session-end-summary.sh`. Order is necessary, and it is not sufficient. `block-premature-stop.sh:150-156` reads `tmp/session/.session-<SID>` to gate the closure check, the in-progress warning and the delegation nudge. A `Stop` array that released the claim first leaves only the stop-phrase scan alive. That is a live hook with three silent gates, a subtler copy of the bug this work fixes. `delegation-stop-hook-runs-before-marker-release` pins the order.
- **Move the claim release from `Stop` to `SessionEnd`.** This is the second half of the same fix, and array order alone does not deliver it. `session-end-summary.sh` called `_release_session` (`.claude/hooks/lib/state-file.sh:71-76`) at the end of every Stop event, and a Stop hook fires between every turn. The claim therefore died after turn one, and all three marker-gated checks fired once per claim and then went silent. The closure gate suffered worst, because it can only exit 3 after commit A lands, many turns after the claim. The release now runs inline in `session-end-scratch.sh:60`, on `SessionEnd`, against the validated session id from stdin (`:43-46`). The `reason = resume` guard at `:38` keeps the claim for a session that will return. Four fixtures pin the new lifetime: `delegation-claim-survives-stop`, `delegation-nudge-fires-on-second-stop`, `delegation-claim-released-at-session-end` and `delegation-claim-survives-resume`.
- **Pin BOTH ends of a lifetime change, not only the end that broke.** A lifetime change needs a fixture for the release, not only for the survival. The first three fixtures all asserted that the claim SURVIVES. Deleting the release line at `session-end-scratch.sh:60` therefore left the whole suite green. The OFF half of the claim lifetime was untested, and a leak was invisible. `delegation-claim-released-at-session-end` asserts the marker is gone after `SessionEnd`. `delegation-claim-survives-resume` asserts the `reason = resume` guard at `:38` keeps it. Whenever you move WHEN a thing dies, write one fixture for alive and one for dead.
- **Pin the registration with a fixture, over describing it in a rule.** Prose was wrong for a month across ten surfaces. `delegation-stop-hook-registered` and `delegation-stop-hook-runs-before-marker-release` read the `Stop` array directly. The precedent was already there in `delegation-reminder-registered`.
- **Exempt markup from the stop-phrase scan, over dropping phrases from the list.** The scan blocked its own first live turn, on a report that quoted a banned phrase in backticks as an example. A new `SCAN` variable strips fenced blocks and inline backtick spans before the loop.
- **Backticks only, not every quoted span.** Stripping double quotes as well would hide real permission-seeking that happens to quote something.
- **Split the phrase list in two, over deleting the phrases that conflicted.** `.claude/rules/session-start.md:72` REQUIRES the model to stop and ask `What next?` once the original task is done. The scan blocked that exact sentence with exit 2, so two live rules contradicted each other and no message satisfied both. Deleting `what next` and its siblings was the cheap fix, and it loses the detection entirely, because the same words ARE premature stopping mid-spec. `PHRASES` (`block-premature-stop.sh:95-124`) still always blocks. `COMPLETION_PHRASES` (`:136-141`) joins the scan only when `OPEN_WORK=1`, which the in-progress warning sets beside itself (`:180`, assembled at `:200-203`). The state check therefore runs BEFORE the scan. Its own exit 2, the closure gate, stays unconditional. `stop-phrase-what-next-allowed-when-no-open-work` (rc=0) and `stop-phrase-what-next-blocks-with-open-work` (rc=2) pin both halves.
- **Bound the PHRASE SCAN with the retry flag, over exiting the whole hook early.** The harness sets `stop_hook_active` when a Stop hook already refused this stop, and nothing in the repo read that field. The first version exited 0 on it, ahead of everything. That also skipped the spec-closure gate, which is a real exit 2. Tripping any phrase on turn N therefore switched the closure gate off for turn N+1. The field is now a flag, `STOP_RETRY` (`:26-29`), and it gates the scan loop alone (`:205-214`). The scan needs the bound, because its only escape is rewording and a session cannot reword a sentence another rule mandates. The closure gate needs no bound, because it has two documented escapes: run commit B, or write `tmp/session/.closure-ack-<stem>` (`spec-closure-check.py:266-269`). It prints the second escape in the very message it blocks with. `stop-hook-honours-stop-hook-active` and `stop-hook-retry-still-runs-state-checks` pin both halves.
- **Allow a stop on input the hook cannot read.** `set -eo pipefail` let a jq parse failure kill the script, so a registered blocking hook returned exit 5, a code its own header never defines. `|| TEXT=""` at `:36` makes malformed input exit 0. `stop-hook-malformed-input-allows-stop` pins it.
- **Correct the learned summaries with dated bullets, over rewriting them.** `1306` and `1289` are historical records. Each carries a `**CORRECTION (2026-07-31).**` bullet naming what the reversal voids.

## Consequences

- All four gates run, on every turn rather than only the first. The stop-phrase scan and the spec-closure check block with exit 2. The in-progress and delegation reasons warn with exit 1. On a retry the phrase scan alone stands down, and the other three still run.
- The closure gate, the in-progress warning and the delegation nudge only fire when the session has CLAIMED a spec (`block-premature-stop.sh:150-156`). A session with no claim gets the phrase scan and nothing else, so inline work on an unclaimed spec is still unreported. `delegation-no-spec-no-nudge` pins that boundary deliberately. Widening it is a separate decision.
- THREE hooks read a marker path that nothing had written since the per-session marker move. All three now read `tmp/session/` (`session-end-summary.sh:19`, `pre-compact-save.sh:18`, `pretool-writeedit.py:1346`).
- `plan/handover/01-delegation-reminder-blocked-files.md` must go in the closure commit, and it is still on disk. Its step 2 instructs a future session to write, into `ai/INDEX.md`, a statement that the reversal makes false.
- A claim leaks when `CLAUDE_CODE_SESSION_ID` is unset, because `SessionEnd` resolves its id from stdin (`session-end-scratch.sh:43-46`). The 24h sweep in `_cleanup_stale_markers` (`.claude/hooks/lib/state-file.sh:82`) bounds the leak.
- **Extending a lifetime can wake a dormant reaper.** That same sweep deletes any marker whose mtime is over 24h old, and it runs from `session-start.sh:11` at every session start in the checkout. `_claim_spec` (`state-file.sh:61-68`) sets that mtime once and nothing rewrites it. So a session running longer than a day lost its LIVE claim, and all three marker-gated checks with it, the moment any other session started. The sweep was harmless while the claim died on the first Stop, and became reachable the instant the release moved to `SessionEnd`. The hook now touches the marker when it reads it (`block-premature-stop.sh:153`), because reaching a Stop proves the session is alive. `delegation-claim-heartbeat-on-stop` and `delegation-claim-survives-stale-sweep` pin it. The general lesson: when you make something live longer, re-read every janitor that was previously unreachable for it.

## Gotchas

- **A hook on disk with green fixtures can still fire on nothing.** Every delegation fixture passed for a month against a script wired to no event. Registration lives in `.claude/settings.json`, and nothing read it until now. Check the array, never the file's existence. This is `1306`'s lesson, and it survived the reversal intact.
- **A phrase scanner that reads its own documentation will block it.** Any greppable banned-phrase list needs a markup exemption, or writing about the list becomes impossible. `stop-phrase-fence-is-not-a-bypass` proves the exemption is not an evasion route.
- **A text filter in front of a gate must fail toward scanning MORE, never less.** The first markup filter dropped every line after an unclosed fence. A message whose fence stayed open then passed a real request with rc=0. A gate that disables itself is worse than the false positive it prevents. An unclosed fence proves the rule, because the author never meant a code block. The filter is at `block-premature-stop.sh:72-88`, and FOUR guards are now enumerated above it at `:54-66`. Their lead-in reads "Four guards", corrected from "Three" when guard 4 was added. An unclosed fence emits its buffered lines at EOF. A fence closes only on a run at least as long as the opener, so a ````markdown wrapper cannot leak. When the filter strips everything, the hook scans the raw text, because an empty string matches nothing. Inline spans are stripped only on a line whose backticks BALANCE. `stop-phrase-unclosed-fence-still-blocks`, `stop-phrase-all-markup-scans-raw-text`, `stop-phrase-nested-fence-ignored` and `stop-phrase-unpaired-backtick-still-blocks` pin the four.
- **The invariant a filter DECLARES is the thing to test it against.** The comment said "scan MORE, never less", and the inline-span strip broke it on its own third guard. The awk `gsub` for a backtick-delimited span ran left to right over the whole line. A stray backtick therefore paired with the OPENING tick of a later legitimate span, and deleted the text between. A real request sits exactly there. A dropped closing backtick is an ordinary typo, so this needed no intent to reach. The strip now runs per line, and only when that line's backtick count is even (`:83`). An odd count leaves the line raw, which scans more. Read a declared invariant as a test list, and write one case per way to violate it.
- **Two consumers of one field must share one pattern.** The hook reads a spec's `| Status |` metadata row, and so does `spec-closure-check.py:54`. The hook's first version anchored on `^Status:`, which matched no spec at all, and the replacement was stricter about spaces than the Python. A stricter reader lets the two disagree about whether a spec is open, so the hook now tolerates surrounding spaces (`:178`). When you copy a field's pattern into a second reader, copy its tolerance too.
- **A fixture that asserts only an exit code can pass through the very bypass it names.** `stop-phrase-fence-is-not-a-bypass` checked `rc == 2` alone. Under an inverted fence toggle the hook discards the outside text and the FENCED phrase matches. That still yields rc=2, so the fixture stayed green through the exact leak it exists to disprove. Assert WHICH rule fired. It now requires `would you like me to` in the output and `let me know` absent, and the fenced phrase sits EARLIER in `PHRASES` than the outside one. The loop breaks on first match (`:207-214`), so a leak changes the reported pattern and the fixture goes red. With the two phrases the other way round a leak stays invisible.
- **A phrase gate that cannot see task state will contradict any rule that mandates a phrase.** The scan matched on wording alone, and wording alone does not distinguish the two failures. `What next?` after the task is done is behavior `.claude/rules/session-start.md:72` REQUIRES. The same words mid-spec are premature stopping. A gate blind to that state must either block a mandated sentence or lose the detection, and it has no third option. Read the state first, then choose the pattern set. When you add a phrase to any greppable list, ask which rule mandates that phrase somewhere, and gate accordingly.
- **A fixture whose setup returns early tests nothing after that point.** `delegation-claim-survives-stop` ran against a fixture project with no git repository, so `session-end-summary.sh` returned at its clean-tree guard (`:46-49`) and never reached the release site. The fixture passed with the bug restored. It now runs `git init` and writes an uncommitted file, and `delegation-summary-reaches-end` asserts the hook wrote its snapshot before the claim is checked.
- **THREE readers used `.claude/.session-<SID>`, a path with zero writers.** `session-end-summary.sh` and `pre-compact-save.sh` left `SELECTED_SPEC` always empty, so no session snapshot ever recorded its spec and the post-compaction Active Spec section never rendered. The third was `c_pre_write_go` in `pretool-writeedit.py`, whose "state file must mention the claimed spec" branch was therefore dead. That one is the sharpest case. The SAME function already resolved the correct path through `state_file()` a few lines above (`pretool-writeedit.py:1337-1346`), so one function read two marker locations. The bug survived because all three exit 0 regardless, so nothing ever went red. Grep the WRITER of a path before you trust any reader of it, and count the readers rather than fixing the first two you find.
- **`make ze-test-health` reads the whole working tree.** During this work it regenerated `test/health/quality-baseline.json` and `test/health/sensitivity-baseline.json` from a concurrent session's uncommitted RFC 7296 tests. Those are ratchet baselines. Committing them blesses numbers no commit contains, and every later run goes red if that work changes. They were excluded here, and they belong to whoever lands the 7296 tests.
