# 1169 — CLI root namespace grammar

## Context
The CLI grammar rules R1-R9 (`ai/rules/cli.md`) were enforced only over the YANG command tree; the `scripts/checks/cli_grammar.go` gate never saw root handlers registered via `registry.MustRegisterRootHandler`. So the root namespace drifted: `ze format` was the carrier for the whole pipe-operator language yet named after one operator *kind* (`ze format match` asks a "format" command for a filter), and four roots hyphenated two ideas that YANG already models as two tokens (`traffic-control`, `isis-decode`, `ospf-decode`, `update-serve`). The goal was to make the root namespace obey the same grammar the tree obeys AND extend the gate so it cannot drift again — the gate being the load-bearing deliverable.

## Decisions
- Name the offline carrier `ze pipe`, not `ze view`/`ze fmt`/etc.: `pipe` is the word the codebase already uses (`pipe.go`, `ParsePipe`, `knownPipeOps`, `ai/rules/cli.md`) and reads correctly at a literal shell pipe. `format` is a *kind within* the operator set, so it could never name the set.
- `update serve` via the **local-handler** registry, not a root handler: `update` is a YANG verb, so `isYANGVerb` returns before root dispatch — a root named `update` is dead code. `RunCommand` consults local handlers before the YANG tree (the mechanism `show version` already uses under the `show` verb).
- `traffic`/`isis`/`ospf` as **root handlers with a closed-keyword sub-dispatch** (member `control`/`decode`) inside the owning package — chosen over a YANG container (these are offline tools with no config surface) and over promoting operators to roots (`ze match` would collide with YANG verbs).
- Extend the gate with a **cross-surface** feeder, not `CheckSiblings` reuse: `CheckSiblings` fires only when the colliding namespace is a sibling at the same tree level, and no `traffic` root existed to be `traffic-control`'s sibling — which is exactly why the gate stayed green over four violations. New pure fn `grammar.CheckRootNamespace(roots, namespaces)` flags a root whose left hyphen-segment names a YANG verb or container.
- Put the fixture test in the `grammar` package, not `scripts/checks/cli_grammar_test.go`: the gate is `//go:build ignore package main`, so its `_test.go` can only run it as a `go run` subprocess and cannot unit-test its functions. A fixture red/green test needs a pure function.
- Hard cuts, no aliases (`git tag` = 0, nothing shipped) per `ai/rules/no-layering.md`; negative ACs assert each old name now fails.

## Consequences
- The grammar gate now has **four feeders** (static YANG gate, plugin-registration, runtime guard, root-namespace). A future hyphenated root whose left segment names a namespace fails `make ze-cli-grammar-check`; the gate prints "Roots checked: N".
- `traffic`/`isis`/`ospf`/`traffic control`/`isis decode`/`ospf decode` are now object-rooted and discoverable (bare `ze traffic` enumerates `control`). Completion/usage/TUI needed no edits — they derive from `registry.ListRoot`.
- The three tool CLIs are now `codegen:skip` and reach `ze`/`ze-appliance` only through their direct dispatch imports (`ze_core_dispatch.go`, `dispatch_isis.go`, `dispatch_ospf.go`), making them consistent with firewall/iface/l2tp (never in `plugin/all`).
- `validate.py`'s `check_cross_package_wiring` now treats `scripts/` as a caller domain, so gate-only helpers (`grammar.Check*`) no longer read as dead.

## Gotchas
- **The rename created a root-name collision in the `ze-test` binary.** `internal/test/cli` registers `ze-test <suite>` roots (`traffic`/`isis`/`ospf`) AND imports `plugin/all` (which imported the tool CLIs). While the tools were `traffic-control`/`isis-decode`/`ospf-decode` they never clashed; after the rename `bin/ze-test ui` panicked `duplicate root command "traffic"`, and `go test ./internal/test/... -tags ze_isis ze_ospf` panicked on `isis`/`ospf` (the ze-test binary itself lacks those tags, so only the unit test caught them). Fix: `// codegen:skip` on the three `cli/register.go`. A rename that frees a token can collide it with a *different* binary's use of that token.
- **`ze update serve` blocks (`ListenAndServe`) but the runner classifies it quick-exit** (`update` ∉ `zeDaemonVerbs`). A foreground `.ci` step would hang; a `cmd=background` ze daemon triggers a BGP peer-exchange check a non-BGP server can't satisfy. AC-8 uses a foreground shell-wrapper + `http=get` (not just `http=wait`: `isSelfValidated` counts `HTTPChecks`, not `HTTPWaits`), mirroring `web-tool-decode.ci`.
- **test/ui `.ci` stdout/stderr matching is CUMULATIVE across a file's commands.** A `!contains=traffic-control` fails if any earlier step (a removed-name test) emits that string — so completion negatives (AC-12) live in their own isolated `root-completion.ci`.
- **`isis-decode`/`ospf-decode` are unambiguous CLI-command references** and were renamed everywhere (including ~10 test `.ci` exec lines the spec's Files-to-Modify missed), but **`traffic-control` is also the config/component identity** (error messages, YANG module, `test/traffic/*.ci`) which stays — so AC-15's "no stragglers" for `traffic-control`/`format` means "no CLI-command references", not zero grep hits.
- The gate is `//go:build ignore`, so it can't be unit-tested in-package; prove the gate WIRING end-to-end by temporarily reintroducing a hyphenated root and watching it flag, then restoring (the pure function's red/green fixture is the per-rule proof).

## Coverage boundary (scope of the deliverable)
The feeder governs the **root** surface only. It does NOT cover the local-handler surface (`registry.MustRegisterLocalMeta`, now including `update serve`): `RegisterLocalMeta`/`RegisterLocal` (`registry.go`) validate only empty-path and nil-handler, never command-name grammar, and `validateCommandName` has no caller. So a future hyphenated *local* meta would not be flagged. This was outside this spec's root-scoped gate deliverable; extending the gate to local metas is a separate piece of work. Three further items are orthogonal to this spec and were left untouched by design: root-level flags like `ze --plugins` are an R3 (no `--flag`) question, not R9 (the Phase 6 feeder's `b>0` guard deliberately skips leading-hyphen roots); the two legitimate `format` value vocabularies (`set cli format` text|table|json|yaml|ndjson vs the editor `| format tree|config`) are unreconciled but both preserved; and `ze pipe` still takes one shell-quoted pipe expression rather than repeated operators natively.
