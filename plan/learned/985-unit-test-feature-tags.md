# 985 - unit tests must compile under the shipped feature set, not bare ze_core

## Context

After the feature-gate work landed present-feature tests (`ze_web`/`ze_lg`/`ze_ssh`
present-tag tests, e.g. `service_web_test.go`, `main_servers_webonly_test.go`,
`build_tag_*_present_test.go`), `make ze-verify` was not exercising them: the unit
target ran `go test -tags ze_core` only, so every `//go:build ze_<feature>`
present-tag test file was excluded from the test binary and silently skipped. The
shipped `make ze` binary builds with `ze_core $(ZE_FEATURES)` (default-on lg/ssh/web
from `feature-gates.txt`), so the unit suite was testing a build shape we never ship.
This commit aligns the two and bundles three smaller gate fixes found alongside.

## Decisions

- **Unit tests run the shipped default-on feature set.** `GO_TEST` is now
  `-tags 'ze_core $(ZE_FEATURES) $(ZE_TAGS)'`, where `ZE_FEATURES` derives from
  `feature-gates.txt` (the same SSOT `make ze` uses, see 983). Present-feature tests
  now actually run.
- **A second bare-core pass keeps absent-feature compile-out tests alive.**
  `GO_TEST_CORE = go test -tags 'ze_core $(ZE_TAGS)'` runs `./cmd/ze/hub` after the
  main pass. The negated tests (`//go:build !ze_lg / !ze_ssh / !ze_web`) only compile
  with the gate off, so they need a build where the feature is absent.
- **The serial ExaBGP fixture seam.** `option=serial` in a `.ci` marks a
  process-driven fixture (`conf-watchdog`: spawns `run ./run/watchdog.run`, 6-step
  stateful announce/withdraw) that conflicts with concurrent harness instances. The
  runner splits selected tests into a parallel batch then a serial batch (limit 1);
  the Python harness (`bin/bgp`) skips the line too.
- **imageserver iface exemption.** `internal/plugins/imageserver/register.go` is
  added to the `iface_resolution.go` allowlist: it resolves through `iface.Addresses`
  first and only falls back to `net.InterfaceByName` when no iface backend is loaded
  (install/provision path) -- the same documented pattern as ldp/provision/diag, not a
  new raw-kernel-name consumer.

## Gotchas

- **Absent-feature compile-out tests MUST live under `cmd/ze/hub`.** The bare-core
  pass only runs that one package. A `//go:build !ze_<feature>` test placed elsewhere
  is silently skipped by BOTH passes (off in the bare-core run's package list, off in
  the main run's tags). A comment at `GO_TEST_CORE_TAGS` in the Makefile records this.
- **A new feature gate needs its negated test added to the bare-core package list**
  if it cannot live in `cmd/ze/hub`. Today all three (lg/ssh/web) do.
- **Program-shape tags are not feature gates.** `!ze_distro` tests run in the main
  pass already (ze_distro is off there); `ze_setup`/`ze_appliance`/`ze_distro`
  present-shape tests are covered by the build targets, not the unit suite -- no
  regression, that was true before this change too.
- **The tmp/go.mod sentinel is regenerated by make.** A `$(TMP_SENTINEL)` target
  recreates `tmp/go.mod` (nested module marker so `go list ./...` skips scratch/QEMU
  caches under tmp/) when missing, and is a prerequisite of the unit targets. It never
  overwrites a hand-edited sentinel.
