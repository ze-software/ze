# 1053 - Config-Surface & Command-Tree Review Checks

**Session:** traffic/anomaly/ddos config nesting + show ddos | **Date:** 2026-07-02

## Context

Nesting `traffic-control`/`traffic-usage` -> `traffic {control,usage}`,
`anomaly-*` -> `anomaly {detect,shape}`, and `ddos-*` -> `ddos {detect,...}`,
plus adding the `show ddos` command tree, surfaced four failure modes that all
compile clean and pass `go build`, but break at daemon startup, in a golden
snapshot, or only on macOS. `/ze-review` had no check for any of them; each was
found by luck (running a test, reading a startup WARN, running a `.ci`). Added a
"Config-Surface & Command-Tree Checks" section to `ai/skills/ze-review.md` and a
step-15 pointer.

## The four failure modes (now review checks)

1. **New wire method missing from the golden snapshot.** `RegisterRPCs` /
   `ze:command` additions must be hand-inserted (sorted) into
   `internal/component/plugin/all/testdata/wire-methods.snapshot` -- `make
   generate` does NOT update it. Missing -> `TestRegisteredWireMethods` fails
   `unexpected wire-methods`. (Re-confirms learned 1046.)

2. **Cross-module container-merge with divergent `description`.** When >1 module
   contributes the same `container show { container X }` (or augments a shared
   config parent), X's `description` must be byte-identical across modules, else
   `YANG command description mismatch node=X` warns every startup. Fix: the shared
   parent is a pure namespace with one description; per-command text goes on the
   leaf command node. This is also why `show traffic`/`show anomaly`/`show ddos`
   are pure namespaces, not terminal commands.

3. **Nested ConfigRoot read with a flat key.** A `ConfigRoot` of `a/b` is
   delivered as `{"a":{"b":{...}}}`; `root["a/b"]` (literal slash key) silently
   returns nil, so the plugin parses an empty config and runs inert with no
   error. Readers must unwrap every segment; doctors/completers must use
   `Tree.GetContainerPath`, never `GetContainer("a/b")`.

4. **`.ci` that loads an interface/firewall-dependent plugin without
   `needs-linux`.** `ddos-detect` (Dependencies: interface) and `ddos-local`
   (firewall) make the daemon start `interface`, which has no OS-default backend
   on darwin -> the test fails on macOS ("no backend configured and no OS default
   available") before the behavior under test runs. Such `.ci` must set
   `option=needs-linux` (all existing ddos/traffic `.ci` already do).

## Consequences

- `/ze-review` step 15 now points at the new section; it fires when a diff nests
  a config container, adds a plugin show/RPC command, registers a wire method, or
  adds a plugin-loading `.ci`.
- All four are mechanizable -- a future `ze-validate` pass could grep for a
  nested `ConfigRoot` read with a flat key, or a `.ci` that configures a
  dependency-pulling plugin without `needs-linux`. The review check is the
  interim guard until that automation exists.

## Gotchas

- The shared working tree during this session held 3+ concurrent sessions' edits.
  `plugin/all/all.go` and the golden snapshots are regenerated by `make generate`
  from ALL registered plugins, so a run can silently fold in another session's
  registrations. Scope commits to explicit `--file` lists and diff-check every
  shared generated file (`all.go`, `*.snapshot`) before staging.
