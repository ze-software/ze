# 1279 -- Perf harness rot, and a reaper that ate a tracked file

## Context

A routine "run the perf benchmark against bird" request found the whole Docker
perf/interop path dead. Five separate defects, none visible from the repo's own
gates, because `make ze-verify` never builds the interop image or runs
`test/perf/run.py`. The oldest had been broken for seven weeks. Fixing them also
destroyed `docs/performance.md` in passing, which is how the sixth was found.

## Decisions

- **Derive the interop image's build tags from `feature-gates.txt`**, not a
  hardcoded `-tags ze_core`. When `ze_bgp` became a compile-out gate
  (2026-07-22), that hardcoded tag list silently produced a **BGP-less** ze: the
  container rejects the perf config with `unknown top-level keyword: bgp`. Perf
  AND the whole Docker interop suite had been exercising a daemon with no BGP
  since. The Makefile and `scripts/evidence/qemu-all-tests.sh` already derive;
  the Dockerfile now does the same awk over the manifest.
- **One build recipe for ze-perf**, in the root Makefile. `mk/perf.mk` kept a
  second copy building `./cmd/ze-perf`, a directory folded into `cmd/ze` by
  `eac6ec186` in June; `make ze-perf` had failed outright ever since. The alias
  now just depends on `$(ZEBIN_PERF)`.
- **A benchmark run never writes `docs/performance.md`.** Chosen over "only
  rewrite it on a full-fleet run", which was the first fix and was not enough:
  `report --doc` emits ONE undated section while the committed file is
  hand-curated with four dated historical ones, so even a complete, fully
  successful run destroys history. The snapshot goes to `tmp/perf-run/` for a
  human to fold in.
- **Left the doc's self-description alone.** It says "This document is
  auto-generated by `ze-perf report --doc`" while carrying hand-added history.
  Both cannot be true, but which one gives is the owner's call about a published
  document, not a fix to make in passing.

## Consequences

- Any future feature gate is automatically in the interop image; adding a line
  to `feature-gates.txt` remains the only edit needed.
- A DUT-filtered perf run is labelled partial in its output instead of quietly
  presenting two DUTs as a fleet comparison.
- `test/perf` joins `scripts/dev` and `test/scripts` as a Python test root
  (`scripts/dev/python_tests_test.go`), so guards there actually run.
- The first trustworthy ze perf number since the `ze_bgp` gate landed. It shows
  a regression against 2026-06-05 (throughput -18%, p50 11ms -> 22ms) with bird
  reproducing its June numbers on the same host as the control. Not bisected.

## Gotchas

- **`open(dest, "w")` + `check=False` is silent data loss.** It truncates before
  the generator runs and then ignores its exit code, so a failing generator
  leaves an empty file and a passing run. This emptied a committed,
  source-anchored document to zero bytes while reporting two benchmarks PASSED.
  Generate to a temp file, check the exit code, then `os.replace`.
- **`argv[0]` dispatch and session binary suffixes are incompatible.**
  `binarySuffixRoot` (`cmd/ze/dispatch.go:127`) takes the segment after the LAST
  `-`, so `bin/ze-perf-<session-id>` ends in the session id and dispatches
  nothing: `ze-perf report` dies with `unknown command: report`. The container
  already bind-mounted the binary as a bare `/usr/local/bin/ze-perf` for exactly
  this reason; the host side now gets the same treatment via a symlink.
- **An age-based `tmp/` reaper eats committed sentinels.**
  `.claude/hooks/session-start.sh` deleted every top-level `tmp/` file older than
  24h -- including the TRACKED `tmp/go.mod` that keeps `go list ./...` out of the
  caches. Being committed, it is old by definition, so **every session start
  silently deleted a tracked file**. `make ze-clean-tmp` had the identical bug.
  Both now exclude it. Reap by pattern, never by age alone, wherever tracked
  files share a directory with scratch.
- **A launch-form change reaches further than the `.ci` sweep.** `ze <config>`
  became `ze start <config>` and `test/ui/deprecated-bare-config.ci` guards the
  removal, but `test/perf/run.py` still used the old form -- outside `test/`'s
  own suites, so nothing caught it. This is the `\bze <arg>` grep from
  `ai/rules/before-writing-code.md`, missed again.
- **Nothing in `ze-verify` covers the Docker perf/interop path**, which is why
  five defects accumulated silently. If you change how ze is built, invoked, or
  named, assume that path is stale until you have run it.

## Files

- `test/interop/Dockerfile.ze` -- feature tags derived from `feature-gates.txt`
- `test/perf/run.py` -- build path, launch form, `argv[0]`, atomic generation,
  committed-doc protection
- `test/perf/run_test.py` -- new; mutation-verified guards for the above
- `scripts/dev/python_tests_test.go` -- `test/perf` as a Python test root
- `mk/perf.mk` -- `ze-perf` alias instead of a stale second build recipe
- `.claude/hooks/session-start.sh`, `Makefile` -- sentinel excluded from reaping
