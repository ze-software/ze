# 1300 -- mcp2026-2-mrtr

## Context

Phase 2 of the `2026-07-28` cutover. Ze's elicitation blocked a handler
mid-dispatch inside `session.Elicit`. The blocked handler upgraded the POST reply
sink to SSE. It then wrote an `elicitation/create` JSON-RPC **request** frame to
the client, and waited on a per-elicit channel for a correlated JSON-RPC
**response**. The revision forbids both halves: "The server **MUST NOT** send
independent JSON-RPC *requests* on this stream" and "The client **MUST NOT** send
JSON-RPC *responses*."

Multi Round-Trip Requests replace it. The server **returns**
`resultType: "input_required"` with an `inputRequests` map, and that reply ends
the original request. The client then gathers the input and retries
the original request with `inputResponses`. The server that processes the retry
needs nothing more than what the retry carries.

## Decisions

- **No `requestState` is minted, and the whole integrity design is not built.**
  Research collapsed this phase. There was exactly one reachable elicit call
  site, and it asked for a single `command` string. That string is itself a tool
  argument the retry carries anyway, so there is no server-side state to carry.
  The rule "at least one of `inputRequests` or `requestState`" is therefore
  satisfied by `inputRequests` alone. That single fact deletes the keyed MAC, the
  principal binding, the expiry, and the request-digest design the spec had
  budgeted at skeleton stage.
- **An arriving `requestState` is rejected, not ignored.** Ze never mints one, so
  no arriving value can be legitimate, and the client's own rule is that it
  "**MUST NOT** include one in the retry" if the result did not carry one.
  `evidence.md` requires the code to "fail closed or say something". A
  rejection does both. A silent drop does neither.
- **The gate is form-mode support, not the presence of the `elicitation` key.**
  The revision declares the capability as `{form?, url?}`, and an empty object
  means form-mode only. "Servers **MUST NOT** send elicitation requests with
  modes that are not supported by the client", so a bare-presence check would
  emit a form request to a url-only client.
- **The schema validator was RECOVERED from git, not rewritten.** Phase 1 deleted
  `elicit.go` for a compile reason -- `(*session).Elicit` lived in it -- not
  because the flat-primitive `requestedSchema` validator was obsolete.

## Consequences

- `ze_execute` became a pure function of (arguments + `inputResponses`),
  resumable from scratch across two independent HTTP requests with no server-side
  continuation. That is the shape the stateless model requires and it is now the
  only shape the handler has.
- A retry that omits the requested key gets a **new** `InputRequiredResult`
  rather than an error. An explicit `decline` or `cancel` is terminal. Unknown
  `inputResponses` keys are ignored. These are the extension's tolerance rules,
  and they keep a slightly-wrong client working rather than fail it.
- URL-mode elicitation is not implemented, and that is correct rather than a gap:
  Ze's one elicitation asks for a `ze` CLI command, which is not a credential,
  and the specification forbids form mode for credentials specifically.

## Gotchas

- **A recovery claim is verifiable, and the test is whether the recovered tests
  needed an edit.** All 11 recovered validator tests are byte-identical to
  `HEAD:elicit_test.go`, and each function body was diffed rather than read in a
  report. A recovered test that needed a change to pass would prove a rewrite,
  and R-4 was written to catch exactly that. One mechanical change was
  unavoidable: the `c_string_concat` hook forbids `+` concatenation, so seven
  sites became `textbuf` chains that produce byte-identical strings. The tests
  then passed with no edit, and that is the proof.
- **The feature was reachable in code and unreachable through its own interface.**
  Phase 1 had set `"required": ["command"]` on the `ze_execute` descriptor for
  its AC-15, correct at the time because elicitation had been deleted. Phase 2
  restored the behavior and never revisited the contract. A schema-validating
  host would never construct the call that triggers MRTR. The fix is structural:
  the descriptor now derives `required` from the same capability the handler
  branches on (`gateExecuteCommandRequired`). The copy is made on write, so the
  shared package-level descriptor is never mutated and the two cannot drift
  again.
- **"No client JSON-RPC response is ever accepted" was true only by accident.**
  A response frame has no `method`, so the header check rejected it for a
  missing `Mcp-Method`. That verdict was correct, and it was reached for an
  unrelated reason with nothing to pin it. The producer now names the condition
  explicitly (`errBodyCarriesNoMethod`), and it still answers `-32020` because
  the specification pins that code to this class. A Go test covers every pair of
  5 frame shapes and 4 header shapes, and a functional test covers the same path.
- **A `reject=` that cannot fire reads as protection and is not.** The assertion
  for "no `elicitation/create` frame is written" never matched. The client prints
  the `result` member of a frame and never the enclosing frame. The test now uses
  a needle that sits inside what the client prints.
