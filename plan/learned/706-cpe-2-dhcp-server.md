# 706 -- cpe-2-dhcp-server

Spec: spec-cpe-2-dhcp-server.md
Date: 2026-05-15

## What this was

DHCP server plugin for ze's CPE/home-router use case. Serves IP leases to LAN
clients per RFC 2131/2132: DISCOVER/OFFER/REQUEST/ACK/NAK/RELEASE/DECLINE state
machine, address pools with bitmap allocation, lease tracking with per-lease
expiry timers, static MAC-to-IP mappings, DHCP options (subnet mask, router, DNS,
domain name, lease time, T1/T2), and per-interface socket binding via
SO_BINDTODEVICE on Linux.

Motivated by VyOS home.conf replacement where the LAN bridge needs to serve DHCP.

## Architecture decisions

1. **Plugin, not component.** Modeled as an independent plugin (like ntp, sysctl)
   because it has its own config tree (`service { dhcp-server { ... } }`) and
   lifecycle. No coupling to the BGP engine or interface management. Registered
   via `init()` in `register.go`, discovered by codegen `all.go`.

2. **Bitmap-backed pool, not the l2tppool code.** The l2tp pool is a separate
   domain (IPCP address assignment for PPP sessions). DHCP has different
   requirements: static mapping exclusion, MAC-to-address tracking, address
   reservation on INIT-REBOOT, and `markUnavailable` for DECLINE. Own pool avoids
   coupling and keeps the code straightforward.

3. **One socket per interface, multi-handler dispatch.** Each listen-interface gets
   one UDP socket (SO_BINDTODEVICE on Linux). The `serveMulti` goroutine tries each
   subnet handler in order. `matchesSubnet` routes packets to the correct handler
   using giaddr (relay), ciaddr (renew), or requested-IP option (init-reboot).
   Pure DISCOVERs with no address hints fall through to the first handler with
   available pool space.

4. **Empty pool for static-only subnets.** `newPool` with invalid start/stop
   returns a zero-size pool. All pool methods guard `p.size == 0` to avoid
   panicking on `netip.Addr{}.As4()`. Static-only subnets work by looking up
   `staticByMAC` in the handler before calling `pool.allocate`.

5. **Platform-specific socket files.** `socket_linux.go` uses
   `net.ListenConfig` with `SO_BINDTODEVICE` syscall. `socket_other.go` falls back
   to plain `0.0.0.0:67` (development/testing on macOS). Follows the same
   `_linux.go`/`_other.go` build-tag pattern as ntp's clock files.

## What surprised us

1. **Spec said `loader_create.go` for wiring.** That file does not exist. Plugin
   wiring is via `internal/component/plugin/all/all.go`, generated by
   `make generate` (scans for `register.go` files importing `plugin/registry`).
   Two test files also maintain expected-plugin lists that need updating.

2. **`safeAppendOption` needed instead of direct writes.** With many DNS servers
   or a long domain name, options can exceed the 576-byte response buffer. A
   bounds-checking option writer prevents panics. Also, the DHCP option length
   field is a single byte, so domain names > 255 bytes produce malformed options
   via silent truncation. Added config-time validation.

3. **Pool methods panic on zero-value `netip.Addr`.** `As4()` panics on the zero
   value. The empty-pool guard (`p.size == 0`) was needed in `reserve`, `release`,
   and `markUnavailable`. The initial test only covered DISCOVER (which uses
   `allocate`, safe via early return), not REQUEST (which uses `reserve`). The deep
   review caught this.

4. **`handleDiscover` must be silent on exhaustion, not NAK.** RFC 2131 Section
   4.3.1: no address available means no response. NAK is only valid for REQUEST.
   Easy to get wrong because the instinct is "reject the client somehow."

5. **`leaseTable.add` leaked pool addresses on lease replacement.** When a MAC
   gets a new address, the old address must be released back to the pool. The
   initial implementation only removed it from `byAddr`.

## Mistakes and corrections (review findings)

| Finding | Severity | Root cause |
|---------|----------|------------|
| listenDHCP bound to 0.0.0.0 not the interface | BLOCKER | Ignored ifaceName param, just used it in error msg |
| DISCOVER on exhaustion sent NAK instead of silence | BLOCKER | Wrong RFC reading; NAK is only for REQUEST |
| handleDecline released addr to pool instead of marking unavailable | ISSUE | RFC 2131 Section 4.3.3 says "mark not available" |
| commitBinding did not mark address in pool bitmap | ISSUE | INIT-REBOOT path skipped pool.allocate |
| buildReply buffer overflow with many options | ISSUE | Fixed 576-byte buffer, no bounds check |
| responseAddr ignored BROADCAST flag | ISSUE | Skipped the flag check, always broadcast |
| handleDecline ignored the packet (used wrong address) | NOTE | Should use requested-IP option, not current lease |
| leaseTable.renew was dead code | NOTE | Handler uses add() for renewals |
| newPool panicked on zero-value start (static-only) | BLOCKER | As4() panics on netip.Addr{} |
| pool.reserve/release/markUnavailable panicked on empty pool | BLOCKER | Same As4() issue, needed size==0 guard |
| buildReply did not copy ciaddr for RENEWING ACK | MEDIUM | RFC Table 3: ciaddr from DHCPREQUEST |
| serverIP zero-value on static-only without default-router | HIGH | Fallback chain stopped at RangeStart |
| domain-name > 255 bytes silently truncated in option | MEDIUM | DHCP option length is 1 byte |

All found across 5 `/ze-review` passes + 1 deep 9-agent review, fixed before commit.
