## Task

`./le commit create` writes a row into the tracked file
`plan/verification-debt/<session>.md` whenever the commit lacks fresh evidence,
and the commit then carries that file. The session-start hook prints
"verification debt: N gate(s) owed", and `create ... push` is refused while any
row is open. Rows are cleared by `./le commit debt-clear` (runs a full verify in
a worktree at HEAD) or answered by `./le commit debt-discharge` (four kinds,
records under `plan/verification-debt/discharged/`).

The ledger is a second copy of a derivable fact: "which commits on this branch
have no green full native verification at or after them". That copy breaks
`ai/rules/principles.md` ("Every fact MUST be declared once"). It costs three
ways today:

| Cost | Evidence |
|------|----------|
| Every commit drags a tracked file it did not author | `checkVerificationGates` (`internal/le/commit/prepare.go`) appends the shard to the commit's paths |
| Parallel sessions collide on it | 2026-10-18: a commit was refused because another session had just committed the debt file |
| It drifts from reality | 369 shards, `./le commit debt-status` on 2026-10-18: 706 open, 696 cleared, 386 discharged (57 not-applicable, 329 owner), while most of those rows sit on commits already on `origin/main` |

Goal (owner decision 2026-10-18, "derive it, write the spec"): delete the
ledger and its write path, and DERIVE the debt from git plus a record of the
last green full verification. The push gate, the `commit create` report and the
session-start hook all read the derivation. A person-act obligation (review,
owner approval) moves into a commit trailer the derivation reads.

## Required Reading

### Architecture Docs
- [ ] `docs/architecture/testing/verify-freshness-scope.md` - certificate, verification debt, discharge
  → Constraint: `WriteCertificate` overwrites `tmp/ze-verify.status` on EVERY run, red or green; on 2026-10-18 it holds `exit=130` over `605de63e22`. So "the last commit a full verify passed over" is not recoverable from the certificate once a later run fails. The derivation needs its own record, written only by a green, uncut, full-mode run.
  → Constraint: `CheckCertificate` stales any non-zero exit and any mode `StagesForMode` does not know (`full-part-2-of-6`), so a cut piece never certifies. The cut aggregation lives in `internal/le/commit/debtpart.go` (`tmp/ze-verify-debt-parts.json`, all pieces green at ONE commit and ONE cut). That aggregation is the only thing in the debt machinery worth keeping, and it must move to the verify side.
  → Constraint: `./le verify worktree` runs in a throwaway worktree and `CopyCertificate` publishes the pair back to the asking checkout. The green record must be published the same way, or it never reaches the checkout that pushes.
  → Decision: the runnable gates (`unverified`, `structural-red-ok`, `missing-full-verify-ok`, `broken-head-fix`) all clear on the same event, one green full verify at or after the commit (`clearDebt` marks EVERY runnable gate passed on exit 0). They collapse to one derived question.
- [ ] `docs/contributing/committing.md` - keywords, push, debt sections

  → Constraint: in a `ZE_REPO_ROOT` tree that is not the Ze checkout (`lepath.IsCheckout` false) no debt is written; the derivation answers NOT-APPLICABLE there too.
- [ ] `ai/rules/precommit-verify.md`, `ai/rules/pre-release.md`
  → Constraint: "The gate is owed before a push"; "A commit MUST NOT be held for a green gate". The derivation keeps both: `create` never refuses for debt, the push does.
- [ ] `ai/rules/completion.md` (generated from `ai/rules/points/completion/directives/verification-debt-is-not-defect-debt.md`)
  → Constraint: the three directives name `plan/verification-debt/<session>.md`, `debt-clear`, `debt-discharge` and `debtGates`; they must be rewritten in the point file and `ai/rules/CORE.md`/`completion.md` regenerated by `./le ai rules condensed-update`, never hand-edited.
- [ ] `.claude/rules/handover-in-repo.md`
  → Constraint: verification state is machine-local (`tmp/`); work moves between Linux and Mac. See Open Question Q1.

**Key insights:**
- Seven gate keys exist (`debtGates`, `internal/le/commit/debt.go`); four are runnable and collapse into one derived "no green full verify covers this commit"; one is retired; two are person acts that need a trailer.
- The certificate cannot be the green record because a red run overwrites it.
- The derived range is bounded by the upstream: what a push publishes is `@{u}..HEAD`.
- No exemption exists today for a runnable gate (`verifyDischarge` refuses a discharge for a runnable gate), so nothing an owner can "skip" is lost by the derivation; exemptions only exist for the two person-act gates.

**Row kinds the producer writes, and their fate:**

| Gate key (keyword) | Row gate name | Written when | Cleared today by | Derived replacement |
|--------------------|---------------|--------------|------------------|---------------------|
| `unverified` | full native verification (not FRESH-green) | certificate not FRESH for the commit's paths, or the keyword | green `debt-clear` | commit is in the derived range (no green full verify at or after it) |
| `missing-full-verify-ok` | full native verification over this commit's Go | commit carries Go and certificate mode is not full, or the keyword | green `debt-clear` | same: the green record only accepts mode full, so a non-full run never covers anything |
| `structural-red-ok` | native structural checks (red) | the keyword admitted a charged structural red | green `debt-clear` | same; the commit-time refusal of an un-admitted structural red STAYS, the keyword's reason moves into a `Structural-red-ok:` trailer for audit only |
| `broken-head-fix` | repository tracked-build/check (HEAD does not compile) | the keyword | green `debt-clear` | same; reason into a `Broken-head-fix:` trailer for audit only |
| `stale-index-ok` | discovery-index freshness | never (retired 2026-09-11) | discharge only | dropped: no commit can owe it, its rows leave with the ledger |
| `review-override` | independent critical review | the keyword admitted a closure without a clean review | discharge only (not-applicable, closed, reviewed, owner) | `Review-owed:` trailer; open until answered (see Q2) |
| `rfc-change-ok` | owner approval for an RFC-tagged test change | the keyword admitted an RFC-tagged unit change without approval | discharge only (not-applicable, owner) | `RFC-approval-owed:` trailer naming the unit; open until answered (see Q2) |

**Behavior to preserve:**
- `create` never refuses a commit for missing verification; it refuses a charged structural red without an admission, and a closure without a clean review or `review-override`, exactly as now.
- `create ... push` is refused while any obligation is open, and the refusal names the command that clears each kind.
- The session-start hook prints one warning line and at most five items, inside its budget, and says on stderr when it cannot answer (never reads "cannot answer" as zero).
- The cut verification (pieces dealt over one commit, all must pass over ONE commit and ONE cut) stays available, because an uncut full verify is OOM-killed on a shared box.
- NOT-APPLICABLE outside the Ze checkout.

**Behavior to change:**
- No tracked debt file is written; no commit carries one.
- `plan/verification-debt/` (369 shards and `discharged/`) is deleted.
- Verbs `debt-list`, `debt-clear`, `debt-discharge` are deleted; `debt-status` answers from the derivation (or is folded into `./le verify status`, see Design Decisions).

## Data Flow (MANDATORY - see `ai/rules/architecture.md`)

### Entry Point
- `./le verify worktree` (uncut, or every piece of one cut) exiting 0 in mode full: writes the green record.
- `./le commit create` (report and push gate), session-start hook: read the derivation.

### Transformation Path
1. Verify engine, green uncut full run: writes `tmp/ze-verify-green.status` (commit SHA, mode, timestamp, tree hash) beside the certificate; a red or cut run never touches it. Cut runs record pieces in the moved progress record; the piece that completes the set over one commit writes the green record.
2. `CopyCertificate` (lifecycle) publishes the green record with the certificate.
3. Derivation (one function, new file `internal/le/commit/owed.go`): read green SHA G; range = commits reachable from HEAD and not from `@{u}`; owed-verify = range commits not ancestors-or-equal of G; owed-person = range commits carrying `Review-owed:` / `RFC-approval-owed:` trailers not answered (Q2).
4. Consumers: push gate refuses on non-empty; `create` prints the counts; hook prints the warning.

### Boundaries Crossed
| Boundary | How | Verified |
|----------|-----|----------|
| verify worktree to checkout | file copy, as `CopyCertificate` does | No |
| derivation to git | `git rev-list`, `git merge-base --is-ancestor`, `git log --format=%(trailers)` over the bounded range | No |

### Integration Points
- `verifyengine.WriteCertificate` / `CopyCertificate` - the green record is written and published next to them.
- `Message` (`internal/le/commit/input.go`) - writes the new trailers, the way it writes `RFC-approved:`.
- `reviewGateRecorded`, `closedSpecStem` (`discharge.go`) - the derived answers for `Review-owed:` reuse these producers (they move into the new file; the rest of `discharge.go` is deleted).

### Architectural Verification
| Check | Holds? | Evidence |
|-------|--------|----------|
| No bypassed layers | Yes | consumers call one derivation function |
| No unintended coupling | Yes | commit reads a verify artifact it already reads (certificate) |
| No duplicated functionality | Yes | deletes the ledger; the derivation is the one statement |
| Zero-copy preserved | N-A | tooling |
| Registration over hardcoding, outbound | Yes | person-act trailers are declared in one table beside the keyword table in `actions.go`; the derivation iterates it |
| Registration over hardcoding, inbound | No | search owed for `debtGates`, `debt-` verb lists in `internal/le/ai/hooks/parity.go`, `completeness_record_test.go`, and every path list naming `plan/verification-debt/` (`doc/check/retired.go`, `doc/citation/policed.go`, `site/producer.go`, `test/weakened/shard.go`, `le/path/commitsession.go`) |

## Risks & Assumptions

### Assumptions
| ID | Assumption | Basis | If wrong | Validated by | Status |
|----|-----------|-------|----------|--------------|--------|
| A-1 | A green full verify at commit G proves every ancestor of G, so commits at or before G owe nothing | `clearDebt` clears every runnable row on one green pass at HEAD | over-claim on an ancestor whose tree differs from G only by paths later reverted; same reading the ledger already makes | read `clearDebt` | unvalidated |
| A-2 | The push publishes exactly `@{u}..HEAD` | generated script runs plain `git push` (`script.go`, `pushMarker`) | a push to another remote/branch escapes the bound | read `renderPush`/script; test with no upstream | unvalidated |
| A-3 | Dropping the rows on commits already on `origin/main` loses no obligation anyone acts on | push is the enforcement point; those commits are published | historical review/RFC owed items vanish; Q3 asks the owner | owner answer to Q3 | unvalidated |
| A-4 | Unpushed commits only exist on the machine that made them | commits move between Linux and Mac through `origin` | a commit moved by bundle/rsync arrives without its green record and reads owed (safe direction) | owner answer to Q1 | unvalidated |
| A-5 | A bounded `git log` over `@{u}..HEAD` fits the session-start budget | today's range is 31 commits; old hook read 369 shards in 0.6 to 0.8 s | hook cut at deadline | timing in `TestSessionStartReportsDerivedDebtWithinBudget` | unvalidated |

### Risks
| ID | Risk | Early signal | Mitigation / fallback |
|----|------|--------------|----------------------|
| R-1 | Red run overwrites the green record and debt reads as all-owed after every failed run | green record changes on a red run | record written only on exit 0, mode full, uncut or completed cut; unit test with a red run after a green |
| R-2 | No upstream (worktree branch, fresh clone) makes the range unbounded or silently empty | `@{u}` fails | refuse to answer with a named error and the fix command (`git branch --set-upstream-to`); push gate refuses; hook says "not derived" on stderr (principles: no silent zero) |
| R-3 | Green record from another branch or worktree sharing `tmp/` covers commits it never saw | G not an ancestor of HEAD | only ancestors-or-equal of G are covered; a G off the branch covers nothing it does not reach |
| R-4 | Cut-piece aggregation lost in the move | no green record after six green pieces | move `debtpart.go` logic and its tests to the verify package before deleting `debt-clear` |
| R-5 | Deleting 369 tracked shards in one commit collides with sessions mid-commit writing a shard | `create` refusal on a removed path | land the code change first (no writer), then the `remove-list` deletion commit |
| R-6 | Person-act trailers written by an old `./le` binary or by hand are misspelled and never read | trailer present but not counted | trailer keys declared once in the keyword table; `Message` refuses a body line starting with a declared key, as it does for `RFC-approved:` |
| R-7 | `git notes`/ref options (Q1) need a push the owner did not order | push of a non-branch ref | recommended option needs no push |

## Blast Radius

| Question | Answer |
|----------|--------|
| What breaks if this is wrong? | the push gate admits an unverified push (if the derivation under-counts) or refuses forever (over-count); nothing in the product |
| How is it reverted? | revert the code commit; the deleted shards return with the revert of the deletion commit |
| Who else touches this path? | every session committing (`commit create`), the session-start hook; `plan/spec-verify-scope-0-umbrella.md` (verify scope) |

## Key Design Decisions
| Decision | Alternatives Considered | Rationale |
|----------|------------------------|-----------|
| Separate green record, written only on green | read the certificate | the certificate is overwritten by red runs (holds exit=130 today) |
| Range bounded by `@{u}..HEAD` | whole history since G | the push publishes only that range; history already pushed owes nothing a push can enforce |
| Runnable gates collapse to one derived question | keep per-gate rows | one green full verify clears all four today |
| Person acts in trailers | keep a small tracked ledger for them | trailers live in the commit, move with it, collide with nothing |
| Cut aggregation moves to verify | keep `debt-clear part` | it is a property of a verification, not of the ledger |
