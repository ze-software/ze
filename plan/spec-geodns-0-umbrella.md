## Task

Port the standalone `geodns` daemon (an EXA SurfProtect tool at
`git.exa.net.uk/tech/dev/surfprotect/geodns`) into Ze as a self-contained edge
plugin `internal/plugins/geodns`. geodns is a small DNS server whose answer for a
host depends on the **client source IP**: each customer-IP class gets its own set
of host→address records, so the same name resolves to different proxies for
different clients.

Two deltas from the reference, set by the user:

- **No Sentry.** Drop all `getsentry/sentry-go` error reporting. Ze uses its own
  logging (`slog`) and Prometheus telemetry.
- **Configuration via YANG.** The reference reads daemon flags/env plus a watched
  folder of `etc/geodns/<ip>` host files. In Ze, the entire configuration —
  daemon settings AND the per-source host records — lives in the YANG config tree
  and reloads on commit. The watched folder is removed.

This umbrella owns the architecture, cross-cutting decisions, and sequencing. The
three child specs own the implementable work.

**Behavior to preserve:**
- Answer selection by client source IP, with most-specific match winning over the catch-all default (the reference's exact-IP-then-internal-then-external precedence, generalised — see Key Design Decisions).
- Record types A, AAAA, SRV only. A vs AAAA auto-detected by a `:` in the address when type is omitted.
- SOA + NS records and `ns1..ns9.<zone>` glue are synthesised, never configured as host records.
- A query for a name with no record returns NOERROR with the synthesised SOA in the Authority section (negative answer), not NXDOMAIN.
- A query name not ending in a configured zone is not answered from host data.
- Live reload of host data without dropping the listener.

**Behavior to change:** (user-requested)
- Remove Sentry entirely.
- Replace the flags/env + watched `etc/geodns` folder with YANG config (daemon settings + per-source host records).
- Add a configurable client-IP source mode (`edns0` / `packet` / `edns0-then-packet`) so geodns works behind CoreDNS or standalone.
- Generalise source matching to CIDR longest-prefix (the reference's string-prefix/exact-map model is replaced).

## Data Flow (MANDATORY - see `ai/rules/data-flow-tracing.md`)

### Entry Point
- Config: an operator commits `service geodns { ... }`; the config subsystem hands the plugin a JSON-serialised `service` section.
- Runtime: a DNS query arrives on the configured UDP/TCP listener (default `127.0.0.1:5300`).

### Transformation Path
1. Config commit → plugin `OnConfigure(sections)` → `parseConfig(JSON)` → in-memory `geodnsConfig` + a longest-prefix source matcher (spec 1).
2. DNS query bytes → `miekg/dns` server mux → handler extracts the client IP per `client-ip-source` (EDNS0 subnet and/or packet source) (spec 2).
3. Client IP → longest-prefix match against `source` CIDRs → referenced named host-set (spec 1 matcher used by spec 2); several prefixes may reference one host-set, preserving the reference's shared `internal` set.
4. Query name + qtype → host-set lookup → A/AAAA/SRV answer, or synthesised SOA/NS, or negative answer with SOA authority (spec 2).
5. Each request/response increments Prometheus counters; `show geodns` reports live status (spec 3).

### Boundaries Crossed
| Boundary | How | Verified |
|----------|-----|----------|
| Config tree ↔ plugin | JSON `ConfigSection` via SDK `OnConfigure`/`InProcessConfigVerifier` | [ ] |
| Plugin ↔ network | UDP+TCP listener per `listen-address` on the shared `listen-port` (v4 + v6) | [ ] |
| Plugin ↔ telemetry | Prometheus counters registered in ze metrics registry | [ ] |
| Plugin ↔ CLI | `show geodns` RPC handler, owner-owned YANG command schema | [ ] |

### Integration Points
- `internal/component/plugin/registry` - `registry.Register` with `RunEngine`, `InProcessConfigVerifier`, `YANG`.
- `pkg/plugin/sdk` - `sdk.NewWithConn`, `OnConfigure`, `Run`.
- `github.com/miekg/dns` - message parse/build, `EDNS0_SUBNET`, server framework.
- `internal/core/textbuf` - buffer-first answer formatting (no `fmt.Sprintf` in the hot path).

### Architectural Verification
- [ ] No bypassed layers (config flows through SDK, not read from disk)
- [ ] No unintended coupling (geodns imports no other edge plugin)
- [ ] No duplicated functionality (reuses miekg/dns, not a hand-rolled wire codec)
- [ ] Zero-copy preserved where applicable (textbuf for formatting)

| ID | Risk | Early signal | Mitigation / fallback |
|----|------|--------------|----------------------|
| R-1 | A large `source` list (one `/32` per customer IP) bloats the config tree and slows commit | slow `make ze-functional-test`, large config | Named host-sets remove per-prefix record duplication; keep the matcher O(prefixes); document scale; reference's own roadmap is a Jarvis bulk-push |

## Design Insights
- The reference's three-level selection (exact file → internal-prefix → external) is exactly CIDR longest-prefix with `/32` host entries, the internal range as a `/16` (etc.), and `external` as `0.0.0.0/0`. Unifying them removes a special case and the two magic filenames.
- The reference's `internal` maps *many* prefixes to *one* host set (`hosts.go` loops the prefix list, all returning the single `internal` set). That sharing is preserved by defining named `host-set`s and letting multiple `source` prefixes reference the same one, rather than inlining (and duplicating) records per prefix.

## Core Insight
A "GeoDNS" is just longest-prefix matching on the client IP returning a per-prefix host table. Ze already has the DNS library and a plugin model with commit-driven reload; the real work is the YANG config surface and the source matcher, not DNS wire code.

## Key Design Decisions
| Decision | Alternatives Considered | Rationale |
|----------|------------------------|-----------|
| CIDR longest-prefix source matching | exact-IP map + internal-prefix list (reference); literal string-prefix (reference README) | One uniform model; `external` = `0.0.0.0/0`; matches a network-OS mental model |
| Named, reusable `host-set`s referenced by `source` prefixes | inline host records per source (duplicated across prefixes sharing a set) | Preserves the reference's many-prefixes→one-set sharing (`internal`); keeps large configs small; `external` = the host-set referenced by `0.0.0.0/0` |
| A/AAAA type optional, auto-detected per address | strict single `type` per name | Matches reference `recordIP` per-address `:` detection; a name can carry mixed A+AAAA |
| Reuse `miekg/dns` | hand-roll DNS in ze buffer-first style | Already vendored at the same version; server + EDNS0 support out of the box |
| `client-ip-source` config enum | hard-code EDNS0-only (reference) | Works behind CoreDNS and standalone; user asked for it to be configurable |
| Per-source records in YANG | keep watched folder | User instruction; gains validation, commit/rollback, `show configuration` |
| Configurable SOA fields | hard-code `hostmaster.exa.net.uk` + serial `2018122500` (reference) | Hard-coded EXA values do not belong in a general plugin |

## Known Limitations
- A host name may carry multiple addresses and mixed A/AAAA (the reference classifies each address by `:`), but only one host entry per name within a host-set (last wins), mirroring the reference.
- All zones share one nameserver list and one SOA config (reference behavior); per-zone NS/SOA is not expressible with the flat leaf-lists.
- The unfinished reference `geoupdate` AXFR experiment and `src/geodns/client.go` are out of scope.
