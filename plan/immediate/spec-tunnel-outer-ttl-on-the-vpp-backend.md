## Task

**What the operator is promised.**
`internal/component/iface/yang/ze-iface-conf.yang` declares `leaf ttl` on the
`gre`, `gretap` and `ipip` tunnel kinds, typed `uint8`, defaulting to 64, with
the description "Outer-header TTL. 0 = inherit from the inner packet". A reader
takes `ttl 32` to set the outer IPv4 TTL on every packet the tunnel
encapsulates. The interface subtree carries one `backend` selector for the whole
daemon, so a reader also takes the leaf to work whichever dataplane carries the
tunnel.

**What Ze does instead.** On the netlink backend the leaf works:
`internal/plugins/iface/netlink/tunnel_linux.go` writes `link.Ttl = spec.TTL`
for each of the three kinds. On the VPP backend it does not, and the refusal for
that case has landed. Commit `d4a3b84f21` put `ze:backend "netlink"` on the three
leaves, so `validateBackendGate` (`internal/component/iface/register.go`) refuses
a VPP-backed tunnel that names any `ttl` value, and names the leaf path, the
active backend, and the backends that implement it. The accepted-and-ignored
half of the defect is therefore closed, and what remains is that the leaf does
not work under VPP at all. The producer says why. `createGRETunnel` and
`createIPIPTunnel` (`internal/plugins/iface/vpp/tunnel.go`) build a
`gre.GreTunnel` and an `ipip.IpipTunnel`, and neither type carries a hop limit.
`GreTunnel` and `GreTunnelV2`
(`vendor/go.fd.io/govpp/binapi/gre/gre.ba.go`) carry type, mode, flags, session
id, instance, outer table id, interface index, src and dst, and V2 adds key.
`IpipTunnel` (`vendor/go.fd.io/govpp/binapi/ipip/ipip.ba.go`) carries instance,
src, dst, interface index, table id, flags, mode and dscp. The one vendored type
that carries a `HopLimit` field is `tunnel_types.Tunnel`
(`vendor/go.fd.io/govpp/binapi/tunnel_types/tunnel_types.ba.go`), and no gre or
ipip message takes it.

**What closing it means.** The refusal exists, so the two ends of the choice are
not build-or-refuse. They are: publish the leaf as netlink-only and leave the
refusal as the answer, or carry the outer TTL through the VPP binapi so one
config works on both backends. Neither is obviously right, and the reason is
that the second is not a change Ze can make alone. The vendored binapi is
generated from the VPP API, so a hop limit on `gre_tunnel_add_del` or
`ipip_add_tunnel` needs VPP itself to carry one, followed by a binapi
regeneration and a VPP version floor. The flag Ze already has does not substitute
for it: `TUNNEL_API_ENCAP_DECAP_FLAG_ENCAP_COPY_HOP_LIMIT` copies the inner hop
limit, which is exactly the `0` case of this leaf and no other value, and the
comment above the annotated leaf records that Ze does not set it. So a cheaper
third option exists and the design has to rule on it: honor `ttl 0` under VPP
through that flag and keep refusing every non-zero value. That option makes one
enum-like value work and leaves 255 refused, which splits one leaf across two
behaviors, and `ai/rules/simplicity.md` is the rule that decides whether the
split earns its place. The parity decision belongs to the owner, because it sets
whether Ze owes VPP feature parity per leaf or publishes per-backend support.

**Owner decision, 2026-09-06: "The VPP API is what it is."** Parity is not
pursued. `GreTunnelV2` and `IpipTunnel` carry no hop limit, only
`tunnel_types.Tunnel` does, and no gre or ipip message takes it, so parity needs
a VPP API change and a binapi regeneration that Ze does not control.

The operator-facing half is already closed. `d4a3b84f21` annotates the three
`ttl` leaves `ze:backend "netlink"`, so a commit that names a `ttl` on a
vpp-backed tunnel is refused rather than silently dropped, which is what
`ValidateBackendFeatures` (`internal/component/config/backend_gate.go`) exists
for. An operator now meets a message instead of a silent no-op.

That leaves this spec holding only the parity the owner declined, so it is
parked at `deferred`. It also no longer passes the `plan/immediate/` test, since
no operator meets it as a bug; relocating it is the owner's re-reading to make
(`plan/README.md`), so it stays here until then.
