Scope is protocol: the change is to what the RFC 5082 related-message filter
claims. No config leaf, no CLI command.

Recovery after compaction: `.claude/rules/post-compaction.md`.

## Task

RFC 5082 Section 3 sorts a packet reaching the control plane into Unknown,
Trusted and Dangerous, where Trusted and Dangerous are "packets that have been
identified as belonging to one of the GTSM-enabled sessions", and extends the
TTL rule to "the related ICMP error handling messages". Ze's IPv4 receive half
of that rule is an nftables input table (`peerTerms`,
`internal/component/gtsm/gtsm.go`) whose terms match an ICMP error by four
things: one of the five related ICMP types, the OUTER source address equal to
the peer, the quoted TCP header carrying the BGP port, and the outer TTL below
the peer's floor. The outer-source condition is the defect. An ICMP error is
generated by whichever router met the problem, never necessarily by the peer,
and the kernel delivers it to the session by the header it QUOTES
(`tcp_v4_err`, `net/ipv4/tcp_ipv4.c`, looks the socket up by the quoted 4-tuple
and never reads the outer source). So a forged error from any address but the
peer's, quoting the session's TCP header and arriving with a low outer TTL, is
not claimed by ze's table, reaches `tcp_v4_err`, and is judged there on the
TTL the forger wrote inside the quote. That is the attack Section 6.1 names:
"related messages provide a significant attack vector to e.g., reset protocol
sessions".

A survey of FRR (`bgp_set_socket_ttl`), BIRD (`bgp_connect`), GoBGP
(`SetTCPMinTTLSockopt`) and OpenBGPD (`session_setup_socket`) found that none
does anything for related messages beyond the min-TTL socket option, and that
every kernel path those options drive (Linux `tcp_v4_err`, `tcp_v6_err`,
OpenBSD `tcp_ctlinput`) associates the error with the session by the quoted
header and constrains the outer source nowhere. Owner ruling, 2026-09-15:
association is by the quoted header, any outer source (reading 2).

The goal: a term claims an ICMP error when its quoted IP header's destination
is the peer (the error is about a packet ze sent to the peer), its quoted TCP
header carries the BGP port, and its type is a related type; the outer source
is not read. The outer TTL floor is unchanged. An error quoting another
destination, or another port, stays Unknown and is delivered whatever its TTL
and source (RFC5082-3-4).

**Key insights:** (minimal context to resume after compaction)
- The lowering reads the quoted header at fixed offsets from the transport header base: ICMP header is 8 octets, so the quoted IPv4 header starts at offset 8; its version/IHL byte is at 8 (must be 0x45), its protocol byte at 17, its destination address at 24 (8 + 16), and the quoted TCP ports at 28 and 30 (`lowerICMPErrorQuotedTCPPort`, `internal/plugins/firewall/nft/lower_linux.go`)
- Every raw read is behind `nfprotoGuard(family, unix.NFPROTO_IPV4)` so it cannot reach the IPv6 family
- `peerTerms` builds `len(relatedICMPTypes) * len(quotedPortSides)` terms per peer; the outer-source match is one element of each term's match list

## Data Flow (MANDATORY - see `ai/rules/architecture.md`)

### Entry Point
- A BGP peer with `connection ttl max N` reaches the reactor's peer reconcile, which publishes the peer set to `gtsm.SetPeers` (unchanged)
- On the wire: an ICMPv4 error datagram arriving on any interface, whose payload quotes an IPv4 header and the first 8 octets of a TCP header

### Transformation Path
1. `peerTerms` (`gtsm.go`) builds each term with `MatchICMPType`, `MatchICMPErrorQuotedDestination{Addr: p.Addr}` in place of `MatchSourceAddress`, `MatchICMPErrorQuotedTCPPort`, `MatchIPv4TTLBelow`
2. `validateMatch` (`validate.go`) accepts the new match in family `ip`/`inet` only, with a valid IPv4 unicast address, and refuses it elsewhere
3. `lowerICMPErrorQuotedDestination` (`lower_linux.go`) emits: `nfprotoGuard(NFPROTO_IPV4)`, the 0x45 check at transport offset 8, a 4-octet read at transport offset 24 compared against the peer address; it does not repeat the protocol check, which the quoted-port match beside it performs
4. The kernel evaluates the term on input; a match with outer TTL below the floor drops before the TCP stack sees it; everything else continues to `tcp_v4_err` as today

| Check | What to look for |
|-------|-----------------|
| Input validation | The quoted header is attacker-chosen bytes inside the ICMP payload; the 0x45 guard keeps offset 24 meaningful, and a quoted header with options matches nothing rather than the wrong bytes |
| Fail closed | A term that fails to lower refuses the whole table apply, as today, and the doctor check reports the missing table |
| Denial of service | The drop stays in the kernel before the TCP stack; the added read is one 4-octet compare per term |

## Design Insights
- The kernel and every surveyed daemon agree that an ICMP error belongs to the session it quotes. Ze's outer-source condition came from the spec that introduced the filter, which modeled the attacker of Section 5.3 (one who spoofs the peer's address) and not the one of Section 6.1 (one who forges an error from anywhere).

## Key Design Decisions
| Decision | Alternatives Considered | Rationale |
|----------|------------------------|-----------|
| Match the quoted DESTINATION, not the quoted source | Quoted source = ze's local address | An error ze receives is about a packet ze sent, whose destination is the peer; ze's local address per peer is not always configured, and the peer address is |
| Keep the quoted-port match beside it | Drop it, since the destination now identifies the peer | The port is what ties the error to the BGP session rather than to any other flow toward the peer (RFC5082-3-4) |
| No new interop scenario | One against FRR | A dropped forged error is invisible to the peer; the kernel proofs are the only observer |
| The owner writes the `test/rfc-changed/` rows | The implementer writes them | The rows record the owner's decision; this spec is that decision, taken 2026-09-15, and the rows quote it |

## Known Limitations
- The filter claims BGP sessions only. BFD and VRRP GTSM sessions quote no TCP header, so their related messages stay Unknown, as before this spec.

## Core Insight
A guard that identifies a flow by a field its consumer never reads protects against one attacker only. `tcp_v4_err` finds the socket by the quoted 4-tuple, so the filter in front of it has to key on the same bytes, or the attacker picks the outer source and walks past.
