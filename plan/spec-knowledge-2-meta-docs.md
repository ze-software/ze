## Task

Four hand-maintained knowledge documents have drifted from the tree they
describe, and none of them has a gate. Child 1 fills `DESIGN-HISTORY.md` with
consolidated knowledge; this spec makes all four checkable so they cannot rot
again.

| Document | Measured state | Change |
|----------|----------------|--------|
| `ai/LEARNED-INDEX.md` | 282 entries, median 190 characters after the link, mean 414, max 2472. 75% exceed the 120-character pointer budget that `ai/rules/detail-budget.md` already sets. 117 KB of its 148 KB is description recoverable from the summaries it links | Enforce the existing budget; move the substance back into the summaries |
| `plan/learned/HOOK-FRICTION.md` | 1,573 lines, 44 entries, 12 already marked dead. Names 16 `.sh` hook files that no longer exist, and one check (`c_rfc_tagged_test`) that never existed | Add a dead-name lint. Do not generate it |
| `plan/learned/DESIGN-HISTORY.md` | 3 commits lifetime, last content change 2026-04-23. `check_doc_links.py` deliberately exempts it, which is why its rot was invisible | Remove the exemption and add a freshness check. Child 1 supplies the content |
| `plan/learned/RECURRING-PATTERNS.md` | 862 lines, 28 patterns. One is dead outright, two name retired `.sh` files, two are now enforced by a gate | Delete the dead entry, fix the stale names, mark the gated ones |

`ai/LEARNED-FULL-INDEX.md` is not in scope: it is generated by
`scripts/dev/learned_index.py`, obeys the pointer budget already (median 27
characters, 0% over), and is the proof that generating what can be generated is
the right answer.

## Data Flow (MANDATORY - see `ai/rules/data-flow-tracing.md`)

### Entry Point
- `make ze-doc-test` runs `check_doc_links.py` over the `MD_GLOBS` corpus.
- A hook check is renamed or removed in `.claude/hooks/`.

### Transformation Path
1. `check_doc_links.py` `check_markdown` walks each enrolled markdown file.
2. A new budget check measures each `ai/LEARNED-INDEX.md` entry after its link
   and reports any over 120 characters.
3. A new name lint extracts backticked `*.sh` and `c_*`/`check_*` tokens from
   `HOOK-FRICTION.md`, `RECURRING-PATTERNS.md` and `ai/rules/hook-mapping.md`.
4. It resolves them against `.claude/hooks/*` filenames and the set of top-level
   `def c_*`/`def check_*` names parsed from both trees with `ast`.
5. An unresolved name fails unless its line sits under `## Retired` or its table
   row says `Retired` or `Fixed at the source`.

## Design Insights

- The generated index obeys the budget and the hand-maintained one does not.
  That contrast is the whole argument for gating anything hand-maintained.
- `DESIGN-HISTORY.md` rotted precisely because it was exempted from the only
  checker that would have noticed. An exemption is a decision to stop looking.


### Two spec premises were WRONG (2026-08-01, found by implementing)

**1. The checker's path.** This spec said `scripts/docvalid/check_doc_links.py`
throughout. That file does not exist. The real one is
`scripts/dev/check_doc_links.py`, and the difference is load-bearing rather than
cosmetic: `scripts/dev` is an entry in `pythonTestRoots`
(`scripts/dev/python_tests_test.go`), so a test placed there is discovered and
run by `TestPythonUnitTests`. A test written at the path this spec named would
have run nowhere while looking present. Corrected throughout.

**2. AC-5 is unsatisfiable as worded.** It required the lint to catch a
`c_rfc_tagged_test` citation in `ai/rules/hook-mapping.md`. That file contains
zero occurrences of that token; it cites `rfc-tagged-test`, the registry LABEL,
which is legitimate. The 4 real `c_rfc_tagged_test` citations are all in
`plan/learned/HOOK-FRICTION.md`. The premise came from a research report the
main thread did not verify before writing it into an acceptance criterion. The
intent (catch the dead name wherever it appears) was applied to both files.

**3. The resolution set had to widen, which is R-1 firing.** Restricting
resolution to the 5 named sources reported `check_frozen_verbs`
(`scripts/dev/ste_check.py`) and `check_coverage_ratchet`
(`scripts/dev/rfc_requirements.py`) as dead. Both are live. The lint now parses
every tracked `.py` under `scripts/` and `.claude/hooks/` and resolves `.sh` by
basename tree-wide, while still asserting the 5 required sources are present and
parseable so it fails closed when one goes missing.

**4. Generated-file coupling, resolved.** Deleting summaries 294 and 363 left
three broken references inside `ai/rules/CONDENSED.md`, which is GENERATED. The
source rules had been repointed, but the digest predated that. Regenerating
cleared them. The digest was already modified before this session began and its
last commit belongs to a concurrent session, so it stays OUT of this commit and
its owner regenerates on top.

## Key Design Decisions
| Decision | Alternatives Considered | Rationale |
|----------|------------------------|-----------|
| Lint `HOOK-FRICTION.md`, do not generate it | Generate from a data file plus the check registry | Its value is prose and its 44 entries use five inconsistent field labels. Generation is 44 manual re-authorings for a mechanical benefit a lint delivers in 80 lines |
| Both checks live inside `check_doc_links.py` | Two new make targets | That file already walks the enrolled markdown corpus and already includes `ai/LEARNED-INDEX.md`, so there is no new wiring and no new target to discover |
| Rebuild and gate `DESIGN-HISTORY.md` | Retire it, as originally planned | It is the purpose-built home for the knowledge child 1 extracts, and 8 places already point at it |

## Known Limitations

- The lint checks that a name exists. It cannot check that the prose describing
  the check is still accurate.
- The freshness check can compare coverage against the corpus. It cannot tell
  whether a subsystem section is a good summary of what it absorbed.
