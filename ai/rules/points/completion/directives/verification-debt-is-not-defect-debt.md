**Verification debt and known defects MUST be recorded truthfully and kept distinct.** An unrun check leaves behavior unverified; it does not establish correctness. A failed check is evidence to diagnose, including when another session's unfinished changes caused it. A known existing-capability defect remains a defect until fixed, and recording it does not discharge the scoped fix obligation or satisfy an unmet acceptance criterion. Classify absent RFC requirements under `ai/rules/rfc-compliance.md`; do not relabel them as verification debt or infer permission to implement them.
**The admission keywords on `./le commit create` are self-service, and you MUST NOT stop to ask Thomas before using one.** `review-override`, `rfc-change-ok`, `structural-red-ok` and `broken-head-fix` each take a truthful one-line reason and write it into the commit as a trailer; a commit is never refused for a missing verification.
**Verification debt MUST be derived, never written: no file records it, and `deriveDebt` (`internal/le/commit/owed.go`) reads it from git, the commit trailers and the scoped record `./le verify changed` writes, on every ask.** Enforcement is at the push, where code reaches users: `./le commit push` refuses while a commit it would publish is not covered by a scoped record, or carries an open `Review-owed:` or `RFC-approval-owed:` trailer. `./le verify changed` over the commit clears the first; a clean review, a recorded Review Gate or a later `RFC-approved:` trailer clears the second. `./le commit create ... attest <commit> "<owner words>"` is an owner attestation and MUST NOT be used where one of those answers applies.
