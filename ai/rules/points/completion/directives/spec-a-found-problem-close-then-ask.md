**A small problem found while working on something else MUST be fixed in the work in hand, and the scope of the spec being worked MUST be widened to carry it: the spec's Task section names the fix and an acceptance criterion covers it, so review and closure judge it (`ai/META-DECISIONS.md`).** A problem is small unless its fix needs a design of its own or an investigation with no end in sight, which is what derails the work it was found in; when unsure, it is small. The fix lands as a commit of its own (`git-safety.md`). A journal row or a new spec MUST NOT stand in for a small fix.
**A problem too big for that MUST be recorded in `plan/journal/<class>.md`, and the implementation scope MUST NOT grow to carry it.** Search `plan/journal/` for the symptom first and use the existing five columns, `| Date | Spec | Surface | Symptom | Fix |`. List the row in the owned journal rows table of the spec that will fix it, commit both, and close the work in hand against its agreed criteria; a finding is not authorization to implement that spec now (`rule-precedence.md`).
**The spec that will fix it MUST be an existing one wherever an existing spec's scope can be amended to take the problem, and a new spec MUST NOT be written until that search has come up empty.** Search `./le spec status` and the work-item folders for a spec that changes the same mechanism, and amend it; `docs/contributing/spec-workflow.md`, "Choosing the destination", carries the order.
**A row MUST NOT exceed 600 characters, and its Fix cell MUST start with `fixed: ` or `open: `. A class is due for a fix pass when `./le spec journal report` marks it DUE: a class captured by a check on its first row dated after the capture, any other class when its counted rows reach the threshold the report prints.** The detail goes in the fix commit, a spec, or `ai/rationale/`: `./le commit create` refuses a longer row added or rewritten against HEAD (`ValidateFile`, `internal/le/spec/journal/validate.go`), and `./le spec journal report` lists the due classes first.
**Defects exposed by scoped proof and defects that block an agreed acceptance criterion MUST follow the fix obligation above.** Proximity to edited code does not make a big problem small: the test is the design or the investigation its fix needs. An absent requirement of an implemented RFC gets its gap record under `ai/rules/rfc-compliance.md`: it is owed work, never a question to the owner.
**Reports MUST state findings that limit the claimed baseline, including unresolved defects and unverified behavior.** Record enough evidence to distinguish an existing-capability defect from an absent feature, but do not turn unrelated discovery into an uncommissioned investigation.
