**A small defect the goal does not depend on MUST be fixed in the work in hand, with the spec's scope widened to carry it and the fix in a commit of its own (`completion.md` carries the size test).** Recording it and walking away is the misreading `ai/META-DECISIONS.md` names.
**Closing comes first for a big one: a defect the goal does not depend on, whose fix needs a design or an open-ended investigation of its own, MUST NOT be fixed on the way to closing the work in hand.** `completion.md` makes you the owner of a defect you walked into, and it does not make you its owner this minute. Work that was finished but never landed is the most expensive failure this repo has, and a large unrelated fix grown inside it is its usual cause: it costs the commit its single focus and the review its scope, and it restarts the gates that were already green.
**For the big one the route is fixed and it has three steps: MUST write one row in `plan/journal/<class>.md` and list it in the owned journal rows table of the spec that will fix it, close the work in hand, and stop.** MUST NOT record it anywhere else, and MUST NOT ask Thomas whether to implement it (`completion.md`). MUST NOT fix it after closing either, unless its investigation is complete and the next point's conditions hold. Rows accumulate by problem class, and a class that collects rows earns its fix in a deliberate pass over the journal.
**Every open row MUST be owned, and the owner MUST be an existing spec wherever one's scope can be amended to take the defect: a new spec, homed per `planning.md`, is written only after that search comes up empty.** `./le commit create` refuses a commit that adds or changes an open row no spec's table lists (`plan/journal/README.md`, "Owned rows"). Resolving rows follows `plan/post-release/engineering/spec-journal-resolution.md`.
**Two more finds are fixed on the spot whatever their size: a test that is wrong about what it asserts, and code related to the problem in hand.** A red test or a red gate is not a third: `pre-release.md` routes it. A defect that blocks the goal of the work in hand is not a find at all. It MUST be fixed, because there is no closing the work in hand around it (`completion.md`).
