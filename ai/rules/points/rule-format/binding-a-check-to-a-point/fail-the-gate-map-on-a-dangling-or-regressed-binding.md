A binding that names a point which does not exist is DANGLING and fails `./le rules gate-map-report`. So are a bare `none`, an empty payload, and a `// ze point:` line outside a top-level function's Go doc comment. The native action registry is fail-closed: every registered check needs a binding, and a binding on an unwired function fails. The gated set is MONOTONIC against git HEAD. A point that carried a binding at HEAD and carries none now REGRESSES and fails. This closes the route from gated to ungated where the comment and the rule stem disappear from the published row together. The same target compares the Hook-to-Rule Mapping table in `ai/rules/repo-maintenance.md` against these comments, so its `Check` and `Enforces` columns cannot drift from the registered functions.
