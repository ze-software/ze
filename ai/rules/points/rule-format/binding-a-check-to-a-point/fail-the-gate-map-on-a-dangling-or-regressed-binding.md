A binding that names a point which does not exist is DANGLING and fails `make ze-rules-gate-map`. So are a bare `none`, an empty payload, and a comment separated from its `def` by code. The gated set is also MONOTONIC against git HEAD. A point that carried a binding at HEAD and carries none now REGRESSES and fails. That closes the one route from gated to ungated that leaves every gate green: delete the comment and the rule stem from its published row together. The same target compares the Hook-to-Rule Mapping table in `ai/rules/repo-maintenance.md` against these comments, so the published `Check` and `Enforces` columns cannot drift away from the checks they describe.
