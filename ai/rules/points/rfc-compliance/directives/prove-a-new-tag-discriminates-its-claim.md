**A tag you add, and a tagged unit whose behavior or claim you change, MUST carry a discrimination record in the same change.** A tag's prose states what its test demonstrates, and no gate can read a sentence, so the proof is a recorded break of the producing code under which that tagged unit itself goes red. `./le rfc discriminate stem <stem> report <path>` proposes the candidate breaks, `./le rfc record` observes one and writes the record, and `./le rfc check` refuses a tagged unit the commit under test added against `HEAD^` and that carries none. The main thread runs these three commands, and an agent lists them as owed commands.
**A commit that changes a tagged test or its claim MUST carry the record `./le rfc record` re-took, or remove the tag with the judge's approval.** The proof belongs to the test, so it goes stale only when the tagged unit or its claim changes: a change to the code the test checks, the producer or paired producer the record broke included, changed, renamed or removed, leaves it standing, because the unchanged test still catches what it caught. `./le commit create` refuses a commit that stales a record the parent held fresh, or deletes one while its tag stays, and its refusal prints the `./le rfc record` line that re-takes each one on its recorded route; a record already stale at the parent refuses nothing. The two proof routes, the closed escape vocabulary and the refusals are in `docs/contributing/rfc-conformance-gates.md`.
**The claim MUST state what the test body checks, and MUST NOT state more.** A claim wider than the assertion converts an unproven MUST into a proven one on the public ledger, which is the violation with a green bar on top. Rewording a claim stales its record and owes a fresh one, because a proof of the old sentence is not a proof of the new one.
