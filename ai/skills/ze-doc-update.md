# Doc Update

Sync the wiki (`../wiki`) and in-tree docs (`docs/`) with all user-facing changes since the last documented commit.

See also: `/ze-commit` (commit after updating)

## Wiki layout

The wiki is a separate git repo at `../wiki`. It mirrors content from `docs/` but is
structured for the GitHub wiki renderer. Key files:

| File | Role |
|------|------|
| `_Sidebar.md` | Navigation tree. New pages must be linked here. |
| `feature-inventory.md` | Master feature list. Every feature gets a row. |
| `status.md` | Honest ledger of what works. |
| `comparison.md` | Ze vs other daemons. |
| `command-reference.md` | All CLI commands. |
| `show-commands.md` | Day-2 operator quick reference. |
| `plugins.md` | Plugin catalogue by category. |
| `glossary.md` | Term definitions. |
| `llms.txt` / `llms-full.txt` | Generated by `go run bin/gen-llms-txt.go`. Never hand-edit. |
| `.source-commit` | SHA of the last main-repo commit the wiki reflects. |

## Steps

### Phase 1: Enumerate

1. **Read the sync point:** `cat ../wiki/.source-commit`.
2. **Enumerate the delta:** `git log <source-commit>..HEAD --oneline --no-merges`. Extract all `feat:`, `fix:` (behavior change), `refactor:` (user-visible), `perf:` (user-visible), config, CLI, API commits. Skip: ai/rules churn, spec lifecycle, test-only, doc-only commits that already updated in-tree docs.
3. **Group by feature area, not by commit.** Multiple commits implementing the same feature (e.g. ipsec-1 through ipsec-11) produce one wiki section, documenting the final state. Present a summary table mapping feature areas to affected wiki and docs/ pages.
4. **Confirm scope:** Proceed immediately unless the user redirects.

### Phase 2: In-tree docs (`docs/`)

5. **Check `docs/` for staleness.** For each feature area in the delta, check whether the corresponding `docs/` file was updated by the commits themselves (`git diff --stat <source-commit>..HEAD -- docs/`). If a feature has no corresponding docs/ update, or if the docs/ content is inconsistent with the code, update it.
6. **docs/ file mapping.** The in-tree docs are organized as:

| Directory | Content |
|-----------|---------|
| `docs/features.md` | Master feature table with status column. Every feature gets a row. |
| `docs/features/*.md` | Per-feature detail pages (bgp-protocol, interfaces, plugins, etc.). |
| `docs/guide/*.md` | Operator guides (configuration, cli, command-reference, rpki, firewall, etc.). |
| `docs/guide/command-reference.md` | Canonical command reference. Wiki mirrors this. |
| `docs/comparison.md` | Feature matrix vs other daemons. |
| `docs/performance.md` | Generated by `ze-perf report --doc`. Only update if regenerated. |
| `docs/config-reference.md` | Config syntax reference. |

7. **Update docs/ files** that are stale. Common gaps:
   - `docs/features.md` missing a row for a new feature
   - `docs/comparison.md` showing "No" for a feature Ze now has
   - `docs/guide/command-reference.md` missing new commands
   - `docs/config-reference.md` missing new config blocks
   - No `docs/guide/<feature>.md` for a new subsystem (create it)

### Phase 3: Wiki (`../wiki`)

8. **Create new wiki pages** for major new subsystems. Each page starts with the pre-alpha banner (`> **Pre-Alpha.** This page describes behavior that may change.`) and ends with a "See also" section and an adapted-from note.
9. **Update existing wiki pages.** For each affected page:
   - Read the current page first
   - Add new sections, rows, or entries for new features
   - Update existing descriptions that changed
   - Do NOT rewrite unchanged sections
   - Do NOT remove existing content unless it is factually wrong
10. **Checklist of wiki pages to check on every sync** (even if no commit seems to touch them):
    - `feature-inventory.md` -- every new feature gets a row or table entry
    - `plugins.md` -- new plugins get a row in the right category
    - `status.md` -- new working features get a row
    - `command-reference.md` -- new CLI commands
    - `show-commands.md` -- new show/monitor commands
    - `_Sidebar.md` -- new pages linked
    - `comparison.md` -- new differentiators or removed gaps
    - `glossary.md` -- new terms
    - `cli.md` -- new pipes, entry points, command groups
11. **Update `_Sidebar.md`** if new pages were created. Place them in the appropriate section.
12. **Regenerate llms files:** `cd ../wiki && go run bin/gen-llms-txt.go`. These are generated from `_Sidebar.md` and page content. Never hand-edit them.
13. **Bump `.source-commit`:** Write `git rev-parse HEAD` to `../wiki/.source-commit`. This is the LAST content step.

### Phase 4: Regenerate reverse index

14. **Regenerate `ai/CODE-TO-DOCS.md`:** Run `./le docs-to-code index-update` to update the code-to-docs reverse index. If any docs/ source anchors were added, changed, or removed, this keeps the index in sync.

### Phase 5: Commit

16. **Prepare the wiki commit with the native commit action.** Run
`ZE_REPO_ROOT=../wiki ./le commit create` from the main checkout, name every
changed or new wiki path with its own `file` keyword, and use this message:

```
docs(wiki): sync wiki with <old-short>..<new-short> (<N> commits)

New pages: <list if any>.

Updated <N> existing pages covering: <feature list>.

Co-Authored-By: Claude <model> <noreply@anthropic.com>
```

Run the generated commit script yourself.

17. **In-tree docs/ changes** are in the main repo working tree. Do not commit them; the user handles that separately (or via `/ze-commit`). Report which `docs/` files were changed so the user knows.

## Rules

- **Group by feature, not by commit.** A feature implemented across 5 commits gets one section documenting the final state, not 5 incremental patches to the wiki.
- **Read source before documenting.** At minimum: register.go, main implementation file, and YANG schema for config features. Do not document from commit messages alone.
- **Read wiki pages before editing.** Every page you plan to edit must be Read first. Edit surgically.
- **`.source-commit` is bumped LAST.** Bumping it claims all intermediate commits are documented.
- **Preserve existing content.** Only add or modify sections relevant to the delta.
- **Match the wiki's tone.** Pre-alpha banner, short paragraphs, tables for reference, code blocks for config examples. No em dashes.
- **Be exhaustive.** Check every page in the checklist (step 7). A feature that only updates the topic page but not feature-inventory.md, plugins.md, status.md, and command-reference.md is incomplete.
- **llms files are generated, never hand-edited.** Always regenerate with `go run bin/gen-llms-txt.go` after all edits.

## Scope Decisions

| Change Type | Wiki | docs/ |
|-------------|------|-------|
| New feature (feat:) | feature-inventory.md + plugins.md + status.md + topic page + command-reference.md | docs/features.md + docs/features/<area>.md + docs/guide/<topic>.md |
| New subsystem | New wiki page + all of the above + _Sidebar.md + comparison.md | docs/guide/<subsystem>.md (create) + docs/features.md row |
| Config syntax change | Topic page config table | docs/config-reference.md + docs/guide/<topic>.md |
| CLI command change | command-reference.md + show-commands.md + cli.md + topic page | docs/guide/command-reference.md |
| New pipe operator | cli.md + show-commands.md + command-reference.md | docs/guide/command-reference.md |
| Bug fix (behavior change) | Topic page | docs/guide/<topic>.md if behavior is documented |
| Performance (user-visible) | performance.md or topic page | docs/performance.md only if regenerated |
| Refactor (no behavior change) | -- | -- |
| Internal (test, CI, tooling) | -- | -- |
| API/RPC change | rest-api.md or grpc-api.md | docs/guide/api.md |
| Go version bump | building.md | -- (go.mod is the source of truth) |
| New build target | building.md + possibly new page | docs/guide/<target>.md |
| Comparison change (new Ze capability, removed gap) | comparison.md | docs/comparison.md |

## Error Cases

| Problem | Action |
|---------|--------|
| `.source-commit` hash not found in git log | Ask user. The wiki may be ahead of or behind the repo. |
| Commit touches code you cannot read | Use `git show <hash> --stat` and source files. Note uncertainty. |
| Wiki page does not exist for a new feature | Create it. Add to `_Sidebar.md`. |
| Feature was added then modified in the same delta | Document the final state only. |
| `go run bin/gen-llms-txt.go` fails | Check that `_Sidebar.md` links are valid slugs. Fix broken links first. |
