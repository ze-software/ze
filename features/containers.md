## Description

Ze runs OCI container images itself, confined and supervised, through the upstream runtime library behind a patch series. What exists, in a build with `ze_container`: the `container` plugin with its config root (`container instance <name>` and its `enabled` leaf), the command `request container restart name <name>`, the container init role inside the `ze` binary, a start path (description, root overlay, create, release, watch) that no test has yet proven on a real kernel, the plugin's doctor codes and runtime doctor checks, and the kernel requirement for a hard CPU limit (`CONFIG_CFS_BANDWIDTH`). `ze_container` is in the default daemon build and in the appliance build, and that build links the image store, which fetches images. Four commands answer: `request container restart name`, `show container list`, `show container image list` and `create container image reference`. The store's other commands refuse as not implemented in this build. A container that declares volumes is refused at start.
