## Description

Offline pre-start checks: runtime platform detection (gokrazy, systemd, container, plain-linux, darwin) with capability probing (read-only root, /perm, systemd, gokrazy socket, reboot, persistent storage), config syntax, YANG validation, TLS certs (missing/expired/invalid), VPP socket, kernel modules, interface existence/state, SSH host key, listener conflicts, plugin binaries, storage integrity, dangling config references, disk space (<5% free), DNS resolver reachability, clock skew (>5 min vs NTP), VPP version (Linux), VPP hugepage reservation (Linux). Platform-aware checks: gokrazy /perm writability, container read-only root, missing Ze-managed clock synchronization, platform-mismatched persistence/DNS paths, and Linux machine-id presence. Config-delivery audit: `doctor-config-root-unclaimed` names a configured subtree that commits and reaches no plugin and no hub handler, with `doctor-config-claims-unavailable` when the claim set cannot be read. Other codes added since: `doctor-tls-reference` (a `certificate` name the PKI store does not hold), `doctor-pki-ca-root-missing` and `doctor-pki-ca-root-expiry` (the local certificate authority root absent, or within 90 days of expiry), `doctor-bgp-capture-directory` (a capture directory the daemon cannot write), `doctor-iface-ra-forwarding` (a unit advertising while its device has IPv6 forwarding off), and `doctor-vpp-lcp-plugin` (`vpp.lcp` on while the running VPP loads no `linux_cp_plugin.so`; a failed probe degrades to a warning rather than an error). Kernel capability gate: a subsystem registers the kernel feature it needs, a predicate that reads the config tree, and a native probe (netlink or procfs, never an external binary). When the configuration uses the subsystem and the kernel lacks the feature, `ze doctor` reports it at error severity, `ze` REFUSES to start with the same message and exit 1, `ze config validate` fails, and a reload is refused with the running configuration still serving. A capability that cannot be DETERMINED warns and ze starts, so an unreadable probe never turns a working deployment into a dead one. There is no operator override. MPLS (`CONFIG_MPLS_ROUTING`, from the fib kernel plugin) and IPsec (`CONFIG_XFRM_USER`, from the ike engine) are enrolled. An empty `vpn { ipsec { } }` block installs no Security Association, so it gates nothing, warns about no kernel module and binds no IKE listener: one predicate answers for all three.
