## Description

YANG nodes that correspond to backend-specific features carry a `ze:backend "<names>"` annotation. The config component runs one whole-tree walk over the tree as written (before any schema default is materialized) at both config doors (`LoadConfig` and `verifyTree`) and in `ze doctor` (`doctor-dataplane-mismatch`), judging each subtree against the declared `DataPlaneSelector` that governs it and any node outside every declared selector root (such as `container network`) against the primary data-plane selector (`interface backend`). Whenever the active backend does not implement the feature, the walk rejects the config with the YANG path, the supporting backends, and the fix command -- instead of letting an Apply-time "not supported" error fire inside the backend. The gate covers `pppoe` access interfaces (refused when the build holds no session provider for the backend `interface backend` selects, so VPP access interfaces need a `ze_vpp` build; global settings without access interfaces remain valid on any backend), `interface` (kernel-only `bridge`, `tunnel`, `veth`, and `vrrp` under the `vpp` backend), `traffic/control` (judged against `traffic control backend`), `firewall` (`ze:backend "kernel"` annotations on `connection-mark`, `notrack`, `connection-mark-set`, `tcp-mss-clamp-to-pmtu`, and the `flowtable` list), and `container` (`container network` judged against `interface backend`). <!-- source: internal/component/l2tp/pppoe/backend_gate.go -- validateBackendGate, registered original-tree validation --> <!-- source: internal/component/config/yang/modules/ze-extensions.yang -- extension backend --> <!-- source: internal/component/config/backend_gate.go -- walkBackendFeaturesTree, validateBackendFeatures, walkBackendNode --> <!-- source: internal/component/config/dataplane_verdict.go -- evaluateDataPlaneVerdict, evaluateBackendFeatureWalk --> <!-- source: internal/component/config/loader.go -- loadConfig, refuseDataPlaneMismatches --> <!-- source: internal/component/config/plugin_verify.go -- verifyTree, refuseDataPlaneMismatches -->
