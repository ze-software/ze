## Description

Packet filter and NAT via the nftables backend on Linux. The abstract model's match types are the `Match` implementations in `internal/component/firewall/model.go`: source/destination address, port ranges, protocol, input/output interface with wildcard prefix, connection state, marks, DSCP, ICMP type, ICMPv6 type, TCP flags, named sets, IPv4 TTL below a threshold, the TCP port and destination quoted inside an ICMP error, ARP operation and sender address, and ND target address. Its action and modifier types are the `Action` implementations: accept, drop, reject, jump/goto/return, SNAT/DNAT with address ranges, masquerade, redirect, notrack, flow offload, set mark/connmark/DSCP/TCP-MSS, counter, log, rate limit. NAT exclude rules emit a Return verdict to skip translation. Global-options container maps keyword toggles (all-ping, broadcast-ping, syn-cookies, source-validation, etc.) to kernel sysctls via the sysctl plugin's default layer; explicit sysctl settings always override. IRR-based prefix-list filtering: `source-asn`, `source-as-set`, `destination-asn`, `destination-as-set` leaves in from-block resolve ASN/AS-SET references to nftables interval sets via the shared IRR PrefixStore (`firewall-irr` plugin). Per-interface source validation: bind an AS-SET to a customer-facing interface via `irr { interface <name> { source-as-set <AS-SET>; } }` to drop ingress traffic with source addresses not in the IRR-resolved prefix set (BCP 38). An IRR answer carrying no prefixes never replaces cached ones: the store keeps the last known good list, `show firewall irr` reports the entry as `stale` with the age of the data, `ze doctor` reports it, and `clear firewall irr asn\|as-set` is the only path that removes prefixes. A binding with no prefixes produces no table at all, so an empty answer cannot leave an interface dropping everything. DNS-sourced address groups: a `domain-group` holds `domain-names`, and `source-domain-group` / `destination-domain-group` leaves in the from-block match the addresses those names resolve to (`firewall-domain` plugin). Each name is re-resolved on its own answer TTL, per family, clamped by `ttl-floor`, and the set is reprogrammed only when the addresses actually changed. Only NXDOMAIN empties a set: a SERVFAIL, a REFUSED or an unreachable server keeps the last good addresses, so a DNS outage is never enforced as a filter. Resolved addresses persist in ZeFS, so a restart with DNS down resumes filtering from them, and every change is appended to a bounded JSON-lines log at `<config-dir>/firewall-domain-group.dns.jsonl`. `show firewall ruleset` shows the DNS name beside each address through the show-enricher registry, adding no field to the shared set model. <!-- source: internal/component/firewall/plugins/irr/sets.go -- buildIfaceTables --> <!-- source: internal/component/resolve/irr/store/store.go -- Refresh keeps last-known-good, Purge --> Component reactor wires into ze's engine lifecycle: Apply on boot and reload, rollback on failure. `ze_` prefix on all kernel tables. Every backend Apply is bounded by a deadline: 10s by default, clamped to 1s..60s (`ze.firewall.nft.netlink-timeout`, ceiling `firewall.MaxBackendDeadline`). The bound is load-bearing rather than cosmetic, because `ApplyAll` holds one process-wide reconcile lock across `Backend.Apply`, so an unbounded kernel call would stall every firewall owner (copp, policy-routes, ddos-local, the firewall engine) and not just one.
