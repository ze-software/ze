# Feature-gate manifest -- SINGLE SOURCE OF TRUTH for compile-out-able features.
#
# One line per gated package:  <build-tag>   <gated-package>
#
# A feature guarded by //go:build <build-tag> is reached ONLY through gated
# registration (the construction registry in cmd/ze/hub/service_registry.go, or
# an ssh_infra.go-style seam). Nothing always-on (untagged, non-test) imports
# <gated-package>; that is what lets the linker drop it when the tag is off.
#
# THIS FILE IS THE ONE PLACE A GATE IS DECLARED. Every consumer DERIVES from it,
# so adding a gated package is a one-line edit here -- not old five-place hand-wiring:
#   - Makefile ZE_FEATURES                      default-on tags for ze / ze-appliance
#   - internal/test/runner TestBuildTags        tags for the functional-test ze binary
#   - scripts/codegen/plugin_imports.go         featureTags: gates <pkg> and <pkg>/yang into all_<tag>.go
#   - scripts/dev/dep_audit.py DISABLEABLE      no always-on import of <pkg>
# Three consumers cannot read this manifest at runtime -- .golangci.yml build-tags,
# gokrazy/ze/config.json GoBuildTags, and docs/guide/quickstart.md's `go install`
# command -- so scripts/codegen/feature_tags.go GENERATES them from this file
# (`make generate`); do NOT hand-edit their tag lists. Drift is gated by the
# scripts/codegen feature_tags --check test, `dep_audit.py --check` (golangci), and
# the appliance gokrazy test. scripts/dev/stress-repro.py reads this file directly.
#
# To add a feature gate: add each owned package that must disappear below, create
# register_<tag>.go + service_<tag>.go (listener service) or a gated seam
# (ssh/gNMI shape), run `make generate`. Full procedure:
# ai/rules/feature-gate-registration.md.
#
# Lines are "<tag> <pkg>"; '#' comments and blank lines are ignored. Reuse the
# same tag for feature-owned sidecar packages such as command schema. The
# generator gates both the direct package and its <pkg>/yang schema package when
# either is discovered.
#
