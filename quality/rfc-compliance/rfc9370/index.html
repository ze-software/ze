Enrolment

Not enrolled (out-of-scope, the requirements ARE extracted and the owner decided not to offer the feature for now, so the absence is a scope decision rather than a conformance gap): OUT OF SCOPE as a document by owner decision, 2026-10-26: the owner rule committed in 1e7a9dbc34 (ai/META-DECISIONS.md, Goal and scope) counts an RFC a profile lists as optional only once Thomas brings it into scope, and this summary's `Optional use cases` row lists this RFC in the optional tier of the vpn-endpoint and vpn-concentrator profiles. The extraction is COMPLETE: the source text is at rfc/full/rfc9370.txt and the extraction sign-off is rfc/extraction/rfc9370.json. Ze implements none of it, and each MUST-level row keeps its `{gap}` note naming the absent producer: all 23 MUST-level requirements are classified, and all 23 are `{gap}`, because Ze's IKE engine implements neither the IKE_INTERMEDIATE exchange (RFC 9242) nor IKE_FOLLOWUP_KE, nor the ADDKE Transform Types 6 to 12. `internal/component/ike/wire/header.go` declares exchange types 34 to 37 only, and `internal/component/ike/wire/payload_notify.go` declares neither ADDITIONAL_KEY_EXCHANGE (16441) nor STATE_NOT_FOUND (47). One Appendix C site states the rationale for a discarded alternative design and is excluded in the extraction sign-off.

What the public ledger says

Status: Future

What the ledger says is covered None: an IKE SA and each Child SA run one Transform Type 4 key exchange. A proposal carrying a Transform Type the engine does not use is refused as a whole proposal (internal/component/ike/crypto/proposal.go::TransformTypeUnderstoodIKE, ikeProposalComplete), which is how an ADDKE Transform Type is treated today, but no test asserts that against an ADDKE type.
What the ledger says remains ADDKE Transform Types 6 to 12, INTERMEDIATE_EXCHANGE_SUPPORTED negotiation, IKE_INTERMEDIATE key exchange rounds, IKE_FOLLOWUP_KE (44), ADDITIONAL_KEY_EXCHANGE (16441), STATE_NOT_FOUND (47) and the multi-secret SKEYSEED update are absent. All 23 MUST-level requirements are annotated {gap} in rfc/short/rfc9370.md. Out of scope by owner decision, 2026-10-26.

the sentence states a fact or describes another document, and directs no implementation		 Appendix C lists alternative designs the authors considered and discarded. This sentence closes the bullet 'Sending post-quantum proposals and policies in the KE payload only', and states what that discarded design would have needed to resist the downgrade attack it describes. The adopted design negotiates additional exchanges through ADDKE Transform Types in the SA payload (Section 2.2.1), so no implementer of this document is bound by the sentence. Therefore, in order to fully prevent any downgrade attacks, using a KE payload alone is not sufficient, and the initiator MUST always indicate its preferred post-quantum proposals and policies in a notify payload in the subsequent IKE_SA_INIT messages following an N(INVALID_KE_PAYLOAD) response.
