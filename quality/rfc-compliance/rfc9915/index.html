Enrolment

Enrolled: DHCPv6 client of the iface-dhcp plugin; RFC 8415 to RFC 9915 put in scope by the owner as an exception to the RFC scope freeze, 2026-10-18

What the public ledger says

Status: Partial

What the ledger says is covered Client role only. The iface-dhcp plugin (internal/plugins/iface/dhcp/) runs a long-lived stateful DHCPv6 client per interface unit: Solicit with Rapid Commit and Advertise selection by preference, Request, Renew at T1 to the leasing server and Rebind at T2 without a Server ID, a Confirm after a device down then up for a lease of addresses alone (NotOnLink drops the addresses and solicits again), the section 15 retransmission engine with a per-interface rate limit, SOL_MAX_RT processing, Reply and Advertise validation, IA_NA addresses installed as /128 with the lease's lifetimes, IA_PD prefix delegation published as an event, expiry teardown and Release on Stop. Tests bound per requirement in rfc/short/rfc9915.md.
What the ledger says remains

Nineteen MUST gaps: Information-request (stateless DHCPv6), Reconfigure and the Authentication option are in scope by owner decision 2026-10-19 and not implemented yet, and the requirements only those features meet are annotated {gap} (plan/post-release/features/spec-dhcpv6-client-0-umbrella.md). On the VPP backend, which reports no interface addresses, the client reads no duplicate address detection outcome and declines nothing, so RFC9915-18.2.10.1-1 is unmet there (plan/journal/zero-value-as-valid-answer.md).

Not offered: the User Class, Vendor Class, Vendor-specific and NTP server options, any use of a delegated prefix (ze publishes it and neither subnets it onto other interfaces nor advertises it in Router Advertisements), and a configurable transmission rate limit; the client always uses a DUID-LL unless a duid is configured. Server and relay roles are not implemented.
