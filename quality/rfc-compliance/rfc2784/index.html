Enrolment

Enrolled: Generic Routing Encapsulation (GRE) base header. Ze fills the tunnel endpoint and encapsulator roles by programming gre and gretap tunnels: on Linux through internal/plugins/iface/netlink/tunnel_linux.go::buildGretun and buildGretap (linux:CONFIG_NET_IPGRE), and on the VPP interface backend (iface-vpp, ze_vpp feature gate) through internal/plugins/iface/vpp/tunnel.go::createGRETunnel. The kernel ip_gre module and VPP build and parse every GRE header. All eleven MUSTs are gaps, because the VPP datapath is a shipped path no test verifies. Two are also unmet on Linux: the kernel processes a packet with the Strict Source Route bit or a recursion bit set (2.3-1, 5.2-1). The other nine hold on Linux, from the flags ze writes (GRE_KEY only, no checksum, version 0), and owe tests

MUST 2.3
positiveno testno positive test

{gap}: unmet on Linux and unverified on VPP. The kernel's gre_parse_header (net/ipv4/gre_demux.c, linux:CONFIG_NET_IPGRE_DEMUX) refuses only the Routing bit (bit 1) and a non-zero version; it accepts the Key and Sequence bits (bits 2 and 3, RFC 2890) and never checks the Strict Source Route bit (bit 4) or the recursion bits, so a packet with bit 4 or bit 5 set is processed, and Linux implements no other part of RFC 1701. The Linux path is the verified half: when the payload's route leads back into the tunnel it came from, the kernel's ip_tunnel_xmit (net/ipv4/ip_tunnel.c, linux:CONFIG_NET_IPGRE) finds the route's device is the tunnel itself, counts a collision and drops the packet, on the link internal/plugins/iface/netlink/tunnel_linux.go::buildGretun creates; no test covers it. The VPP half is unverified: iface-vpp (internal/plugins/iface/vpp/register.go, ze_vpp feature gate) installs the tunnel through internal/plugins/iface/vpp/tunnel.go::createGRETunnel, and no test shows VPP discards a looping payload
RFC2784-5.2-1 As stated in Section 5.3, a packet with non-zero bits in any of bits 1-5 MUST be discarded unless the receiver implements RFC 1701. (§5.2) {gap}, no test unmet on Linux and unverified on VPP, as RFC2784-2.3-1. The kernel's gre_parse_header (net/ipv4/gre_demux.c, linux:CONFIG_NET_IPGRE_DEMUX) refuses only the Routing bit and a non-zero version, so a packet with the Strict Source Route bit or a recursion bit set is processed. On VPP, iface-vpp (internal/plugins/iface/vpp/register.go, ze_vpp feature gate) installs the tunnel through internal/plugins/iface/vpp/tunnel.go::createGRETunnel, and no test shows VPP discards it
